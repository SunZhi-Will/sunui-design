# 拋棄紙感，全面改成質感：深度分析（2026-11-18）

> 起因：使用者要的一直是「質感」，不是「紙感」。從 11-04 起，整套設計語言、文案、給 agent 的規則、免費與 Pro 區塊，都建立在「紙」這個錯誤的字上。今天稍早的 `網站質感升級深度分析-2026-11-18.md` 只修了網站外殼，並建議「保留紙感系列、免費 block 不動」，這個方向也是錯的：它把錯誤的根留著，只在外面刷一層。本報告的前提是**紙不再是品牌、不再是預設系列、不再是任何規則的理由**。
>
> 方法：本機原始碼計數（2026-11-18，`grep`、讀 `registry.json`），加上前一份報告已經做過的 Linear / Vercel / Stripe / Resend 實測。Pro 區塊只引用名稱與計數，沒有引用原始碼。

## 一、結論

1. **錯的不是幾個色碼，是推導鏈。** 「紙感」不只決定了 `#f7f7f7` 這種顏色，它還是 DESIGN.md 裡十幾條禁令的理由：不准陰影、圓角 6px 上限、平面、不准毛玻璃、不准任何漸層、動畫要「模擬撕票根」、結果要像「印出來的一行墨字」、齒孔與撕邊是招牌。把紙拿掉，這些規則要逐條重審，不能只換顏色。
2. **紙感滲透的範圍（實測）：**
   - 免費 block：44 個預設走紙感系列（`meta.series` 缺省即紙感），44 個寫死紙面色碼，11 個用 `Stamp`，41 處 `border-dashed`（打孔線）。
   - Pro：60 個目錄寫死紙面色碼，紙、紙邊、墨三組色碼合計約 296 處，`border-dashed` 108 處。
   - 網站：首頁核心示範 `hero-compare` 拿「紙感優惠券」當 SunUI 的代表；首頁開場在程式與註解裡叫「3D 紙牆」；系列標籤「票券」；圖示頁標題「從同一張紙裁出來的圖示」，還宣傳「微斜約 10° 的印章」（這條甚至和 DESIGN.md 禁止傾斜印章互相矛盾）。
   - 給 AI 的出口：`guidelines.ts`（MCP、skill、`llms-full.txt` 共用）第一段就是「Paper commerce」；`llms.txt` 已改成 Refined，但同一段還寫著 "Paper series design language: paper surfaces, ink text"；`registry.json` 有 126 處、`content/registry-i18n` 有 251 處紙與墨的字眼。
3. **最危險的是給 agent 的規則。** 人看網站一次，agent 每次裝 SunUI 都會讀 `get_design_rules`，照「紙是平的、無陰影、rounded-md 以下」去改買家的程式碼。只要這份還在，SunUI 每被用一次，就在外面複製一次紙感。這是第一個要改的地方，而且很便宜。
4. **質感的定義**：不是更花，是**有材質、有光、有精度、有手感**。紙感是「把厚度拿掉」，質感是「把厚度做對」。去 AI 感的底線（藍紫漸層、漸層字、光暈、彩色霓虹陰影、emoji、假倒數、彩帶）照舊，因為那些是 2026 年公認的 AI 樣貌，和紙無關。
5. **時程建議**：Founding 開賣（11-27）前九天，先做「規則與門面」：設計文件、agent 規則、首頁比較示範、開場、OG 圖、Founding 買家會先看到的 Pro 場景。免費 block 與其餘 Pro 在 11-27 到 12-31 用一支 codemod 加人工修整批次重做。凍結令禁止的是「新增」免費 block，重做既有 block 不違反，但要排在 Pro 之後。

## 二、紙感規則逐條重審

把 DESIGN.md 每一條拆成三類：A 是真正的去 AI 感或可用性規則，保留；B 是從紙推導出來的，拋棄或改寫；C 是好規則但被紙的語言包住，改說法保留。

| 現行規則 | 類 | 處理 |
|---|---|---|
| 一句話「紙感電商：紙、墨、齒孔、撕邊」 | B | 刪除，換成第三節的新一句話 |
| 紙 `#f7f7f7` / 紙邊 `#e2e2e2` / 墨 `#171717` 寫死色碼 | B | 改用材質 token（第三節），吃買家 shadcn 主題 |
| 品牌專色 `--sunui-spot` 只用在選中、折扣、進度 | A | 保留，這是 SunUI 最好的一條規則，和紙無關 |
| 不用米白、暖灰、stone | A | 保留（米白襯線鼠尾草綠是新的 AI 預設） |
| 不准漸層 | B/A | 拆開：**裝飾性漸層填色、漸層字**仍禁；**模擬光線的漸層**（表面由上而下 1 到 3% 明度差、邊緣淡出遮罩、金屬或玻璃的高光）允許 |
| 不准光暈、彩色陰影 | A | 保留 |
| 不准模糊、毛玻璃 | B | 改成：毛玻璃只給浮在內容上的功能層（黏頂列、浮動工具列、彈出層），內容層仍不用 |
| 紙是平的，無陰影 | B | 改成四階高度（第三節），陰影永遠帶 hairline，深色模式用頂邊高光 |
| 圓角 `rounded-md` 以下，不用大圓角 | B | 改成同心圓角表，跟 `--radius` 走 |
| 打孔線、半圓缺口是招牌 | B | 拋棄當招牌。只有題材本身就是票券（如登機證、取貨券）才用，而且當作內容不當作品牌 |
| 結果用 `Stamp`，「像印出來的一行墨字」 | C | 元件改名 `Result`（保留 `Stamp` 匯出別名相容舊安裝），視覺改成有材質的狀態列：圖示有描線動畫、底色升一階、品牌專色 |
| 只有三種彈簧 | A | 保留，彈簧本身就是手感。`stamp` 彈簧改名 `pop`，舊名留別名 |
| 只在使用者動作時動，不做進場 | C | 保留核心（不做裝飾性進場、不做常駐呼吸），但允許**浮層落定**：彈出層、抽屜、面板從 `scale(.96)` 與 4px 位移進場，200ms 內 |
| 不做慶祝 | A | 保留不放彩帶煙火；但「結果的那一下」要有份量：一次按壓回彈或描線，不是只淡入 |
| 「動畫要模擬實體：撕票根」 | C | 改寫成「動畫要有物理：質量、慣性、阻尼」，不再綁紙 |
| 單次 400ms 以內、reduced motion、連續性、錨點、密度分層 | A | 全部保留 |
| 數字 tabular-nums、CJK 可替換 | A | 保留 |
| 優惠碼 `tracking-[0.12em]`「像印出來的序號」 | C | 保留寫法，理由改成「等寬序號好核對」 |
| 預覽區不放測試按鈕、真實語氣文案 | A | 保留 |

結論：A 類大約一半，那是 SunUI 真正的資產；B 類正是讓網站和 block 看起來「像線稿、像收據」的那一半。

## 三、新的設計語言：質感

### 一句話

**精密的物件：有材質、有光、有手感。** 黑白灰為底，一處品牌色；物件有厚度，光從上方來，每一下互動都有重量。

### 1. 材質 token（取代紙、紙邊、墨）

block 不再寫死色碼，改讀一組 SunUI 變數，變數預設回退到 shadcn token，所以裝進任何主題都成立。用 shadcn registry 的 `cssVars` 欄位隨 block 一起安裝。

| 角色 | 變數 | 預設回退 | 用途 |
|---|---|---|---|
| 表面 | `--sunui-surface` | `var(--card)` | 卡片、券面、面板 |
| 凹面 | `--sunui-inset` | `var(--muted)` | 輸入框、軌道、未選取格 |
| 邊線 | `--sunui-edge` | `color-mix(in oklab, var(--foreground) 9%, transparent)` | 全部 hairline，alpha 值在任何底色都乾淨 |
| 高光 | `--sunui-highlight` | 淺色 `rgb(255 255 255/.7)`，深色 `rgb(255 255 255/.06)` | 物件頂邊 1px 內高光 |
| 高度 | `--sunui-e1` / `e2` / `e3` | 同網站 `--sh-1/2/3` | 卡片 / 懸停與下拉 / 面板對話框 |
| 文字 | `text-foreground` / `text-muted-foreground` | shadcn | 不再叫「墨」 |
| 品牌專色 | `--sunui-spot` | `var(--primary)` | 不變 |

### 2. 光與高度

- 一頁一個光源，正上方。陰影多層、極淡、負擴散，永遠和 1px 邊線一起出現（數值沿用網站 `globals.css` 已經上線的四階）。
- 深色模式不靠投影：表面提亮一階，加頂邊高光。
- 主按鈕加 1px 內高光與按下 `scale(.97)`；凹面元件（輸入框、開關軌道）用 1px 內陰影，讀起來是「凹進去」。
- 允許的漸層只有一種用途：模擬光。表面上亮下暗不超過 3% 明度差；不准兩種色相以上的漸層。

### 3. 形狀

- 同心圓角：控制項 6px、卡片 12px、面板 16px，內圓角 = 外圓角 − 內距。block 端寫成 `rounded-[calc(var(--radius)+2px)]` 這類跟主題走的值。
- 物件要有邊緣處理：1px 邊線 + 頂邊高光，大面積物件可加極淡的表面漸層。

### 4. 字

- Geist 可變字重 400 / 510 / 590 / 680，字距隨字級收緊，中文不加負字距（網站已經這樣做）。
- block 不綁字體，跟買家主題；但規定字重階與字距表。

### 5. 手感（動效）

- 三種彈簧不變，名稱改為 `snappy` / `gentle` / `pop`。
- 每個可按的東西都要有按下狀態；每個結果都要有「落定」那一下（描線、回彈一次、數字滾動），不是硬切也不是淡入就結束。
- 浮層進場 `scale(.96)` + 淡入，抽屜用 `cubic-bezier(.32,.72,0,1)`。
- hover 進快退慢（出現 0ms，消失 150ms）。

### 6. 招牌：用什麼取代齒孔和印章

紙感的辨識度來自「票券的形狀」，質感的辨識度要來自**互動的品質**，建議三個可被看見的招牌：

1. **按壓的重量**：所有按鈕、卡片、開關都有一致的按下物理（同一組彈簧、同一個 0.97），使用者點過三個 block 就認得是 SunUI。
2. **結果落定**：`Result` 元件的描線勾、計數滾動、外框變形，是全庫共用的一個「成功時刻」。
3. **一處品牌色**：沿用。拖動色票換品牌色的示範，換到質感版的券上依然成立。

## 五、不改會怎樣、改了的風險

- **不改**：網站外殼已經是質感，block 還是紙，首頁說「有質感」，點進去看到的是收據。不一致比單純紙感更傷，買家會覺得是兩個產品拼起來的。
- **風險 1，時間**：P0 加 P1 約 6 個工作天，壓在 Founding 前。如果做不完，P1 的 Pro 場景砍到 6 個，首頁比較示範不能砍。
- **風險 2，已安裝的使用者**：`Stamp` 留別名、registry 名稱不變，舊安裝不會壞；新版 block 需要 `cssVars`，若買家用舊版 shadcn CLI 沒裝到變數，回退值仍會生效，所以 token 一定要寫回退。
- **風險 3，滑回 AI 樣貌**：「允許陰影、模擬光的漸層、功能層毛玻璃」最容易被做過頭。檢查表要寫死上限（陰影不透明度 ≤ 8%、漸層明度差 ≤ 3%、單一色相、毛玻璃只在浮層），並保留「拿掉這個效果會不會遺失資訊或手感，不會就拿掉」這條測試。
- **風險 4，辨識度暫時下降**：齒孔與印章是目前唯一一眼認得的符號。新招牌（按壓重量、結果落定、一處品牌色）要靠首頁比較示範把它講出來，所以那個示範的品質決定這次轉向成不成功。

## 七、限制

- 計數是字串比對，`gradient` 等關鍵字包含遮罩用的正當用法，只當規模參考。
- 「質感」的判斷基於對標與設計推論，沒有使用者測試。
- Pro 場景的實際重做工時沒有逐一估算，6 個工作天是依 codemod 能處理約七成機械替換推算。
