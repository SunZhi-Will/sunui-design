# 首頁首屏文案優化（2026-11-07）

範圍：首頁 hero 的 eyebrow、標題、副標、數量條、比較圖說明。四語已改進 `apps/web/lib/messages.ts`。

## 一、原文診斷

| 位置 | 原文（zh-TW） | 問題 |
|---|---|---|
| 標題 | 黑五、雙 11、聖誕、過年，每一檔的活動頁都能直接上線。 | 1. 檔期順序錯：雙 11 在黑五之前。2.「直接上線」過度承諾，接案者一看就知道還要接 API、換品牌色，反而降低信任。3. 只說「可以做」，沒說痛點。 |
| 副標 | 倒數、優惠券……用紙與墨做成，為行事曆上的每一檔特賣準備。 | 1.「每一檔」與標題重複。2.「紙與墨」在 eyebrow、副標、圖說出現三次，資訊密度低。3.「特賣」是泛詞，台灣電商圈習慣說「檔期、促銷、活動頁」。 |
| 副標尾句 | 程式碼完全屬於你。 | 方向對（shadcn 的核心賣點是擁有原始碼），但抽象。改成可以想像的畫面：「原始碼放進你的 repo，想怎麼改都行」。 |
| 數量條 | 28／其中為動效庫 | 數字在上、標籤在下，讀起來是「28 其中為動效庫」，不通順，也看不出 28 已含在 104 內。 |
| 圖說 | 同一張券、同一個優惠。……拖動中線比較。 | 「同一個優惠」可以更具體（同樣折 $15），右邊沒有點名 SunUI，比較的主角不清楚。 |

## 二、外部參考

- 同類產品的 hero 都是「一句定位 + 一句規格」：Tailark 寫「做行銷網站的 shadcn registry」，Magic UI 寫「給 Design Engineer 的 UI 庫」，副標再列技術棧與數量。SunUI 的差異是有明確的「場景」（檔期），所以標題可以比它們更具體，直接講場景裡的痛點。
- Dev tool 文案的共識是「結果優先、具體優先」，但給內行受眾的工具，功能本身就能暗示好處。所以標題講結果（不必重做），副標講功能清單，兩邊分工。
- 商業模式報告已把主客群收窄為接案者與小型 agency，他們的痛是「每一檔都要重做一次倒數、優惠、加購」，在乎的是從 brief 到上線省幾天，不是區塊數量。新標題直接對這個痛點。
- 台灣電商「月月都是節」，設計工作大量是重複改版（商業週刊報導）。「不必每檔重做」正好說中這件事。

## 三、改寫後（已上線到 messages.ts）

| 位置 | zh-TW | zh-CN | en | ja |
|---|---|---|---|---|
| 標題 | 少一點閃爍，多一點下單。 | 少一点闪烁，多一点下单。 | Less glow, more checkouts. | きらめきは控えめに、注文はもっと。 |
| 副標 | 倒數、優惠券、購物車、結帳到集點卡，不靠漸層和光暈，每一塊都為成交而設計。一行指令裝進專案，或交給你的 coding agent，原始碼歸你。 | 倒计时、优惠券、购物车、结算到集点卡，不靠渐变和光晕，每一块都为成交而设计。一行命令装进项目，或交给你的 coding agent，源码归你。 | Countdowns, coupons, carts, checkout and loyalty cards. No gradients, no glow: every piece is designed to close the sale. Install with one command or hand it to your coding agent, and the source is yours. | カウントダウン、クーポン、カート、購入手続き、スタンプカードまで。グラデーションやグローに頼らず、どのブロックも購入につながるように設計しています。…ソースはあなたのものです。 |
| 動效數量 | 組動效庫（含在免費內） | 组动效库（含在免费内） | motion libraries, included in free | 個のモーションライブラリ（無料に含む） |
| 圖說 | 同一張券，同樣折 $15。左邊是 AI 工具的預設長相……右邊是 SunUI，只有紙和墨。拖動中線看差別。 | 同样减 $15 | same $15 off; Right is SunUI | 同じ $15 引き；右は SunUI |

改寫原則（第二版，2026-11-07 依 Sun 選定「少閃爍，多下單」方向）：

1. **標題主打轉換**：一句話同時說出差異（不靠特效）與好處（下單），對接案者和品牌主都成立。第一版「不必每檔重做」已撤下。
2. **對句節奏**：「少一點……，多一點……」兩段等長，配合標點斷行，桌面與手機都是工整的兩行。
3. **紙感只說一次重點**：eyebrow 說「紙感」，副標用反面定義（不靠漸層和光暈），圖說再用視覺證明。
4. **擁有權收成一句**：「原始碼歸你」。

沒動的：eyebrow 與 metaTitle（「有紙感的 React 電商區塊」）維持不變，避免影響 SEO 與已被索引的標題。

## 四、還沒處理的觀察

1. **CJK 標題斷行（已修）**：原本 zh-TW 標題會斷成「聖／誕」。新增 `components/phrase-text.tsx`，在全形標點後切段、每段 inline-block；h1 加上 `word-break: auto-phrase`（日文依詞組斷）與 `overflow-wrap: anywhere`（詞組比手機寬時才硬斷）。四語在 1280 與 375 寬度都驗證過，無溢出。
2. **安裝指令顯示 localhost URL**：正式站應改成 namespace 寫法（`npx shadcn add @sunui/add-to-cart-button`），短、好記、也像正式產品。
3. **數量條強調免費數量**：104 放在第一位，和「主客群不在乎數量、Pro 才是收入」的策略相反。可考慮第一格換成「個檔期場景（Pro）」或把 Pro 放前面。

## 五、延伸研究（第二輪，2026-11-07）

### 5.1 同類產品首屏：大家都在賣「好看」與「數量」

| 產品 | 標題 | 佐證方式 |
|---|---|---|
| shadcn/ui | The Foundation for your Design System | 無數字，靠品牌 |
| shadcnblocks | The ultimate block set for Shadcn UI & Tailwind | 2866 blocks、2241 components |
| Aceternity UI | The React component library for beautiful landing pages | 200+ 元件、120,000+ 使用者 |
| Launch UI | Give your big idea the design it deserves | 73.9k+ 公司與開發者 |
| Magic UI | UI library for Design Engineers | 150+ 免費動效元件 |
| Tailark | Shadcn Registry for building marketing websites | 300+ blocks、四套主題 |
| Medusa | Open-Source Agentic Commerce Platform | 主打 agent |
| Stripe Checkout（日文站） | すぐに使えるオンライン決済ページ | 購入率、最高 46% 營收成長 |

觀察：

1. **元件庫全部在承諾「好看、突出」**（beautiful、stand out、design it deserves），沒有一家把「成交」放進標題。「少一點閃爍，多一點下單」是這個類別裡唯一講商業結果的標題，差異化成立。
2. **數量是軍備競賽，SunUI 打不贏**。對手動輒 2866、120,000+；SunUI 的 104／41／28 擺在首屏反而顯得小。Evil Martians 的研究也指出，數字型佐證適合個人工具，B2B 更常用客戶 logo 或一句推薦。→ 首屏數量條應換掉（見 5.5）。
3. **Agent 已成電商基礎設施的主打詞**（Medusa 把 Agentic 放進標題）。SunUI 的 agent 段落方向正確，可以考慮在副標保留「交給你的 coding agent」。
4. **付款業者講「購入率」**。Stripe 日文站用「購入率」，日文副標可直接用這個詞，比「購入につながる」更像行內話。

### 5.2 去 AI 感是正在發生的趨勢，標題踩在浪頭上

- 多篇 2026 年的文章把「紫藍漸層、到處發光、假的 Live 徽章、大圓角」列為 AI 預設樣貌，修正建議一致是**克制**：漸層只用在一個焦點、狀態徽章只在狀態為真時顯示。
- Built In 的評論說 AI 介面「AI slop has no position」，信任流失時沒人會抱怨，只是默默離開。這正是「少一點閃爍」要對抗的東西。
- **風險**：同一篇文章把 AI slop 比作當年的擬物化（亞麻紋、玻璃反光）。「紙感」如果只被理解成紙紋材質，可能被歸類成新一輪擬物化。→ 文案應把紙感說成**立場**（克制、條件寫清楚、只在顧客動手時才動），而不是**紋理**。目前副標用「不靠漸層和光暈」這種反面定義，方向是對的；「為什麼選 SunUI」第一點「是一種材質，不只是主題」值得改寫。

### 5.3 「多一點下單」要有根據：從放棄結帳的原因反推

Baymard 2025：平均購物車放棄率約 70%；在已準備購買的放棄者中，**額外費用（運費、稅、手續費）最常見，約 48%**，被迫註冊帳號約 19%，付款方式不足約 10%。

SunUI 的設計正好對著這些原因：

| 放棄原因 | SunUI 對應 |
|---|---|
| 結帳時才看到額外費用 | 優惠券把條件寫在券面（「滿 US$80 可用」）、免運門檻提示 |
| 流程冗長 | 結帳、購物車區塊 |
| 不信任 | 不用假倒數、不用閃爍特效 |

→ 這是「多一點下單」的論證素材，適合放在「為什麼選 SunUI」，不要寫成具體百分比承諾（SunUI 沒有自己的 A/B 數據）。

### 5.4 誠實的急迫感：可以成為新的賣點

- 歐盟 2022 年檢查 399 個電商網站，148 個有黑暗模式，其中 **42 個使用假倒數計時**。FTC 2022 年報告也把假倒數列為四大黑暗模式之一。
- 中國 2025 年雙 11 產業報告指出，消費心智從「囤貨衝動」轉向「理性消費」，京東用「價保 30 天」把低價承諾變成可驗證的保障。
- SunUI 的倒數處理了 hydration 與分頁切換的正確語意（商業模式報告已列為 Pro 價值）。→ 可提煉成一句賣點：**「倒數照實走，條件先講清楚。」** 這同時回應監管趨勢與消費者變理性，競品沒有人在講。

### 5.5 各語行內用語

| 語言 | 業界常用詞 | 建議 |
|---|---|---|
| zh-TW | 轉換率、結帳率、檔期、活動頁、免運門檻（Omnichat：平均結帳率約 25%） | 「下單」「成交」口語且通用，維持 |
| zh-CN | 大促、会场、利益点、满减（如「满200减20」）、转化 | 副標可用「大促」；「为成交而设计」可改「为转化而设计」更像行內話，但「成交」更直白，兩者皆可 |
| ja | ファーストビュー、購入率、導線、離脱 | 副標「購入につながるように」可換成「購入率を上げるために」 |
| en | conversion、checkout、cart abandonment | 「close the sale」偏業務口吻，可改「built to convert」 |

### 5.6 已套用（2026-11-07，四項全做）

1. **數量條換成差異點**：「4 種語言文案，內建」「CJK 中日文標點與換行」「0 個假倒數」，不再跟競品比區塊數量。`countdown-banner` 依真實的 `endDate` 倒數、會進入已結束狀態並顯示實際日期，「0 個假倒數」有根據。
2. **「為什麼選」第一點**：「是一種材質，不只是主題」改為「是一種立場，不只是質感」，補上理由（促銷頁該讓人看清楚，而不是看花眼）與「優惠條件寫在券面上」。
3. **誠實急迫感**：「為什麼選」第二點加入「倒數照實走，條件先講清楚」，並把「都能直接上線」改成「都用得上」。
4. **用語微調**：en 副標改用 built to convert，ja 副標改用「購入率を上げるために」。
