# Kubai Icons 2.0（雙色版）深度分析

> 日期：2026-11-22
> 對象：X 貼文 `x.com/Kubai087/status/2124033523195806015`（枯白 Kubai，2026-11-21），GitHub `kubai087/kubai-icons` 的 v2.0.0 release（2026-11-20）與 `LICENSING.md`。
> 前情：`reports/kubai-icons 參考分析-2026-11-05.md`（含 11-09 更新）、`reports/150 動態圖示同屏深度分析-2026-11-22.md`（今天稍早，同屏牆已提交 3c31052）。

## 1. 結論

1. **這則貼文改變的不是 SunUI 該學什麼，而是 150 規劃的第三期該不該做。** Kubai 現在有約 3,000 個 MIT 動態圖示（分層版約 2,500，雙色版 502），React、Vue、web component、靜態 SVG 都有，stars 從 11-09 的 448 漲到 1,088。跟觀默那則同一天出現，代表「免費動態圖示」這條路已經擠滿了。**建議把 150 規劃第三期從「通用圖示補到 150」縮成「SunUI 區塊與 Pro 場景用得到的才補」**，大約 20 到 30 個，不追數量。
2. **雙色風格本身不能照搬，但它的「實心淺色主體 + 一處強調」跟 SunUI 已有的東西很接近。** SunUI 像素圖示早就是「30% 墨色填色 + accent」的雙色結構；線條圖示也有「最多一處 accent」。可以考慮的是在現有線條庫加一個**單色的 `soft` 變體**（封閉形狀填 currentColor 的低透明度），而不是新開一套彩色雙色庫。這是既有圖示集的功能，不違反凍結，但工時不小，排在 PH 之後。
3. **真正該學的是它的自檢從「截圖給人看」進化成「量測後寫 findings.md」。** SunUI 的 `check-icons.mjs` 還停在截圖。11-05 報告的 P2（把規則寫成可驗證的數字）至今沒做，`ICONS.md` 裡沒有間距、最小細節、組合圖形這幾條。這是現在就能做、而且直接強化 AI-facing 定位的事。
4. **它的行銷格式驗證了今天的同屏牆。** 影片開場是「One skill, one style, every time」，結尾是上下兩排圖示跑馬燈夾著標題。同屏牆錄成影片時可以用同樣的結構，但只用黑白。
5. **授權沒變：圖示 MIT，skill 不能碰。** 雙色版的規則、幾何工具、自檢都在 `styles/duotone/`，屬於 Kubai Icons License。不搬程式、不改寫或翻譯規則，只學方法。

## 4. 對 SunUI 的影響

### 4.1 對 150 規劃的修正（最重要）

今天稍早的 150 規劃第三期，是在 PH 之後補約 73 個通用圖示、約 103 組動作，讓線條動態到 150 個。對照 Kubai：

| 面向 | Kubai | SunUI 第三期做完 |
|---|---|---|
| 動態圖示數 | 約 3,000 | 150 |
| 框架 | React、Vue、web component、靜態 SVG | React（shadcn 複製） |
| 授權 | MIT | MIT |
| 風格 | 分層（有漸層投影）、雙色 | 1.5 線條、像素 |

數量差 20 倍，覆蓋率永遠追不上。5 到 7 天的工時換到的是「比較少的同類品」。所以：

1. **第一期（同屏牆）不變。** 它展示的是 SunUI 已有的東西，成本已經付了。
2. **第二期不變**，而且更有理由：Pro 賣場景與檔期圖示，Kubai 沒有農曆新年、檔期這類物件，也不賣組好的頁面。
3. **第三期縮小**：只補 SunUI 區塊與 Pro 場景實際用到的通用圖示（設定齒輪、資料夾、Wi-Fi、雲端這類），20 到 30 個，其他交給使用者自己選圖示庫。
4. **加一條相容路線**（11-09 已提過）：SunUI 區塊收圖示的 props 接受任何 React 圖示元件，文件寫明 lucide、kubai 都能直接放。這比補圖示更有用。

### 4.2 雙色風格：哪些能用、哪些不能

| Kubai 雙色的元素 | 跟 SunUI 規則的關係 | 判斷 |
|---|---|---|
| 實心淺色主體 | 不違反 DESIGN.md（不是漸層、光暈、模糊），但網站只用黑白灰 | 可以用單色做：主體填 currentColor 的 10% 到 15% |
| 強調部位用品牌色 | SunUI 已有 `--sunui-icon-accent`，預設跟著 currentColor | 已經有了 |
| 每個圖示一種顏色（影片裡的彩虹配色） | 違反「網站只用黑白灰」 | 不用 |
| 16 網格實心 | SunUI 線條是 24 網格，像素是 16 網格 | 像素版本來就是 16 網格雙色結構 |
| 角標變體（加、勾、off） | 11-09 的 P8 提過 `badge` prop，未做 | 值得做，購物車數量、通知點是電商頁剛需 |

**`soft` 變體的做法**：在現有線條圖示的封閉形狀（購物車籃子、信封、資料夾本體）標一個 `body` 屬性，`<Icon variant="soft">` 時用 `fill="currentColor" fill-opacity="0.12"` 畫出來。線條不變、accent 不變，所以在按鈕與文字裡照樣跟著顏色走，黑白網站上也成立。工作量是逐個標註 101 個圖示的主體，約 1 到 1.5 天，加上動態版的 body 要跟著部件動。

### 4.3 自檢：從截圖到量測

| | SunUI `check-icons.mjs` | Kubai 雙色 `check.mjs` |
|---|---|---|
| 輸出 | 尺寸頁、影格頁截圖 | `findings.md`（文字報告） |
| 判斷者 | 人或 agent 看圖 | 腳本量測，列出不合格項目 |
| 量測項目 | 無 | 主要形狀、主色佔比、間距、重疊、小部件、內縮、每一格動作 |

對 SunUI 的意義：agent 用 MCP 的 `get_icon` 擴充圖示時，如果有一支能跑的量測腳本，它可以自己修到合格，不用等人看截圖。這跟 SunUI「AI-facing」的定位完全一致。

要自己寫，不能參考它的程式碼。SunUI 的線條圖示是 SVG path，量測可以在瀏覽器裡用 `getBBox()`、`getTotalLength()` 與取樣點做：

1. **出界**：每個圖示與動態版每一格的 bbox 必須在 24 網格的 2 到 22 之內（ICONS.md 已有內容區規則，只是沒檢查）。
2. **最小細節**：任何獨立子路徑的 bbox 長邊 ≥ 2 單位。
3. **間距**：兩條不相連的子路徑之間的最近距離，要嘛 0（相接），要嘛 ≥ 2。
4. **accent 數量**：每個圖示最多一個 accent 節點（ICONS.md 第 28 行）。
5. **動態歸位**：hover 類播完最後一格必須等於靜止格。

輸出 `check-out/icons/findings.md`，有任何一項不合格就非零結束。這同時補上 11-05 報告的 P2。

### 4.4 行銷格式

Kubai 的影片和同屏牆可以直接對照：

| Kubai 影片 | SunUI 可以怎麼拍 |
|---|---|
| 開場一句賣點 | 「One standard, line and pixel」或用現有 `/icons` 標題「用同一套標準畫出來的圖示」 |
| 網格逐一 hover | 同屏牆本身 |
| 跑馬燈夾標題 | 兩排同屏牆夾 SunUI 標誌與網址 |
| 彩色底 | 不用，維持黑底白線（跟觀默那則一樣，也跟 Kubai 形成對比） |

黑白在一片彩色雙色圖示裡反而好認。

## 5. 不做

1. 不做彩色雙色圖示庫（違反黑白網站規則，也是新的免費項目）。
2. 不收錄 Kubai 的任何圖示。即使 MIT 允許，風格與 SunUI 不一致，而且凍結期間不擴充。
3. 不參考 `styles/duotone/` 的規則文字、幾何工具、`check.mjs` 程式碼。
4. 不追數量。
