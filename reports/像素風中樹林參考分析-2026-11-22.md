# 像素風中樹林（pixel-grove）參考分析

> 2026-11-22。來源是 Best Designs On X 轉的一支 50 秒錄影「Pixel Play」，作者 @SolutionB2u（x.com/bestdesignsonx/status/2123929385866875355）。貼文沒有原始碼，技術拆解是逐格看錄影推回來的。【已驗證】表示這次在瀏覽器實際看過；【推論】是從錄影反推；【估算】【建議】是判斷。

## 0. 結論先講

1. **招牌是「風是一個可以調的物理量」**：三棵像素樹（櫻花、灌木、楓樹）一直在風裡搖，使用者調風速、陣風、方向，樹的反應是連續、可預期的；風夠大（Storm）時葉子被一團一團吹離樹冠，順風飛出畫面或落地堆積，按「Grow back」再長回來。【已驗證】
2. **它可信的原因是「骨架」**：Skeleton 開關把葉子藏起來，露出一棵分岔的樹枝骨架，而且骨架本身也在搖。代表葉子不是整張圖在晃，而是黏在一根一根會彎的枝條上；枝越細越末端，擺幅越大，還有相位延遲。這就是看起來像「真的樹」而不是「一張在左右歪的 sprite」的差別。【推論】
3. **值得做，只能做成 Pro，放 story 系列**。免費型錄凍結到 2027-01-12；Pro 裡已經有六個 pixel-* 場景（gacha、check-in、boss-sale 等）都在 story 系列，這棵樹林是同一條線的「季節檔期主視覺」。【建議】
4. **零相依、單一 canvas**：低解析度畫布（每個美術像素放大成 3 到 4 個螢幕像素），樹是程式生成的枝條骨架，葉子是附著在枝端的像素團；風是正弦加平滑雜訊；被吹落的葉子是有阻力與重力的粒子。不需要任何圖片素材，所以買家可以換樹種與色票。【建議】

## 1. 錄影逐項拆解

取樣 0、4、10、18、23、29、35 秒，並放大看過控制列。【已驗證】

| 時間 | 畫面 | 怎麼做的（推論） | 判斷 |
|---|---|---|---|
| 0s | 只剩光禿禿的樹枝，地上一圈草；兩側樹冠只看得到一半 | Skeleton 開著，葉子隱藏；枝條在搖 | **帶走**：骨架開關是講解用的，也是買家調樹形時的除錯畫面 |
| 4s | 淺灰底，三棵完整的樹：粉色櫻花、綠色灌木、橘色楓樹；底部一條白色膠囊控制列 | 每棵樹一套 4 到 5 階色票，左上受光、右下陰影 | 帶走，色票照 story 系列的 rice 與 ink 調 |
| 10s | 樹冠輕輕晃，地上有少量花瓣 | Breezy：低風速、低陣風；樹冠以樹幹根部為支點左右擺 | 帶走 |
| 18s | Weather 開成 Storm、方向 Left；三棵樹的葉子大量往左飛散，樹冠被吹薄；底部出現「Grow back」 | 風超過門檻後，枝端的葉團依機率脫落成粒子 | **帶走**，這是最有戲的一刻 |
| 23s | 深色主題，鏡頭拉近單一灌木，下方出現頁碼點與左右箭頭 | 同一個場景可以切成單棵樹的展示模式 | 帶走成 `focus` 模式；demo 不做輪播 |
| 29s | 深色，單棵櫻花，左邊一大片花瓣被吹走中，樹冠還剩一半 | 落葉粒子有阻力，速度會趨近風速；越小越輕飄 | 帶走 |
| 35s | 回到淺色、Breezy、Right；樹冠已重新長滿，Grow back 按鈕還在 | Grow back 讓脫落的葉團從枝端重新長出（縮放進場） | 帶走 |

控制列的欄位：風向袋圖示、Weather（開關加 Breezy / Storm 二選一）、Direction（Left / Right）、Wind speed（滑桿，Calm 到 Gale）、Gusts（滑桿，Light gusts 到 Wild gusts）、Show（Skeleton、Sound 兩個開關）。【已驗證】

為什麼有效：
- **因果直接**：一個滑桿對應一個看得見的物理量，調了馬上看到樹怎麼回應，沒有「播放一段動畫」的感覺。
- **有不可逆的後果，又可以復原**：葉子吹掉就是吹掉了，地上會堆；Grow back 把它還回來。這給了玩的理由。
- **像素是誠實的**：所有東西都對齊美術像素，連飛散的花瓣也是 1 到 2 格的方塊，所以畫面很乾淨，不會有抗鋸齒的糊邊。

## 2. 技術拆解（怎麼做）

### 2.1 樹：遞迴生成的枝條骨架【建議】

- 從樹幹開始遞迴長枝：每段有長度、粗細、角度；分岔 2 到 3 支，長度乘 0.68 到 0.8，粗細乘 0.7，角度加減 18 到 38 度。深度 5 到 6 層。用固定的 seed（mulberry32）讓同一棵樹每次長得一樣。
- 每段枝存「深度」與「相位」。畫的時候由根往外累加角度：`angle = base + sway(depth, t)`，所以末端的位移是整條枝鏈的總和，自然出現「根部幾乎不動、末端甩很大」。
- 樹種只是參數：櫻花（開展、葉團小而多、粉色）、灌木（短幹、很多低分岔、圓團）、楓樹（寬冠、葉團大、橘色）。

### 2.2 風：正弦加平滑雜訊【建議】

- `wind(t) = dir * (speed + gusts * noise(t * 0.35))`，noise 是 1D value noise（兩個 hash 之間用 smoothstep 內插），陣風因此是一陣一陣的，不是規律的擺。
- 每根枝的擺角：`(wind * k / thickness) + sin(t * f + phase) * flutter * wind`。粗的枝硬、細的枝軟；flutter 給每根枝不同頻率，避免整棵樹同步。
- 風向改變時不跳：wind 用臨界阻尼彈簧追目標值，大約 0.6 秒轉向。

### 2.3 葉子：附著在枝端的像素團

- 每個枝端（深度 ≥ 3）掛一個葉團：一個 6 到 14 格半徑的圓內，依雜訊挑格子，形成破碎的邊緣。每格依「相對葉團中心的方向」上色：左上亮、右下暗、隨機點一些最亮與最暗，就是錄影裡那種顆粒感。
- 葉團的位置跟著它的枝端走，所以整團會被枝帶著搖；團內每格再加一點點獨立的抖動（0 或 1 格），看起來像葉子在顫。

### 2.4 吹落與長回

- 風力超過門檻（約 0.55）時，每秒每個葉團有 `(wind - 0.55) * rate` 的機率掉一小撮格子（不是整團）；掉下來的格子變成粒子，速度 `v += ((wind * 60) - v) * drag * dt`、`vy += g * dt`，加一點上下擾動，落地後停住、慢慢淡掉，地上留下一層落葉。
- 葉團剩不到 15% 就不再掉，樹不會被吹到全禿（除非開 Skeleton）。
- Grow back：每格依序（從枝端往外）以 0.4 秒長回，間隔隨機，像重新發芽。

### 2.5 聲音【建議】

- WebAudio：白雜訊 buffer 循環，過一個 bandpass（頻率 300 到 900Hz 跟著風速），增益跟著陣風。預設關閉，只在使用者打開開關之後建立 AudioContext（瀏覽器規定要使用者手勢）。

### 2.6 效能與無障礙

- 畫布是美術解析度（例如 寬 × 120 格），CSS 放大加 `image-rendering: pixelated`；每格 `fillRect`。三棵樹約 2,000 到 3,000 格，每格一次 fillRect 在桌機與手機都是 1ms 級。
- 畫面外或分頁隱藏時停 rAF（IntersectionObserver 加 visibilitychange），跟其他 pixel-* 一樣。
- reduced motion：樹靜止、不吹落，Grow back 直接補滿；聲音照開關。
- 畫布是 `role="img"`，`aria-label` 寫目前的天氣與風向；控制都是原生的 button 與 range input。

## 3. 跟 SunUI 規則的衝突與取捨

| 原作元素 | 規則 | 處理 |
|---|---|---|
| 粉、綠、橘三種樹色同框 | craft 系列禁多色相；story 系列允許插畫色票，強調色只有一個 | 放 story 系列。插畫內的色票不算 UI 強調色（pixel-check-in、pixel-gacha 已有先例）；UI 外框與控制列只用 `--story-*` |
| 白色膠囊控制列、iOS 開關 | story：圓角 2 到 4px、1px 線框 | 控制列做成 story 面板：直角小圓角、細線框，開關改成方形像素感的切換 |
| 常駐搖動 | story：唯一允許的常駐循環是「下一句」提示 | 例外說明：這個 block 的內容本身就是動畫（跟 pixel-build-progress 的工人一樣）；畫面外停、reduced motion 靜止 |
| 粒子 | craft 禁粒子 | story 的 pixel-* 都用像素粒子，維持；粒子都是對齊格子的方塊，不是光點 |
| 聲音 | 沒有規範 | 預設關，使用者手勢才開 |

## 4. 和現有 block 的差別

用 tree、wind、leaf、season、pixel 比對 free 與 Pro registry：【已驗證】

| 現有 | 差在哪 |
|---|---|
| `pixel-fx`（免費） | 一次性的像素特效（爆開、彩紙、溶解），沒有場景與持續的物理 |
| `pixel-check-in`、`pixel-gacha` 等（Pro） | 都是「一個機制加獎勵」；沒有會持續回應參數的生態場景 |
| `day-night-hero`、`sky-time-switch`（Pro） | 換時間與天色；這裡換的是風與季節 |
| `lunar-new-year`、`festival-banner`（Pro） | 節慶檔期 banner，裝飾是靜態或循環的；這裡的主角是可以玩的 |

四個問題（`免費與付費切分規劃-2026-11-05.md`）：
- **可替代性低**：Magic UI、React Bits 沒有程式生成的像素樹與風場；這類效果多半是 Unity 或影片。
- **工時中**：樹的生成與三個樹種的調校、風場、落葉粒子、控制列、展示版，約 1 天。【估算】
- **商業距離中**：季節檔期主視覺（春櫻、夏日、秋楓、冬日）的背景與彩蛋；遊戲與遊戲化活動頁的世界觀小物；「風大了，葉子掉了」可以接「季末清倉」這類文案。距離不如付款元件近，但它是展示型錄與 Product Hunt 影片的好素材。
- **展示價值高**：型錄卡片在風裡搖、滑一下游標就沙沙作響，一眼就懂。

## 5. 規格（實作依據）

名稱 `pixel-grove`，Pro、story 系列、interaction `section`。

```ts
<PixelGrove
  trees={["sakura", "shrub", "maple"]} // 1 到 4 棵；樹種 sakura | shrub | maple
  weather="breezy"            // breezy | storm；storm 會吹落葉子
  direction="right"           // left | right
  windSpeed={0.35}            // 0 到 1
  gusts={0.3}                 // 0 到 1
  skeleton={false}            // 只畫枝條
  sound={false}               // 風聲，使用者手勢後才發聲
  theme="rice"                // rice（亮）| ink（暗）
  pixelSize={3}
  seed={7}
  controls                    // 顯示內建控制列（預設 true）
  onLeavesChange={(left) => {}} // 剩下的葉子比例 0 到 1，給檔期文案用
/>
```

- 游標穿過樹冠：局部推一下葉團（沙沙），點樹會搖落一小撮。這是錄影裡沒明確看到、但讓型錄卡片能被「玩」的補充。【建議】
- Grow back 按鈕只在有葉子掉落時出現。
- demo：秋季檔期主視覺，標題「秋日選物，風一吹就換季」，三棵樹加內建控制列。card：單棵楓樹在中風裡搖，游標可以推。
- preview（公開展示版）：只有 rice 色票、固定三棵樹、內建控制列只留 Weather 與 Grow back；沒有 Skeleton、Sound、props API、ink 主題與 onLeavesChange。

## 6. 不做的事

- 不做 3D、不做 voxel、不用圖片素材。
- 不做錄影的頁碼輪播（單棵展示用 `trees={["maple"]}` 就夠）。
- 不放進免費型錄。

## 7. 延伸變化（同日追加）

使用者要求「更多不同變化」。原作只有三棵樹與風；追加的都是同一套引擎換參數，不另開元件。

| 變化 | 做法 | 為什麼 |
|---|---|---|
| 白樺 `birch` | 細高白幹，右側一道陰影、隔幾格一道黑橫紋；小而碎的金葉 | 秋季第二種顏色，白幹在一排暖色樹裡是錨點 |
| 柳樹 `willow` | 短骨架，每個枝端垂一把柳條；每格記住離掛點多遠（`hang`），越下面被風推得越遠、自己也慢慢盪 | 風的「重量感」最明顯的樹形，夏季主角 |
| 松樹 `pine` | 主幹一節一節往上，每節掛一層兩端微垂的針葉，越上層越窄，頂上一個小尖；針葉兩端也帶 `hang` | 冬季與聖誕檔期；跟開展樹冠完全不同的輪廓 |
| 天空 `sky` | `rain`：斜落的 1×3 雨絲，落地濺兩格就消失。`snow`：緩慢飄落，落地停留；樹冠每欄最上面那格隨時間逐一積白（約 8 秒積滿，放晴後 3 秒退掉） | 同一個檔期頁可以換天氣，不必換圖 |
| 場景 `groveScenes` | 春（櫻、柳、櫻）、夏（灌木、柳、灌木，下雨）、秋（楓、白樺、楓）、冬（松、灌木、松，下雪）、夜（ink，白樺、柳、松，下雨） | 買家直接 `{...groveScenes.winter}` 就有一個完整檔期畫面 |

實作中修掉的兩個問題：
- 樹太高頂到畫布：除了寬度，也量頂端；任一邊超出就整棵等比縮小重長。
- 縮小重長後樹形變了：葉團的格子數跟著縮放改變，原本共用一條亂數，後面的枝條就長歪。改成每團葉子各自一條亂數，樹形在任何尺寸都一樣。

展示版只放春夏秋冬四個 rice 場景；夜晚（ink）、骨架、風聲、天空切換只在完整版。

## 8. 修正「被切割、透視怪」（同日，使用者回饋）

- 原因：每團葉子各自打光（左上亮、右下暗），整個樹冠變成一堆各自立體的棉花球，看起來被切開，透視也亂。另有枝條往下長、松樹層與層之間有縫。
- 改法：整棵樹一起打光，以上亮下暗為主、左右只帶一點；每團自己的明暗只留三成，保留一簇一簇的起伏；顆粒改成 2×2 的一片葉子，不是單格雜點。枝條每層往垂直拉回，最低不低於水平上方約 15 度。松樹每層約節距的六到九成厚，剛好相接；針葉兩端不再各自擺動，避免裂出直縫。
- 改前改後對照：`.compare/pixel-grove/index.html`。

## 9. 做成 SunUI 自己的東西，不是一看就知道是抄的（同日，使用者回饋）

上一版的問題：畫面結構和原作一對一。同樣三棵樹、同樣一條「Weather / Direction / Wind speed / Gusts / Show」的控制列、同樣的 Grow back，等於把錄影做成元件。差異只有樹種與天氣，這些都還是原作的延伸。

這一版留下原作的引擎（骨架樹、風、落葉），把「人怎麼跟它互動」和「它在頁面上做什麼」換成 SunUI 自己的：

| 原作 | SunUI 版 | 為什麼是 SunUI 的 |
|---|---|---|
| 四個滑桿與開關調風 | **拖一下就是一陣風**：放開時的水平速度變成往那個方向的陣風，幾秒內退掉 | SunUI 的招牌是動態，風應該用手做出來，不是用表單填出來 |
| 看不見的風 | **墨色筆觸**：風夠大時，一撇一撇短筆觸從上風處掃進來，頭實尾斷，像毛筆收鋒 | story 系列「墨與燈」的墨；也讓使用者看見自己拖出來的風往哪裡走 |
| 純觀賞的玩具 | **金色小燈籠與獎勵卡**：中間那棵樹掛一盞燈籠（story 唯一的強調色金），搖樹三下或颳大風就鬆脫、掉落、彈兩下，落地處打開這一季的優惠卡（標題、說明、可複製的優惠碼） | 店家與檔期頁是旗艦系列：同一個畫面從裝飾變成「找到的優惠」，跟 pixel-gacha、pixel-check-in 同一條 Pro 路線 |
| 一排標籤分段控制 | **風向標**：一根竿子一條風袋，左右拖一個控制同時決定方向與強弱，風袋從垂下到拉直；過四分之三自動變暴風。天空與聲音縮成三個像素圖示 | 一個控制取代四個；外觀是場景裡的物件，不是後台表單 |
| 骨架開關在控制列 | 骨架只留成 prop | 那是除錯畫面，不是給訪客的功能 |

刻意不做：燈籠不發光暈、落地不放彩紙（story 與 craft 都不慶祝）；獎勵卡是一張面板，從落地點往上 8px 淡入，240ms，story 的 ease。

展示版（公開）有拖曳風、筆觸、燈籠與固定優惠卡、四季切換和一條簡單的風滑桿；完整版才有風向標、天空與聲音控制、ink 夜晚、骨架、reward 與 onHarvest API、多語系 labels。
