# 其他頁面 UI/UX 深度分析（2026-11-20）

範圍：首頁以外的所有公開頁面。首頁已有多份分析（`首頁從零重做深度分析-2026-11-20.md` 等）而且其他工作階段正在改，這裡不重複。價格頁今天已重做（金額上色、方案卡等高、計算機兩欄、FAQ 手風琴），只在最後補一句。

方法：在 dev server（localhost:3100）實際打開每一頁，桌面 1440×900 與手機 375×812 各看一次，淺色深色都看，再回頭查程式碼確認原因。

看過的頁面：`/blocks`、`/blocks/[slug]`（以 add-to-cart-button 為例）、`/icons`、`/docs`、`/docs/installation`、`/docs/motion`、`/docs/changelog`、`/license`、`/checkout/pro`（開賣前會轉到價格頁）、404。

---

## 一、總評

整體已經乾淨、一致，沒有明顯壞掉的版面。問題集中在三類：

1. **上線前會傷信任的細節**：授權頁寫著「Draft for review」、區塊原始碼裡的中文註解、手機上找不到圖示頁。
2. **型錄的第一眼**：卡片舞台顏色忽黑忽白、預覽先空白一兩秒、手機上篩選器佔掉整個首屏。
3. **文件頁太素**：寬螢幕右半邊全空，更新紀錄只是一串文字連結。

---

## 二、P0：上線前一定要修（傷信任）

### 1. 授權頁公開寫著「Draft for review」

`/license` 標題下方顯示「Draft for review. Last updated November 4, 2026.」（`lib/messages.ts:474`，四個語系都有）。付錢的人最在意的就是授權條款，看到「草稿」會懷疑條款還會變。

**建議**：條款定稿後把 `updated` 改成「Last updated ...」，四個語系一起改。如果還沒定稿，至少在 Product Hunt（2027-01-12）前定。

### 2. 區塊原始碼有中文註解，會被複製進買家的專案

107 個免費區塊裡有 97 個的 `.tsx` 含中文（主要是 props 的 JSDoc，例如 `/** 印在飛行吊牌上的商品小圖 */`）。影響：

- 英文介面的區塊頁，「Or install manually」的程式碼區直接顯示中文註解，看起來像沒做完。
- `npx shadcn add` 之後，這些中文註解會進到買家的專案。海外買家讀不懂 props 說明，等於少了文件。
- Pro 區塊大概也一樣（未檢查，Pro 是另一個 repo）。

**建議**：把 JSDoc 與行內註解翻成英文，這是內容工作，不改程式邏輯。工作量大（近百個檔案），適合開一個獨立工作階段批次處理，並加一個 lint 規則或腳本擋住新的中文註解進 `registry/`。內部用的中文說明可以移到各區塊的 README 或 `reports/`。

### 3. 手機上沒有「圖示」入口

`components/site-nav-links.tsx:13` 讓「圖示」只在寬度 ≥ 400px 時顯示，而且沒有漢堡選單。iPhone 15（393px）、iPhone SE（375px）都小於 400，所以**大部分 iPhone 上完全進不去圖示頁**，只能靠頁尾。

**建議**：二選一。
- 手機改成「區塊 / 文件 / 價格」加一個「更多」選單，裡面放圖示、GitHub、語言、主題。
- 或把語言切換縮成圖示，空出位置讓四個連結都放得下。

## 三、P1：型錄 `/blocks`

### 4. 卡片舞台的底色不一致

同一排卡片，有白底（Coupon Wallet）、黑底（Campaign Landing、3D Book、Cloth Curtain）、淺灰底（Add To Cart）。每張單看都好看，排在一起就很花，眼睛會被黑卡拉走，讀不出「這是一套」。

**建議**：
- 卡片外框統一用同一個舞台色（淺色模式 `--stage`，深色模式對應色），區塊自己的黑色背景縮在舞台裡面，周圍留一圈舞台色的邊。
- 或讓深色區塊在型錄裡一律用淺色主題預覽，點開詳細頁才看深色。

### 5. 預覽先空白一到兩秒

卡片的 iframe 在進入視窗前 300px 才載入（`components/live-preview.tsx:56`），載入前只有一塊灰色。首屏三張卡大約空白 2 秒，捲動時也一路是灰塊，看起來像壞掉。整頁 194 個 iframe、高 23,580px，手機上更慢。

**建議**：每張卡先放一張靜態截圖（poster），iframe 準備好再淡入替換。截圖可以在 build 時用 Playwright 產生，或先手動截首屏與 Pro 的二十張。這也能順便減輕手機上的負擔：手機只顯示截圖，點開才載入真的預覽。

### 6. 卡片資訊太少

卡片下方只有名稱和收藏鈕。Pro 有黑色小標，免費沒有標示。看不出這個區塊做什麼、屬於哪個系列、有沒有互動。

**建議**：名稱下面加一行灰字，放系列或互動類型（例如「Press · Commerce」），資料已經在 `registry.json` 的 `meta` 裡。滑過時可以再顯示一句 `description`。

### 7. 手機上篩選器佔掉整個首屏

375px 寬時，搜尋、「Start from a page」、「All series」、「All interactions」、All/Free/Pro、Saved 疊成四行，第一張卡在 585px 以下，**首屏看不到任何區塊**。加上頂部的創始會員橫幅在手機上折成兩行，又再吃掉一截。

**建議**：手機上只留搜尋框加一個「篩選」按鈕，點開是底部抽屜。創始會員橫幅在手機上縮成一行（「Founding: $79 lifetime · Notify me」）。

## 四、P1：區塊詳細頁 `/blocks/[slug]`

首屏做得好：麵包屑、標籤、標題、一句說明、主按鈕、可切裝置寬度與主色的預覽，順序很清楚。下面「When to use / Watch out / Also called」三欄也很實用。

### 8. 缺 props 說明表

買家要用區塊，第一個問題是「可以傳哪些 props」。現在只能去讀程式碼（而且註解是中文，見第 2 點）。

**建議**：從 TypeScript 型別或 JSDoc 自動產生一張 props 表（名稱、型別、預設值、說明），放在預覽和安裝步驟之間。第 2 點翻成英文後就能直接用。

### 9. 原始碼區塊太長

「Or install manually」把整份元件原始碼攤開，頁面被拉得很長，相關區塊被推到很下面。

**建議**：程式碼預設收合成約 20 行，加「展開全部」與「複製」，大部分人只會用 CLI 安裝。

### 10. 主按鈕只有一個

首屏只有「Install with the CLI」。想先看程式碼或想交給 AI 代理的人要往下捲才找得到。

**建議**：主按鈕旁邊加一顆次要按鈕「Copy prompt」（現在在下方的「Let your agent add it」區塊），符合「AI 代理也能用」的定位。

### 11. 相關區塊先空白

頁尾「Similar blocks」三張卡一開始也是灰塊。第 5 點的截圖方案可以一起解決。

## 五、P2：圖示 `/icons`

這頁是全站做得最完整的：設計原則五張卡、分類格線、右側固定的詳細面板（大圖、四種尺寸、Copy JSX / SVG、標籤、相關圖示），都很好。

### 12. 四條安裝指令疊在一起

Static、Animated、Pixel、Pixel animated 四條指令垂直排，每條都太長、出現橫向捲軸，在首屏顯得很重。

**建議**：改成一個指令框，上面用兩組切換（Line / Pixel、Static / Animated）決定顯示哪一條，和下方圖示格線的切換連動。

## 六、P2：文件 `/docs/*`

### 13. 寬螢幕右半邊空著

1440px 時內容欄約 370px 寬，右邊約 400px 完全空白，看起來像沒排完。

**建議**：右側加「On this page」目錄（列出本頁 h2，捲動時標示目前段落）。這是開發者文件的慣例，順便解決空白。

### 14. 介紹頁的「下一步」只是文字連結

「Install your first block / Set up Pro / Use SunUI from an AI agent」三個是全文件最重要的入口，現在是底線文字。

**建議**：改成三張小卡，各有圖示與一句說明，跟圖示頁的原則卡用同一種樣式。

### 15. 更新紀錄只有一串文字

`/docs/changelog` 只有日期、區塊名稱、PRO 標。這頁本來最能證明「每週都有新區塊」，現在完全沒有畫面。

**建議**：每個區塊名稱旁放一張小縮圖（同第 5 點的截圖），或每週挑一個做成大卡。這頁之後也很適合拿來發社群貼文。

### 16. 動效字典的前言太長

`/docs/motion` 在表格前有一大段四條規則加三種判定說明，真正的字典要捲一段才看到。

**建議**：規則收合成一個「How verdicts work」可展開區塊，讓搜尋框和表格上移到首屏。

## 七、P3：其他小地方

17. **404 頁的瀏覽器標題**是預設的「SunUI: refined animated blocks for React」，應該改成「Page not found | SunUI」。頁面本身（404 卡片、猜你要找的區塊、兩顆按鈕）做得好。
18. **結帳頁**開賣前會轉到價格頁的候補表單，行為正確。開賣後的結帳表單這次沒看到，開賣前要用 `web-checkout` 設定另外走一遍。
19. **價格頁**今天已改完。金額顏色只用在價格頁，其他頁面維持黑白灰，不要擴散。
