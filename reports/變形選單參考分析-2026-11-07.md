### 關鍵觀察

1. **popover 從第一格就是完整尺寸**，用 `width: max-content` 固定。動的不是 popover，是 popover 裡的內容。
2. **錨點就是選單的起點**。收合狀態只有一個圓點，打開時圓點變成膠囊，再撐開成完整選單，視線從頭到尾停在同一個點上。
3. **長出來的方向跟著翻面走**。翻到上方置中時，內容改成從底部中央往上長；在右側時，從左側中央往右長。

## 2. 技術原理

整套是三個 CSS 新功能疊起來：

| 層 | 做什麼 | 寫法 |
|---|---|---|
| Anchor positioning | popover 黏在錨點旁邊，空間不夠時依序嘗試備案位置 | 錨點 `anchor-name: --menu`；popover `position-anchor: --menu`、`position-try-fallbacks: --top-center, --top-left, ...` |
| Anchored container query | 讓 popover 內部知道「現在用的是哪個備案」 | `@container anchored(fallback: --top-left) { ... }` |
| Grid 對齊當原點 | popover 是一個 grid，內容用 `justify-self` 和 `align-self` 決定貼在哪個角或哪一邊；內容的寬高從錨點大小補間到完整大小，自然就從那個角長出來 | 每個 fallback 一組 `justify-self` / `align-self` |

重點在第三層的巧思：一般做法是動 `transform-origin` 加 `scale`，但 scale 會把文字一起壓扁。jhey 的做法是**容器不動、內容的盒子長大**，原點交給 grid 對齊處理。這樣文字從頭到尾是正確比例，只是被外框慢慢露出來。

### 支援度

- 回覆裡有人指出 `anchored()` container query 目前只有 Chromium 支援（該回覆寫 Chrome 143 起），Firefox 與 Safari 還沒有。這個版本號本報告沒有另外查證。
- 退化方式不錯：不支援時 popover 一樣打開、一樣翻面，只是內容不會從對應的角長出來。可以當漸進增強。

## 3. 為什麼這支影片有效

1. **一個錨點貫穿所有狀態**。這正是 `DESIGN.md` 第 4 節第 5 條的連續性原則：同一個幾何貫穿所有狀態，點還是點，只是長大。選單不是「出現」，而是「按鈕變成選單」。
2. **把解法畫在畫面上**。紅色標註、手寫註解、屬性名直接疊在示範上，觀眾一邊看動態一邊讀懂原理。這是 jhey 一貫的教學格式，也是書籤多的原因：看完就知道怎麼抄。
3. **解決的是真問題**。翻面之後動畫方向不對（選單翻到上方，卻還是從上往下長），是每個做過 dropdown 的人都遇過的瑕疵。大部分元件庫的解法是用 JS 算 `transform-origin`，Radix 也是用 CSS 變數把算好的原點傳出來。這支影片說的是：瀏覽器自己知道選了哪個備案，直接問它就好。

## 4. 問題與風險

1. **只有 Chromium**。對 SunUI 的買家（自由接案者與小型代理商做活動頁）來說，Safari 是 iPhone 流量的大宗，純 CSS 版本在最重要的平台上沒有核心效果。
2. **示範是右鍵選單，不是電商情境**。Copy、Duplicate、Play as Slideshow 是相簿 App 的動作。直接搬進電商頁面沒有意義，要換成真實會出現的次要動作。
3. **選單蓋住錨點**。打開後圓點被選單蓋住，要關閉只能靠 Escape、點外面或選一項。影片沒有展示關閉，也沒有展示鍵盤操作。
4. **無障礙看不出來**。影片無法判斷 `role="menu"`、方向鍵、焦點回到觸發鈕這些有沒有做。popover API 本身有 light dismiss，但選單語意要自己補。
5. **可替代性高**。morphing popover 在 2025 到 2026 年已經是常見題材（Motion 的範例、各家元件庫的 dropdown 動畫），單獨做一個「會變形的選單」很難當成賣點。

## 5. 對 SunUI 的意義

### 5.1 凍結規則下能不能加

`AGENTS.md`：免費目錄凍結到 2027-01-12，新的免費項目只能是從 Pro 場景抽出來的 atom。用四個測試看（`免費與付費切分規劃-2026-11-05.md`）：

| 測試 | 單獨當一個 block | 當 Pro 場景的一部分 |
|---|---|---|
| 可替代性 | 高，到處都有 morphing dropdown | 低，購物車列尾的次要動作加上抽屜內翻面，市面上沒有現成的 |
| 自己做的時間 | 短（純 CSS 版本幾十行） | 中（裁切祖先、列的層級、鍵盤、四語、Safari） |
| 離營收距離 | 遠 | 近，購物車就是結帳前一步 |
| 展示價值 | 中 | 高，抽屜裡的列尾圓鈕長成選單，很適合錄成短影片 |

結論：**不做成獨立賣點，做成 Pro `cart-drawer` 的 atom**。免費版 `morph-menu` 是從 cart-drawer 的列尾動作抽出來的，符合凍結規則的例外條款。

### 5.3 實作取捨：為什麼不用純 CSS

| jhey 的做法 | SunUI 的做法 | 理由 |
|---|---|---|
| `anchored(fallback:)` 判斷側邊 | JS 量測：觸發鈕位置、選單尺寸、可見範圍，選出角落 | Safari 與 Firefox 都要有完整效果 |
| 可見範圍是視窗 | 可見範圍是視窗與所有會裁切的祖先取交集 | 選單常放在抽屜、捲動清單裡；購物車抽屜的品項清單本身就會捲動 |
| 內容盒子寬高補間，grid 對齊當原點 | `clip-path: inset(... round r)` 從觸發鈕大小補間到整張選單 | 一樣是「容器不動、露出範圍長大」，文字比例不變；不觸發版面重排，只用一個屬性 |
| 錨點是獨立的圓點 | 觸發鈕的圖示留在選單角落，外框長開時 100ms 退場 | 視線的錨點，同 `DESIGN.md` 第 4 節第 5 條 |
| 未展示關閉 | 關閉時內容先退、外框縮回觸發鈕，再把焦點還給觸發鈕 | 進出對稱 |
| 未展示鍵盤 | `role="menu"`、上下鍵、Home、End、Escape、Tab 關閉、點外面關閉，打開時焦點到第一個可用項目 | 選單語意 |
| | reduced motion 下直接切換，不做裁切動畫 | `DESIGN.md` 第 4 節第 3 條 |

橫向翻面規則：往空間大的一側長。列尾的按鈕因此會往左蓋回自己那一列，而不是伸出卡片外。縱向預設往下，不夠才往上。

### 5.4 實作中踩到的坑

1. **網站主題沒有 `--popover` token**。shadcn 專案有，但 SunUI 官網的主題只定義到 `--card`，用 `bg-popover` 會變透明。改用全站一致的 `bg-card`。
2. **`window.innerHeight` 在裝置模擬下會飄**。內建瀏覽器的 375px 模擬裡，同一個頁面有時讀到 375x420、有時讀到 498x558，導致該往上翻的選單往下開。改用 `document.documentElement.clientWidth/clientHeight`，這本來就是正確的版面視窗尺寸（不含捲軸）。
3. **Cart drawer 的每一列有 `overflow-hidden`**（為了高度進出場動畫），選單會被裁在列裡。解法是選單打開的那一列改成 `relative z-10 overflow-visible`，等收合動畫結束（新的 `onClosed` 回呼）才還原，收合途中不會被突然裁掉。

## 6. 後續可做

1. **錄 launch 素材**：cart-drawer 打開、列尾圓鈕長成選單、選「稍後購買」後那列收起。正好接上 `訂單追蹤卡參考分析` 4.4 節說的 16 秒單卡格式。
2. **Chromium 的漸進增強**：之後若要純 CSS 版，可以在支援 `anchored()` 的瀏覽器改走 CSS 路徑、其他瀏覽器保留 JS。目前不值得維護兩條路徑，先不做。
3. **其他 Pro 場景的列尾動作**：`order-tracker`（複製追蹤碼、聯絡物流、改約）與 `product-filter-grid`（商品卡的次要動作）都能直接用同一個 atom。

## 7. 一句話總結

這支影片的價值不在 CSS 新語法，而在一個原則：**選單不是出現，是按鈕長成選單，而且從按鈕所在的角長出來**。SunUI 用 JS 量測換取全瀏覽器一致，用 `clip-path` 保留「容器不動、露出範圍長大」的手法，並把它放進 Pro 購物車抽屜的列尾，讓這個效果離營收只差一步。
