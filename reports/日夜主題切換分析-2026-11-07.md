# 日夜主題切換：UIUX 深度分析與落地規劃

> 來源：枯白啃设计 @Kubai087，2026-11-07 貼文（Lumno 設定頁，16 秒影片）。
> 方法：逐格擷取影片 6.0s、7.0s、7.3s、7.6s、8.0s、10.0s、14.0s，對照 SunUI 網站與 registry 現況。
> 決策（2026-11-07，使用者選定）：網站加「系統 / 淺色 / 深色」手動切換，並帶動所有 block 預覽；外殼維持中性灰。元件做成 Pro 場景 `day-night-hero`，抽出免費原子 `theme-picker`。

## 1. 貼文在做什麼

一句話：**深色模式不是把白底換黑底，是讓同一個地方入夜。**

影片裡的設定頁頂部有一張水彩風的白日風景（草地、蝴蝶、遠山、小屋）。切到 Dark 時：

1. 插圖換成**構圖完全相同的夜景版**（AI 生成）：同一座山、同一隻蝴蝶、同一間屋，只是天變深藍、蝴蝶發出微光。
2. 插圖四周的介面色**跟著入夜**：不是純黑，是深藍灰；分頁列變成半透明的夜色玻璃。
3. 轉場是**一次短交叉淡化**（7.3s 到 7.6s 之間完成，約 250ms），沒有花俏的擦除或圓形展開。

## 2. 拆解：為什麼這個做法有效

| # | 手法 | 影片證據 | 為什麼有效 |
|---|---|---|---|
| 1 | 成對插圖，構圖一致 | 8.0s 與 10.0s 的山稜線、蝴蝶位置完全重疊 | 交叉淡化時沒有東西「跳位」，大腦讀成「同一個地方時間變了」，而不是「換了一張圖」。這跟 order-island 用縮圖當錨點是同一個原理 |
| 2 | 周邊色帶色相 | 夜景頁底是深藍灰而不是 `#000` | 插圖是藍夜，介面如果是中性黑，交界處會出現一條「圖是圖、UI 是 UI」的斷層。讓 UI 吃插圖的色相，整頁才是一個空間 |
| 3 | 插圖下緣漸隱進頁面 | 草地往下淡進卡片背後 | 插圖沒有硬邊框，所以換色時邊框不會閃 |
| 4 | 主題選項是「縮小的真實介面」 | 三張卡片各畫一條搜尋列，Follow system 是左深右淺各半 | 使用者選之前就看到結果，不用讀字。「跟隨系統」用對半切，比任何圖示都好懂 |
| 5 | 選中狀態是角落勾勾 + 外框 | Light 卡右下角的圓形勾 | 不靠顏色辨識選中，色弱與深淺兩種底都讀得到 |
| 6 | 轉場短而一次 | 約 250ms 交叉淡化 | 切主題是高頻、低情緒的操作，長動畫會變成干擾。驚喜來自「圖也變了」，不是來自動畫本身 |

### 可以做得比貼文更好的地方

- **影片裡的夜景是另一張點陣圖**，要準備兩份、兩倍下載量。用 SVG 畫同一個場景，日夜只是換變數與幾個元素（太陽換月亮、星星淡入、窗戶亮燈），檔案只有一份，而且可以把「入夜」做成有層次的小動作：先天色、再星星、最後窗戶一盞一盞亮。
- **影片沒處理減少動態**。`prefers-reduced-motion` 時應該直接換，不淡化。
- **影片只在設定頁有效果**。網站層級的主題切換若用 View Transitions API，整頁可以一起交叉淡化，不用每個元件自己寫轉場。

## 3. 對照 SunUI 現況

| 項目 | 現況 | 問題 |
|---|---|---|
| 主題來源 | `globals.css` 只用 `@media (prefers-color-scheme: dark)` | 使用者無法手動切換。開發者多用深色系統，大部分訪客看不到紙感的淺色版（11-06 UIUX 診斷 2.5 已指出） |
| block 預覽 | iframe 跟著作業系統 | **買家想看某個 block 的深色版，只能去改作業系統設定**。這是型錄最實際的缺口 |
| Tailwind `dark:` | v4 預設跟媒體查詢 | 沒有辦法強制淺色或深色 |
| 用 JS 判斷主題的程式 | `fit-stage.tsx` 只聽 `matchMedia` | 手動切換後不會重算表面色 |
| 自帶主題的 block | `checkout-steps`、`reservation-timer` 的 `SYSTEM_CSS` 只看媒體查詢 | 強制淺色時仍顯示深色 |
| 寫死淺色的 block | 約 66 個檔案有 `bg-white` 之類 | 深色時白卡。手動切換讓更多人看見這個問題，**要排進後續修正** |

## 4. 規劃與落地

### 4.1 網站：三態主題切換（本次完成）

- **慣例跟 shadcn / next-themes 一致**：`<html class="dark">` 或 `class="light"` 代表強制，沒有 class 代表跟系統。買家專案大多就是這個慣例，block 在網站上和安裝後的行為一致。
- `globals.css` 用 `@custom-variant dark`：`.dark` 底下一律深色；或系統深色且沒有 `.light`。沒有 JavaScript 時仍然正確跟隨系統。
- `<head>` 內嵌一小段腳本，在第一次繪製前從 `localStorage` 套用 class，避免閃白。同一段腳本監聽 `storage` 事件，所以**所有 block 預覽 iframe 會即時跟著切換**。
- 頁首加主題按鈕，點開是 `theme-picker` 卡片（縮小的真實介面）。切換用 View Transitions 做約 250ms 交叉淡化，減少動態時直接換。
- 外殼維持中性灰，不改成藍灰：DESIGN.md「純中性灰」的規則不動。藍灰夜色留給 `day-night-hero` 這種有插圖的場景，因為原則 2 的前提是「插圖有色相」，SunUI 外殼沒有插圖。
- 修正 `fit-stage.tsx`、`checkout-steps`、`reservation-timer` 讓它們也認 `.light` / `.dark`。

### 4.2 免費原子 `theme-picker`（本次完成）

從 Pro 場景抽出的原子，符合凍結期規則（只允許 Pro 場景的原子）。

- 三張卡片：系統（左深右淺對半）、淺色、深色，每張畫一條縮小的搜尋列。
- `role="radiogroup"`，方向鍵移動，選中是外框加角落勾勾。
- 附 `useThemeMode()`：讀寫 `localStorage`、套 `.light` / `.dark` 到 `<html>`、用 View Transitions 淡化，可以直接取代 next-themes 的最小需求。
- 網站自己的頁首就用它（吃自己的狗糧）。

### 4.3 Pro 場景 `day-night-hero`（本次完成）

**時段活動主視覺**：同一個地方，白天和晚上賣不同的東西。

- 內建 SVG 風景（山、湖、小店、路燈），日夜共用構圖。入夜順序：天色與周邊色（0ms）、太陽沉下月亮升起、星星淡入、店家窗戶依序亮燈。
- 周邊配色用 scoped CSS 變數：白天是紙色，夜晚是深藍灰 `#141a26` 一族，原則 2 的實作。
- 文案與優惠跟時段走：例如白天「早鳥 9 折」、晚上「深夜限定免運」。商業理由：夜間是電商轉換高峰，時段限定優惠是檔期常用手法。
- `mode` 三種：`"day"` / `"night"` 受控；`"theme"` 跟網站主題（讀 `.dark` 與系統）；`"clock"` 依當地時間（`nightFrom`、`dayFrom`）。
- 可傳 `art={{ day, night }}` 換成自己的成對點陣圖，元件負責交叉淡化與下緣漸隱。
- 依賴 `@sunui/theme-picker`，demo 裡直接用原子切換。

四項測試（免費與付費切分規劃）：可替代性低（市面沒有成對插圖 + 時段優惠的組合）、自建時間高（插圖、轉場順序、時段邏輯）、離營收近（直接是活動頁主視覺）、展示價值高（切換一次就懂）。

## 5. 後續（未做）

1. **修 66 個寫死淺色的 block**：手動切換上線後，深色白卡會更常被看到。建議依系列分批，先修首頁精選與 Pro 依賴到的免費 block。
2. block 面板加「只切這個預覽」的局部主題按鈕，不影響整站（目前是整站一起切）。
3. 農曆新年檔期包（2027-02-06）可以出一組「除夕夜」成對插圖，直接套進 `day-night-hero`。
