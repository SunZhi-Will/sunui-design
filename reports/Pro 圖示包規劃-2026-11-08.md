# Pro 圖示包規劃

> 日期：2026-11-08
> 起因：四套圖示（線條、動態線條、像素、動態像素）全部免費公開，沒有 Pro 分層。
> 相關：`reports/免費與付費切分規劃-2026-11-05.md`（方案 C）、`reports/商業模式深度分析-2026-11-06.md`（季節包）、`reports/iconmcp 參考分析-2026-11-07.md` 第 7 節第 2 點、`apps/web/ICONS.md`。

## 1. 結論

1. **現有四套圖示維持免費，不收回。** 已用 MIT 推上公開 repo，收不回來；圖示也是免費 block、Pro 場景與 agent（`search_icons`）共用的基礎建設。
2. **Pro 圖示 = 檔期圖示組，跟著季節包與 Pro 場景出。** 不做「單賣的大型圖示庫」。每一檔一組，只收那個檔期才有的物件（紅包、燈籠、福字……），通用物件（gift、coupon、truck）留在免費庫。
3. **第一組是農曆新年（2027 羊年），跟農曆新年季節包一起在 12 月下旬上架。** 製作從 11/28 開始，不佔用 11/27 Founding 開賣前的 21 天。
4. **Pro 場景改用 Pro 圖示，而不是各自畫。** 目前 `festival-banner`、`pixel-gacha`、`pixel-boss-sale` 等都在檔案裡直接畫 SVG，網格是 120、14、10、22 各不相同，正是 ICONS.md 一開始要解決的問題。

## 2. 為什麼這樣切

用 11-05 的四問檢查「檔期圖示組」：

| 問題 | 答案 |
|---|---|
| 可替代性 | 低。Lucide、Heroicons 沒有紅包、燈籠、福字這類物件，有的也不是紙品風格，更沒有像素本色版 |
| 工時 | 一組 12 到 16 個，線條 + 像素 + 動態，約 3 到 5 天（沿用現有幾何框架與自檢腳本） |
| 商業距離 | 近。直接是季節包的素材，也讓 Pro 場景外觀一致 |
| 展示力 | 高。檔期圖示很適合 X 影片與電子報當主圖 |

反過來看「把既有圖示的一部分改成 Pro」：四問全部不過，還會讓已經裝過的人以為被收回，不做。

## 3. 範圍：每一組收什麼

規則：

1. 只收**檔期限定**的物件。免費庫已有的（gift、coupon、truck、timer、sparkle）不重畫，Pro 場景直接用免費版。
2. 每組 12 到 16 個，**線條（24 網格）與像素（16 網格）兩種都要**，動態版挑 4 到 6 個最有實體動作的。
3. 規格完全沿用 ICONS.md：線寬 1.5、一個 accent 部位、像素精靈圖畫法與 `pixelPigments` 本色對照。不另開一套規範。
4. 若某個圖示其實是通用物件（例如「蝴蝶結」），就當作 Pro 場景抽出的原子放進免費庫，符合凍結規則的例外。

## 4. 授權與交付

### 4.1 誰拿得到

**已決定（2026-11-08）：Pro 授權包含所有檔期圖示組；季節包賣的是整頁模板與素材組裝。**

理由：Pro 場景（例如 `lunar-new-year`）會依賴這些圖示。如果圖示只在季節包裡，Pro 授權買家裝場景時會缺依賴，也違反「Pro 授權終身包含所有 blocks」的承諾。季節包的獨立價值仍在（整頁、文案四語、品牌色 token、主視覺）。

另一個選項是「圖示只在季節包裡，Pro 場景改回自畫」，會讓場景與圖示各自分歧，已否決。

### 4.2 檔案與網址

| 項目 | 位置 |
|---|---|
| 原始碼 | Pro 私有 repo：`registry/pro/icons/sunui-lunar-icons.tsx`、`sunui-lunar-pixel-icons.tsx`、對應動態版 |
| manifest | `registry/pro/registry.json`，`type: "registry:ui"`，`meta.tier: "pro"`，`registryDependencies` 指向免費的 `sunui-icons` / `sunui-pixel-icons`（共用 `Icon` 元件與型別） |
| 安裝 | `/r/pro/sunui-lunar-icons.json`，走現有授權檢查，不另開路由 |
| 場景依賴 | `lunar-new-year`、`festival-banner` 的 `registryDependencies` 加上 `@sunui-pro/sunui-lunar-icons` |

幾何格式要跟免費庫相同（`icons` 物件 + `recipes`），讓免費的 `Icon` 元件能直接渲染 Pro 幾何，Pro 檔只放資料不放元件。

### 4.3 對外展示，不外洩原始碼

| 地方 | 做法 |
|---|---|
| `/icons` 頁 | 新增「Pro：農曆新年」分組，圖示正常顯示並標 Pro，點開只給安裝指令，不給「複製 SVG」 |
| MCP `search_icons` | 搜得到 Pro 圖示，結果標 `tier: pro` 與安裝指令（對應 iconmcp 報告第 7 節第 2 點） |
| MCP `get_icon` | Pro 圖示不回傳 SVG / TSX，改回「這是 Pro 圖示，用 `npx shadcn add @sunui-pro/...` 安裝」 |
| `llms-full.txt` | 不列 Pro 幾何，只列分組名稱 |

注意：`/icons` 頁一旦用 SVG 渲染，幾何就在 HTML 裡，懂的人仍能複製。這跟 Pro block 的線上 demo 一樣，靠授權條款而不是技術阻擋。若想多一道門檻，可以在 `/icons` 的 Pro 分組改用建置時輸出的 PNG，成本很低，看你要不要。

但這裡有個限制：`lib/agent/icons.ts` 目前從 `@/registry/icons/*` 直接 import 幾何。Pro 幾何在私有 repo，公開站建置時可能不存在（AGENTS.md：Pro 目錄可能缺席，建置仍要成功）。所以 MCP 與 `/icons` 只能讀一份**不含幾何的 Pro 圖示索引**（名稱、分組、關鍵字、PNG 預覽路徑），放在公開 repo，例如 `lib/pro-icon-index.ts`。
