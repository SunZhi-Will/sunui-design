# Pro 內容防 AI 蒸餾分析

日期：2026-11-08
範圍：別人用 AI（爬蟲、agent、反混淆工具、截圖轉程式碼）把 SunUI Pro 的內容「蒸餾」出來，變成免費或自家商品。
方法：盤點 `apps/web` 實際曝光面（含對正式 build 的 chunk 實測），再上網查詢 2025 至 2026 的攻擊工具、平台防護、競品做法與法律現況。

---

## 一、結論

1. **最大的洞不在授權端點，在預覽。** `/r/pro/*` 有授權檢查、MCP 與 `llms-full.txt` 都不給 Pro 原始碼，這三處做對了。但每個 Pro block 的 demo 都在瀏覽器即時渲染，**整支元件的編譯後程式碼會原封送到任何訪客手上**。實測三個 Pro block（card-dock、count-chart、redline-reveal）的獨特字串都能在 `.next/static/chunks/*.js` 原文找到。count-chart 的 chunk 22.5 KB，原始碼 30 KB（含註解與 demo），Tailwind class、SVG path、aria 屬性、狀態邏輯全部保留，只是變數名被縮短。這等於 AGENTS.md「Pro 原始碼只由 `/r/pro/*` 提供」那條規則，在編譯後的形式上被繞過了。
2. **擋不住，只能拉高成本、留下證據、讓複製品過期。** 研究顯示 LLM 反混淆已是成熟工具鏈（webcrack 拆 bundle、humanify 用 LLM 重新命名），混淆器對 LLM 的阻擋效果有限；截圖或網址轉程式碼工具也普及。「看得到就仿得到」是前提，不是待解的問題。
3. **所以防線分三層，依投資報酬排序：**
   - **少給**：Pro 預覽改成「展示版」，不再送出完整元件（P0，Founding 前做）。
   - **可追**：每份授權交付的原始碼帶隱形指紋，加上定期程式碼搜尋與 DMCA 流程（P1）。
   - **不值得偷**：Pro 的價值放在持續更新與季節包，蒸餾只能拿到一張快照（延續 11/06 商業分析的結論）。
4. **不要做的事**：JS 混淆、封鎖右鍵或 DevTools、全站封鎖 AI 爬蟲。前兩者擋不住 LLM 又傷效能與體驗，第三者會砍掉 SunUI 最重要的通路（agent 透過 MCP 與 llms.txt 找到你）。

## 二、威脅模型：誰會怎麼蒸餾

| 路徑 | 做法 | 需要的成本 | 目前防護 | 風險 |
|---|---|---|---|---|
| A. 前端 chunk 還原 | 開 `/preview/<pro>`，從 Network 抓 chunk，丟給 LLM 或 webcrack + humanify 還原成 TSX | 幾分鐘、幾美分 | 無（只有 minify） | **高** |
| B. 截圖或錄影轉程式碼 | 截 demo 畫面或錄影，用 v0、screenshot-to-code、CloneUI 等工具重做 | 幾十分鐘，動效還原度中等 | 無，也無法有 | 中 |
| C. 付費者外流 | 買一份授權，把原始碼放上 GitHub、Discord 或打包轉賣；或把授權碼分享出去 | 一份授權費 | 原始碼頂端註解（可刪）、每 key 每日 20 個 IP | 中 |
| D. 付費者用 agent 洗稿 | 拿 Pro 原始碼叫 agent 改寫成「不同」的元件包再發佈 | 一份授權費 + 幾小時 | 授權條款禁止 | 中 |
| E. 訓練爬蟲 | AI 公司爬站收進訓練資料，日後模型能吐出相似元件 | 0（對方的成本） | robots.txt 擋 `/preview/` 與 `/api/`，但不擋 `/_next/static` | 低到中 |

A 是唯一「零門檻、高還原度、可規模化」的路徑，也是唯一能靠工程手段大幅收斂的。B 的產出是「像」，不是「同」，而且法律上本來就難管（見第四節）。C、D 靠追蹤與法律。E 對 Pro 的影響主要來自 A：只要 chunk 是公開的，爬蟲就可能收到。

### 實測曝光面

| 端點 | 給出什麼 | 判定 |
|---|---|---|
| `/r/pro/<name>.json` | 原始碼，需 Polar 授權 + 限流 + IP 計數，`Cache-Control: private, no-store` | 安全 |
| MCP `get_block`（`include_source`） | Pro 只回描述，明確拒絕給原始碼 | 安全 |
| `llms.txt`、`llms-full.txt`、skill | 只有 Pro 的名稱、用途、安裝方式 | 安全 |
| block 頁 `/blocks/<pro>` | Pro 不讀 sources，沒有程式碼區塊 | 安全 |
| `/preview/<pro>`（iframe） | `next/dynamic` 載入 `registry/pro/<name>/demo.tsx`，整個元件打包成 client chunk | **外洩** |
| 首頁卡片預覽 `card.tsx` | 同上，只是較小的 demo | **外洩**（範圍較小） |
| robots.txt | `Disallow: /preview/`，但 chunk 在 `/_next/static/`，而且 robots 是自願遵守 | 形同沒有 |
| source map | 正式 build 沒有開 `productionBrowserSourceMaps` | 安全（`.next` 裡的 `.map` 是 dev 殘留） |

另外兩個授權端的小洞：

- `lib/license.ts` 的限流、快取、IP 計數都存在**單一 instance 記憶體**。部署在 serverless 時每個 instance 各算各的，「每日 20 個 IP」與「每 15 分鐘 100 次」實際上會被放大好幾倍。檔頭註解已預告要改 Redis / KV，Founding 前應該做。
- 交付原始碼只在頂端加一段帶 `displayKey` 的註解。外流者第一件事就是刪掉它，所以它只能嚇阻，不能追蹤。

## 三、外部研究重點

### 1. LLM 反混淆已經是現成工具

- [humanify](https://github.com/jehna/humanify) 用 LLM 只負責「取名字」，結構改寫交給 AST 工具，所以輸出與原碼行為一致；README 建議先用 webcrack 拆 webpack bundle 再丟進去。也就是說，Next.js chunk 正好是它的標準輸入。
- [JsDeObsBench](https://arxiv.org/abs/2506.20170v1)（ACM CCS 2025）用 javascript-obfuscator 的七種變換（含控制流平坦化、字串加密、self-defending）測 GPT-4o 等模型：LLM 在「化簡、可讀性」上表現強，弱在語法精確與可執行性。換句話說，**混淆能讓還原出的程式碼多幾個 bug，但擋不住人看懂它**。而 SunUI 的價值大多在 Tailwind class 字串與 SVG path，這些是字面值，混淆器加密後執行時仍要解回來。
- 已有 agent skill 專門教 agent 做 JS 逆向（例如 [reverse-engineer-js](https://skillselion.com/skills/vladmdgolam/agent-skills/reverse-engineer-js)），代表這件事已經被包成一鍵流程。

### 2. 截圖轉程式碼普及，但還原度有上限

- [screenshot-to-code](https://github.com/parrth20/screenshot-to-code) 支援直接貼網址複製網站；商業工具如 [CloneUI](https://peerpush.com/p/cloneui) 宣稱八成以上還原（廠商自述）。
- 實測評論指出這類工具多半只抓首屏、看不到互動狀態（[影片評測](https://rosetta.to/u/1littlecoder/the-best-way-to-clone-websites-in-2025)）。對 SunUI 而言，**動效的時間曲線、狀態切換、reduced-motion 替代、CJK 斷行**這些看不出來的部分，是這條路徑還原不了的。

### 3. 競品怎麼做：主要靠條款與 DMCA，不靠技術

- Tailwind Labs 對 Tailwind UI / Tailwind Plus 的外流，公開紀錄都是向 GitHub 送 DMCA（[2024-03 一次處理十幾個 repo](https://git.randommeaninglesscharacters.com/github/dmca/src/branch/master/2024/03/2024-03-19-tailwind.md)、2025-06 處理 GitHub Pages 上的整包複製）。沒有找到他們做程式碼層技術防護的資料。
- [Magic UI Pro](https://pro.magicui.design/license)、[Aceternity UI Pro](https://ui.aceternity.com/licence)、[shadcn.io](https://shadcn.io/license) 的授權都以「禁止轉售、禁止做成競品」為核心，同樣沒有技術防護。
- 業界共識是：元件庫賣的是時間與一致性，複製無法根絕，只能讓正版明顯更划算，並對公開散布者執法。

### 4. 封鎖 AI 爬蟲：守規矩的擋得住，不守規矩的要靠行為偵測

- Cloudflare 2025-08 報告指 Perplexity 在被封鎖後改用一般 Chrome UA 與未公開 IP 繼續爬（[Cloudflare 原文](https://blog.cloudflare.com/perplexity-is-using-stealth-undeclared-crawlers-to-evade-website-no-crawl-directives/)），同時指出 OpenAI 的爬蟲有遵守 robots.txt。結論：**robots.txt 只對守規矩的有用**。
- Cloudflare [AI Crawl Control 與 Pay per crawl](https://developers.cloudflare.com/ai-crawl-control/features/pay-per-crawl/what-is-pay-per-crawl/) 讓站方依爬蟲分別放行、封鎖或收費；第三方報導稱 2026-09 起對部分方案預設封鎖混用型 AI 爬蟲（未找到 Cloudflare 一手公告，僅供參考）。
- Vercel [BotID](https://vercel.com/kb/guide/protect-ai-endpoints-with-vercel-botid) 是隱形挑戰，可在 route handler 用 `checkBotId()` 判斷請求是否為自動化，並辨識已驗證的善意 bot。注意：沒有挑戰標頭的 curl 請求在正式環境會被判為 bot，所以**不能放在 `/r/pro/*` 與 `/mcp` 前面**（shadcn CLI 與 agent 就是 curl 型的合法客戶端）。

### 5. 浮水印與指紋：要選「改寫後還活著」的位置

- 學界與廠商的共識是：替每份交付加不同的隱藏識別碼，外流時可以追到買家（[Collberg 1999 綜述](https://www2.cs.arizona.edu/~collberg/content/research/papers/collberg99software.pdf)、[Jscrambler 說明](https://jscrambler.com/glossary/source-code-watermarking/)）。
- 同一批資料也指出弱點：靜態浮水印會被重構或最佳化抹掉，多位買家比對差異也能找出指紋。所以**指紋要放在「功能上需要、改了會壞或很麻煩」的地方**，而不是註解。

### 6. 法律：條款要寫進機器可讀的形式，外觀本身難保護

- 歐盟 DSM 指令的 TDM 例外允許權利人保留權利，但必須是機器可讀的形式；報導指出漢堡高等法院在 Kneschke v. LAION（2025-12-10）確認了這點。歐盟執委會正在徵詢並將公布認可的機器可讀協定清單（[執委會 FAQ](https://digital-strategy.ec.europa.eu/en/faqs/stakeholder-consultation-ai-and-copyright-compliance)）。robots.txt 管爬取，[TDMRep](https://blckalpaca.at/en/knowledge-base/seo-geo/technical-seo/robotstxt-and-ai-eu-legal-situation-and-tdm-opt-out.md) 專門表達著作權保留，兩者可以並用。
- UI 的「外觀與手感」在著作權上歷來很難主張（Apple v. Microsoft 敗訴），但**逐字或近乎逐字的程式碼複製**是清楚的侵權；Figma 的 AI 生成功能因為產出幾乎複製 Apple 天氣 App 而暫停（[AppleInsider](https://forums.appleinsider.com/discussion/236953)），顯示「高度可辨識的複製」仍會被認定有問題。對 SunUI 的意涵：**能告的是路徑 A 與 C（程式碼本身外流），路徑 B（看著重做）基本上管不到**。這進一步說明為什麼要先堵 A。

## 四、對策

### P0：Pro 預覽不再送出完整元件（Founding 2026-11-27 前）

目標是讓路徑 A 只能拿到「展示版」，而付費才拿到「完整版」。兩者的差異就是 11/06 分析說的 Pro 真正價值：一致性與正確性的總和。

做法：每個 Pro block 多一個 `preview.tsx`（或由 build script 產生），只包含：

- 固定一種變體、寫死的 demo 資料，**沒有 props API**（客戶要的是可設定的元件，不是一張固定畫面）。
- 不含四語文案表、不含 CJK 標點與斷行處理、不含倒數的 hydration 與分頁切換語意、不含完整 reduced-motion 替代路徑（展示版直接停在終態即可）。
- 視覺與動效保留，因為那是要讓人看了想買的部分，而且路徑 B 本來就拿得到。

`scripts/generate-previews.mjs` 對 Pro 改指向 `preview.tsx`，`card.tsx` 同理。這樣外洩的是「長得像、但不能直接上線」的程式碼，蒸餾者要補的正是最花時間的部分。

成本：每個 Pro block 約 15 至 30 分鐘（多數是刪程式碼），目前 64 個 Pro 目錄要分批做；可以先做首頁與 Founding 主打的那幾個。
取捨：展示版若明顯少了無障礙，對懂行的買家可能是扣分。展示頁可以加一行「完整版含四語、reduced-motion、CJK 斷行」，把差異變成賣點。

替代方案（若時間不夠）：Pro 預覽改成循環影片 + 一個可點的單一互動。最省事、外洩最少，但轉換力明顯較弱，不建議當長期方案。

### P0：授權端改用共享儲存

`lib/license.ts` 的 `hits`、`ipsByKey`、`cache` 改存 Vercel KV / Upstash Redis。否則「一把 key 被分享給整個 Discord」時，IP 上限在 serverless 下會失靈。這也是追蹤路徑 C 的基礎資料（哪把 key、哪天、多少 IP、抓了哪些 block）。

### P1：每份交付帶隱形指紋（2026-12 前）

在 `/r/pro/*` 的 `buildRegistryItem` 交付時，依 `licenseId` 決定性地注入指紋，位置要選改寫後仍會存活的：

- **執行期會用到的常數**：例如動畫的某個 easing 或 duration 值在人眼無差異的範圍內微調（0.42 對 0.43），或 SVG path 某個控制點差 0.01。刪掉要逐一比對，且 Prettier 與 Tailwind 排序外掛不會動到它們。
- **不要用 class 順序**：`prettier-plugin-tailwindcss` 會重排，客戶一存檔指紋就沒了。
- 每份用多個點（例如 8 至 12 處）組成編碼，即使被改掉一部分，比對剩下的仍能縮小到單一買家；多人比對差異的情況，靠點位多與只在少數 block 放來降低風險。

配套：在 `/r/pro/*` 記錄 `licenseId` 對應的指紋種子，外流時跑一支比對腳本即可指認。

### P1：定期搜尋 + DMCA 流程

- 每週用 GitHub code search 搜幾個 Pro 獨有字串（SVG path、特殊 class 組合、元件名），可以做成排程任務。
- 準備好 DMCA 範本與流程（Tailwind Labs 的公開通知可作格式參考），找到就送。外流發生時，指紋決定要不要撤銷該授權（Polar 撤銷後 `invalidateLicense` 已能即時生效）。

### P1：機器可讀的權利保留，分流 AI 爬蟲

SunUI 的通路就是 agent，所以**不能全面封鎖 AI**，要分清楚：

| 類型 | 例子 | 對免費內容 | 對 Pro 預覽 |
|---|---|---|---|
| 搜尋與即時取用 | OAI-SearchBot、ChatGPT-User、Claude-User、Claude-SearchBot、PerplexityBot | 放行 | 放行（展示版） |
| 訓練爬蟲 | GPTBot、ClaudeBot、CCBot、Google-Extended、Applebot-Extended、Bytespider、meta-externalagent | 放行（讓模型學會 SunUI 的免費 API 有利通路） | 擋 |

具體：

1. `robots.ts` 針對訓練爬蟲加 `Disallow: /preview/`（已對所有人擋）並保留其他路徑開放；不要擋 `/_next/static/`，會讓搜尋引擎渲染失敗。
2. 加 `/.well-known/tdmrep.json` 與對 `/preview/*`、`/r/pro/*` 回應 `tdm-reservation: 1` 標頭，讓權利保留符合歐盟「機器可讀」要求。成本不到一小時，法律上的價值大於技術價值。
3. 若之後放 Cloudflare 在前面，用 AI Crawl Control 對訓練爬蟲設封鎖，並利用它的行為偵測擋偽裝 UA 的爬蟲。Vercel BotID 只適合放在 `/preview/*` 的 HTML 頁面，**不要放在 `/r/pro/*`、`/r/*`、`/mcp`、`/llms*.txt`**。

這一層擋不住路徑 A 的人工或 agent 操作（它們用真的瀏覽器），所以它是 P0 的補強，不是替代。

### P2：條款補強（四語）

`messages.ts` 的 license 已有「不得作為 AI 元件生成器的訓練資料或輸出」，方向正確。建議補兩點，四語同步：

- 明確允許：在自己或客戶的專案裡用 AI 寫程式工具讀寫、修改 Pro 原始碼。避免付費者誤以為用 Claude Code 改元件是違約（那正是 SunUI 主打的使用方式）。
- 明確禁止：用 AI 改寫 Pro 原始碼後，以任何名義公開散布、轉售或做成元件庫、模板或資料集（對應路徑 D「洗稿」）。

### P2：讓複製品過期

這是唯一真正的護城河，已在 11/06 與 11/07 的商業分析中定案，這裡只強調它與防蒸餾的關係：

- 蒸餾拿到的是一張快照。每檔期的季節包、元件的修正與升級、shadcn 與 React 版本相容性，都只有正版會持續拿到。
- 更新紀錄（`/docs/changelog`）要讓這件事看得見：每次修了什麼 Pro 的邊界情況，寫出來。買家看到的是「持續維護」，盜版使用者看到的是「我的版本已經落後」。

## 五、不建議做的事

| 做法 | 為什麼不做 |
|---|---|
| javascript-obfuscator 等混淆 | JsDeObsBench 顯示 LLM 能化簡混淆碼；class 字串與 SVG path 執行時必須還原；chunk 變大、執行變慢，與 11/07 效能優化方向衝突 |
| 封鎖右鍵、DevTools、複製 | 對任何會開 Network 面板或用 agent 的人無效，只會讓正常訪客反感 |
| 全站封鎖 AI 爬蟲或 agent | 砍掉 MCP、llms.txt、agent 安裝這條主通路 |
| BotID 或 CAPTCHA 擋 `/r/pro/*`、`/mcp` | shadcn CLI 與 agent 是合法的非瀏覽器客戶端，會被誤擋 |
| 只靠 robots.txt | Perplexity 案例顯示不守規矩的爬蟲會偽裝 UA |
| 把 Pro 預覽改成 server component 以為就安全 | 有互動與動效的元件一定要在 client 執行，程式碼終究要送到瀏覽器 |

## 六、行動清單

| # | 項目 | 時間 | 成本 | 擋的路徑 |
|---|---|---|---|---|
| 1 | Pro 預覽改展示版：先做首頁與 Founding 主打的 block，`generate-previews.mjs` 對 Pro 指向 `preview.tsx` | 11/27 前 | 每個 15 至 30 分鐘 | A、E |
