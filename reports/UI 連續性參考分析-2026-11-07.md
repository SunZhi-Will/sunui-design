# UI 連續性參考分析（2026-11-07）

來源：
- 枯白啃設計（@Kubai087）2026-11-06 的貼文，談「為什麼邏輯合理的產品看起來還是不精緻」。
- 貼文引用的影片：stacked（@stackedlol）「dynamic island concept for a fintech startup」，19.5 秒，2840x2160。

## 1. 貼文的論點

1. 很多產品不精緻，主因之一是 UI 缺少「連續性」。
2. 連續性指的是：流程或介面狀態改變時，元素怎麼流暢地過渡。
3. 連續不是生硬切換，不是交叉淡化，也不只是形變，而是「感受的遷移」：利用使用者注意力的慣性，完成一瞬間的資訊切換。
4. 例子：早期 iOS 頂部標題列的標題轉場、Liquid Glass 裡圖示按鈕點下後展開成選單。
5. 行動建議：讓 Agent 檢查下拉選單、抽屜、手風琴表單有沒有做足過渡，並思考過渡發生時頁面上其他元素會受到什麼影響。

## 2. 影片逐格拆解

以 10fps 抽格觀察，整段只有**一個黑色膠囊**，從頭到尾沒有被換掉：

| 階段 | 內容 | 外框 |
|---|---|---|
| 輸入 | 搜尋圖示、「Trade anything...」、送出鈕 | 中寬 |
| 思考 | 「Thinking」、代號與槓桿、金額、像素菱形載入 | 變寬變高 |
| 下單 | 圓點脈動、「Placing trade order」、摘要 | 寬度不變 |
| 成交 | 轉圈變勾、「Order filled」、成交價 | 縮窄 |
| 持倉 | 頭像、標籤、走勢小圖、損益數字持續跳動 | 再變寬 |

觀察到的手法：

1. **外框是同一個**：寬高用彈簧補間，換狀態那一格外框會略微外擴再收回（輕微 overshoot）。
2. **舊內容很快退場**：約 1 格（100ms）內模糊加淡出，不等它完整播完。
3. **新內容分層進場**：主文先清楚，灰色副文晚一到兩格才從模糊變清楚。眼睛先讀到「Order filled」，再讀到細節。
4. **左側圖示是錨點**：位置固定，只換圖形（菱形、圓點、轉圈、勾、頭像）。視線一直停在左邊，右邊的字換了也不覺得是「換了一個元件」。
5. **最後狀態是活的**：損益與走勢持續更新，告訴使用者這不是結束畫面，而是持續狀態。
6. 兩側的左右箭頭只是影片用來切換狀態的展示控制。

## 3. 為什麼有效

- 位置與外框不變，大腦把它當成「同一個物件的新狀態」，不需要重新定位。
- 舊內容退得快、新內容主文先到，資訊交接沒有空窗，也沒有兩份文字疊在一起的混亂（交叉淡化的問題）。
- 外框寬度跟著內容走，資訊量多時給空間，少時收回，形狀本身也在傳遞「現在比較重要／不重要」。

## 4. 對 SunUI 的意義

### 跟現有規則的衝突

影片用了**模糊**做內容交接，而 `DESIGN.md` 檢查表明確禁止模糊。紙感版本的翻譯：

| 影片做法 | SunUI 紙感翻譯 |
|---|---|
| 模糊加淡出退場 | 100ms 淡出，不模糊 |
| 由模糊變清楚進場 | 6px 位移加淡入，用 `gentle` 彈簧 |
| 黑色膠囊 | `bg-card` 加邊框，結果用 `Stamp` |
| 外框彈簧改寬 | 量測內容寬度，用 `gentle` 補過去 |
| 像素菱形載入 | 縮圖外圈的描邊轉圈（載入是允許的循環） |

### 跟策略的關係

- 免費目錄凍結中（見 `reports/商業模式深度分析-2026-11-06.md`），所以不新增免費 block。
- 這個概念的價值在「組合起來的場景」：購物袋、付款、訂單、物流本來分散在四個 block，用一個外框串起來，正是 Pro 賣的東西（見免費與付費切分的選項 C）。

## 5. 已落地

1. **Pro 場景 `order-island`**（`apps/web/registry/pro/order-island/`）：一個狀態膠囊走完 bag、paying、placed、shipping、declined。
   - 外框寬度量測後用彈簧補間。
   - 左側商品縮圖全程不卸載，付款時外圈轉、失敗時輕搖。
   - 文字換行：舊的 100ms 退場，主文先到、副文晚 60ms。
   - 訂單成立用 `Stamp`；reduced motion 下全部立即切換、資訊完整；`aria-live` 播報每個狀態。
2. **設計規則**：`DESIGN.md` 第 4 節加第 5 條「連續性」與檢查表一項；`lib/agent/guidelines.ts` 同步英文版，MCP、skill 與 `llms-full.txt` 都會帶到。

## 6. 下一步建議

依貼文的行動建議，對現有 block 做一次連續性稽核，優先順序：

1. 展開收合類：Pro `faq-accordion`、`cart-drawer`、`upsell-drawer`，免費 `side-panel`、`dialog-sheet`、`expanding-search`。重點是下方內容有沒有跟著滑，還是直接跳。
2. 狀態切換類：`loading-button`、`add-to-cart-button`、`confirm-button`、`payment-status-banner`、Pro `checkout-button`。重點是按鈕是否變形而不是換成另一顆，有沒有錨點。
3. 多步流程：`checkout-steps`、Pro `order-tracker`。重點是步驟之間的資訊有沒有延續。

稽核本身不新增 block，不違反凍結。

## 7. 稽核結果（2026-11-07）

檢查標準就是 `DESIGN.md` 第 4 節第 5 條：同一個外框變形、有錨點不動、舊內容快退新內容分層進、周圍內容滑動不跳。範圍是第 6 節列的 13 個 block，再加上掃描時發現的幾個。

### 需要修（依嚴重度）

| 嚴重度 | Block | 問題 | 建議改法 |
|---|---|---|---|
| 高（已修） | `confirm-button`（免費，product） | 完全沒有動畫。第一下按完，標籤從「刪除」硬切成「確認刪除」，按鈕寬度瞬間跳；轉圈直接冒出；下方提示文字硬換 | 按鈕用 `layout` 讓寬度補間，標籤用 `popLayout` 上下換行；轉圈從寬度 0 長出；提示行淡入 |
| 高（已修） | `payment-status-banner`（免費，product） | 完全沒有動畫。出現、關閉、pending 轉 success 都是硬切。左側圖示位置本來就是好錨點，但圖形直接換 | 出現從上方滑入、關閉滑回；文字用 `popLayout` 換行；圖示格保留，轉圈換成圓點時淡入 |
| 中 | `checkout-button`（Pro） | 收據從按鈕下方印出很好，但按鈕本身的圖示與文字在 idle、processing、success、error 之間硬切，底色從主色瞬間變成紙色 | 圖示格固定不動、只換圖形；文字用 `popLayout`；底色加 150ms 過渡 |
| 中 | `order-tracker`（Pro） | 狀態推進時，圓點瞬間填滿、實線虛線瞬間切換，結果標記在舊站消失、新站出現，沒有「走過去」的感覺 | 已走路段改成可補間的進度線，從舊站畫到新站；結果標記等線畫到才出現 |
| 中 | `newsletter-signup`（Pro） | 送出後表單整塊換成完成畫面（三元運算子直接切），卡片高度瞬間跳 | 外框高度用 `height: auto` 補間，表單退場、完成文字分層進場；郵戳目前 `absolute` 壓在內容上，也違反結果標記規則，一併改到動作發生的位置 |
| 中 | `expanding-search`（免費） | 搜尋框展開寬度補間做得好，但建議清單只有淡入淡出；邊打字邊篩選時清單高度與列直接跳 | 清單外框高度補間，列的增減用 `layout` 與 `popLayout` |
| 低 | `checkout-steps`（免費，product） | 換步驟時圓點底色與勾硬切 | 底色 120ms 過渡，勾用描線（product 系列的 120ms 規格） |
| 低 | `dialog-sheet`（免費） | 桌面版對話框從畫面中央縮放淡入，跟觸發按鈕沒有空間關係 | `transform-origin` 設在觸發按鈕方向；底部抽屜版不用改 |
| 低 | `shipping-options`（免費） | 選取圈的墨點有彈簧，但卡片外框顏色瞬間換 | 外框顏色加 120ms 過渡即可 |

### 已經做到，不用動

| Block | 做法 |
|---|---|
| `faq-accordion`（Pro） | 內容高度 `auto` 補間，下方題目跟著滑 |
| `cart-drawer`（Pro） | 從右推入；刪除商品時列高收合；金額數字上下換行；免運進度線補間 |
| `upsell-drawer`（Pro） | 抽屜推入，加購區高度補間 |
| `side-panel`（免費） | 從邊緣推入、推回 |
| `loading-button`（免費） | 按鈕 `layout` 縮成轉圈再展開，文字 `popLayout` 換行：本身就是連續性範例 |
| `add-to-cart-button`（免費） | 標籤飛進購物車圖示，數字跳動：跨元件的連續 |
| `sliding-tabs`（免費） | 底線用 `layoutId` 滑到新分頁 |
| `toast-stack`（免費） | 疊放、展開、移除都有位移 |

### 建議順序

1. 兩個高嚴重度的免費 block 先修：`confirm-button`、`payment-status-banner`。它們在目錄裡、會被 agent 搜到，現在是反例。
2. 接著 Pro 的 `checkout-button`、`order-tracker`、`newsletter-signup`：Pro 賣的就是精緻度。
3. 低嚴重度的幾項一次批次處理。
