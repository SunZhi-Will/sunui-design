# Altura 動態功能卡 參考分析

> 2026-11-07。來源是 Kevser（@kevserctk，產品設計師）在 X 的貼文「I Prompted. UI Animation.」（2026-11-06，7,775 次觀看、314 讚、223 書籤、12 則回覆）。影片 4 秒循環、2880 × 1804。【已驗證】表示這次在瀏覽器逐格或在 repo 實測；【推論】【建議】【估算】是判斷。

## 0. 結論先講

1. **這不是動畫炫技，是「用動作證明文案」。** 三張卡各只有一個動詞：收集、起草、完成。回覆裡最有見地的一則（Adam Fard）就點出這點：第一張卡在你讀字之前就說明了「context, already gathered」。【已驗證】
2. **書籤比異常高（223 / 314 = 0.71）。** 比 self-building-page 的來源貼文（634 / 1,020 = 0.62）還高。代表看的人是在「存參考」，觀眾主要是設計師與前端，正是 SunUI 想觸及的人。【已驗證，比值為推論依據】
3. **對 SunUI 最大的意義是警訊，不是素材。** 奶油紙底、mono 標籤、細線格、編號、黑色 CTA，這套語彙和 SunUI paper 系列高度重疊，而作者說它是「prompt 出來的」。外觀已經不是護城河，SunUI 能賣的是行為：狀態、無障礙、離屏暫停、四語系、可被 agent 正確安裝。【推論】
4. **建議用法，依優先順序：** (a) 拿這個結構講 SunUI 自己的三個主張，放首頁與 Product Hunt 頁；(b) 做成 Pro 場景裡的一個區段（電商版預設內容），不做成新的免費 block；(c) 把「一卡一動詞」寫進設計文件。

## 1. 畫面結構

| 區域 | 內容 | 手法 |
|---|---|---|
| 左上 | `■ Why teams switch` 小標，兩行大標「Less busywork. / More momentum.」 | mono 小標加方塊符號，大標細字重、緊行距 |
| 右上 | 三行說明「Altura handles the follow-ups, prep and status updates...」與黑底「Start free →」 | 標題與 CTA 分居兩側，不堆在一起 |
| 下方 | 三欄卡片，細線分隔，外框四角有小黑點（裁切標記） | 像設計稿的出血線，暗示「設計師工具」氣質 |
| 每張卡 | 暖色沙丘照片，上面疊半透明玻璃 UI 面板；下面是 `01` mono 編號、標題、灰色說明 | 照片給溫度，UI 給可信度，文字給意義 |

Altura 是虛構產品（AI 助理，處理 follow-up、會議準備、狀態更新）。【已驗證】

## 2. 逐格拆解（每 0.4 至 0.5 秒取一格）

### 卡 01：Context, already gathered

- 左邊三個來源標籤：Calendar、Inbox、CRM，用直角折線接到右邊一個白色方塊。
- 白色方塊有 Figma 式的四角選取把手，中間是點狀轉圈載入。
- **光點沿連線依序流動**：0.0 秒從 Calendar 出發，0.4 秒輪到 Inbox，0.8 秒到 CRM，抵達時來源標籤會短暫發光，方塊外框有一層呼吸的光暈。
- 4 秒內三條線各跑一到兩輪，所以畫面上永遠有一條線在動。

### 卡 02：No follow-up left behind

- 面板標題「Follow-up drafted」，右邊「■ just now」的小方塊在閃。
- **三條灰色骨架線從左往右長**（0.0 秒短，1.6 秒接近滿），表示草稿正在寫。
- 3.9 秒時骨架線縮回三個小方塊，接回 0 秒的開頭，循環沒有接縫。
- 底部「✓ Approve & send」主按鈕、「Edit」次按鈕全程靜止。動的只有內容，操作點不動。

### 卡 03：Get your hours back

- 面板「Cleared today · ■ Auto」，三個待辦：Send recap to Harbor & Co.（Email）、Update deal stage（CRM）、Prep Thursday brief（Docs）。
- **依序打勾**：0 秒第一項已勾，0.8 秒第二項勾上，1.6 秒第三項先半透明再實心，勾上的那一列底色變亮。
- 下方「Focus time」進度條從約 20% 一路長到滿，2 秒後維持滿格到循環結束。

### 三張卡的節奏

| 時間 | 卡 01 | 卡 02 | 卡 03 |
|---|---|---|---|
| 0.0 秒 | Calendar 光點出發 | 骨架線短 | 第 1 項已勾，進度條 20% |
| 0.8 秒 | CRM 光點抵達 | 骨架線變長 | 第 2 項勾上，進度條 70% |
| 1.6 秒 | 下一輪開始 | 骨架線接近滿 | 第 3 項勾上，進度條 95% |
| 2.0 至 3.5 秒 | 光點繼續巡迴 | 停住 | 全部完成，靜止 |
| 3.9 秒 | 回到起點 | 縮回方塊 | 回到起點 |

觀察：前半秒三張卡同時在動，後半段只剩卡 01 在動。這給眼睛一個「事情做完了」的停頓，也讓循環重新開始時有對比。【已驗證】

## 3. 為什麼有效

1. **一卡一動詞，動作就是證據。** 文案說「已收集」，畫面就是三條線流進一個點；文案說「不會漏」，畫面就是草稿自己長出來；文案說「時間拿回來」，畫面就是打勾加進度條滿格。讀者不用讀說明就懂。
2. **動作詞彙極少。** 只有五種：光點沿線移動、骨架線伸長、打勾、進度條填滿、載入轉圈。全部是小幅度、低對比，沒有彈跳、沒有縮放、沒有 3D。
3. **用真 UI 縮圖，不用圖示插畫。** 面板裡有具體的客戶名（Harbor & Co.）、工具名（Email、CRM、Docs）、時間戳（just now）。具體名詞讓它看起來像真產品。
4. **操作點靜止，內容在動。** 按鈕、標題、標籤位置全程不動，這和 `UI 連續性參考分析-2026-11-07.md` 的「錨點不動」是同一個原則。
5. **4 秒、無接縫循環。** 剛好是 X 自動播放一輪不會被滑走的長度，重播時也看不出起點。
6. **照片加玻璃面板。** 照片的暖色把整頁從「SaaS 模板白」拉開，玻璃面板讓 UI 與背景分層。缺點是沙丘照片本身很像 AI 生成圖，近看會有「AI 感」。

## 4. 「I Prompted」這件事的意義

- 作者同一系列還有「I Prompted This Design.」，同一個 Altura 品牌。這是一個「AI 做設計」的內容帳號定位。【已驗證】
- 回覆有人問「用什麼做的、prompt 花多少」，我看的時候作者沒回。所以**不知道成品是真的可執行程式碼，還是逐格合成的影片**。【已驗證：未回覆】
- 對 SunUI 的推論【推論】：
  - 這種「奶油底 + mono + 細線 + 小動畫」的編輯感，已經是 AI 生成的預設品味之一。SunUI paper 系列看起來和它很接近，如果只靠外觀，買家會覺得「我自己 prompt 也有」。
  - 但 prompt 出來的通常沒有：reduced motion、離屏與分頁隱藏時暫停、鍵盤可達、四語系、品牌色 token、真實狀態（真的能勾、真的能送）。這些正是接案者交給客戶時會被驗收的東西，也是 SunUI 要在文案上講清楚的差異。
  - 更積極的說法：SunUI 的 MCP 與 skill 本來就是讓 agent「prompt 出來」的管道。行銷可以直接借這句話：「你也可以 prompt 出這個，而且裝進專案就能上線。」

## 5. SunUI 現有能力對照

用 `search_blocks` 搜「三張動態功能卡、agent 流程、待辦自動完成」，沒有完全對應的 block。【已驗證】但原子都有：

| 原作元素 | SunUI 現有 | 差距 |
|---|---|---|
| 光點沿連線流向中心節點 | `svg-effects` 的 `animated-beam`、`flowing-connectors`（免費） | 有，需組裝 |
| 骨架線伸長 | `skeleton-set`、`loading-effects`（免費） | 有，需改成「寫入中」語意 |
| 依序打勾加進度條 | `addon-checklist`、`tier-progress`、`free-shipping-progress`（Pro） | 有 |
| 三欄功能卡加預覽 | `drop-release-hero` 的 FeatureCard（Pro） | 只在 hover 時動，不是常駐循環 |
| 整段產品示範 | `step-demo`、`scripted-demo`、`scroll-story`（免費） | 太重，是整個視窗，不是卡片縮圖 |

結論：**缺的不是元件，是「把三個小循環同步編排成一個區段」的組合。** 這正好是 Pro 該賣的東西（組合好的場景），而不是新的免費 block。

## 6. 做成 Pro 是否合理（四個問題）

| 問題 | SaaS 原樣 | 電商改編版 |
|---|---|---|
| 可替代性 | Magic UI 有 bento 格加 animated beam，免費 | 沒看到電商語意的同類 |
| 工時（使用者自己做） | 約 1 至 1.5 天【估算】：三個循環、同步時鐘、無障礙、離屏暫停 | 同左 |
| 商業距離 | 遠（AI SaaS 官網，客群 C） | **近**：活動頁常見的「為什麼在這裡買」區段 |
| 展示價值 | 高（書籤比 0.71） | 中高 |

電商改編版的三張卡【建議】：

1. **優惠自動疊加**：「會員折扣」「滿額券」「信用卡回饋」三個標籤沿線流進購物車節點，節點顯示折後價跳動（接 `animated-number`）。
2. **下單就出貨**：出貨單面板的品項列一行行長出來，最後蓋上「已出貨」印章（接 paper 系列的收據與 `stamp` 語彙）。
3. **免運只差一點**：清單依序打勾（已加購、已用券、已選超取），免運進度條填滿。

這三個動詞（省、快、免運）就是檔期頁最常寫的三句賣點，而且全部可以接到現有 Pro 元件。

## 7. 建議的下一步

### 7.1 首頁與 Product Hunt 頁（最優先，零型錄成本）【建議】

用同一個結構講 SunUI 自己的三個主張：

| 卡 | 標題 | 動作 |
|---|---|---|
| 01 | Your agent already knows the catalog | Cursor、Claude Code、v0 三個標籤沿線流進 SunUI 節點（MCP 查詢） |
| 02 | Install plan, drafted | `npx shadcn add ...` 指令逐字長出來，下方「Approve & install」 |
| 03 | Ship the campaign today | 倒數、優惠券、免運條依序打勾，「上線」進度條填滿 |

理由：把「agent 透過 MCP 幫你裝區塊」這件抽象的事，壓成 4 秒看得懂的影片，和 self-building-page 一起當 PH 發表素材。它不新增 block，不違反免費層凍結。

### 7.2 Pro 區段：`live-value-props`（或併進 campaign-landing）【建議】

- 預設內容用第 6 節的電商版，另附 SaaS 版示範內容給客群 C。
- 一個共用時鐘驅動三張卡（像 `step-demo` 的「每格是 t 的純函數」），確保三卡同步、可凍結、可截圖。
- 必備：reduced motion 直接顯示每張卡的完成狀態；離屏與分頁隱藏時暫停；動畫區 `aria-hidden`，文字照常可讀；照片可換成 `gradient-backdrop` 避免 AI 沙丘感。
- 工時約 1 天【估算】，大部分是編排與三語系文案。
- 若過程中抽出一個通用原子（例如「沿線流向節點」的卡片版），依凍結規則可以放免費層。

### 7.3 寫進設計文件【建議】

在 `DESIGN-product.md` 加一條「常駐動態」規則，並同步 `lib/agent/guidelines.ts`：

- 一張卡只有一個動詞，動作必須對應標題的主張。
- 循環 4 秒以內，無接縫；後半段留靜止，給「完成」的感覺。
- 按鈕與標籤不動，只動內容。
- 同一區段共用一個時鐘，錯開而不是各跑各的。

## 8. 不建議做的事

- 不要照抄 Altura 的品牌、文案、沙丘照片。只取結構與節奏。
- 不要做成新的免費「feature-cards」block。原子已在免費層，組合應該留在 Pro，而且凍結期間也不允許。
- 不要為了追這個風格再加動效庫。這支影片證明的是「少即是多」：五種小動作就夠了。
