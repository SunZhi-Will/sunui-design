# 訂閱自動續扣實作計畫（2026-11-20）

背景：2026-11-20 決定 Pro 月訂（NT$590 / US$19）與年訂（NT$3,190 / US$99）改成到期自動扣款。買斷方案（founding、pro、team）維持一次性付款。原本的設計是預付期間制：不綁卡，SunUI 自己記到期日，到期前 7 天寄信，客戶用同一個 email 再買一期延長同一把授權碼。

## 1. 金流能力查證

### Polar（美金）

原生支援訂閱商品（recurring_interval：month / year）。Polar 是 merchant of record，負責存卡、排程扣款、失敗重試（dunning）、各國消費稅，並提供客戶自助入口（customer portal）讓客戶取消、換卡、看收據。

相關通知：
- `order.paid`：每一期扣款成功都會有一筆 order。`billing_reason` 區分 `subscription_create`（第一期）與 `subscription_cycle`（續扣）。order 帶 `subscription_id` 與 `subscription.current_period_end`。
- `subscription.canceled`：客戶取消，`cancel_at_period_end` 為 true，這期用到結束。
- `subscription.uncanceled`：取消後又恢復。
- `subscription.past_due`：扣款失敗，Polar 進入重試。
- `subscription.revoked`：訂閱真正結束（取消到期，或重試全部失敗）。

### SHOPLINE Payments（新台幣）

查證來源：`docs.shoplinepayments.com/guide/quick/`、`/guide/session/`、`/api/trade/create/`。

- **有定期扣款**：`POST /api/v1/trade/payment/create`，`paymentBehavior: "Recurring"`、`autoConfirm: true`，帶 `paymentCustomerId` 與 `paymentInstrument.paymentInstrumentId`，顧客不在場由伺服器發動。
- **但現在用的導轉式結帳不能綁卡**。導轉式文件寫明只有一般付款，綁卡、快捷、定期付款要用「內嵌式」：前端載入 SHOPLINE JS SDK，用 `customerToken` 綁卡（`CardBind` 或 `CardBindPayment` 並帶 `savePaymentInstrument: true`），SDK 參數 `subscribeAgreement` 要顯示「定期購物信用卡代扣協議」。
- **SHOPLINE 不排程**：它只提供「用已存的卡扣一次」的 API，排程、失敗重試、寬限期、取消都要 SunUI 自己做（每天的 cron 找到期的訂閱，呼叫 Recurring 扣款）。
- **未確認**：商家帳號是否要另外申請開通定期扣款（文件沒寫），Recurring 是否免 3DS。開工前要問 SHOPLINE 業務。

結論：SHOPLINE 做得到，但等於重寫一條新台幣結帳（內嵌式 SDK 頁面、存 `paymentCustomerId` 與 `paymentInstrumentId`、自建扣款排程、重試、取消頁、解綁），而且要先確認商家帳號有開通。

## 2. 新台幣怎麼做：三個選項

| 選項 | 做法 | 優點 | 缺點 |
|---|---|---|---|
| A | SHOPLINE 內嵌式 SDK 綁卡 + SunUI 自己排程 Recurring 扣款 | 台灣客戶刷台幣、無海外手續費 | 工作量最大；要先確認開通；扣款、重試、取消全部自己維護；11/27 前做不完 |
| B（建議先做） | 月訂、年訂一律走 Polar 美金訂閱；SHOPLINE 只賣買斷 | 現成、穩定，取消與換卡交給 Polar 入口；11/27 前做得完 | 台灣客戶刷美金，約 1.5% 海外交易手續費；繁中頁面訂閱改標美金 |
| C | B 先上線，Product Hunt 之後再評估 A | 兼顧時程與在地體驗 | A 的工作只是延後，不是取消 |

原本建議 C。**作者 2026-11-20 決定：美金和台幣都做**，也就是 Polar 訂閱 + 選項 A 同時實作，見第 5 節。

## 3. Polar 實作細節

### 商品設定
- `POLAR_PRODUCT_IDS` 裡的 `monthly`、`yearly` 改成 Polar 的訂閱商品（月繳、年繳），買斷三個維持一次性。
- Webhook 增勾：`subscription.canceled`、`subscription.uncanceled`、`subscription.past_due`、`subscription.revoked`（`order.paid`、`order.refunded` 保留）。
- 新環境變數 `POLAR_ORG_SLUG`：組客戶入口網址 `https://polar.sh/<slug>/portal`（sandbox 是 `sandbox.polar.sh`）。客戶在入口用 email 驗證碼登入，SunUI 不用自己做身分驗證。

### 續扣怎麼延長 `expiresAt`
- 第一期（`subscription_create`）：照現在的 `fulfillOrder` 發授權碼，另外記 `polarsub:{subscription_id}` 對應授權 id，授權加 `autoRenew=1`、`polarSubscription`。
- 續扣（`subscription_cycle`）：用 `subscription_id` 找到授權，新建一筆 `renewal` 訂單（帳務才對得上），`expiresAt` 設成這筆 order 的 `subscription.current_period_end`；沒有這欄時用現有到期日往後加一期。金額照樣比對 `net_amount`。
- 同一個 email 已經有自動續扣中的訂閱時，結帳頁擋下第二筆（避免重複扣款），改導去客戶入口。

### 取消
- 美金：客戶入口取消。`subscription.canceled` 把授權標成 `autoRenew=0`，到期日不動，這期用完為止。`uncanceled` 改回 1。
- 新台幣（選 B 時）：沒有新台幣訂閱，不需要。選 A 時要另做取消頁（email 驗證連結 + 呼叫 SHOPLINE unbind）。
- 授權頁、信件、401/403 訊息都附客戶入口網址。

### 扣款失敗與寬限期
- Polar 自己重試（dunning），期間訂閱是 `past_due`。
- SunUI 給自動續扣的授權 7 天寬限：`expiresAt` 過了 7 天內仍可安裝，讓 Polar 有時間重試。`past_due` 時寄一封「扣款失敗，請到入口換卡」的信。
- `subscription.revoked`：重試失敗或取消到期，授權 `autoRenew=0`，`expiresAt` 若還在未來就改成現在，寬限立刻結束。
- 已經裝進專案的 block 不受影響，這點維持不變。

### 每天的 cron 信
- 自動續扣中的授權：到期前 7 天寄「將於某日自動扣款 US$19 / US$99，要取消請到入口」。年訂一定要寄（金額大、間隔長），月訂也寄，避免意外扣款的爭議。
- 已取消（`autoRenew=0`）且還沒過期的：寄「訂閱將於某日結束，不會再扣款」，附續訂與買斷連結。
- 舊的預付制授權（沒有 `autoRenew`）：照舊寄到期提醒，續約改成開一筆新的自動續扣訂閱。

### 結帳揭露
- 結帳頁訂閱說明、定價頁 FAQ、`proTerms`、授權頁、授權碼信都寫明：到期自動扣款、扣款前 7 天寄信通知、隨時可在客戶入口取消、取消後用到這期結束、不按比例退款。
- 四個語系（en、zh-TW、zh-CN、ja）同步。

### 退款與拒付
- `order.refunded` 現有邏輯保留（訂閱退款把到期日扣回一期）。退款不自動取消訂閱，要取消由客戶或作者在 Polar 操作。

## 4. 本機測試

- `POLAR_ENV=dev`：結帳直接入帳，訂閱授權標成 `autoRenew=1`。
- 單元測試：用 `signPolar` 產生簽章，對 webhook 解析與續扣到期日計算寫測試（`tests/polar.test.ts`、`tests/subscription.test.ts`）。
- Sandbox 端對端：需要作者在 Polar sandbox 建兩個訂閱商品並設好 webhook，才能跑真的續扣（sandbox 可以用 API 觸發提前續扣或等週期）。

## 5. 實際實作（2026-11-20，美金與台幣都做）

### 新台幣（SHOPLINE 內嵌式 + SunUI 排程）
- 結帳：新台幣月訂、年訂不再走導轉式，改到 `/checkout/card`。前端載入 SHOPLINE SDK（`components/shopline-card-form.tsx`），強制綁卡並顯示定期扣款協議；伺服器呼叫 `payment/create`（`CardBindPayment`），回 `nextAction` 給 SDK 完成付款與 3D 驗證。
- 入帳：`trade.succeeded` 照舊入帳，同時把 SHOPLINE 會員 id 與卡片 id 寫到授權（`slpCustomer`、`slpInstrument`）。卡片資訊可能從付款回應、付款通知或 `customer.instrument.binded` 先到，用 `slpref` / `slppending` 對回授權（`lib/orders.ts`）。
- 續扣：每天的 cron 在到期前 12 小時內用 `Recurring` 扣款，新建一筆 `recurring` 訂單，成功就從原到期日往後加一期。失敗在到期後第 1、3、5 天重試（`lib/subscription-core.ts`），第一次失敗寄信請客戶換卡；重試用完或寬限期過了就結束訂閱並解除綁卡。同一期同一次重試有鎖，不會重複扣款。
- 取消、恢復、換卡：`/account`（寄到訂閱 email 的 24 小時簽章連結，`lib/account.ts`）。取消只把 `autoRenew` 改 0，卡留到期滿才由 cron 解綁；換卡走 `CardBind`（NT$1 授權隨即取消），新卡由綁卡通知寫回，舊卡解綁，重試次數歸零。
- 新環境變數 `SHOPLINE_CLIENT_KEY`；沒設定時結帳頁的訂閱只提供美金。

### 美金（Polar）
- `monthly`、`yearly` 改成 Polar 訂閱商品。第一期 `order.paid` 照一般訂單入帳並記 `polarsub:{id}`；之後每期 `subscription_cycle` 用訂閱 id 找授權，新建續扣訂單，到期日設成 Polar 這一期的結束時間。
- `subscription.canceled / uncanceled / past_due / revoked / updated` 對應取消、恢復、扣款失敗信、結束、換方案。
- `/account` 的取消與恢復呼叫 Polar API（`cancel_at_period_end`，token 要有 `subscriptions:write`），換卡與收據連到 Polar 客戶入口（`POLAR_ORG_SLUG`）。

### 共通
- 寬限期 7 天（`licenseExpired` 對 `autoRenew` 的授權加 7 天）。
- 同一個 email 已有自動續扣中的訂閱時，結帳頁擋下第二筆。
- cron 信：自動續扣中寄「將於某日扣款」，已取消寄「將於某日結束」，2026-11-20 前的預付制授權照舊寄續訂提醒。
- 文案：結帳頁、刷卡頁的自動續扣揭露，定價頁訂閱區、FAQ、`proTerms`、授權頁、授權碼信，四個語系同步。

### 已驗證 / 還沒驗證
- 已驗證（本機 `SHOPLINE_ENV=dev`、`POLAR_ENV=dev` 加記憶體 Redis）：新台幣月訂入帳並記卡、重複訂閱被擋、cron 續扣延長一個月、`/account` 取消與恢復、Polar 續扣通知延長到期日、重送不重複入帳、past_due / canceled / uncanceled / revoked、金額不符標記。單元測試涵蓋寬限期、扣款排程、通知解析。
- **還沒驗證，上線前要做**：SHOPLINE sandbox 真的綁卡付款與 Recurring 扣款（要 clientKey，並先向 SHOPLINE 確認商家帳號已開通綁卡與定期扣款；文件有幾處欄位名稱不一致，見 `lib/shopline.ts` 的 `cardFromPayment`）；Polar sandbox 建兩個訂閱商品、勾新的 webhook 事件，跑一次真的續扣（Polar sandbox 可以手動觸發）與取消。
