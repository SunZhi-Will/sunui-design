# kubai-icons 參考分析

> 日期：2026-11-05
> 對象：https://github.com/kubai087/kubai-icons （clone 於 commit `f4dc5bb`，35 個檔案）
> 目的：看它哪些做法值得 SunUI 圖示系統（`ICONS.md`、四套 `registry/icons/*`）借鏡，哪些不能碰。

## 一句話結論

它真正的價值不在 66 個圖示，而在「讓 AI 每次都畫出同一種風格」的那套流程：**數字化的硬規則 + 現成引擎 + 無頭瀏覽器自檢 + 盲測迭代**。視覺風格（漸層、投影、內發光）直接違反 `DESIGN.md`，授權也禁止改寫規則文字，所以**只學方法，不搬程式與文字**。

---

## 1. 它是什麼

一個 Claude skill。給它功能清單或產品程式碼，它畫出和既有 66 個圖示同風格的圖示，可交付「hover 會形變的 SVG + JS」或「靜態 SVG 檔」。

| 檔案 | 行數 | 角色 |
|---|---|---|
| `PROMPT.md` | 130 | 全部設計規則，每條都是硬性要求（簡中） |
| `SKILL.md` | 63 | skill 入口：流程九步、何時問動態或靜態 |
| `src/engine.js` | 296 | 顏色推導、外描邊遮罩、漸層與濾鏡、插值動畫、色板、runtime |
| `src/icons.js` | 1213 | 66 個範例圖示，每個是 `svg / target / draw` 三件組 |
| `src/app.js` + `index.html` | 221 | 展示頁：`ORDER` 決定顯示順序、色板切換、demo 開關 |
| `scripts/check.mjs` | 184 | 無頭 Chrome 截圖自檢 |
| `scripts/export.mjs` | 127 | 匯出不依賴 JS/CSS 的靜態 SVG |
| `scripts/media.mjs` / `pack.mjs` | 262 | README 動圖、打包成兩種 zip（一般版與 marketplace 版） |
| `history/` | 3 個 HTML | 定型前的三個版本，保留作為過程記錄 |

技術上是零依賴的瀏覽器全域腳本（不是 ES module、沒有 TypeScript、沒有框架）。

## 2. 引擎怎麼運作

### 2.1 圖示的資料形狀

```js
{
  name: '文件夹',
  svg: (u) => `...<path data-n="back" .../>...`,      // 只畫一次的骨架，可變部位用 data-n 標名
  target: (hover, state) => ({ back: [...], fx: 7 }), // 回傳靜止或懸停時的「數字」
  draw(p, E) { at(E.back, { d: rp(p.back, ...) }) }   // 把插值後的數字寫回 DOM
}
```

重點：**動畫的對象是數字，不是 CSS 屬性**。`target` 回傳任意巢狀的數字物件（座標陣列、角度、0→1 進度），引擎逐數插值後交給 `draw` 重算路徑。所以能做到 path 形變、鉸鏈翻轉、先開蓋再抽信這種有順序的動作，而不需要 morph 函式庫。

### 2.2 動畫：可中途折返的兩組關鍵影格

- 每個部位只有兩組值：靜止、懸停。460ms、`cubic-bezier(0.22, 1, 0.36, 1)`，自己用牛頓法解 bezier。
- `go()` 永遠**從畫面上當下的數值出發**，滑進滑出再快都會平滑折返，不跳格。
- 持續或往復的動作（鬧鐘響、指南針擺）不用 loop，而是用一個 0→1 的進度派生出「振盪後收斂」：
  - 靜止與結束都要擺正：`角度 = A·(1−o)·sin(kπo)`
  - 從偏角收斂到目標：`角度 = A·(1−o)·cos(kπo)`
  - 因為 ease-out 很強，振盪會擠在前段，k 取 2 到 3 即可。結束狀態穩定，沒有無限循環。
- `prefers-reduced-motion` 時直接跳到終點。

### 2.3 顏色：一個主色推導全部

- 所有色標都以參考藍 `#5393FF` 寫死在圖示裡，例如 `data-t="stop-color:#93BBFF"`。
- 渲染時用「相對參考色的明暗比例」逐通道換算到目前主色（沿用 Lumno 的 `tintFolderColor`）。換一個主色，整個圖示的漸層、描邊、投影一起換。
- 屬性標記驅動重繪：`data-t`（跟主色）、`data-w`（白色標記，清透色板下自動轉深色）、`data-pure`（大面積純色，清透色板下變成白到純色的漸層）。
- 色板分三類：彩色（每個圖示一色）、清透（一個基色，填色提亮 10%、描邊壓暗 16%、白標記轉深）、黑色。

### 2.4 外描邊

SVG 沒有 outside stroke，它的做法是：描邊畫 2 寬，再用自己的形狀做 mask 遮掉內側一半。每個 `.ol` 元素一個 mask，每一幀同步 mask 的 `d`。代價是 DOM 與重繪量大。

## 3. 流程：它最值得學的地方

### 3.1 規則全部是可驗證的數字

`PROMPT.md` 幾乎沒有形容詞，全是數字與二選一判斷：

- 畫布 `0 -2 31 29`、中心 (15.5, 12.5)，四種 keyline（圓 23、方 20.6、橫 23×18.4、直 18.4×23），有機形狀可超出約 1 單位補償。
- 線寬只有三檔：內容線 1.6、方向符號 2.2、描邊 1。
- 最小細節 2.4 單位（24px 下約 1.9px），比這小就刪或放大，語意核心也不例外。
- 間距規則「要嘛正好貼住，要嘛離開 2 以上」，0 到 2 之間的縫一律不行。
- 色帶規則「描邊內側的色帶至少 2，不夠就去掉」，禁止「描邊裡只剩一條細縫」。
- 白色分兩種：白色內容（紙、螢幕，永遠白）與白色標記（畫在色塊上的符號，會隨色板轉色）。內容一旦移出容器落到淺色背景，就不能再是純白無描邊。
- 組合圖形：主體至少一個方向頂滿 keyline，輔助元素（放大鏡、箭頭）明顯更小、壓角或緊鄰。

每條規則都能被截圖檢查，而不是靠「看起來協調」。

### 3.2 自檢腳本 `check.mjs`

只用系統裡的 Chrome（`--headless=new --screenshot`），**零 npm 依賴**：

| 輸出 | 用途 |
|---|---|
| `rest.png`、`hover.png` | 靜止與懸停結束 |
| `frames.png` | 0% 到 100% 共 6 列中間幀，往復動作只能從這裡判斷 |
| `size-24.png`、`size-28.png` | 實際尺寸可讀性 |
| `palettes.png` | 每個色板一列 |
| 終端輸出 | 頁面載入期的腳本錯誤 |

幾個值得照抄的小技巧：

1. `--force-prefers-reduced-motion`：讓狀態直接跳到終點，否則無頭瀏覽器常截到半路。
2. 錯誤在任何圖示程式執行前就註冊監聽，寫進 `documentElement.dataset.err` 再讀回，避開 `file://` 下只顯示 "Script error." 的問題。
3. `--with`：新圖示旁邊一定放幾個既有圖示，同尺寸對比。
4. `--accent #F59E0B`：全部換成淺主色，專門抓淺色上看不清的標記。
5. `--scale 3`：放大找細縫。
6. 名字不在 `ORDER` 就直接報錯，避免截圖默默漏掉。

### 3.3 盲測迭代

README 的「Drawn by the skill」六個圖示，是一個只拿到 `SKILL.md` 與 `PROMPT.md` 的全新 session 畫的。每輪盲測把「它不得不自己猜的地方」補成規則。CONTRIBUTING 也把「跑一次盲測並回報猜測點」列為主要貢獻方式。規則是從證據長出來的，不是一次寫完。

### 3.4 畫之前先寫一句「物體 + 動作」

每個功能先寫「文件夾打開」「鎖彈開」這種一句話，動作必須是物體本身會做的事，明文禁止引申義（例如為了表達「歷史」讓時鐘倒轉）。之後再找 `icons.js` 裡結構最接近的範例照著寫。

### 3.5 交付與發行

- 動態與靜態共用同一份定義，靜態只是 `export.mjs` 把某色板、某狀態解算成獨立 SVG（id 加前綴、樣式寫進屬性）。
- `pack.mjs` 打兩個 zip：一般 skill，與把 `version`、`display_name` 提到 frontmatter 頂層的 marketplace 版。
- 投稿圖示會在 hover 時顯示作者，`history/` 保留演進過程。

## 4. 弱點與限制

| 項目 | 問題 |
|---|---|
| 技術形態 | 全域腳本、無型別、無模組，無法直接當 React 元件或 shadcn registry item 發佈 |
| 不吃 `currentColor` | 顏色由引擎解算，圖示無法跟隨文字顏色，在一般 UI（按鈕、選單）裡反而難用 |
| 效能 | 每個圖示兩個 filter（feGaussianBlur）、每條外描邊一個 mask、每個圖示自己的 rAF。66 個同時 demo 沒問題，放進長列表或小尺寸大量使用會吃重 |
| 小尺寸 | 漸層與 0.7 單位內發光在 16px 下幾乎看不見，風格的層次感依賴 24px 以上 |
| 命名 | 圖示名稱是簡體中文字串，當作程式 key 對多語系與搜尋不友善 |
| 授權 | source-available，見第 6 節 |

## 5. 與 SunUI 圖示系統對照

| 面向 | kubai-icons | SunUI 線條（含動態） | SunUI 像素（含動態） |
|---|---|---|---|
| 網格 | 31×29，四種 keyline | 24，內容 3 到 21 | 16，內容 1 到 14；動態影格 20×20 |
| 視覺 | 前後片分層、漸層、投影、內發光 | 1.5 線條、currentColor、最多一處朱紅 | 精靈圖：外框、30% 填色、陰影、左上亮點 |
| 顏色 | 一個主色解算全部 | `currentColor` + `--sunui-icon-accent` | 墨色透明度分級 + 朱紅 |
| 動畫機制 | 數字插值 + `draw` 重算路徑 | framer-motion variants，陣列為一次性關鍵影格 | 逐格換圖，無補間 |
| 中途折返 | 有，從當下數值出發 | hover 陣列離開時「立即歸位不倒放」 | toggle 會倒回，hover 立即歸位 |
| 往復動作 | 阻尼振盪公式，結束穩定 | 手寫關鍵影格陣列（如 bell） | 手繪影格 |
| 動作語意 | 「物體本身會做的事」，禁引申 | 「動作要有實體意義」 | 同左 |
| 規則可驗證性 | 高，幾乎全是數字 | 中，有網格與線寬，缺間距、最小細節、組合圖形規則 | 中，有字元與光源，缺間距規則 |
| 自檢 | `check.mjs` 自動截圖 + 錯誤擷取 | 「到 /icons 用 16、24、Light、Dark 各看一次」，人工 | 同左 |
| 盲測 | 有，是規則來源 | 無 | 無 |
| 靜態匯出 | CLI 批次 | `/icons` Copy SVG（單個） | 同左 |
| 依賴 | 零 | framer-motion | 零 |

我們的語意原則已經跟它同方向。真正的落差在**自檢自動化**與**規則的可驗證程度**。

## 6. 授權：能碰與不能碰

Kubai Icons License 摘要（第 2、3、6 條）：

- 用 skill 畫出來的圖示屬於使用者，可商用。
- 66 個範例圖示可用在產品裡，**但不能自己組成圖示集、pack、library 再發佈**。SunUI 的 icons registry 正是 library，所以**不能收錄它的任何範例圖示**。
- 引擎可以複製進「放你自己圖示集的專案」，但該專案**不得包含改寫或翻譯自 `PROMPT.md`、`SKILL.md` 的文字，也不得作為生成圖示的 skill、prompt 或範本提供**。SunUI 有 `lib/agent/` 的 skill 與 MCP，正好踩線，所以**引擎程式也不要搬**。
- 不得把規則改寫或翻譯後散佈。我們的 `ICONS.md` 與 `guidelines.ts` 若要補規則，必須用自己的話、自己的數字，針對自己的網格重新推導，不能逐條對譯。

可以安心學的是：一般數學（bezier 解法、阻尼振盪公式）、無頭 Chrome 截圖這種通用工程手法、以及「硬規則 + 自檢 + 盲測」這個方法論本身。

風格面也要再強調一次：`DESIGN.md` 第 11 行「不准為了好看加漸層、光暈、模糊、彩色陰影」。kubai 的層次感完全建立在這些東西上，**視覺上一項都不能拿**。

## 7. 建議 SunUI 採納的做法（依效益排序）

### P1. 圖示自檢腳本 `scripts/check-icons.mjs`

照它的思路，零依賴、用系統 Chrome：

- 開一個只渲染指定圖示的頁面（可以做成 `/icons/check?only=a,b&with=c,d` 的內部路由，或靜態 HTML）。
- 輸出：16px、24px、48px 三種尺寸 × Light/Dark；動態版加 `frames.png`（hover 與 toggle 各取 0%、25%、50%、75%、100%，像素版則直接排出全部影格）。
- 開 `--force-prefers-reduced-motion` 截終點；另開一次不加旗標、用 URL 參數指定進度截中間幀。
- 錯誤寫進 `data-err` 讀回。
- 這能把 `ICONS.md` 的「到 /icons 人工看一次」換成 agent 也能跑的步驟，直接對應我們「AI-facing」的產品方向。

### P2. 把 `ICONS.md` 的規則補成可驗證的數字

用我們自己的網格推導，至少補四條：

1. **間距**：線條版「相鄰元件要嘛共用一條線，要嘛間距 ≥ 2」；像素版「要嘛相接，要嘛空 ≥ 1 格」。0 到 2 之間的縫在 16px 下會糊成一條。
2. **最小細節**：線條版在 24 網格下 ≥ 2 單位；像素版單點只准用在亮點，其他細節 ≥ 2×2 格。
3. **組合圖形**：主體一個方向頂滿內容區，輔助元素（角標、箭頭）明顯更小、壓角或緊鄰。
4. **自檢清單**：把上面的檢查做成勾選表放在 `ICONS.md` 末尾，並同步到 `lib/agent/guidelines.ts`（AGENTS.md 規定改設計文件要同步）。

### P3. 盲測流程

用一個只拿到 `ICONS.md` 與 SunUI skill 的新 session，請它畫三個圖示集裡沒有的物件（例如 receipt-check、loyalty-badge、gift-wrap），記錄每一個「不得不猜」的點，補成規則。這也是驗證 `lib/agent/` skill 是否足以讓外部 agent 正確擴充 SunUI 的好方法，可以寫進 `scripts/eval-agent-search.mjs` 旁邊。

### P4. 動畫機制的兩個改進

1. **阻尼振盪**取代手寫往復陣列：bell、search 的擺動改成一個 0→1 進度派生 `A·(1−o)·sin(kπo)`，結束保證歸零。framer-motion 可用 `useMotionValue` + `useTransform` 實作。
2. **hover 可折返**：目前「離開時立即歸位不倒放」在快速滑過時會跳一下。對 toggle 類以外、單一值 hover 的部位，可以改為從當下值回到靜止。要不要做取決於 DESIGN.md 對「離開動作」的偏好，建議先挑 3 個圖示試。

### P5. 「物體 + 動作」一句話前置步驟

新增動態圖示前，先在 recipe 旁註解寫一句（「優惠券沿打孔線撕開」），並明文禁止引申義。我們已經有這個精神，寫成步驟後 agent 比較不會亂加縮放閃爍。

### P6. 批次靜態匯出（低優先）

`/icons` 目前只能單個 Copy SVG。可以加一個 CLI 或 `/r/icons/*.svg.zip`，一次匯出某組、某尺寸，給設計師進 Figma。

### P7. skill 發行包裝（低優先）

它的 `pack.mjs` 把 skill 打成一般版與 marketplace 版兩種 zip（frontmatter 欄位位置不同）。SunUI 的 `/skills/` 端點若要上架 skill marketplace，可以參考這個做法補 `version`、`display_name` 等欄位。

## 8. 明確不做

- 不採用漸層、投影、內發光、外描邊遮罩這套視覺語言（違反 DESIGN.md）。
- 不收錄它的任何範例圖示（授權禁止納入 library）。
- 不複製 `engine.js`、`check.mjs` 的程式碼，也不翻譯或改寫 `PROMPT.md` 的條文；自檢腳本與規則全部自己寫。
- 不改用「一個主色解算全部顏色」：SunUI 圖示必須吃 `currentColor`，才能嵌進按鈕與文字。
- 不用中文字串當圖示 key。
