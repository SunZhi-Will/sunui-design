### 為什麼好用

1. **一個拖動控制兩個尺度**。縮圖帶是精確的索引（看得到全部款式），商品列是展示（看得到實物比例）。兩者綁在同一個位置值上，手指拖的是索引，眼睛看的是商品。
2. **視差說明了因果**。縮圖帶跟手指 1:1，商品列以另一個間距跟著走，使用者一眼看出「我拖的這條在控制後面那排」。
3. **目前是誰，不靠標記**。中間那一款前移、變大、標題換字，三個訊號一起指向同一件。
4. **深入層是同一個物件**。點開不是換頁，是同一罐移到左邊、其他退場，回來時原路退回。

## 3. 技術拆解與 SunUI 做法

| 效果 | 參考的樣子 | SunUI 做法 |
|---|---|---|
| 商品 | WebGL 罐子，有光澤與倒影 | 商品圖由使用者傳入（ReactNode）；demo 用線描的墨色瓶罐。倒影與光澤是漸層與光暈，DESIGN.md 不准，改成一條 1px 紙邊的檯面線 |
| 位置 | 3D 相機 | 一個 motion value `pos`（浮點索引）。商品 x =（i − pos）× 商品間距，縮圖 x =（i − pos）× 縮圖間距；同一個值，兩種間距就是視差 |
| 目前那一款 | 前移變大 | 與 pos 的距離換成 scale 1 → 0.84、淡墨；距離超過 3 款淡出 |
| 拖動 | 縮圖帶 | framer-motion pan（3px 才算拖，點擊照常有效），`touch-action: pan-y` 讓手機還能上下捲動頁面。放手依速度推算目標，再用 gentle 彈簧吸附 |
| 大字 | 交叉疊印 | 淡墨大字，換款時舊字 100ms 淡出、新字逐字從下方捲上（每字錯開 18ms）。不用半透明疊印（讀不出字） |
| 點開 | 商品移到左側，右側面板 | 依 DESIGN.md「多步轉場依序做」：其他商品與縮圖帶先退（180ms），目前商品再移到左邊（gentle），最後面板主文先到、副文晚 60ms。窄螢幕改為商品縮小上移、面板從下方出現 |
| 結果 | 無 | 面板有「加入購物車」，加入後在按鈕原位用 `Stamp` 顯示已加入 |

## 4. 和 SunUI 規範的對照

- 顏色：紙、紙邊、墨、淡墨；主要動作用主題 primary。沒有暗色舞台、倒影、光點、漸層。
- 不做進場動畫與常駐循環：只在拖動、點擊、按鍵時動。
- 鍵盤：左右鍵換款，Enter 開啟，Esc 關閉；開啟時焦點移到關閉鈕，關閉後回到商品。換款時 `aria-live` 只報一次「名稱，第 3 款，共 8 款」。
- reduced motion：pos 直接跳到目標，點開直接換到終點畫面，資訊不變。
- 密度分層：陳列架是總覽層（平、看得到全部款式），面板是深入層（說明與規格表是精確讀法）。

## 5. 其他四段為什麼這次不做

- 地板海報、螺旋卡片、走廊：都是作品集的「氣氛」，核心是 3D 鏡頭與光影，換成紙感後只剩換圖，也不對應電商動作。
- 翻頁書：已有 `fold-invite-card` 與型錄翻頁類需求重疊，且免費型錄凍結中。
- 若之後要做檔期整頁場景，走廊的「沿路前進、走到哪件標題就換」可以改寫成「沿著時間軸逛新品」的 A 級場景，先記在這裡。

## 6. 為什麼放 Pro

免費型錄 2026-11-06 起凍結。四項測試：可替代性低（市面 carousel 沒有雙尺度視差的索引帶）、自己做要處理拖動推算、吸附、多步開啟與焦點管理、直接用在新品系列頁與品牌頁、展示價值高。歸 Pro，B 組。
