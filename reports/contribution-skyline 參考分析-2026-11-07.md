# Contribution Skyline 參考分析（2026-11-07）

來源：Divan Raj（@desdivj）2026-11-05 的貼文「Turned a contribution graph into a skyline.」，附一段約 10 秒、無聲、循環播放的影片。

## 一句話結論

這支影片紅的原因不是 3D，而是**同一份資料在兩個層級用兩種密度呈現**：總覽用平面點陣（好掃描），點開的側邊面板才給 3D 天際線（好探索），兩者之間有連續性。對 SunUI 來說，短期可以直接拿走的是「宣傳影片的拍法」與「裝飾留給深入層」這條設計規則；做成 block 則不符合凍結期與商務定位，先列為候選，不動工。

## 2. 影片逐段拆解

以約 1 秒一格抽樣觀察（影片右下角是倒數計時）：

| 階段 | 畫面 | 手法 |
|---|---|---|
| 總覽 | macOS 視窗裡的 Analytics 儀表板：三張 KPI 卡、營收折線、Billing flow 漏斗、工時長條、Tasks shipped 點陣、Delivery health 表 | 背景是模糊的風景桌布，視窗像產品截圖 |
| 推近 | 鏡頭放大到下半部，游標移到點陣卡 | 假鏡頭運動，把視線導向主角 |
| 懸停 | 點陣上出現提示：「Thu, Nov 6 · 14 tasks shipped · Billing Revamp 6」 | 先在平面版證明「每一點都有資料」 |
| 展開 | 右側滑出面板「Tasks shipped」，左邊儀表板保持可見 | 面板標題與卡片同名，數字 1,516 從卡片延續到面板 |
| 天際線 | 26 週 × 7 天的等角長條，橘色深淺對應數量；懸停一根顯示「Mon, Dec 1 · 34 tasks · Busiest」、各專案拆分、4 位貢獻者頭像 | 3D 的遮擋問題用提示補回精確數字 |
| 切換 | 3D / Grid 分段控制，切到 Grid 變回平面點陣，再切回 3D | 3D 只是一種視角，精確閱讀永遠有退路 |
| 其餘 | Weekday rhythm、Cycle time、Throughput 折線、Team 表格（每人最近 8 週小長條） | 面板本身是完整的二級頁 |

1 秒抽樣看不出 3D 與 Grid 之間有沒有補間形變，只能確認有切換、且 3D 視角在切回時略有不同。

## 3. 為什麼有效

1. **熟悉的隱喻加一個變形**。GitHub contribution graph 人人看過，把它立起來就有「啊，原來可以這樣」的瞬間。熟悉降低理解成本，變形提供新鮮感。
2. **漸進揭露的密度分配**。儀表板一次要讓人掃很多卡，點陣最省空間、最好比較；使用者主動點開時才有注意力欣賞 3D。裝飾放在使用者已經表態有興趣的地方。
3. **連續性**。卡片標題、總數、配色、時間範圍在面板裡全部延續，面板從右側滑入但不遮住原本的儀表板，使用者知道自己在「同一份資料的深入版」裡。這跟昨天 `UI 連續性參考分析-2026-11-07.md` 講的是同一件事。
4. **3D 沒有犧牲可讀性**。等角長條天生有遮擋、高度難比較，作者用三件事補救：懸停提示給精確值、上方四個統計數字（總數、最忙的一天、最長與目前連續天數）給結論、Grid 切換給精確閱讀。
5. **影片本身的拍法**。10 秒、無聲、循環、真實游標、一次只做一個互動、鏡頭推近再展開。滑時間軸的人不用開聲音、不用讀字就能看懂。

## 4. 弱點與不該照抄的地方

- **它是 SaaS 分析儀表板，不是商務或活動頁**。SunUI 的定位是 commerce 與 campaign，這個情境本身不在範圍內。
- **毛玻璃桌布、柔和陰影、漸層面**都違反 `DESIGN.md` 紙感規則（平面、1px 紙邊、無陰影、不准毛玻璃）。
- **想法不新**：GitHub 自己 2021 年就做過 Skyline（把一年 contribution 做成可 3D 列印的城市）。新的是「放進產品 UI 的深入層」這個位置，而不是 3D 天際線本身。
- **假資料很好看，真資料常常不好看**。真實的貢獻分布可能大半是零，城市會變成空地加幾根電線桿。
- 182 根長條在手機上幾乎無法懸停，影片只展示桌面版。

## 5. 對 SunUI 的意義

### 5.1 立刻可用：宣傳影片的拍法（直接服務 PH 上線）

PH 上線前要做 block 展示影片與首頁動圖，這支影片是可以照抄的範本：

1. 長度 8 到 12 秒，無聲可懂，頭尾接得上可以無縫循環。
2. 先給完整場景（上下文），再假鏡頭推近到主角。
3. 真實游標，一次只示範一個互動。
4. 結尾展示「同一份東西的另一種視角」，給人想存起來的理由。
5. 目標是書籤，不是喜歡：讓設計師覺得「之後做案子會用到」。

適合套用的 SunUI 素材：Pro 的 `cart-drawer`、`order-tracker`、`self-building-page`，正好都有「從小卡片展開到完整面板」的故事。

### 5.2 立刻可用：一條設計規則

> 總覽層保持平面、密、好比較；裝飾與 3D 只放在使用者主動點開的深入層。

這跟 SunUI 目前的設計文件不衝突，反而是紙感規則的延伸：紙感版面本來就克制，把「華麗」的預算集中在一個焦點上。若要寫進 `DESIGN.md`，記得同步 `apps/web/lib/agent/guidelines.ts`。

### 5.3 做成 block：先不做，列為候選

**凍結期規則**：免費目錄凍結到 2027-01-12，新免費項目只能是 Pro 場景拆出的原子。所以不新增免費的 contribution skyline。

如果要做，唯一說得通的形式是**商務化的 Pro 場景**，例如：

- **年度購物回顧（Year in Review）**：顧客這一年的訂單做成天際線，最高那根是雙 11 那天。年底活動頁，季節性剛好落在 12 月。
- **商家的大促時段熱度**：雙 11 或黑五 24 小時 × 7 天的成交量城市，用在活動結束後的戰報頁。

用四問檢查（`免費與付費切分規劃-2026-11-05.md`）：

| 問題 | 判斷 |
|---|---|
| 可替代性 | shadcn、Magic UI、React Bits 沒有等角貢獻城市，有差異 |
| 製作時間 | 1 到 2 天。`tiny-chart` 已有 `layoutIso`（每格三個面加地板格線），投影可重用；`dialog-sheet` 或 `side-panel` 當深入面板 |
| 離營收距離 | 偏遠。年度回顧的主要使用者是平台方，不是接案做活動頁的工作室 |
| 展示價值 | 高，很適合當 PH 影片素材 |

結論：展示價值高但離營收遠，而且 12 月的季節包排的是農曆新年（2027-02-06 檔期，12 月下旬出）。**現在不做**。上線後若要做年底包，可以把「年度回顧天際線」放進候選清單。

### 5.4 如果之後真的要做：紙感翻譯與技術要點

| 影片做法 | SunUI 紙感翻譯 |
|---|---|
| 橘色漸層、柔和陰影 | 每根長條三個平面：頂面最淺、左面中、右面最深，同一個墨色的三階，無漸層 |
| 毛玻璃桌布 | 拿掉，紙底 |
| 深色提示框 | `bg-card` 加 1px 邊框，數字用 tabular nums |
| 長條升起 | 依對角線（週 + 天）錯開的 `gentle` 彈簧，像城市從左後往右前長出來 |

技術上：

1. 用 SVG 而非 CSS 3D：182 根長條各三個多邊形，依「由後往前」排序繪製，懸停用多邊形命中，比 CSS `preserve-3d` 穩定。
2. 3D 與 Grid 的切換用同一個投影參數 t（0 是俯視平面、1 是等角），高度同時歸零，城市「躺平」成點陣，這是連續性的關鍵，比直接換元件好。
3. 減少動態偏好下預設顯示 Grid，不播升起動畫。
4. Grid 版本就是無障礙版本：方向鍵在格子間移動，每格有 aria label；3D 版本加一個隱藏的資料表。
5. 資料稀疏時（大半是零）要有保底：零值畫成地板格，不畫長條，並在上方統計列先給結論。

## 6. 建議行動

1. PH 宣傳影片照第 5.1 節的五點規格拍，先拿一個 Pro 場景試做。
2. 把第 5.2 節的規則加進 `DESIGN.md` 與 `guidelines.ts`（小改動，可以現在做）。
3. 「年度回顧天際線」寫進上線後的候選清單，凍結期內不動工。
