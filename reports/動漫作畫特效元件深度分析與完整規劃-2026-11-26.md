## 1. 它是什麼

十二個一般 UI 控制項（主按鈕、次按鈕、開關、滑桿、勾選框、單選、輸入框、分頁、評分、進度條、通知、提示），**靜止時很普通，一用就像動畫原畫師在演一記打擊**：

| 控制項 | 一用之後 |
|---|---|
| 主按鈕 | 按下壓扁；放開時反白一格、背後炸開衝擊星、四角滾出雲、「ドン!」落下；`done()` 補一個勾 |
| 次按鈕 | 小壓扁加三道楔形 |
| 開關 | 43 張用 GPT Image 畫的影格：旋鈕拖影衝過去、撞到底濺起水花、軌道淹滿 |
| 滑桿 | 拇指拉成水滴、彈簧延遲；拖快會捲起積雲，放手飛出一道月牙 |
| 勾選框 | 兩道月牙繞框、水晶碎片、勾自己畫出來、網點字「ズザッ」 |
| 單選 | 點彈進來、一扇楔形、兩團煙、空心「ポン」 |
| 輸入框 | 每打一個字，游標位置揚起灰塵 |
| 分頁 | 凸起的分頁滑過去、拉長、落地時楔形加一團煙 |
| 進度條 | 前緣騎著雷雲、地上石子浮起、「ゴゴゴゴ」；完成時衝擊星、「ドン!」、勾 |
| 評分 | 星星一顆接一顆彈出，五星有衝擊 |
| 通知 | 拖影滑入、落地揚塵加「ズザッ」，縮小離場 |
| 提示 | 像對話框彈出，帶煙與「カチッ」 |

外觀：白底、粗墨線（3.2px）、紫色硬投影（6px 7px 0）、特效雙色（白、淡紫、紫線）、粉紅點綴、義大利斜體粗字。

## 2. 它怎麼做的（讀過原始碼）

- **一個共用核心 `core.js`（約 300 行，40KB）**：每個元件檔都複製一份，第一個載入的設 `window.SakugaFX`，其他共用。所以頁面上任何組合都只有一張畫布、一個動畫迴圈。
- **一張固定在最上層的畫布**蓋住整頁、不吃指標事件，特效用頁面座標畫，跟著控制項捲動。需要畫在控制項「後面」的特效（衝擊星）另開一張元件內的背景畫布。
- **自己的彈簧類別**（`Spring(x, k, d)`，8ms 子步），加 `squashy()`：按住壓扁、放開過衝、帶一點傾斜。
- **十一種程式畫的特效**：`burst` 衝擊星、`puff` 煙、`donut` 煙圈、`shards` 水晶碎片、`slash` 月牙、`lines` 速度線、`ticks` 點綴楔形、`ring`、`splash` 水花、`kira` 閃光、`wob` 晃動弧線。每個都是「亮面、陰影、外框」三層扁平填色。
- **六個擬聲字**：用 GPT Image 畫，再用 potrace 描成路徑寫進核心；每個字與顏色只烘一次，之後每格一次 `drawImage`。兩種字型樣式：空心、網點。
- **共用時鐘**：`later(ms)` 跑在同一個時鐘上而不是 `setTimeout`，所以 `look.mjs` 能停住時間、一格一格截圖。
- **每個元件本身只有約 50 行**：一個 Web Component（`extends Base`），裡面是真的 `<button>` / `<input>` / `role="switch"`，可以進表單（`formAssociated`）。
- **驗收工具**：`test.mjs` 用 DevTools 協定送真的觸控與按鍵、在 390px 檢查橫向捲動與表單值；`look.mjs` 把一次反應拆成指定時間點的影格並排。

### 它的規則和 SunUI 驚人地接近

| Sakuga 規則 | SunUI 對應 |
|---|---|
| 跟手的東西用彈簧，不用 easing；拉伸來自速度 | DESIGN.md 第 5 節：動畫要有物理、跟手用彈簧 |
| 壓扁要保持體積 | motion-principles 的 squash and stretch |
| 靜止時是普通控制項，沒有常駐動畫 | 不做裝飾性進場與呼吸動畫 |
| 狀態立刻改變，特效只是裝飾；資訊不能靠特效 | reduced motion 下資訊完整 |
| 特效靠縮小或變細離場，不改透明度 | （SunUI 沒有寫，值得學） |
| 一個反應拆成預備、打擊、餘韻、落定，每拍一到兩個特效 | （SunUI 沒有寫，值得學） |
| 一次反應最多一個擬聲字，放在打擊那一格 | 無 |
| 交付前一格一格看 | 「Show changes side by side」的精神 |

所以這不是「花俏的特效庫」，而是一套**有紀律的動態語言**。這也是它被大量收藏的原因：開發者收藏的是「終於有人把動漫感做得不俗氣」。

## 3. 和 SunUI 現行規則的衝突

這是要先講清楚的部分，十二個全做會同時撞到四條規則。

### 3.1 craft 系列明文禁止

DESIGN.md 第 5 節第 3 點：「結果要有落定的那一下，但不慶祝……不放煙火、粒子、彩帶」。第 9 節禁止清單：「彩帶煙火粒子」「彩色陰影」。Sakuga 的核心就是爆點、碎片、煙、紫色硬投影。**它不可能是 craft 系列的 block**，硬塞進 craft 會兩邊都失去意義：去掉特效它就是普通控制項，留著特效 craft 的規則就破了。

### 3.2 免費型錄凍結（到 2027-01-12）

十二個新免費 block 加一個特效核心，直接違反凍結。唯一可用的例外是「從 Pro 場景拆出來的原子」。

### 3.3 方案 C：特效庫必須免費

2026-11-05 決定：動態特效庫一律免費（MIT），Pro 賣組合好的場景，不賣更多特效變體。理由是這類東西在別處免費、程式碼公開後無法再鎖。Sakuga 本身就是 MIT 免費，把它的同類物鎖進 Pro 違反這條，也賣不動。

### 3.4 和現有 block 大量重疊

| Sakuga | SunUI 已有 |
|---|---|
| 按鈕按壓、成功勾 | `button-effects`（16 種）、`micro-interactions`（success check、like burst） |
| 開關 | `micro-interactions` stretchy toggle、`kelvin-switch`（Pro） |
| 勾選框 | `micro-interactions` drawn checkbox |
| 滑桿 | `range-slider` |
| 分頁 | `sliding-tabs`（五種形狀） |
| 評分 | `star-rating` |
| 進度、載入 | `loading-effects`（26 種）、`pixel-build-progress`（Pro） |
| 通知 | `toast-stack` |
| 擠壓伸展 | `motion-principles` |
| 畫布特效疊在元素上 | `pixel-fx` |

功能上沒有一個是新的。**新的是「動漫作畫」這個表現層。**

### 結論

規則本身已經指出答案：**這是一個新系列，不是十二個新 block**。而 SunUI 已經有一個完全一樣的先例：

> **像素系列** = 免費的 `pixel-fx`（畫布特效原子）＋ Pro 的 `pixel-gacha`、`pixel-boss-sale`、`pixel-preregister`、`pixel-check-in`……（組好的活動場景）。

動漫系列照抄這個結構就同時滿足 3.1 到 3.4。

## 4. 不要直接移植它

MIT 允許照搬（保留授權聲明即可），但不建議：

1. **沒有差異**：Sakuga 自己就在 shadcn registry 上（`npx shadcn add finktheartist/sakuga-vfx/button`）。SunUI 再發一份同樣的東西，使用者沒理由用我們的，還會被看成抄襲，傷害「質感」定位。
2. **技術模型不同**：它是 Web Component 加 `<script>` 標籤；SunUI 是 React + Tailwind + `motion`，block 要能被移植指南轉成 Vue、Svelte、SwiftUI。照搬等於在 registry 裡放一個異類。
3. **素材是別人生成的**：擬聲字與開關的 43 張影格是作者用 GPT Image 生成的，開關檔案 500KB。用了就是把別人的畫放進我們的產品。
4. **擬聲字只有日文**：SunUI 有 zh-TW、zh-CN、ja 三個在地化讀者，這反而是我們能做得更好的地方。

**要學的是方法與規則（第 2 節那張表），自己寫引擎、自己畫字、自己定樣式。** 報告與程式註解裡標明啟發來源。

## 5. 樣式：建議成立 `anime` 系列

### 5.1 系列名

- 系列 id：`anime`（`meta.series: "anime"`），設計文件 `apps/web/DESIGN-anime.md`，guidelines.ts 同步英文版。
- 不叫 `sakuga`：會和那個庫撞名，看起來像我們的分支。
- block 名稱前綴 `anime-`（和 `pixel-` 對稱）。

### 5.2 和 craft 的關係

| 項目 | craft | anime（建議） |
|---|---|---|
| 粒子、爆點、煙 | 禁止 | **允許，這是系列本體**，但受第 2 節的節拍規則限制 |
| 彩色硬投影 | 禁止 | 允許一種：`4px 5px 0` 品牌專色淡色，當作靜止時的招牌（通過 256px 驗收） |
| 外框 | 1px 邊線 | 2.5 到 3px 墨線（`--foreground`） |
| 顏色 | cobalt 專色＋三語意色 | **同一套**，不開新色相：特效亮面 `--card`、陰影面專色 18%、外框專色、點綴用語意紅；擬聲字墨色加白邊 |
| 彈簧 | snappy、gentle、pop | 同三種，另加一組「壓扁」參數（低 0.5、寬 0.24 這類） |
| 結果 | `Result` 圓片，不慶祝 | 可以有一記打擊，但仍要落定在 `Result` 或勾上 |
| reduced motion | 資訊完整 | 同，且所有畫布特效關閉、只留狀態變化 |
| 字 | 跟主題 | 跟主題；控制項上的字可用斜體粗體作系列招牌 |

**不用紫色加粉紅**：那是 Sakuga 的識別色，也違反 2026-11-22「不加新色相」。用 cobalt 專色後，買家換品牌色時特效的線條一起換，這是 Sakuga 做不到的（它的特效色寫死在 `P` 物件）。

### 5.3 擬聲字

自己畫，三種語言各一組，同一個語意槽位：

| 槽位 | ja | zh-TW / zh-CN |
|---|---|---|
| 衝擊 | ドン | 砰 |
| 點擊 | カチッ | 喀 |
| 咻 | シュッ | 咻 |
| 彈出 | ポン | 啵 |
| 滑停 | ズザッ | 唰 |
| 轟鳴 | ゴゴゴ | 轟 |

元件收 `locale`（或讀 `<html lang>`），預設 en 時用日文（這是大家認得的「動漫感」）。字的製作：用圖像模型或手繪出原圖，描成 SVG 路徑（原作的 potrace 流程可參考，工具自己寫），路徑放在引擎檔裡，不另外抓檔。要先出一張六字乘三語的樣張給使用者看過才寫進去。

### 5.4 256px 驗收

靜止時的招牌：粗墨線加專色硬投影的控制項外殼。縮到 256px、遮掉文字仍認得出是這個系列。

## 6. 架構

### 6.1 免費原子：`anime-fx`（引擎）

- `registry/free/anime-fx/anime-fx.tsx`，目標 400 行內。
- 內容：一張全頁 `position: fixed` 畫布（單例，第一個用到時建立，沒有特效時停迴圈）、`Spring`、`squashy` hook、共用時鐘（`later` 也走它，方便截影格）、十一種特效函式（重寫，不複製）、擬聲字繪製與烘焙快取、`at(el, fx, fy)`。
- 匯出 React API：`useAnimeFx()` 取得特效函式；`<AnimeFxLayer />` 可選（不放也會自動建立）；`burst(el, opts)` 這類直接吃元素。
- 和 `pixel-fx` 一樣是畫布疊在元素上，但 pixel-fx 是「疊在父層」、anime-fx 是「全頁一張」。不合併：兩者的座標模型不同，合併會讓兩邊都變複雜。
- 原作已知的限制要一開始就處理：畫布在最上層會飛過 modal（提供 `container` 選項限制範圍）；背景特效會被 `overflow: hidden` 切掉（文件寫清楚）。
- 依賴：只有 `motion`、`cn`。不依賴 shadcn 元件（符合 2026-11-22 的薄耦合規則）。

### 6.2 十二個控制項

每個一個 `registry/free/anime-<name>/`，內部是真的原生元素或正確 ARIA，鍵盤完整，能進 `<form>`：

| SunUI block | 對應 | 備註 |
|---|---|---|
| `anime-button` | 主、次按鈕 | `variant="primary" \| "secondary"`、`done()` 由 ref 呼叫 |
| `anime-toggle` | 開關 | **不用影格**，程式畫：旋鈕拖影、撞擊、`splash`。這是十二個裡最難的，預留最多迭代 |
| `anime-slider` | 滑桿 | 拇指依速度拉成水滴，快拖才出雲 |
| `anime-checkbox` | 勾選框 | |
| `anime-radio` | 單選群組 | 方向鍵切換 |
| `anime-input` | 輸入框 | 揚塵跟著游標；中文輸入法組字中不觸發（`compositionstart` 到 `compositionend`），原作沒處理 |
| `anime-tabs` | 分頁 | 方向鍵、`role="tablist"` |
| `anime-rating` | 評分 | 用語意琥珀色（`--sunui-rating`），不用專色 |
| `anime-progress` | 進度條 | 完成時落定到勾 |
| `anime-toast` | 通知 | 計時器在 hover、focus、分頁隱藏時暫停 |
| `anime-tooltip` | 提示 | hover、focus、點擊都能開，Esc 關 |
| `anime-loader` | 載入 | 原作 README 寫十二個但只列了十一個；用這格補一個「轟」的等待動畫，取代主次按鈕算兩個 |

`registryDependencies`：每個都依賴 `anime-fx` 與 `utils`。

### 6.3 Pro 場景（讓免費原子合法的那一步）

凍結例外要求「從 Pro 場景拆出來」。所以順序是**先有 Pro 場景，原子才能進免費型錄**。建議兩個場景，各自用到一半以上的控制項：

1. **`anime-preregister`（動漫遊戲預約頁）**：預約按鈕（衝擊）、平台單選、同意勾選、預約人數進度條（里程碑解鎖時「轟」）、成功通知。買家：遊戲、動漫周邊活動頁的接案者。這也直接能用在使用者自己的遊戲《方界：破碎祭壇》。
2. **`anime-merch-drop`（周邊限量開賣）**：分頁切商品、數量滑桿、加入購物車按鈕、評分、提示說明尺寸、庫存進度。

這兩個和 `pixel-preregister`、`pixel-gacha` 同一個買家族群，也是 Pro 的電商與活動主軸，不偏離定位。

### 6.4 移植指南

引擎是單例畫布加手寫特效，Vue、Svelte 照搬容易；SwiftUI、Flutter 要用 Canvas 重畫，量大。**上線時只對 React 交付，移植指南列為後續**，不在這輪做驗證（驗證規則要求新 agent 一輪通過，十二個加引擎太重）。

### 時程上的現實

- 今天 11-26，創始價明天（11-27）開賣，Product Hunt 在 1-12，剩 47 天。
- 這個系列不在上線的關鍵路徑上，但它的**展示力**是今年看到最高的之一（10.8 萬觀看，收藏數幾乎等於按讚數，代表開發者存起來要用）。
- 建議做法：階段 0 到 3（約 6 天）先做，得到「一個引擎、三個控制項、一個 Pro 場景」，足夠當 PH 的展示亮點；階段 4 到 6 等 PH 素材與付款流程都完成再排。這樣十二個仍然全做，只是分兩批。

## 8. 需要使用者決定

1. **系列定位**：同意成立獨立的 `anime` 系列（允許特效，不受 craft 的禁止粒子規則約束）嗎？
2. **凍結例外**：同意以「Pro 場景的原子」名義把 `anime-fx` 與十二個控制項放進免費型錄嗎？（照方案 C，特效庫本來就該免費。）
3. **顏色**：同意用 cobalt 專色取代原作的紫加粉紅嗎？（建議同意；不然要開新色相。）
4. **擬聲字**：日文為預設、中文依語系切換，可以嗎？還是中文版一律用中文字？
5. **分批**：先做階段 0 到 3（約 6 天），其餘排在 PH 素材完成後？還是十二個一次做完？
6. **Pro 場景題目**：預約頁加周邊開賣，還是換別的？
