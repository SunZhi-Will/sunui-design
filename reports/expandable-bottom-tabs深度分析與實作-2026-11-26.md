# expandable-bottom-tabs 深度分析與實作

日期：2026-11-26
來源：https://github.com/rit3zh/expandable-bottom-tabs（作者自述靈感來自 Yana Yank 的設計）
分析方式：讀完 `src/` 的元件、hook、reducer 與幾何函式，並在瀏覽器逐格看 README 的 10.8 秒示範影片。沒有在 iOS 模擬器上建置執行。

## 一句話結論

值得做。它不是一個「會展開的分頁列」，而是**一條固定高度的列，在三種版面之間連續變形**：分頁、工作區卡、個人卡（外加狀態選單）。SunUI 目錄沒有同類（`app-shell` 的底部分頁列與 `sliding-tabs` 的 dock 都不會變形成卡片）。免費目錄凍結到 2027-01-12，所以做成 **Pro** 區塊 `morph-tab-bar`。

## 原作怎麼做到的

### 1. 三個數字驅動全部版面

| 值 | 意思 |
|---|---|
| `expansion` 0 到 1 | 收合（分頁列）到展開（卡片） |
| `focus` 0 到 1 | 展開時中間是工作區卡（0）還是個人卡（1） |
| `menu` 0 到 1 | 狀態選單開合 |

每一塊的 `left`、`width`、透明度都是這三個值的純函式。好處是隨時可以打斷：展開到一半點別的地方，所有東西從目前位置接著走。這是整個專案最值得學的一點。

收合時**不重設** `focus`，所以收回時沿原路徑回去。

### 2. 變形模糊（MorphBlur）

出場的內容同時模糊、淡出、縮小，進場的相反。兩個頭像不換元件，只做一次 `sin(π × p)` 的模糊脈衝：中途最糊、兩端清楚，眼睛追得到它，又看不出尺寸切換的接縫。影片 1.86 秒那一格整條列都是糊的，下一格就是清楚的工作區卡。

### 3. 黏液選單（goo）

三個圓角矩形（按鈕、頸、本體）畫在同一層，先高斯模糊再用色彩矩陣把 alpha 拉硬（`24a - 12`），靠近的形狀就黏在一起。精妙處在本體四個邊**錯開時間**：

| 邊 | 進度區間 |
|---|---|
| 上緣 | 0 到 0.55（先衝上去） |
| 下緣 | 0.15 到 0.75（晚一點脫離按鈕） |
| 左右 | 0.2 到 1（最後攤開，只有左緣允許過衝） |

頸的寬度 1、0.55、0 收細到斷開，按鈕同時用 `sin` 鼓起 14%。選項內容到 0.55 之後才出現，並被裁在本體形狀裡。

### 4. 其他細節

- 狀態圖示是**同一個圓**減去一塊圓角矩形，五個數字（x、y、寬、高、圓角）各跑一條彈簧，所以圖示之間是變形不是替換。
- 狀態按鈕：按下縮到 0.84，狀態改變時彈到 1.18。
- 選單可按住拖過各列、放開選取；高亮塊第一次直接就位，之後才用彈簧滑動。
- 返回鍵順序：`dismiss` 先關選單，再按一次才收合。

## 原作的問題（這次一併修掉）

| 問題 | 影響 | SunUI 版做法 |
|---|---|---|
| 版面讀整個視窗寬 | 平板、側欄、嵌在卡片裡都不對 | 量自己容器的寬（ResizeObserver） |
| 320px 手機上個人卡的名字欄約只剩 22px（照常數推算） | 名字幾乎看不到 | 列寬 340px 以下時，沒被聚焦的那張卡收到 0，寬度讓給主卡 |
| 從個人卡收合後再開工作區卡，`focus` 從 1 一路插值到 0 | 兩張卡走混合路徑 | `expansion` 接近 0 時先直接跳 `focus`（此時版面與它無關，看不出來） |
| 展開後再點目前的卡片沒有任何事發生 | 卡片是死路 | `onWorkspacePress`、`onAccountPress` |
| 狀態寫死在元件內 | 接不到後端 | `status` / `view` / `activeId` 都可受控 |
| 看不見的圖層沒有完整排除焦點與讀屏 | 讀屏可能讀到隱藏內容 | 隱藏層一律 `inert`，焦點移到對應的新位置 |
| 沒有減少動態處理 | 模糊與形變照跑 | reduced motion 全部立即切換 |
| 圖示綁分頁路由名 | 改路由就掉成預設圓點 | 圖示由 `tabs` 傳入 |

## 移到網頁的取捨

| 原作 | 網頁版 | 理由 |
|---|---|---|
| iOS 26 Liquid Glass（GlassView、GlassContainer 融合） | 85% 不透明的毛玻璃加頂邊高光 | DESIGN.md 規定毛玻璃至少 80% 不透明；真液態玻璃已經是 `liquid-glass-nav` 的招牌。玻璃塊之間的融合沒有做 |
| Skia goo | SVG filter，另加 1px 邊線環（feMorphology） | 零依賴；原作靠陰影分邊，SunUI 要求陰影一定配 hairline |
| SwiftUI `numericText` | 狀態字依順序上下滑動 | 網頁沒有對應 API |
| Reanimated 彈簧四組 | SunUI 三組彈簧 | DESIGN.md 第 5 節。展開不再過衝 |
| 淺灰選中膠囊加藍字 | **烤漆品牌色鍵**，而且它就是錨點：展開時同一個鍵從分頁底下滑成左側圓鍵 | DESIGN.md 要求靜止時看得見的材質與跨狀態錨點。原作這裡是兩個元件交叉淡化 |
| 原生手勢 | Pointer Events 加完整鍵盤（方向鍵、Home、End、Enter、Escape） | 網頁必要 |

沒有沿用原作的頭像、Expo 標誌、配色、SF Symbols 與四個狀態圖形路徑。狀態圖形用 SunUI 自己的圓與切口尺寸畫，顏色用既有語意色（綠、琥珀、紅、灰）。

## 產品判斷

- 適合：社群、聊天、社團、課程社群這類「分頁 + 目前工作區 + 我的狀態」的手機版 App。
- 不適合：分頁超過 4 個（360px 下每格會小於 60px）、沒有工作區或帳號概念的網站（用 `app-shell` 或 `sliding-tabs`）。
- 商店情境可以替換：工作區 = 目前門市，個人卡 = 會員。

## 第二版：貼近原作（2026-11-26）

使用者看過第一版後回饋「跟原本的還是差好多」。重新逐格比對影片並與自己的畫面並排，找出第一版的問題。第一版的分析只讀原始碼和少數影格，**漏掉了原作最醒目的兩個效果**：它們來自 iOS 原生元件（`react-native-cupertino-tabs` 與 `GlassContainer`），原始碼裡看不出長相。

| 項目 | 第一版 | 第二版 |
|---|---|---|
| 切分頁 | 色塊直接滑過去 | 選中塊浮起成玻璃放大鏡，超出列高，內容放大、邊緣色散；可按住跟著手指滑 |
| 玻璃 | 各塊獨立毛玻璃 | 同一層液態圖形：靠近時黏出尖角，展開時像水滴一樣拉開 |
| 選中樣式 | 飽和藍烤漆鍵 | 淺灰膠囊，圖示與文字用品牌色 |
| 彈簧 | SunUI 三組（幾乎不回彈） | 原作的彈簧數值 |
| 尺寸 | 間距 8、選單字 15px、圓角 20 | 間距 10、17px、26 |
| 示範 | 卡片外框、細線圖示、文字頭像 | 手機下半部、實心圖示、照片頭像（取自 SunUI 既有素材） |
| 展示版 | 圓點代替圖示、黏液沒有頸、不能點 | 外觀與完整版一致，可點（不能拖） |

**刻意偏離 DESIGN.md**（只限這個區塊，理由是忠於原作手感）：彈簧不用三組標準值且有回彈；沒有第 7 節的烤漆招牌，改由玻璃本身當招牌；放大鏡邊緣有橘藍色散（光學效果）。上文「移到網頁的取捨」表中的毛玻璃、烤漆鍵、三組彈簧三列已被本節取代。玻璃改為不透明的 SVG 圖形，所以不再有背景模糊。

放大鏡是用放大的複製圖層加邊緣遮罩做出來的，不是真正的折射，色散比原作淡。

第二版重測：型別與 55 項測試通過；滑鼠點分頁、拖過分頁、鍵盤、狀態選單、Escape、284px 窄版正常，主控台沒有錯誤。未驗證項目同上一節；多了一項要看的是 Safari 上多個 SVG filter 同時動畫的流暢度。
