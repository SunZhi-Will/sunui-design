# Agentic Toasts 影片拆解與實作深度分析

日期：2026-11-26
來源：X 貼文 `pitus_/status/2125619571705196849`（Phil Pitus，「Agentic toasts」）。影片 21.6 秒、2746×2160。作者在回覆裡說明：不是建在 Sonner 上、全部用程式寫、可以互動。
方法：在瀏覽器裡把影片逐格停下（0.15 到 21.5 秒，約 150 個時間點），整張與局部放大比對。文中秒數都是實測。

## 1. 影片是什麼

淺灰底上一疊白色通知，內容是 AI 代理在背景工作時回報的六件事。和一般 toast 的差別只有一個，但很關鍵：**左邊不是狀態圖示，是一張 56×24 左右的小圖表**，直接把「發生了什麼」畫出來。

| 通知 | 小圖表 | 動作 |
|---|---|---|
| Tests passed，52 in 1m 12s | 10×4 的格子，由左到右一欄一欄亮起，前緣是藍色（執行中），後面變綠 | 無 |
| PR #482 merged，`fix/checkout-flake → main` | 分支線：基線、分支拉起、兩個 commit 點、併回主線的大圓點，線是描出來的 | 無 |
| Deploy failed，Migrate timed out | 五個步驟點連成一條線，前兩個綠，第三個紅色叉，後面空心 | Retry |
| Build 40% faster，52s, usually 1m 26s | 八根長條依序長出來，前七根灰（過去的建置），最後一根綠而且比較矮 | 無 |
| Context almost full，184k of 200k | 9×3 的格子幾乎全滿，琥珀色 | Compact |
| Session finished，Auth refactor · +142 −38 | 格子：綠（新增）、紅（刪除）、灰（沒動） | 無 |

副標是等寬字的時候（分支名）用 mono，數字 `+142` 綠、`−38` 紅。

| 1.65 到 2.25 | 分支線描出來（約 300ms），兩個 commit 點、合併點依序出現 |
| 2.55 | 第三張到。這一格拍到新舊內容疊在一起、都帶模糊：舊內容退、新內容進，同一個位置 |
| 2.85 到 3.6 | 步驟點依序走：空心環先變藍框（輪到它），再變綠實心，連線跟著變綠 |

## 3. 技法清單

1. **小圖表取代圖示**。圖示只能說「成功」或「失敗」，小圖表說得出「52 個都過」「卡在第三步」「這次比平常矮一截」。這是整支影片的價值所在，其餘都是標準 toast。
2. **圖表在抵達時畫出來一次**：格子掃亮、線描出、長條長出、步驟點走過。畫完就停，沒有常駐動畫。
3. **往後退的堆疊**：新的蓋在前面，舊的變成上方薄邊，最多兩條。
4. **滑過展開**：堆疊變列表，關閉鈕這時才出現，動作鈕讓位。
5. **原地變形的動作**：按下 Retry 不是關掉通知再跳一張新的，是同一張通知換標題、換副標、圖表從失敗處接著走。圖表位置是錨點。
6. **進行中的字有亮帶掃過**，結束時停。
7. **結果落定**：最後一點放大、光環擴散一次、打勾。
8. **模糊是轉場的黏著劑**：進場、退場、換文字、按鈕消失都帶 4 到 6px 模糊，只存在於那 150 到 200ms。
9. **關閉往右滑出**，其餘補位。

## 4. 哪些照搬、哪些必須改（對照 `apps/web/DESIGN.md`）

| 影片做法 | SunUI 立場 | 處理 |
|---|---|---|
| 小圖表 | 可以，它是資料，不是裝飾 | 照做，四種：`cells`、`steps`、`bars`、`merge` |
| 抵達時畫一次 | 可以：是資料狀態改變，不是裝飾性進場 | 每段 400ms 以內；reduced motion 直接顯示完成的樣子 |
| 綠、紅、琥珀、藍、紫五個顏色 | 語意色只有紅、琥珀、綠，其餘走品牌專色，不開新色相 | 綠 `--sunui-success`、紅 `--destructive`、琥珀 `--sunui-warning`（回退到 `--sunui-rating`）、藍與紫都改成 `--sunui-spot`。合併圖用品牌色，不用紫 |
| 淡藍膠囊按鈕 | 每個 block 要有一個靜止時看得見的材質 | 動作鍵用品牌色烤漆鍵，和免費 `toast-stack` 同一顆 |
| 字上的亮帶 | 常駐動畫只有載入中例外 | 只在 `busy` 時出現，reduced motion 改成一般文字 |
| 光環擴散加打勾 | 結果要落定一次，不慶祝 | 光環只擴散一次（500ms），圓片用 `pop` 彈簧 |
| 模糊轉場 | 可以，但單次 400ms 以內 | 進場、退場、換文字都在 200ms 內 |
| 按下動作後原地變形 | 正是第 5 節第 6 點「連續性」 | 舊文字 100ms 退場，主文先到、副文晚 60ms，圖表不動 |
| 琥珀用在「快滿了」 | 文件寫琥珀只給星星 | 這裡是「警告」，同樣是全世界認得的意思。先用可覆寫的 `--sunui-warning`，**要不要把警告正式列進語意色，需要你決定**（見第 7 節） |

## 5. 放在哪裡

- 免費型錄凍結到 2027-01-12，而且這不是 Pro 場景抽出來的原子，所以做成 **Pro 場景 `agent-toasts`**。
- 與既有 block 的差別：
  - `toast-stack`（免費）：一般通知，左邊是圖示或商品縮圖，動作按下後通知關閉。堆疊、展開、滑動關閉的做法這次沿用。
  - `jobs-tray`（免費）：背景工作的托盤，重點是進度百分比與佇列。
  - `order-island`（Pro）：單一膠囊走完一段流程。
  - 這支是「一疊通知，每張自帶小圖表，動作在原地完成」，目前沒有。
- 用途：AI 代理、CI/CD、背景自動化的產品，把「代理剛做完什麼」用一眼看得懂的方式回報。

## 6. 實作規格

`registry/pro/agent-toasts/agent-toasts.tsx`，只依賴 `framer-motion` 與 `cn`。

- `useAgentToasts({ max })`：`push`（同一個 id 再推一次是**原地更新**，不會跳到最前面）、`update(id, patch)`、`dismiss`、`clear`。
- `AgentToasts`：`toasts`、`onDismiss`、`placement`（top、bottom）、`fixed`、`visibleCount`、`peek`、`gap`、`duration`、`locale`、`labels`。
- 每張通知：`title`、`description`、`mono`、`glyph`、`busy`、`action`、`duration`。有動作或 `busy` 的通知不會自動消失（呼應貼文底下的回覆：失敗的那張要留到有人處理）。
- 小圖表：
  - `cells`：`cols`、`rows`、`cells`（每格一個色調，欄優先）；附 `fillCells(total, [tone, count]…)`。
  - `steps`：`total`、`done`、`state`（running、failed、done）。
  - `bars`：`values`（0 到 1），最後一根上色。
  - `merge`：分支併回主線。
- 圖表全部用 CSS transition 畫（顏色、`stroke-dashoffset`、`scaleY`），不佔 JS 動畫迴圈；六張同時在場也只有幾十個 SVG 節點。
- 無障礙：`section` 有名稱、清單是 `aria-live="polite"`；滑過或鍵盤聚焦都會展開；Escape 關最前面那張、聚焦時 Delete 關該張；收合時後面的通知 `inert`；可左右滑動關閉。
- 展示版 `preview.tsx`：寫死的六張通知劇本，沒有計時、滑動關閉、語系與文字覆寫。

## 7. 風險與待決定

- **警告色**：DESIGN.md 目前把琥珀限定在評分。這支用了 `var(--sunui-warning, var(--sunui-rating, #e8a020))`。建議把「警告」正式加進語意色（同一個琥珀，不開新色相），再同步 `lib/agent/guidelines.ts`。這次沒有改設計文件。
- **結果沒有用共用的 `Result`**：步驟圖最後的打勾只有 10px，放不下 `Result` 的圓片加文字，結果文字由通知標題承擔。手法（品牌感圓片、`pop` 一次）一致。
- 圖表的資料要接真實事件。示範用計時器依序推六張，產品裡不要用假計時。
- 通知不是紀錄：重要的失敗除了通知，頁面上也要有常駐的位置看得到。
