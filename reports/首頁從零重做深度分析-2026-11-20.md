# 首頁從零重做：深度分析

2026-11-20。目標：把之前的做法全部放下，做一個好看的「元件庫展示形象首頁」。這份先講為什麼前四版都不行，再講這次照什麼做。

## 1. 前四版為什麼都不行

| 版本 | 做了什麼 | 你的反應 | 真正的原因 |
|---|---|---|---|
| 元件牆 | 置中標題，下面一整面自製的小卡 | 普通無趣 | 構圖和 shadcn 一樣，卡片是黑底灰字 |
| 大標題加白圓 | 標題放大到 160px，右邊一顆可拖的圓 | 文字太大 | 把特例當通則，沒有量過別人的字級 |
| 小標題加白圓 | 標題縮回 66px | 上面一大塊空白，圓不特別 | 首屏沒有任何產品內容 |
| 太陽照卡片 | 七張自製小卡前後交疊，光跟著太陽走 | 好亂 | 卡片大小不一、互相壓到、沒有對齊 |

四版有同一個毛病：**每一版都在發明一個別人沒有的東西，卻沒有先把別人都做對的基本功做好。** 而且四版的主角都是我另外做的小卡，不是 SunUI 真正的區塊。

## 2. 這次實際看了什麼

用同樣的寬度（1440）把這幾站從上往下逐段看過，不是只看首屏：

**React Bits**（最接近 SunUI 該有的樣子）
- 全頁同一個內容寬度，段落標題靠左、約 30px、下面一行灰字，右邊最多一顆按鈕。
- 每一段都是整齊的格子：上排兩張大的、下排三張小的。
- 每一格的構造一樣：上面一大塊畫面，下面一行名稱加一行說明。
- 畫面都是「一眼就好看」的東西：金屬質感的環、發光的標誌、照片、地形線。沒有一格是表單。
- 段落的版面會換：格子、左文右圖、格子、格子。

**Animate UI**
- 首屏只有標題、指令、兩顆按鈕，非常乾淨。
- 第二段是招牌：一開始卡片散在標誌四周，往下捲會收成整齊的九宮格，標題從「每個元件都是活的」換成「去玩吧」。亂只出現一瞬間，停下來的時候一定是整齊的。
- agent 那一段是一個終端機加一個成果，一句話對一個結果。

**Magic UI**
- 淺色、置中、留白很大。標題下面一排技術標誌，接著是成品網站的展示。
- 好看的原因是節制：一個畫面只做一件事。

**shadcn/ui、Aceternity、Skiper、Motion、Osmo**（前幾輪看過，結論不變）
- 首屏一定有實際的產品畫面，而且佔畫面一半以上。

### 共同的做法

1. **一個內容寬度用到底。** 只有少數橫向的帶狀元素會衝出去。
2. **格子是整齊的。** 等間距、對齊、不重疊。有動態的站，靜止時也是整齊的。
3. **每一格是「大畫面加一行字」。** 畫面本身要好看。
4. **段落之間有很大的留白**（100 到 160px），每段只講一件事。
5. **標題字級 40 到 72px**，段落標題約 30px。
6. **首屏有真的產品。**

## 3. SunUI 手上有什麼

把 194 個區塊的預覽圖排成一張總表看過。老實的結論：

- **縮到卡片大小還好看的，大約 30 個。** 共同點是裡面有照片、插畫或大塊的明暗：景深主視覺、日夜主視覺、前後對照滑桿、布簾、3D 書、檔期活動頁、Lookbook、桌燈調光、色溫開關、玻璃方塊、節慶月曆、標本掃描、貼紙板等等。
- **其餘一百多個是黑底上的灰色小控制項**（按鈕、表單、清單）。它們放進頁面裡是好的，但縮成縮圖時幾乎是一片黑。

這解釋了為什麼「把區塊排成牆」一直不好看：隨便挑的話，大部分格子是黑的。**首頁要放的是挑過的那 30 個。**

## 4. 這次的做法

原則只有一條：**不發明，把別人都做對的事做好，內容用 SunUI 真正的區塊。**

| 段落 | 內容 | 參考 |
|---|---|---|
| 開場 | 置中：小標籤、標題、一句話、兩顆按鈕、安裝指令。背景是很淡的格線，從上往下淡出 | Animate UI、Magic UI |
| 區塊跑馬燈 | 兩排真的區塊預覽圖（挑過的 30 個），等大、等間距，慢慢往相反方向移動，兩側淡出。滑鼠移上去就停，點了進區塊頁 | Magic UI 的 Showcase |
| 數字 | 一排四個數字：區塊、動效庫、Pro 場景、語言 | React Bits 的 What's inside |
| 動手試 | 整齊的格子，上排一大一小、下排三張，每一格是真的區塊在跑，下面一行名稱 | React Bits、Animate UI |
| Pro 場景 | 一個大框放一整頁的場景，下面三張 | React Bits 的 Build the whole product |
| 差在哪裡 | 左邊三句話，右邊對照示範 | React Bits 的左文右圖 |
| 交給 agent | 標題、一句話，下面是現成的 agent 示範 | Animate UI |
| 價格與收尾 | 一張卡加候補名單，最後一句話兩顆按鈕 | 通用 |

不做的事：

- 不用自製的小卡當展示內容。
- 不做傾斜、交疊、散落的排法。
- 不加顏色。顏色只出現在區塊自己的預覽裡。
- 標題不超過 72px。
- 不做太陽、調光、光源這類招牌互動。先把基本功做好，招牌以後再說。

## 5. 風險

- 跑馬燈用的是靜態預覽圖，不是即時元件。即時的部分在下面的「動手試」。如果你覺得首屏一定要是活的，要再調整。
- 預覽圖只有深色版。切到淺色時，跑馬燈會是白底上的深色卡片。
- 這次仍然是照我的判斷挑區塊。哪幾個該上首頁，你可能有不同看法，換名單很容易。
- 首頁在另一個 session 也被改過（一個完整區塊當開場）。這次重做會取代它，原本的檔案我有另外備份。
