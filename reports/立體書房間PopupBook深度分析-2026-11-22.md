# 立體書房間（Pop-up Book）深度分析

> 2026-11-22。來源：Dakshie（@duckwhocodes，Avail 的 design/frontend，在做 retroui.io）2026-11-21 23:53 的貼文「playing around with a fun idea」，9.4 秒影片，發文約一天 3.4 萬次觀看、1,937 個讚、834 次收藏。
> 【已驗證】是這次在瀏覽器實際看過的（影片逐格看了 8 個時間點）；【推論】是從畫面推回來的；【建議】是判斷。

## 結論先講

1. **它是什麼**：一本「星形立體書」（star book / carousel book）。所有書頁的一條邊都釘在同一根垂直書脊上；翻到哪一頁，相鄰兩頁就打開成 90 度，變成一間房的兩面牆，地板攤平、家具立起來。其餘頁面疊在兩側，露出一小截。【已驗證】
2. **好看的原因不是 3D，是「折紙守規矩」**：牆在轉、地板沿對角線折起來、家具晚半拍冒出來，每個動作都是一張紙真的做得到的。觀眾不用學就看得懂「這是一本書」。【推論】
3. **技術上不難，我已經重做出來**：不用 WebGL、不用 CSS 3D。等角投影是正交投影，平面映到螢幕是仿射變換，所以一面牆的插圖只要一個 SVG `matrix()` 就貼得上去。地板的折法可以解析解出來（下面第 3 節）。樣張：`/preview/popup-book-study`。【已驗證】
4. **對 SunUI 的價值**：很符合「質感 + 動態」的主軸，而且線條與底色全部跟著 `--sunui-spot`，換品牌色整本書跟著換。最適合的用途是「把進度或分區做成一個看得見的空間」：新手導覽、門市樓層、活動攤位、方案比較。【建議】
5. **放哪裡**：免費型錄凍結到 2027-01-12，不能是新的免費 block。建議當 **Pro 場景**（例如 `popup-store-tour`：門市或活動會場的立體導覽），之後若要開放，抽出折紙引擎當原子，符合凍結規則第一條例外。Pro 已有 `catalog-flipbook`、`fold-invite-card`、`cutaway-spec`，同一個「紙本機構」家族，但沒有一個是房間型的。【建議】

## 1. 原作在做什麼【已驗證】

逐格觀察（影片 0.0 到 8.0 秒）：

| 時間 | 畫面 |
|---|---|
| 0.6s | bedroom 還沒完全打開，兩面牆接近 90 度，牆上有窗、相框；家具還沒出現 |
| 1.4s | 完全打開，床、書桌、椅子、地毯都立起來了 |
| 3.0s | 翻到 bathroom：原本的右牆轉到左邊，後面疊著的頁面整排往旁邊推一格 |
| 5.2s | kitchen |
| 6.5s | balcony，最後一頁，右箭頭變淡 |
| 8.0s | 往回翻，地板折成 V 形立起來，可以清楚看到它是沿對角線折的 |

介面元素：左右箭頭（到頭變淡）、底下一行手寫體房名、書本下方一片柔和的影子。線條是藍紫色細線，底色接近白，插圖是淡彩。回覆裡最多人要的是「做成一整圈」（Make it full circle），也就是最後一頁接回第一頁。

## 2. 拆成三個機構

| 機構 | 真實的紙怎麼做 | 動畫上的意義 |
|---|---|---|
| 書脊與頁面 | 每頁一條邊黏在書脊，可以繞書脊轉 | 翻頁 = 一面牆掃過 90 度 |
| 地板 | 一張正方形，沿對角線折一刀，兩半各黏在一面牆的底邊 | 牆合起來時地板自己立起來，不需要另外的動畫 |
| 家具 | 立體書的 V 折立牌 | 房間打開到一定角度才「站起來」，比牆晚半拍 |

第二點是整件作品最聰明的地方：地板不是淡入淡出，是被兩面牆「帶著」攤平。這就是質感的來源。

## 3. 實作方式【已驗證】

檔案：`apps/web/app/(preview)/preview/popup-book-study/`

| 檔案 | 內容 |
|---|---|

| `rooms.tsx` | 四間房（Studio、Library、Café、Greenhouse）的牆、地板插圖與家具 |
| `study.tsx` | 樣張頁：翻頁（可調疊頁角度、慢動作）、套用在新手導覽 |

### 3.1 頁面角度

N 間房要 N + 1 頁。第 k 間打開時，第 i 頁的方位角：

- `i ≤ k`：`-(k - i) × gap`（往左疊）
- `i ≥ k + 1`：`90 + (i - k - 1) × gap`（往右疊）

位置 `p` 是連續的浮點數，兩個整數設定之間線性內插。翻一頁時只有一張頁面轉 90 度，其他頁各挪一格 `gap`（預設 14 度），跟原作一樣。

### 3.2 投影與貼圖

等角投影：`screen = ((x - y)·cos30°, (x + y)·sin30° - z)`。平面在正交投影下是仿射的，所以：

- 牆的插圖在自己的座標（x 0..120、y 0..150）裡畫，套一個 `matrix(a b c d e f)` 就貼到牆上。
- 牆只畫面向鏡頭的那一面；背面的插圖把 x 換成 `W - x`，兩面都不會左右顛倒。
- 線條用 `vector-effect: non-scaling-stroke`，牆被壓扁時線不會變粗變細。

### 3.3 地板的折法（解析解）

兩面牆夾角 θ，對稱軸是方位角 β。地板正方形邊長 W，對角線頂點 D 必須同時滿足：離牆角 W√2、離兩面牆的外角各 W。解出：

- 水平距離 `dx = W / cos(θ/2)`
- 高度 `dz = W · √(2 - 1 / cos²(θ/2))`

θ = 90 度時 dz = 0，地板平鋪；θ → 0 時 dz = W，兩半各自貼回牆上。地板的兩個三角形再各用一個仿射矩陣貼地毯、木紋、磁磚。

### 3.4 畫的順序

所有東西都是圍繞同一根垂直軸的扇形，從固定方向看，**跟觀看方向差越多度的越先畫**就對了（不用 z-buffer）。地板的排序用它兩面牆的中線，所以打開的那間地板一定畫在自己的牆之後、家具之前；背對鏡頭的房間地板自然被牆蓋住。

### 3.5 動態

- 彈簧：stiffness 170、damping 22，略欠阻尼，牆停下前會多走一點點再回來。
- 家具：房間開到 72 度以上才開始長高，每件有自己的 delay（0 到 0.5），ease-out cubic。合起來時也在 72 度前先收平，不會穿過正在轉的牆。
- 拖曳：書頁跟著手指走（220px 一間），超出頭尾有 1/3 阻力，放開時依速度多帶 0.12 秒的慣性決定停在哪一間。
- `prefers-reduced-motion`：直接跳到目標，沒有轉動。
- 房名：只有目前那間不透明，切換時上下位移 10px + 3px 模糊，300ms，用站方的 ease 曲線。

### 3.6 色彩

（初版）全部是品牌專色的深淺：線條 `--sunui-spot`，牆 4%、地板 9%、封面 14%，家具三階 10、20、34%。後來改成物件本色，見第 7 節。光從左上來，每一面依法向量混入 0 到 16% 的 foreground。換品牌色、切暗色模式都自動跟著變（樣張頁目前在暗色下驗證過）。

| 項目 | 原作 | 這次 |

## 5. 能用在哪裡【建議】

| 用途 | 為什麼適合 |
|---|---|
| 新手導覽 / 設定步驟 | 每一步一間房，「完成度」變成看得到的空間。樣張第 02 節就是這個 |
| 門市、展場、活動會場導覽 | 每一區一頁：入口、試衣間、咖啡區、櫃台。最貼近 SunUI 的電商旗艦方向 |
| 方案比較 | 三種方案三間房，房間裡的家具多寡就是功能多寡 |
| 404 / 空狀態 | 空房間，家具還沒搬進來 |
| 品牌故事 | 一頁一個年份或一個章節 |

不適合：資訊密度高的地方（房間裡放不了表格）、小於 320px 寬的位置（插圖細節會糊掉）。

## 6. 還沒做、下一步

1. **整圈模式**（原作回覆裡最多人要的）：頁面平均分佈在 360 度，最後一頁接回第一頁。幾何上只要把 `pageAngle` 換成環狀，排序規則不用改。
2. **插圖品質**：現在是幾何線條，要當 Pro 場景賣，每間房的插圖要再細一個等級（窗簾、植物葉形、光影），而且要定一套「立體書插圖」的畫法寫進 DESIGN.md。
3. **房間內互動**：點家具出現說明（導覽用途需要）。
4. **效能**：每幀重算所有面並重新渲染 SVG，四間房沒問題；超過八間房或手機低階機要量 frame time。
5. **無障礙**：目前 SVG 是 aria-hidden，房名用 aria-live 播報；做成正式場景時要補每一間的文字描述。

## 8. 最佳化（2026-11-22）

| 項目 | 改前 | 改後 |
|---|---|---|
| clipPath id | 同一頁 5 本書共用 3 個 id（重複 5 次） | 每本書用 `useId` 產生自己的 id；伺服器與瀏覽器的 id 實測一致，沒有 hydration 錯誤 |
| 插圖重繪 | 每幀都比對整棵牆、地板插圖 | 插圖包在 `memo` 裡，參照不變就跳過；每幀只更新多邊形與 transform |
| 看不到的書 | 同步翻頁時，捲出畫面的書也跑動畫 | `IntersectionObserver` 判斷，不在畫面內就直接跳到目標 |
| 家具前後 | 用中心點排序，靠太近可能顛倒 | 腳印不重疊時依 s、t 判斷誰在後面，重疊時（桌上螢幕、盆上植物）低的先畫；每間房只算一次 |
| 公開 repo | 引擎檔案未追蹤，但可能被誤 commit | 樣張資料夾加進 `.git/info/exclude`（只在本機，不改任何追蹤檔） |

量測方式：網址加 `?perf`，`window.__pbBench(n, noMemo)` 用 `flushSync` 同步把一本書推過 n 個位置，量 render、比對與寫入 DOM 的時間，不受分頁在不在前景影響。

結果（開發模式，每本書每幀，五次取中位數）：關掉插圖 memo 0.365ms，開著 0.267ms，約省 27%。一幀的預算是 16.7ms，所以 JS 這邊從來不是瓶頸。**還沒量的**：SVG 的繪製（paint）成本，要在瀏覽器面板顯示時，或在 production build 上用 Performance 面板量；手機低階機也還沒測。
