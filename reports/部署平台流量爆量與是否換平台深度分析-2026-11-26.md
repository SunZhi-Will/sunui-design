# 部署平台流量爆量與是否換平台深度分析

日期：2026-11-26
資料來源：Vercel 用量頁（團隊 SunZhi's projects，2026-10-26 至 11-25）、`vercel project ls`、DNS 與 HTTP 標頭實測。

## 一句話結論

**不用換平台，但要升級 Vercel Pro（每月 20 美元）。** 爆的不是流量，是 Hobby 的「Fluid Active CPU 每月 4 小時」，而且 85% 是 beacon（sunkoro.com）吃掉的，它已經搬去 Google 了。SunUI 自己的負載很小，但 Hobby 不准商用，加上整個帳號一起停權的連坐風險，Product Hunt 上線前一定要離開 Hobby。

## 1. 現況：不是流量爆，是 CPU 爆，而且整個帳號被停

| 項目 | 用量 | Hobby 上限 | 狀態 |
|---|---|---|---|
| Fluid Active CPU | **6h 37m** | 4h | **超過 165%，觸發停權** |
| Fast Data Transfer（頻寬） | 17.47 GB | 100 GB | 17%，沒事 |
| Fast Origin Transfer | 3.62 GB | 10 GB | 36%，沒事 |
| Function Invocations | 156K | 1M | 16%，沒事 |
| Image Transformations | 5.3K | 5K | 略超 |

Vercel 的提示原文意思是：自 2026-11-25 起因 Fluid Active CPU 超過 Hobby 合理使用上限，**整個團隊的部署暫停，到 2026-12-25 才解除**。

實測影響：

- `sunui.synvize.com` 回 `HTTP 402`，`x-vercel-error: DEPLOYMENT_DISABLED`。**SunUI 正式站現在是掛的。**
- 團隊裡另外 20 多個專案（wtma-landing、fangjie-landing、vozmira-landing、kapzoom 等）一起停。
- `sunkoro.com` 正常（`server: Google Frontend`），因為已經搬走。

## 2. 誰吃掉 CPU

| 專案 | Active CPU | 佔比 | Invocations |
|---|---|---|---|
| **beacon（sunkoro.com）** | **5h 37m** | **84.9%** | 91,336 |
| wtma-landing | 25m 16s | 6.4% | 11,047 |
| fangjie-landing | 10m 8s | 2.5% | 18,130 |
| vozmira-landing | 9m 15s | 2.3% | 7,002 |
| vwonest-web | 8m 9s | 2.1% | 3,579 |
| 其他全部 | 約 7m | 約 2% | 少量 |
| **sunui** | **0s** | **0%** | 幾乎沒有 |

重點：

1. **beacon 一個專案就超過 4 小時上限**，其他專案加起來只有約 1 小時。
2. beacon 每次呼叫平均約 **220ms CPU**（5h37m ÷ 91K）。一般 SSR 頁面約 20 到 50ms，所以它不只是流量多，每個請求也很重（推測是每頁都即時查資料庫、渲染講義或做驗證，沒有快取）。
3. 圖表上 beacon 是每天穩定 10 到 20 分鐘，不是某天突然暴衝。它是結構性的超量，不是被攻擊。
4. **SunUI 本身在這 30 天幾乎沒用到 CPU**，它不是元兇。

## 3. 你已經做的事為什麼還不夠

你把大流量（beacon）搬去 Google 是對的，這一步解決了「下個月還會再爆」的問題：扣掉 beacon，剩下的專案每月約 1 小時 CPU，只用 Hobby 額度的 25%。

但有三件事搬走 beacon 解決不了：

1. **停權不會因為搬走就解除。** 這期的 6h37m 已經記帳了，Hobby 只能等到 12/25，或升級 Pro 立即解除。SunUI 等一個月等於正式站剛定網域（11-22）就消失一個月，shadcn 索引的送審也會卡住。
2. **Hobby 條款只准個人非商業使用。** SunUI 賣 Pro 授權、跑 Shopline 金流和續訂 cron（`vercel.json` 的 `/api/cron/renewals`），本來就不該在 Hobby。被抓到的處理方式也是停權。
3. **連坐。** Hobby 的上限是整個團隊共用的，任何一個小專案爆了，SunUI 就一起掛。這次就是 sunkoro 把 SunUI 拖下水。2027-01-12 Product Hunt 當天如果再發生一次，損失遠大於 20 美元。

## 4. 平台選項比較

| 選項 | 月成本 | 遷移工作 | 能否立刻恢復 | 風險 |
|---|---|---|---|---|
| **A. 現有團隊升級 Vercel Pro** | 20 美元起（含用量額度，可設支出上限） | 零 | 能，升級即解除 | 超量改為計費而非停權，要設 Spend Management |
| B. 搬 Cloudflare Workers（OpenNext 或 vinext） | 約 5 美元 | 大 | 不能，要先改完 | SunUI 的區塊頁、MCP、`/r/` 端點在執行期用 `fs` 讀 `registry/`、`content/`（見 `next.config.ts` 的 `outputFileTracingIncludes`），Workers 沒有檔案系統，要全部改成打包時內嵌。Pro 授權驗證、Redis 計數、cron 也要重接 |
| C. 跟 beacon 一起放 Google Cloud Run | 依用量，低流量很便宜 | 中 | 不能，要先搬 | 要自己處理 CDN、預覽部署、網域、環境變數 64 個；失去 Vercel 的 preview 流程 |
| D. 什麼都不做，等 12/25 | 0 | 零 | 不能 | SunUI 掛一個月；仍違反 Hobby 商用條款；PH 當天可能再被連坐 |

### 為什麼不建議現在換到 Cloudflare

Cloudflare 長期確實便宜，靜態資源頻寬也不計費。但 SunUI 的架構大量依賴執行期讀原始碼（那正是 Pro 授權與 port guide 的核心），換到 Workers 不是改設定，是重寫資料讀取層。離 Product Hunt 只剩 47 天，凍結期的時間應該花在 Pro 場景和上線準備（AGENTS.md 的既定方針），不是遷移基礎設施。上線後若流量真的大到 Vercel 帳單難看，再評估。

## 5. Product Hunt 當天的頻寬估算

SunUI 的重量在 `public/cards`：212 支卡片影片共 24MB（平均約 113KB），另有 480p 版 9.7MB、海報 9.8MB。

- 一般訪客滑過目錄約載入 3 到 6MB。
- PH 當天 5,000 到 20,000 訪客，約 **15 到 120GB**。

Hobby 的 100GB 在好的情況下會爆；Pro 含 1TB，綽綽有餘。這也是不能留在 Hobby 的理由之一。

## 6. 建議行動（依順序）

1. **今天：現有團隊升級 Pro**，讓 SunUI 和其他 20 多個網站立刻恢復。升級後馬上到 Settings → Billing 開 **Spend Management**，設每月上限（例如 50 美元）並勾選達到上限時暫停，避免超量變成無上限帳單。
2. **把 beacon 在 Vercel 上的專案停用或刪除**（它的網域已經指向 Google）。不然 `*.vercel.app` 網址被爬蟲掃到，CPU 還是記在這個團隊。
3. **兩個落地頁改靜態**：fangjie-landing 有 18K、wtma-landing 有 11K 次 function 呼叫，落地頁應該是純靜態輸出，改完 CPU 幾乎歸零。
4. **beacon 在 Google 上要留意**：每請求 220ms CPU 的問題沒有因為換平台消失，只是換個地方付錢。值得找出熱點路由加快取。
5. **SunUI 暫不遷移。** PH 上線後一個月看 Vercel 帳單，若每月超過約 50 美元，再把 `public/cards` 影片搬到 Cloudflare R2（零出站費），這是改動最小、省最多的一步。

## 7. 決定：不升級，等 12/25 解除（使用者，2026-11-26）

這條路可行。扣掉 beacon 後，平常月用量只有 CPU 上限的 25%、頻寬的 17%。代價與要先做的事：

**代價**
- SunUI 正式站 11/25 到 12/25 掛一個月，解除後只剩 18 天到 Product Hunt。shadcn 索引送審要等網站恢復再送。
- Hobby 不准商用的條款風險還在，Pro 授權開賣前要再想一次。

**解除前一定要做（不然 12/25 一恢復又可能爆）**
1. **停用或刪除 Vercel 上的 beacon 專案**，連同它的網域設定。恢復後它的 `*.vercel.app` 網址被爬蟲打到，CPU 仍然記在這個團隊。
2. **fangjie-landing、wtma-landing、vozmira-landing 改純靜態輸出**，三個加起來每月約 45 分鐘 CPU、36K 次呼叫，改完幾乎歸零。

**Product Hunt 當天的兩個地雷（Hobby 會直接停權，不是收費）**
3. **圖片優化 5,000 次上限**：這期已經用到 5.3K。SunUI 的海報用 `next/image`（`components/live-preview.tsx`、`app/(site)/docs/changelog/page.tsx`），上線流量一來很容易爆。海報本來就是預先截好、尺寸固定的 jpg，在 `next.config.ts` 設 `images: { unoptimized: true }` 就不再耗這個額度。
4. **頻寬 100GB 上限**：估算 PH 當天 15 到 120GB。把 `public/cards` 的影片（約 34MB）搬到 Cloudflare R2（免費額度內、出站不計費），SunUI 自己的頻寬會降到很低。

做完這四件，12/25 之後即使 PH 當天流量大，最可能撞到的上限也都拆掉了。

## 附：查證方式

- 用量：Vercel 儀表板 Usage 頁，Fluid Active CPU 與 Invocations 依專案分組。
- `vercel usage` CLI 在 Hobby 拿不到資料（沒有計費訂閱）。
- 停權狀態：`curl -sI https://sunui.synvize.com` 回 402 `DEPLOYMENT_DISABLED`。
- beacon 去向：`sunkoro.com` 解析到 Google（216.239.x.x），回 `server: Google Frontend`。
- Hobby 上限數字以 Vercel 儀表板顯示為準（CPU 顯示為 6h 37m / 4h）；Pro 的含量與單價請以升級頁當下顯示為準。
