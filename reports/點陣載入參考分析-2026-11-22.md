# 點陣載入：參考分析與實作

> 日期：2026-11-22
> 參考：Elia（UI Arc 作者）在 X 的貼文「Loading screens can be pretty too」，7.3 秒影片，2026-11-21。
> 結果：`loading-effects` 多一個 `DotMatrixLoader`，免費型錄數量不變（仍是 75）。

## 1. 結論

1. **影片在講的不是「一個好看的 spinner」，而是「同一個元件把整段上傳講完」**：等待、百分比、完成，畫面上的東西從頭到尾不換，只是點的亮法在變。這是它好看的真正原因，也是 SunUI 現有載入元件沒有的。
2. **歸類是動態效果，所以放免費**：照 option C（動態效果庫免費，Pro 賣組合場景），加進現有的 `loading-effects`，不是新區塊，不違反 2026-11-06 的凍結。
3. **顏色照 SunUI 規則改**：參考是藍色載入、綠色完成。SunUI 出廠讀 `--sunui-spot`（沒設時退回 `--primary`，黑白主題下就是黑），錯誤讀 `--destructive`。買家設一行 CSS 就變成影片那樣。
4. **補了影片沒做完的部分**：錯誤狀態（叉加一次輕晃）、reduced motion、螢幕閱讀器文字、離開畫面停止。

## 2. 影片逐格拆解

逐格停在 0、0.5、2.4、3.6、4.6、5.6、6.6 秒看（1920×1080 原片）。

| 時間 | 狀態列 | 畫面 |
|---|---|---|
| 0 到 1.5 秒 | Waiting for size | 六格 7×7 點陣各自循環：Wave、Spiral、Rain、Ripple、Snake、Scan |
| 1.6 到 4.8 秒 | 29%、64%、90% | 每格依自己的順序把點補滿。Wave 由左到右一欄欄補，Rain 由下往上，Snake 由外圈往內，Ripple 由中心往外 |
| 5.6 秒 | Uploaded | 全部點亮並轉成綠色 |
| 6.6 秒起 | Uploaded | 只剩組成打勾的 7 顆點，其他退回暗點 |

上方有 Loading、Progress、Success、Error 四個分頁與 Replay。影片只示範了 Progress 一路到 Success。

## 3. 為什麼它好看（可以拿來用的原則）

| 原則 | 影片裡怎麼做 | SunUI 怎麼落實 |
|---|---|---|
| 暗點一直在 | 熄滅的點保留淡淡的灰，網格永遠看得出來 | 熄滅時 opacity 0.16、縮到 0.72，不是消失 |
| 樣式延續到進度 | 每種循環的「方向」就是它補滿的順序 | `FILL_RANK`：六種樣式各有自己的填充順序 |
| 結果由同一批點組成 | 打勾不是另外疊一張圖，是點陣裡的點 | `CHECK` 與 `CROSS` 都是格子座標 |
| 先滿再收 | 完成時先全亮一下，才收成勾，有「到了」的感覺 | 全亮 160ms，勾的 7 顆點各間隔 35ms 點亮 |
| 換狀態不跳 | 狀態之間是漸變 | 每顆點的亮度以時間常數 60 到 90ms 追目標值，換狀態、改數值都自然過渡 |

## 4. 實作

| 項目 | 內容 |
|---|---|
| 元件 | `DotMatrixLoader`，在 `registry/free/loading-effects/loading-effects.tsx` |
| Props | `pattern`（6 種）、`state`（loading / progress / success / error）、`value`、`size`（sm 33px、md 43px、lg 60px）、`color`、`label`、`doneLabel`、`errorLabel` |
| 繪製 | 49 個 span，一個 requestAnimationFrame 直接寫 opacity 與 transform，不經過 React 重繪；結果畫完、數值追到就停止迴圈 |
| 無障礙 | `role="status"`，念出「Loading」、「Loading 38%」、「Done」或「Failed」 |
| reduced motion | 載入時停在一個固定畫面；進度、勾、叉直接到位，資訊不少 |
| 離開畫面 | 用現有的 `useActive`（useInView），看不到就不跑 |
| 示範 | demo 最下面一張整列卡：四個狀態分頁、Replay、六種樣式、狀態列。按「進度」會自己跑到 100 再變成功 |
| 型錄卡 | `dot-matrix` 變體：三格，自己循環 載入 → 進度 → 成功 |
| 文件 | `registry.json` 描述、`whenToUse`、4 個別名；`content/registry-i18n/loading-effects.json` 三語同步 |

## 5. 和參考的差異

| 參考 | SunUI | 理由 |
|---|---|---|
| 藍色載入、綠色完成 | 一律品牌專色，錯誤用 `--destructive` | `DESIGN.md`：SunUI 不選顏色；綠色在黑白主題裡會是唯一的雜色 |
| 沒看到錯誤 | 叉，加一次 0.36 秒的輕晃 | 上傳一定會失敗，少了這個就不能直接用 |
| 只有影片 | 開放 `value`，買家接真正的上傳進度 | 參考的百分比是假的；SunUI 的元件要能接資料 |

## 6. 後續（沒有在這次做）

1. **Pro 場景使用**：`file-dropzone` 與 `hoop-upload` 的上傳中狀態可以換成 `DotMatrixLoader`，讓上傳、百分比、完成在同一個位置講完。這是 Pro 那邊的改動，要另外排。
2. **首頁互動牆**：要不要放一格點陣，等使用者看過再決定，不主動加。

並排比較頁：`.compare/dot-matrix/index.html`（不進版控）。

## 7. 2026-11-22 追加：更豐富的顏色

使用者要求「增加更豐富的顏色」。

| 項目 | 內容 |
|---|---|
| `palette` prop | `spot`（預設，品牌專色，行為不變）、`status`（成功時轉綠，讀 `--sunui-success`，沒設時是 `oklch(0.7 0.16 155)`）、四種漸層 `aurora`、`sunset`、`lagoon`、`prism` |
| 漸層做法 | oklch 只換色相，亮度與彩度固定，每顆點一樣重；載入與進度沿對角線緩慢流動，結果靜止 |
| 勾的漸層 | 勾只留 7 顆點，沿對角線只會吃到一小段色相，所以結果改成由左到右，整條漸層都在勾上 |
| 錯誤 | 不管哪個配色都讀 `--destructive`，失敗不會被當成裝飾 |
| 示範 | 狀態分頁下方六顆色票，預設極光；型錄卡每跑完一輪換下一種漸層 |
| 規則 | 元件預設仍是品牌專色（library 預設不帶顏色）；顏色只在區塊預覽裡，不碰網站外框 |
| 避開 AI 色 | 極光原本是青到紫（色相 175 到 300），正是 `為什麼取消黑白後還是黑白深度分析` 點名要避開的範圍，改成翠綠到金黃（165 到 95） |

深色模式：preview 頁沒有吃到切換，這次沒有看過深色畫面。漸層亮度 0.7，理論上兩種底色都讀得到，之後要補看一次。

前後並排：`.compare/dot-matrix/colour.html`。

## 8. 2026-11-22 追加：八種變化

使用者要求「做出不一樣的變化」，看過樣張後選擇全部保留。

| 新 prop | 值 | 效果 |
|---|---|---|
| `shape` | dot（預設）、square、diamond、ring、bar | 圓點、像素方格、菱形、亮起時由外往內填滿的空心環、像等化器的短直條 |
| `glow` | 布林 | 亮點用自己的顏色發光，像 LED，適合深色底 |
| `emphasis` | fade（預設）、scale | fade 是暗點維持大小變淡；scale 是暗點縮成小點、亮點長大 |

示範卡加一列「樣式」：原版、像素方格、菱形、空心環、霓虹 LED、縮放顆粒、直條、琥珀面板。選樣式會一起換配色，之後仍可用色票改色；霓虹與琥珀放在深色面板上。型錄卡每跑完一輪換下一種樣式。

樣張頁：`/preview/dot-matrix-study`（不進導覽與 registry，跟 `color-study` 同類），八種並排，可切換狀態或自動輪播。截圖：`.compare/dot-matrix/variations.html`。
