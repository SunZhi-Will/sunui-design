# Pro 場景規劃：工作區分頁 workspace-tabs（2026-11-22）

前情：`reports/側邊欄開關不要跳與動態分頁深度分析-2026-11-22.md`。那份分析拆解了 @diegohaz 的 app shell 影片，並已把 `app-shell` 的開關改成固定位置。這份是影片後半「動態分頁」的 Pro 場景規劃，尚未動工。

## 1. 為什麼放 Pro

| 四問 | 判斷 | 偏向 |
|---|---|---|
| 可替代性 | shadcn、Magic UI、React Bits 都沒有瀏覽器式動態分頁；網路上的 Chrome 分頁仿作多半沒有無障礙、溢出與排序 | Pro |
| 工時 | 一天以上：關閉後焦點去向、溢出捲動、拖曳與鍵盤排序、反向圓角跟著滑、品牌搬家、四語文案 | Pro |
| 商業距離 | 遠，是工具介面 | 免費 |
| 展示力 | 很適合拍「192px 對 0px」前後對照短片 | 行銷素材 |

三題有兩題偏 Pro，放 Pro。跟定位的關係要講清楚：Pro 主力是商店與檔期，這個場景不在主力上，所以 demo 用**商店後台**情境（開著「訂單 #1042」「商品」「春季檔期」幾個分頁），讓它同時是一個賣家每天會用的畫面。

## 2. 組成

- 新 Pro block：`registry/pro/workspace-tabs/`，series `product`，`registryDependencies: ["utils", "@sunui/app-shell"]`。
- 匯出兩層：
  - `WorkspaceTabs`：分頁列本身，可以單獨放進任何版面。
  - `WorkspaceShell`：`AppShell` 加上 `WorkspaceTabs`，處理側邊欄收合時的品牌搬家與開關錨定。
- 免費 `app-shell` 需要補兩個小東西（屬於修改既有 block，不是新增）：
  1. `desktopTopBar?: (state: { collapsed: boolean }) => ReactNode`：內容欄頂端的插槽，高度與側邊欄標題列對齊（上緣 20px、高 32px）。
  2. `collapseMode?: "rail" | "hidden"`：`hidden` 時側邊欄寬度收到 0（影片的做法），開關改畫在固定層，座標與展開時完全一樣。

  這兩個是通用能力，免費用戶也受益；分頁本身仍只在 Pro。

## 3. 規格

### 分頁外觀（沿用 `sliding-tabs` 的 folder 做法）

- 選中分頁是凸起的表面，與下方面板同一形狀；兩側反向圓角半徑與面板圓角相同（`rounded-xl` 的 12px），三個圓角一致。
- 選中形狀用共享 `layoutId` 滑到新分頁，`springs.snappy`。
- 未選中分頁滑過時出現 `bg-foreground/[0.04]` 淡底膠囊。
- 分頁間 1px 分隔線；選中或滑過的分頁**兩側**分隔線隱藏（用 `data-active`、`data-hover` 加相鄰選擇器，不走 React state）。
- 選中分頁貼齊面板左緣時，左側反向圓角拿掉，面板左上角圓角動畫到 0（影片 3 秒處）。
- 寬度：先從 200px 縮到 96px（像 Chrome），縮不下才溢出；標題截斷用右側淡出遮罩。
- 未儲存：6px 狀態點，滑過時換成關閉鍵（VS Code 做法），點只用狀態色，符合 product 規則。

### 動作

| 動作 | 行為 | 時長 |
|---|---|---|
| 新增 | 新分頁寬度從 0 長出並設為選中，自動捲到看得見；`+` 固定在最右，不跟著捲 | 180ms |
| 關閉 | 寬度收到 0、淡出，鄰居滑過來補位；關掉的是選中分頁時，選右邊鄰居，沒有就選左邊，焦點跟過去 | 180ms |
| 中鍵 | 關閉 | |
| 拖曳排序 | framer-motion `Reorder`，水平軸；拖到邊緣自動捲動 | |
| 溢出 | 兩端出現淡出遮罩，只有該方向還有內容時才顯示箭頭；垂直滾輪轉成水平捲動 | |
| 收合側邊欄 | 開關不動；品牌從側邊欄淡出，同時在分頁列最前面出現品牌膠囊，分頁整排往右滑；展開時反過來 | 240ms，與側邊欄寬度同步 |

### 鍵盤與無障礙

- `role="tablist"`，roving tabindex；左右鍵移動、Home、End。
- 聚焦分頁上按 Delete 或 Backspace 關閉；`Alt+Shift+左右` 搬移位置。
- 關閉、新增、搬移時用 `aria-live="polite"` 報一次（例：「已關閉 春季檔期，目前在 商品」）。
- 關閉鍵 `aria-label` 帶分頁名稱；觸控裝置（`pointer: coarse`）關閉鍵常駐。
- reduced motion：全部瞬間切換，資訊不缺。

### 窄螢幕

- 768px 以下分頁列改成「分頁數」按鈕，點開是清單面板（像行動版 Safari），可切換與關閉。
- 375px 不破版。

### API 草稿

```ts
interface WorkspaceTab {
  id: string;
  label: string;
  icon?: ReactNode;
  dirty?: boolean;
}

interface WorkspaceTabsProps {
  tabs: WorkspaceTab[];
  activeId: string;
  onActiveChange: (id: string) => void;
  onClose?: (id: string) => void;
  onAdd?: () => void;
  onReorder?: (ids: string[]) => void;
  /** Shown before the first tab, e.g. the brand while the sidebar is collapsed */
  leading?: ReactNode;
  locale?: string;
  labels?: Partial<WorkspaceTabsLabels>;
  children?: ReactNode; // panel content
}
```

狀態由使用者持有（受控），因為分頁通常跟路由或文件清單綁在一起；demo 裡示範用 `useState` 管。

## 8. P1 結果（2026-11-22）

- 溢出：分頁列可以橫向捲動（垂直滾輪也會轉成橫向），兩端有淡出，只有那一側還有分頁時才出現箭頭；選中分頁、新增的分頁會自動捲進視野。`+` 跟在最後一個分頁後面，放不下時固定在最右。
- 排序：拖曳（framer-motion `Reorder`，拖到邊緣會帶著列捲動）或 `Alt+Shift+左右`，鍵盤搬移時焦點留在原分頁。
- 播報：關閉、新增、搬移各用 `aria-live="polite"` 報一句，四語文案都有（例：「已關閉 訂單 #1042，目前在 商品。」）。
- 窄螢幕：容器寬度小於 28rem 時，分頁列換成一顆「目前分頁 + 數量」的按鈕，點開是所有分頁的清單，可切換、關閉、新增；開啟時焦點落在目前分頁，上下鍵移動，Esc 關閉並把焦點還給按鈕，點外面也會關。
- **跟規劃不同**：取消「寬度從 200px 縮到 96px」這一段。它跟新增、關閉的寬度動畫互相衝突，而且 CSS 沒有「縮到 96px 但短分頁不被撐大」的乾淨寫法；改成標題最多 200px、放不下就捲動，跟 VS Code、Arc 一樣，標題也比較讀得出來。
- 驗證中修掉的：`+` 被推到最右邊、窄螢幕清單超出外框、清單背景透明（網站主題沒有 `--popover`，改用 `bg-card`）、清單開啟時焦點落在第一列而不是目前分頁。
- 已知限制：自動化測試用的「瞬間拖曳」（只有按下和放開，中間沒有移動）不會排序，真的滑鼠拖曳與逐步移動都正常。拖曳時的邊緣自動捲動只在指標移動時觸發，停在邊緣不動不會一直捲。
- 下一步 P2：免費 `app-shell` 加內容欄頂端插槽與完全隱藏的收合方式，`WorkspaceShell` 處理品牌搬家與開關錨定。

## 9. P2 結果（2026-11-22）

**免費 `app-shell`（公開 repo）**
- `collapseMode="rail" | "hidden"`：`hidden` 時外層裁切框把寬度動畫到 0，側邊欄本身維持全寬，所以內容不會重排，像整片滑走；收起後側邊欄是 `inert`，鍵盤進不去。
- 開關改成畫在側邊欄外層、絕對定位（左 14px、上 22px），品牌列留一個同尺寸的空位。三種狀態（展開、圖示欄、隱藏）都在同一點，動畫中途量也一樣。放在 DOM 最前面，Tab 鍵第一個就到它。
- `layout="padded" | "flush"`：`flush` 時桌面內容區拿掉留白與最大寬度、改用側邊欄底色、側邊欄右邊線拿掉，讓內容自己畫面板；手機版不變。
- 新增 `components/ui/app-shell.tsx` 轉接檔（同 morph-menu 的做法），讓 Pro 可以用 `@/components/ui/app-shell` 匯入。
- `registry.json` 的描述與 watchOut、`content/registry-i18n/app-shell.json` 三語已更新。
- 回歸：免費 demo 的開關位置不變（394, 111），手機框沒有開關。

**Pro `WorkspaceShell`（`registry/pro/workspace-tabs/workspace-shell.tsx`）**
- `AppShell` 加 `layout="flush"` 加 `WorkspaceTabs`；分頁設定放在 `tabBar` 一個物件裡，其他 props 原樣傳給 `AppShell`。
- 側邊欄收合時，品牌（logo 與名稱，是連到首頁的連結）從分頁列最前面長出，分頁往右滑；展開時縮回。時長與曲線跟側邊欄寬度一樣（300ms、`cubic-bezier(0.32,0.72,0,1)`），看起來是同一個動作。只在桌面發生。
- `hidden` 模式收合時，品牌前面多留 32px 給固定的開關，於是畫面變成影片裡的「開關、品牌、分頁」一排。
- 對齊：內容上方留 14px，分頁列中線（14 + 4 + 18 = 36px）落在開關中線（22 + 14 = 36px）上。實測兩種模式都等高。
- 驗證：兩種模式收合前、動畫中、收合後，開關座標都相同；`aria-label`、`aria-expanded` 正確切換。

**跟規劃不同**
- 取消「選中分頁貼齊面板左緣時，面板左上角圓角變 0」：分頁列左邊一直有留白，選中分頁不會貼齊左緣，不需要這個變化。

## 11. 照原作重做版面（2026-11-22）

並排對照後發現版面讀錯（詳見分析報告第 7 節）。修正內容：
