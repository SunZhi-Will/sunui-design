# glass-cube-hero 參考分析

> 2026-11-08。來源是 Frank Reitberger（@_pwd_）在 X 的貼文「Codevember 2026 / 06 / Orrery」，一支 36 秒的錄影加上可以直接玩的頁面 dasprinzip.com/codevember2026/06-orrery.html（WebGPU、three.js r186、TSL）。這份回答四件事：它用了哪些技術、哪一招值得帶進 SunUI、怎麼改成能賣的商業場景、實作取捨。【已驗證】表示這次在瀏覽器或原始碼實際看過；【建議】【估算】是推論。

## 0. 結論先講

1. **招牌只有一個：一塊會晃動的玻璃方塊，裡面裝著一個發光的小世界。** 方塊本身沒有任何幾何細節，全部的「實體感」都來自四件事：折射、菲涅耳反光、邊緣琥珀色的倒角光、地板倒影。內容（星系）是體積光線步進畫出來的，所以轉動時有真的視差。【已驗證】
2. **做成 Pro 場景 `glass-cube-hero`（showcase 系列）。** 把「方塊裡的世界」換成可切換的檔期內容：星系（深夜開賣、香氛、科技新品）、雪景（冬季與聖誕禮盒）、金色火星（農曆新年、週年慶）。和 memory 裡「Pro 賣組好的場景，檔期包」的方向一致，也符合免費凍結規則（不新增免費項目）。
3. **不用 three.js。** 原作的效果其實全在一支片段著色器裡，three.js 只負責相機、兩個網格和 bloom。SunUI 已經有原生 WebGL1 的 `loop-shader-hero`，沿用同一套寫法（一個全螢幕三角形 + 一支著色器）可以零相依、gzip 後十幾 KB，不必讓使用者為了一個首屏裝 600 KB 的 three。
4. **不照抄。** 程式碼全部重寫，只取技術概念（這些都是公開的圖學手法）。名字不用 Orrery，視覺收斂到 showcase 的深色加琥珀金；音效、滾輪縮放、外部 OBJ 模型都不帶。

## 1. 錄影與頁面逐項拆解

| 觀察 | 怎麼做的（讀原始碼確認） | 判斷 |
|---|---|---|
| 方塊表面像融化中的冰，頂面有水波 | 不動幾何，只用兩層 3D value noise 擾動法線（1.3 倍與 4.5 倍頻率），強度由 `wobble` 控制 | **帶走**，便宜又有效 |
| 邊緣反光強、正面透 | Schlick 菲涅耳：F = 0.04 + 0.96(1 − cosθ)^5，反射方向查一個程式算的「攝影棚環境」 | 帶走 |
| 星系在方塊裡有深度，轉動有視差 | 折射後的光線在方塊內做體積步進：先粗步 20 格算光暈與星雲，再只在星系盤的薄板範圍內細步 56 格算旋臂、核心與塵埃吸收 | **帶走**，「只在薄板內步進」是效能關鍵 |
| 星星又多又銳利 | 3D DDA 網格走訪：光線一格一格穿過格子，每格雜湊出一顆星，算光線到星的最短距離，高斯成點；四層不同密度、各自隨機旋轉避免看出格線 | 帶走，簡化成兩層 |
| 方塊側面斜看時偏蜂蜜色 | 掠射角時把內部顏色乘上琥珀色（假的次表面散射） | 帶走 |
| 倒角有一圈金邊 | `1 − max(|n|)` 偵測倒角，疊琥珀色 rim | 帶走 |
| 地板倒影 | 第二個網格 y 軸翻轉放在下面，用較少步數的同一支著色器畫，往下淡出 | 帶走，改成同一支著色器裡反射光線再追一次 |
| 光從方塊溢出 | three 的 BloomNode 後製 | 改成便宜的解析光暈（光線到方塊中心的距離），不做多通道後製 |
| 左上角標題、下方「拖曳旋轉 · 滾輪縮放」 | HTML 疊在畫布上，IBM Plex Mono，顆粒 SVG 疊層 | 版型帶走，文案換成商業用 |
| sound on | WebAudio 合成和弦與嗡鳴，按鈕開關 | **不帶**：商業頁不該出聲，也增加體積 |
| 滾輪縮放 | OrbitControls | **不帶**：放在長頁面裡會搶走頁面捲動 |
| 換內容（Inside 選單）、OBJ 模型 | 可切換程式生成冰塊或載入 OBJ | 只留「換內容」，改成檔期內容 |
| 動態解析度 | 量每格耗時，太慢就降 pixel ratio（0.5 到 1.5） | 帶走 |
| 手機降級 | 偵測粗指標小螢幕，步數與星層減半 | 帶走 |

為什麼有效：一個靜物，卻讓人想伸手去轉。方塊是「容器」，裡面放什麼都會被賦予珍貴感，這正好是商品首屏要的東西（香水、珠寶、限量款、檔期主題）。

## 2. 和現有 block 的差別

| 現有 | 差在哪 |
|---|---|
| `loop-shader-hero`（Pro） | 平面背景著色器，沒有物件、沒有互動 |
| `shader-campaign-banner`（Pro） | 平面墨流，同上 |
| `point-cloud`（免費動效） | Canvas 2D 點雲，沒有材質與光 |
| `depth-hero`（免費動效） | 圖層視差，是 2.5D |
| `gift-box-reveal`（Pro） | 開箱互動，不是展示物件 |

MCP `search_blocks`（glass cube、snow globe、refraction）沒有任何近親。【已驗證】

四個問題（`免費與付費切分規劃-2026-11-05.md`）：
- **可替代性低**：Magic UI、React Bits 的免費層沒有真的體積折射物件，要做通常得裝 three 或 R3F。
- **工時高**：體積步進、DDA、折射、倒影、互動與效能調校約 2 天【估算】。
- **商業距離中高**：三種內容直接對應三個檔期包（冬季、農曆新年、深夜開賣）。
- **展示價值很高**：型錄卡片一眼就懂，也是 Product Hunt 影片素材。

結論：Pro，showcase 系列，排進型錄 A 組（整頁與檔期場景）。

## 3. 元件設計

```
GlassCubeHero   標題、說明、CTA、內容切換 + 舞台 + 狀態列
 └ 一支片段著色器：玻璃方塊、三種內容、地板倒影、光暈、色調映射
```

| prop | 作用 | 預設 |
|---|---|---|
| `inside` | galaxy 星系 / snow 雪景 / embers 金色火星 | galaxy |
| `palette` | 每種內容有內建配色；也可給 `{ bg, warm, cool }`，warm 是光源與倒角，cool 是空氣與星雲 | 依 inside |
| `align` | 寬版時方塊在右（文案在左）或置中 | right |
| `spin` | 自動旋轉弧度／秒，0 關閉 | 0.25 |
| `wobble` | 表面晃動強度，0 是平整玻璃 | 0.45 |
| `renderScale` | 最高渲染倍率，實際會依耗時自動降到 0.5 | 1 |
| `poster` | 首格前與 WebGL 不可用時顯示 | 無 |
| `eyebrow`、`title`、`description`、`cta`、`locale`、`labels` | 與其他 hero 一致 | |

互動與無障礙：
- 拖曳旋轉（左右轉、上下改俯角，放開有慣性），方向鍵每次轉 15°，舞台可聚焦並有說明文字。
- 狀態列：Motion 開關（WCAG 2.2.2，超過 5 秒的動態必須能暫停）、狀態、目前角度（直接寫進 DOM，不經 React）。
- 離開畫面、分頁隱藏、關閉 Motion 時停止繪製；關閉時拖曳仍可用，只在互動時重畫。
- 減少動態效果：不自動旋轉、內容不動，停在一格靜止畫面，拖曳仍有效但沒有慣性。
- 畫布 `aria-hidden`，意義全部在 HTML 文案裡。

## 4. 實作取捨

1. **WebGL1 而非 WebGPU。** WebGPU 在 Safari 與部分 Android 仍不穩，商業首屏不能賭。WebGL1 的限制（迴圈次數要是常數）用「固定上限 + 依品質 break」解決。
2. **外殼用 SDF 光線步進的圓角方塊，內部出口用解析的 AABB。** 外殼要圓角才有倒角光；內部只需要出口距離，用板塊相交一次就好。先用外接盒剔除，方塊外的像素只花一次盒子測試。
3. **倒影不另開網格。** 打到地板的光線反射後再追一次方塊，用低品質旗標（星系細步 14 格、星星一層），只佔畫面一小塊。
4. **光暈不做後製。** 光線到方塊中心的距離取指數衰減，乘內容的平均色。看起來像 bloom，成本是一行。
5. **色彩管線**：hex 在 JS 轉成線性，著色器裡算完做 ACES 近似色調映射再轉回 sRGB，最後加一點時間顆粒打散色帶。
6. **效能**【估算】：M1 筆電 1440×800 全幅、倍率 1 約 6 至 9 ms；手機自動降到 0.5 至 0.75。實測數字見第 5 節。

## 5. 驗證

2026-11-08 在 Chrome（Apple Silicon，DPR 2）對 `localhost:3100/preview/glass-cube-hero` 實測【已驗證】：

| 項目 | 結果 |
|---|---|
| 完整 demo，舞台 1022×480，渲染倍率 1 | 121 fps（螢幕上限），動態解析度沒有觸發降級 |
| 三種內容切換（星系、雪景、金色火星） | 全部正常，文案與配色跟著換 |
| 拖曳 | 左右轉帶慣性，上下改俯角並夾在範圍內 |
| Motion 開關關閉 | 角度停住，狀態顯示「已暫停，仍可拖曳」，aria-checked=false |
| 暫停時按方向鍵 | 一次 +15°，只重畫一格 |
| 型錄卡片（19rem 窄版） | 方塊在上、標題在下，容器查詢正確切換版型 |
| 主控台 | 沒有錯誤 |
| `tsc --noEmit`（排除其他 session 的 `.next*` 舊產物） | 通過 |

調校紀錄：相機一開始太近（方塊佔滿 92% 高），距離由 5.6 拉到 9.2；俯角 0.2 時頂面掠射反光一片橘色，改成 0.32 並把地平線暖光減半；星系盤傾斜加大，正面更看得到旋臂；火星的煙霧減量，避免整塊變成不透明的橘色。

未驗證：手機實機（粗指標降級路徑）、Safari、WebGL 不可用時的 poster 路徑。

## 6. 後續可做【建議】

- 內容第四種「香水瓶剪影」或吃一張商品去背圖當內容（投影到方塊中心的發光平面），讓品牌放自己的商品。這是最直接的變現點，但要先確認折射後的圖不會糊到看不出商品。
- 方塊外型參數化（圓柱、球）做成「玻璃容器」家族，對應聖誕雪球。
- 錄一支 10 秒影片給 Product Hunt 素材。
