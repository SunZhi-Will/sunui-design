參考：Soybean°（@soybonjour）在 X 發布的 UI/UX 探索「filter navigation bar」，12 秒影片。
本文件只描述觀察到的互動與動態，實作全部自寫，成品為 Pro block `ink-filter-bar`（`apps/web/registry/pro/ink-filter-bar/`）。

## 2. 為什麼好用

1. **篩選狀態有地方住**。選了什麼不靠標籤變色來猜，而是直接併進「結果」這個物件：結果條＝目前條件的總和。這比一般 chip 的 active 樣式多回答了一件事：這些條件一起決定了這個數字。
2. **因果是看得見的**。墨從結果條那一側流過來，數字同時捲動，動作和結果在同一個視線範圍內發生。
3. **同一個外框變形**。標籤沒有被換掉，只是被灌滿、靠攏，符合 DESIGN.md「連續性」那一條。
4. **逆向操作是對稱的**。取消就是倒帶：墨退回去、標籤回原位。使用者不用學第二套規則。
5. **懸停預告**。外框起伏只在游標停留時發生，提示「這是可以被灌滿的容器」，不是常駐循環。

## 3. 技術拆解與做法

| 效果 | 參考的樣子 | SunUI 做法 |
|---|---|---|
| 墨頸、凹口 | 兩灘墨相近時黏成一灘 | 只把墨形狀放在一層 SVG，套 goo 濾鏡（模糊後收緊 alpha，邊緣仍銳利）；文字與外框在上層 HTML，不受濾鏡影響 |
| 墨頸生成 | 點擊瞬間兩側同時長出墨 | 在間隙放一條「橋」矩形，高度 0 → 0.62 倍；goo 讓它自然長成沙漏 |
| 灌墨 | 凸弧前緣從左往右 | 左錨定、`rounded-full` 的墨層，寬度＝標籤寬 × 墨量；墨量很小時是貼著左緣的透鏡形 |
| 字反白 | 墨蓋到哪字就反白到哪 | 兩層字：底層墨色字、上層紙色字放在同寬的裁切層裡，跟墨層用同一個動態值 |
| 位置 | 標籤靠攏、互相疊過 | 自己算排版（結果條、成員、過渡中、閒置），每個標籤一組 x/寬度動態值，用 gentle 彈簧；過渡中的標籤 z 軸在上，有紙色底 |
| 數字 | 每一位各自滾動 | 每位數一個 `AnimatePresence`，依增減方向捲動，各位錯開 40ms |
| 懸停起伏 | 外框像水面 | `feTurbulence` + `feDisplacementMap`，只在滑鼠懸停時套用；觸控與 reduced motion 不套 |

### 時序（單次動作都在 400ms 內，依序進行）

- 選取：必要時先滑到結果條旁（gentle 彈簧）→ 墨頸 180ms → 灌墨 360ms → 收縫
- 取消：先拉開縫（墨頸保持）→ 退墨 320ms → 墨頸 140ms 斷開 → 回原位

## 4. 和 SunUI 規範的對照

- 顏色：只用墨 `#171717 / #ededed` 與頁面底色，淡墨 `#a3a3a3 / #737373` 用在「筆結果」。沒有漸層、光暈、彩色。
- 「不用模糊」：goo 濾鏡內部用了模糊，但輸出邊緣經 alpha 收緊後是銳利的，畫面上看不到模糊，判定符合精神。
- 不做慶祝、不做進場動畫；懸停起伏只在使用者動作時發生。
- reduced motion：位置、墨量直接跳到終點，沒有墨頸與起伏，數字直接換。
- 已知取捨：按鈕在 DOM 中維持原始順序，鍵盤 Tab 順序是篩選的原始順序，不跟著視覺重排（避免移動 DOM 讓焦點遺失）。

## 5. 為什麼放 Pro

免費型錄 2026-11-06 起凍結。依四項測試：可替代性低（市面 chip 元件沒有這種結果條合併）、自己做要處理排版狀態機與濾鏡分層、直接用在分類與搜尋頁、展示價值高。歸 Pro。

## 6. 驗證紀錄

- 以 10 至 40 倍慢速在 Chrome 逐格檢查：墨頸生成、凸弧前緣、字反白、相鄰與不相鄰選取、取消中段成員、Light 與 Dark。
- 修正兩個問題：量字寬原本用 `getBoundingClientRect`，在型錄卡片縮放時會量錯，改用 `offsetWidth`；灌滿後紙底在反鋸齒邊緣透出一圈，改成成員狀態才拿掉紙底。
