# 貼紙板參考分析（2026-11-07）

參考：Sam（@samirande_，19 歲設計工程師）在 X 發表的 Stick It Up（stickitupx.vercel.app，npm `stick-it-up`）。貼文主張「你的 UI 值得比無聊圖示更多的東西」，產品是 60 多張手繪 SVG 貼紙，免費開源，可以 npm 安裝或複製貼上，歡迎 PR 投稿貼紙。發文當天約 2,800 次瀏覽、94 個讚。
本文件只描述觀察到的做法，實作全部自寫，成品為 Pro block `sticker-board`（`apps/web/registry/pro/sticker-board/`）。沒有使用、描摹或重製對方任何一張貼紙圖。

## 2. 拆解：它到底做了什麼

用 DOM 與 CSS 檢查首屏的貼紙：

1. **白邊是畫在 SVG 裡的**。每張貼紙是一個 `<img src="/stickers/blueberry.svg">`，模切白邊和細陰影都是美術檔的一部分，CSS 沒有任何 filter。代價：每張圖都要美術先畫好白邊，使用者自己的圖不能直接變貼紙。
2. **三層包裝**：最外層 `absolute` 定位加 `pop` 進場（`scale(0) rotate(-20deg)` 到原尺寸），中間一層跑 `float` 常駐循環（上下 10px），最內層 `pointer-events-auto touch-none select-none`，`cursor: grab`。
3. **拖動**：拖到哪就停在哪，不回原位；放手後繼續漂浮。拖動中有輕微傾斜。
4. **賣點是素材，不是元件**。互動很薄（拖、漂、彈），真正的價值是 60 張風格一致的手繪圖，以及「給網站個性」這個情緒定位。

## 3. 為什麼值得做，以及不能照抄的地方

值得做的：

- 「個性」是現在 AI 生成網站最缺的東西，和我們 2026-11-06 的去 AI 感分析同一個方向。
- 貼紙是實體紙品，和 SunUI「紙感電商」的語言完全對得上：優惠券、收據、集點卡之後，貼紙是同一個家族。
- 拖動貼紙的手感好玩、好錄影，型錄卡片一拖就懂。

不能照抄的：

- **對方的貼紙圖**：有自己的社群授權與 Art Disclaimer，不使用、不描摹。我們用自己的像素圖示（`sunui-pixel-icons` 的 pigment 色）當示範圖。
- **常駐漂浮與進場彈出**：DESIGN.md 第 4 節禁止進場動畫與常駐循環。我們只在使用者動作時動：撕起、拖動、壓下。
- **純素材庫的商業模式**：免費型錄凍結中（2026-11-06 決定），而且素材庫無法鎖在 Pro 後面。所以我們賣的是「讓任何圖變成貼紙並且能下單」的場景，不是一包圖。

## 4. 我們的版本：sticker-board

### 4.1 核心差異：模切白邊由元件自動生成

對方把白邊畫進每個 SVG；我們用一個 SVG filter 從任何圖的透明度長出白邊：

```
SourceAlpha → feMorphology dilate(outline) → feGaussianBlur(outline/2) → feFuncA discrete(0 1) 門檻
→ feFlood 白色 → feComposite in → 墊在 SourceGraphic 底下
```

膨脹後再模糊、再取門檻，轉角會變圓，像真的刀模。原圖不經過模糊，像素圖示一樣銳利。結果：SVG、`<img>`、像素圖示、emoji 傳進去都會變成貼紙，買家不用請美術重畫白邊。這是整個元件最有彈性的地方，也是對方沒有的。

### 4.2 三種用法，同一個元件

| 用法 | 寫法 | 場景 |
|---|---|---|
| 客製商品 | `sheet`（預設開）、`max`、`summary`、`onSubmit` | 托特包、筆電包、手機殼、筆記本：從貼紙片撕下來貼，加價算進總額，排版跟訂單一起存 |
| 主視覺裝飾 | `sheet={false}` 加 `defaultValue` | 活動頁、首屏、空狀態：貼紙可以推來推去但撕不掉，底下的文字與連結照常可點 |
| 單張靜態 | `<Sticker>` | 插在標題字裡，等於參考網站首屏標題裡的那幾張 |

`children` 就是表面，任何節點都行；位置用 0 到 1 的相對值，任何尺寸排得一樣。`value`、`defaultValue`、`onChange` 可受控或不受控。

### 4.3 動態（只回應動作）

| 時機 | 做法 | 彈簧 |
|---|---|---|
| 撕起 | 從貼紙片上 72% 尺寸放大到 108%，陰影由貼平的細線變成浮起的深陰影 | snappy |
| 拖動 | 依水平速度往前傾，最多 22°，停手 80ms 回正 | snappy |
| 貼下 | 從 108% 回到 100%，stamp 彈簧帶一點壓下去的回彈；每張有固定歪斜角（由 key 雜湊出 -8° 到 8°），重新整理不會跳 | stamp |
| 沒貼到 | 從表面外放手，貼紙滑回貼紙片上它原本的位置 | snappy |
| 撕下 | 已貼上的拖出表面就撕掉，140ms 淡出 | |

減少動態效果時：不傾斜、不浮起，位置直接跳到終點，資訊完全不變。

### 4.4 無障礙與鍵盤

- 貼紙片上每張都是按鈕，點一下或 Enter 就貼在最空的位置（5×4 候選點裡離現有貼紙最遠的一點），焦點移到新貼上的那張。
- 已貼上的貼紙是按鈕：方向鍵移動 2%（Shift 8%），`[` `]` 轉 5°，Delete 撕下並把焦點還給貼紙片。操作說明用 `aria-describedby` 讀出。
- 貼上、撕下、貼滿都在 polite live region 播報。
- 加入購物車成功用 `Stamp` 放在按鈕原位，失敗顯示重試。排版一改，「已加入」就回到可再加入。

### 4.5 實作中踩到的坑

- **拖動時調整疊放順序會讓拖動失效**：一開始在 pointerdown 就把那張移到陣列最後（最上層），React 搬動 DOM 節點時指標捕捉被釋放，pointerup 收不到，貼紙卡在浮起狀態。改成拖動中用 `zIndex` 暫時置頂，放手後才改陣列順序。
- **暗色模式下像素圖的外框不見**：像素圖示的外框用 `currentColor`，暗色模式下墨色變淺，印在白色貼紙上就消失。貼紙面固定用亮色紙的墨色並設 `color-scheme: light`，貼紙在任何主題都像印在白色貼紙上。

## 5. 設計規範對照

| 規則 | 狀態 |
|---|---|
| 不做進場動畫、常駐循環 | 遵守。拿掉了參考的 float 與 pop |
| 只用三種彈簧 | 遵守（snappy、stamp） |
| 不准彩色陰影 | 遵守，陰影全是中性黑 |
| 傾斜 | **刻意例外**：DESIGN.md 禁止的是結果標記（Stamp）傾斜。貼紙是實體物件，歪著貼是它的物理本質；結果仍用直立的 Stamp |
| 顏色只有黑白灰 | 介面元素（貼紙片、結帳列、表面）全是紙與墨；彩色只在買家傳入的貼紙圖上，那是內容不是介面 |
| 結果用 Stamp、放在動作位置 | 遵守 |
| 250 行 | 約 600 行，與其他 Pro 場景（lineup-shelf 425 行）同級，因為包含拖曳、鍵盤、受控狀態與結帳 |

## 6. 分級與後續

- 型錄分級放在 B（免費沒有對應的招牌互動），排在 `lineup-shelf` 後面。和 `peel-sticker-coupon` 是不同機制（那是撕開看底下，這是貼上去），C 組近親規則不適用。
- 四項測試：替代性（市面上的貼紙庫都是素材，沒有「任意圖變貼紙並可下單」的元件）高；建置時間中；離營收近（客製周邊是直接下單場景）；示範價值高（一拖就懂）。
- **可以拆成免費原子**：`Sticker`（靜態模切貼紙）符合凍結期唯一允許的新增方式（從 Pro 場景拆出的原子）。要不要拆由使用者決定，拆的話要補 registry.json、i18n、usage。
