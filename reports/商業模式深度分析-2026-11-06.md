# SunUI 商業模式深度分析

> 2026-11-06。這份不重做市場研究（見 `SunUI 商業化深度規劃.md`、`免費與付費切分規劃-2026-11-05.md`），而是拿那兩份的計畫對照 repo 的實際狀態，回答三個問題：這門生意的結構撐不撐得住、目前的執行有沒有偏、接下來 21 天該做什麼。【已驗證】表示這次直接查 repo 或 GitHub；【延用】引用前兩份報告；【估算】【建議】是推論。

## 0. 結論先講

1. **計畫本身是對的，執行偏掉了。** 定位（電商檔期）、定價（79 / 129 / 349 買斷）、通路（registry 與 agent 內轉換）、切分（方案 C）都合理。但過去三天 70 個 commit 幾乎全部花在免費層，而商業化需要的東西（部署、推送、收款、名單、量測、進索引）一件都還沒完成。離 2026-11-27 Founding 開賣剩 **21 天**。
2. **商業模式的最大結構弱點不是價格，是「一次買斷、沒有回購」。** 一位客戶一生只貢獻約 US$118。解法就在定位裡：電商檔期天生是**有行事曆的需求**，每一檔都要新頁面。把收入從「賣一次授權」改成「授權 + 每檔期一次的季節包」，回購就有了理由。
3. **目標客群要再收窄一次：接案者與小型 agency，不是泛前端開發者。** 他們每年做好幾檔活動頁、願意為省時間付錢、會買 Team。這個客群也決定了 Pro 該做什麼：整頁、整套、可換品牌色的檔期套件，而不是更多單點 block。
4. **免費層已經變成另一個產品。** 動效庫從計畫的 13 組長到 28 組，裡面有絨毛肖像、像素圖示、點雲、等角圖表。它們很適合拍 demo，但吸引的是「看動畫的人」，不是「要做檔期頁的人」。要嘛建一座明確的橋（每個動效都連到一個 Pro 場景），要嘛停手。

【已驗證】11/04 起公開 repo 有 70 個 commit，Pro repo 總共 12 個。最近兩天的主題是 tiny-chart、plush-portrait、像素圖示、pixel-fx、motionsites 九個動效、motion-prompt 系列。用 11/05 報告自己定的四問（可替代性、工時、商業距離、展示力）去套，它們只有「展示力」偏高，「商業距離」全部是遠。

## 2. 商業模式拆解

### 2.1 一頁畫布

| 要素 | 現在的設計 | 評估 |
|---|---|---|
| 客群 | 「寫 React 的電商與行銷頁開發者」 | 太寬，見第 3 節 |
| 價值主張 | 可直接上線的檔期動畫區塊，預設無障礙、CJK、授權清楚 | 對，而且是真空白【延用】 |
| 通路 | X 影片、shadcn 索引、agent 401、Product Hunt | 對，但都還沒啟動 |
| 收入 | 一次買斷 79 / 129 / 349 | 單價合理，**缺回購** |
| 成本 | 每月 US$30 至 60 + 作者時間 | 金錢成本近零，時間成本是全部 |
| 關鍵資產 | 紙感設計語言、四語文案、registry + MCP 基礎建設 | 設計語言是唯一難複製的東西 |
| 護城河 | 無法靠程式碼（agent 可重寫） | 只能靠「整套一致」與持續更新 |

### 2.2 單位經濟【估算】

| 方案 | 售價 | 扣平台與出款（約 8.5%）後 |
|---|---|---|
| Founding | US$79 | 約 US$72 |
| Pro | US$129 | 約 US$118 |
| Team | US$349 | 約 US$319 |

買斷模式下 LTV 就等於第一張單。基準情境一年 160 筆、約 US$1.8 萬【延用】。換成時間來看：11 月到 1 月若投入約 300 小時，以台灣資深接案時薪約 NT$1,500（約 US$47）計，機會成本約 US$1.4 萬。**基準情境下，第一年產品收入大約只打平機會成本**，真正的報酬來自兩件事：它能不能變成可回購的生意，以及它帶來的接案。

### 2.3 三個結構弱點

**弱點一：沒有回購。** Tailwind Plus 的經驗是買斷只能靠新客，改訂閱也救不了，因為客戶拿完就退【延用】。SunUI 不能只賣「現在與未來所有 block」，因為「未來的 block」對已付費者沒有再付一次的理由。

**弱點二：程式碼不是護城河。** 定位本身說「轉換點在 agent 裡」，但同一個 agent 也能在兩分鐘內寫出一張優惠券卡。免費層透過 MCP 把完整原始碼交給 agent，agent 讀完就能仿出 Pro 的「變體」。Agent 做不好的是：一整頁風格一致、倒數在 hydration 與分頁切換時的正確語意、CJK 標點與換行、reduced-motion 的完整替代路徑、四語文案。**Pro 的價值要放在「一致性與正確性的總和」，單個元件撐不起來。**

**弱點三：兩個品牌住在一起。** paper 系列的設計規則禁止漸層、光暈、載入入場與待機迴圈（`DESIGN.md`），動效庫正好全是這些。對買家來說，首頁上一半是紙感電商、一半是點雲與絨毛肖像，看不出這是「做檔期頁的工具」。11/05 已決定首頁每個風格一張卡，方向對，但根本問題是**免費層的重心已經從「電商原子」移到「動效展示」**。

## 3. 客群：該賣給誰

| 客群 | 付費意願 | 回購 | 規模 | 跟 SunUI 的契合 |
|---|---|---|---|---|
| A. 接案者與小型 agency（做檔期頁） | 高，一個案子就回本 | **高**，每年多檔 | 中 | **最高**，Team 方案的天然買家 |
| B. Headless 電商開發者（Shopify Hydrogen、Next.js Commerce、Medusa） | 高 | 中 | 小 | 高，而且 Hydrogen 本身就是 React |
| C. Indie SaaS（定價、升級、結帳頁） | 中 | 低 | 大 | 中，要跟 shadcnblocks 拚量 |
| D. 動效愛好者、設計師 | 低 | 低 | 大 | 只當流量來源 |

【建議】主攻 A，次攻 B，C 用既有 block 組一個「SaaS billing」情境頁順便收（TA 模擬也提過【延用】），D 只用來拍影片。

為什麼是 A：他們的痛點正好是「每一檔都要重做一次倒數、優惠、庫存、加購」，而且有預算週期（客戶付錢）。他們不在乎 SunUI 有幾個 block，在乎的是**收到 brief 到上線能省幾天**。這也是 TA 模擬裡台灣接案者「$79 會買」的原因。

B 值得額外一提：Tailwind Labs 已經加入 Shopify【延用】，Shopify 生態裡寫 React 的 headless 店面開發者，正是「電商 + React + Tailwind」三者交集。這個市場不大，但搜尋意圖精準，做一頁「Hydrogen 上怎麼用 SunUI」的說明成本很低。

## 4. 核心建議：把它變成「檔期行事曆」生意

電商檔期是少見的**有固定日期的需求**。這讓 SunUI 有機會做到一般 UI kit 做不到的事：每一檔都給既有客戶一個再付錢的理由。

### 4.1 收入結構

| 層 | 內容 | 價格【建議】 | 作用 |
|---|---|---|---|
| 免費 | 電商原子 + 動效庫（MIT） | 0 | 被 agent 與搜尋找到 |
| Pro 授權 | 全部 Pro blocks 與基礎模板，終身更新 | US$129（Founding 79） | 主收入，維持不變 |
| Team | 5 席 | US$349 | agency 主力方案 |
| **季節包** | 一檔一套：整頁模板 + 主視覺 + 倒數 + 文案四語 + 品牌色 token | 單售 US$49，**Pro 會員 US$29** | 回購引擎 |
| 客製服務 | 「兩週交一個檔期頁」 | NT$3 萬起 | 第一年最可靠的現金 |

季節包要遵守一條規則：**Pro 授權終身包含所有 blocks，季節包只是「組好的整頁與素材」**。這樣既不違反「所有未來 block 都包含」的承諾，也讓季節包有獨立價值（省的是組裝與文案的時間），對應 11/05 方案 C 的「Pro 賣場景」。

### 4.2 行事曆【估算，日期以 2026 至 2027 年為準】

買家通常在活動前 3 至 6 週開始做頁面，所以**季節包要在檔期前 6 週上架**。

| 檔期 | 活動日 | 季節包上架 | 備註 |
|---|---|---|---|
| 黑五 / Cyber Monday | 2026-11-27 / 11-30 | 已經太晚 | 11/27 開賣 Founding，主打「下一檔」 |
| 雙 12 / 聖誕 | 12-12 / 12-25 | 11 月中 | 若趕得上，可當 Founding 贈品 |
| 農曆新年 | 2027-02-06 | **12 月下旬** | Founding 期間的第一個季節包，PH 發表時可展示 |
| 情人節 | 2027-02-14 | 1 月初 | 英文市場 |
| 618 | 2027-06-18 | 5 月初 | 華語市場 |
| 雙 11 / 黑五 2027 | 2027-11-11 / 11-26 | 9 月底 | 第二年的大檔 |

這張表同時是**內容行事曆**：每個季節包上架就是一輪 X 影片與電子報，比「每週新增 3 個 block」更好講故事。

### 4.3 黑五開賣的訊息要改

在黑五當天賣「檔期區塊」，對需要做黑五頁的人已經來不及。【建議】Founding 的主訊息改成：「現在用 $79 鎖定終身 Pro，第一個農曆新年套件 12 月底送到。」把時間差變成預購的理由。

## 5. 免費層怎麼處理

| 選項 | 做法 | 建議 |
|---|---|---|
| 繼續加動效 | 維持現在的速度 | 不建議，邊際流量遞減，且稀釋定位 |
| 凍結 + 搭橋 | 動效庫凍結在 28；每組在 `meta.usage` 與 block 頁標出「在哪個 Pro 場景裡被用到」 | **建議** |
| 拆品牌 | 動效庫另開 SunUI Motion 子站 | 等有流量數據再決定，現在做是分心 |

搭橋的具體做法：Pro 場景的 block 頁列出它用到的免費元件；免費動效的頁面底部放「看它在雙 11 主視覺裡的樣子」連到 Pro 預覽。這讓「免費越強，Pro 越有說服力」（11/05 方案 C 的邏輯）真的在頁面上發生，而不只是在報告裡。

另外，非動效的免費 block 從 58 長到 74，【建議】重新凍結在現在的數字，新增只限 Pro 場景拆出來的原子。

排序原則：先接通收錢的管道，再補 Pro 內容，最後才是行銷素材。

| 週 | 日期 | 必做 | 完成標準 |

| 1 | 11/06 至 11/12 | 推送 64 個 commit（切分已定案）；買網域並部署；Polar 台灣個人 KYC 實測，同步申請 Dodo；Resend 接上 waitlist；免費 registry 加匿名安裝計數；凍結免費與動效 | 正式網址可裝免費 block；Polar 測試模式能完成一筆購買 |

## Conclusion

SunUI 的計畫已經想清楚「賣什麼、賣多少、在哪裡成交」，真正缺的是兩件事。第一是**接上水管**：部署、推送、收款帳號、名單、量測，這些都是一兩天的工作，卻決定 11/27 能不能收到第一筆錢。第二是**讓客戶有理由再回來**：買斷模式下一位客戶只值一張單，但電商檔期每年有六、七次，季節包把這個行事曆變成回購。產品已經做得夠多了，接下來 21 天的價值，在於讓第一個陌生人付錢。
