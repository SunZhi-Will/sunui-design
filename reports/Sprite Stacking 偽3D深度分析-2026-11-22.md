# Sprite Stacking 偽 3D 深度分析

> 2026-11-22。來源：Daniel White（@dwhitedesign，Attio 的 design engineer）2026-11-20 的貼文，以及他的 repo `danielwh2/sprite-stacking`（MIT）。貼文本身是 37 秒的錄影，x.com 擋自動讀取，影片沒看到；技術拆解根據 repo 的原始碼、SKILL.md 與 pipeline 圖。
> 【已驗證】是這次在瀏覽器實際看過的；【推論】是從程式或文件推回來的；【建議】是判斷。

## 結論先講

1. **技術本身很簡單，值得吸收**：一疊水平切片，每片轉同一個角度、垂直壓扁、往上抬 1 格，由下往上畫。沒有 WebGL、沒有模型檔，一張小圖轉到任何角度都是銳利像素。【已驗證】
2. **SunUI 有現成的原料**：125 個 16 × 16 像素圖示，加上 pigment 色階。原 repo 要畫四張視圖；我們只有正面一張，所以我改成三種「從一張正面長出體積」的方式（擠出、充氣、繞軸），不用多畫任何東西。【已驗證】
3. **能用在 UI/UX 上，但不是每個尺寸都好**：放大到 4 倍以上、在互動的那一刻（hover、拖曳、登場、載入）效果很好；在 16 到 24px 的靜態圖示上，比原本的平面版難讀。所以它是「互動狀態」，不是「取代平面圖示」。【已驗證】
4. **放哪裡**：免費型錄凍結到 2027-01-12，這不能是新的免費 block。最順的路是當 Pro 像素場景的原子（pixel-gacha 開獎、pixel-check-in 簽到獎勵、pixel-preregister 預約獎勵、pixel-boss-sale 掉寶），等之後要開放時再從 Pro 場景抽出來，符合凍結規則的第一條例外。【建議】

樣張：`/preview/sprite-stack-study`（不進導覽、不進 registry）。

## 1. 原作在做什麼

貼文一句話：畫上、側、前、後四張像素視圖，工具把體積雕出來、切片、疊起來，就能轉到任何角度。它是一個 agent skill，給 Claude Code、Codex、Cursor 用。

repo 內容【已驗證】：

| 檔案 | 作用 |
|---|---|
| `SKILL.md`（19KB） | 給 agent 的完整流程與規則，含一張「犯過的錯 → 規則 → 怎麼強制」的 Lessons 表 |
| `scripts/views_to_slices.py`（29KB） | Python + Pillow + NumPy：去背、去外框、統一色盤、visual hull 雕刻、輸出切片條、檢查圖、獨立 viewer |
| `scripts/viewer.html`（100KB） | 軟體光柵化 viewer：轉台、場景、切片掃描、爆炸圖、開車模式、晝夜、雨雪、16 方向輸出 |
| `references/engines.md` | Canvas 2D、Godot、Unity、Phaser 的接法 |

四步驟：

1. **視圖**：上、側、前、後，正交，一列排開。
2. **雕刻**：體素只在四張視圖都蓋到的地方留下（visual hull）。
3. **切片**：體積由地面往上切成一條水平切片。
4. **渲染**：每片旋轉、垂直壓扁（俯角）、往上抬 1px。

值得記下來的渲染規則（他踩過、寫進 Lessons 表的）：

- 旋轉中心用 `(w - 1) / 2` 加最近鄰取樣；用 `floor(w / 2)` 偶數寬度轉 90 度會晃半格。
- 外框整疊描一次，不要每片各描，否則身體裡會出現縫和雜點。
- 先在 1 倍美術解析度畫好，再整數倍放大；連續的動作（浮動、繞圈）保持浮點，最後一次才取整。
- 登場不要淡入，改成切片由下往上冒出來；前沿要推過頂片再多一段，最上面幾片才不會最後一幀跳上去。
- 1px 粗的細部（旗桿、天線）轉的時候會閃爍，至少畫 2px。
- 球體會被壓扁成蛋，要補償；有方向光的球要在渲染時算明暗，不要烘進貼圖。

這張 Lessons 表本身也是好做法：每個錯誤要嘛變成程式裡的防呆，要嘛變成一條規則，跟我們的 DESIGN.md 寫法很像。

## 3. 這次做了什麼【已驗證】

檔案都在 `apps/web/app/(preview)/preview/sprite-stack-study/`：

- `stack-core.ts`：引擎。體素結構、三種成形、四視圖雕刻（`carve`，保留原作的方法給手繪物件用）、平滑法線、逐片反向映射光柵化、地面影子、整疊外框。
- `pixel-stack.tsx`：React 元件 `<PixelStack icon="potion" mode="lathe" behavior="drag" />`。從圖示的 SVG 路徑還原點陣，用瀏覽器算出 pigment 色（`oklch(from var(...))`、`light-dark()` 都能解），畫面外停止 rAF，配色或主題改變時重建，尊重 `prefers-reduced-motion`。
- `study.tsx`、`page.tsx`：七段樣張。

### 3.1 三種成形方式

| 模式 | 做法 | 適合 | 不適合 |
|---|---|---|---|
| slab | 整個形狀往後擠出固定厚度 | 硬幣、盾牌、寶箱、禮物、皇冠、獎盃 | 圓的東西 |
| puff | 依距離邊緣多遠決定厚度，中間厚邊緣薄 | 愛心、史萊姆、星星、寶石、雲 | 有細線的圖示 |
| lathe | 每一列繞垂直軸轉一圈，形狀看半徑、顏色從正面直投 | 藥水、蘑菇、杯子蛋糕、燈籠、珍奶 | 皇冠、獎盃（把手和尖角會轉成碗或圓盤） |

兩個做的過程中修掉的問題，之後若正式做要留著：

- **slab 的側面不能換色**。我原本讓側面用外框色、正反面用圖案，結果俯看時每片只露出約 1 格寬的邊，取樣常落在中間那層，整枚硬幣變成黑的。改成整條擠出同一個顏色就好了。
- **lathe 的顏色要從正面投過來，不能照半徑取**。照半徑取的話，正面中央取到的是那一列最外面的外框格，整個物件變成一團暗色。改成「形狀看半徑、顏色看自己的 x」之後，藥水、蘑菇都讀得出來。

### 3.2 光

光固定在世界座標（左上、偏向鏡頭），法線跟著物件轉，所以轉的時候明暗會流動，這是看起來像 3D 的主要原因。明暗分 4 階（不是連續漸層），像素畫的色階才不會變糊。正對鏡頭的面約等於原本的平面色，背光面約六成。第一版太暗（正面只有八成），跟平面圖示放一起像髒掉，調亮後才對得上。

### 3.3 七個介面用法（都在樣張裡試過）

| # | 用法 | 互動 | 評價 |
|---|---|---|---|
| 01 | 三種成形 | 自轉 | 示範用 |
| 02 | 選單圖示 hover 轉一圈 | 移入或 Tab 聚焦轉 360 度、鏡頭抬一點，900ms 停回 | 好玩，但靜止時在 3 倍大小比平面版難讀；只適合遊戲感的介面 |
| 03 | 商品或獎勵轉台 | 拖曳轉、慣性、上下拖改俯角、閒置自轉、切片間距滑桿 | **最強**，8 倍大小很有質感，切片拉開是很好的「看結構」時刻 |
| 04 | 獎勵登場 | 切片由下往上冒、彈一下、地面波紋，之後可拖 | **很強**，比淡入或縮放有記憶點，直接對應 gacha、開箱 |
| 05 | 載入中的金幣 | 按鈕裡的金幣自己轉 | 小巧、成本低，金幣在 2 倍下讀得出來 |
| 06 | 卡片裡的物件跟游標偏 | 游標位置對應角度與俯角 | 不錯，比整張卡片 3D 傾斜克制 |
| 07 | 爆炸圖 hover | 移入時切片拉開 | 可用，但 16 層的小圖示拉開後資訊不多；手繪的高解析物件會好很多 |

## 4. 能不能用在 UI/UX 上：判斷

**適合的地方**：獎勵、寶物、道具、商品「被拿到」或「被檢視」的那一刻。也就是 Pro 像素場景的高潮點。在這些地方，它比淡入或縮放更有物件感，而且是 SunUI 別家沒有的東西（Magic UI、React Bits 沒有 sprite stacking）。【推論】

**不適合的地方**：

- 一般產品的 UI 圖示（設定、搜尋、選單）。偽 3D 會把介面拉向遊戲風，跟 craft 系列的「質感」方向不合。
- 小於 3 倍（48px）的靜態顯示。厚度只有 1 到 2 格時，側面會吃掉正面的細節。
- 細線條的控制符號（勾、叉、箭頭）。

**跟目前定位的關係**：首頁頭條是質感與動效，商店與活動頁是旗艦。這個技術的位置在「活動頁裡的遊戲化時刻」，跟 Pro 的像素場景是同一條線，不會拉走主軸。

### 階段 2：PH 之後再評估

- 從 Pro 場景抽出 `pixel-stack` 原子給免費版（凍結規則允許從 Pro 場景抽原子）。
- 給 `/icons` 的像素圖示加一個「3D 預覽」切換（只在大圖預覽裡，不改圖示本身）。
- 手繪高解析物件（30 到 50 層）用原作的四視圖雕刻 `carve()`，做季節檔期的主角物件（年節紅包、聖誕禮盒）。

### 不建議做的

- 把原作的 viewer 整套搬進來（場景、開車、天氣）。那是展示用，跟 UI 無關，100KB。
- 用 WebGL 重做。Canvas 2D 軟體光柵在這個尺寸已經夠快，WebGL 只增加複雜度。

## 6. 風險與注意

- **效能**：每幀逐片反向映射。16 × 16 × 16 的物件在 8 倍大小約 50 × 70 美術像素，一幀遠低於 1ms【推論】。一頁很多個時，只有正在互動的那個跑 rAF（樣張已經這樣做：靜止時停、畫面外停）。
- **無障礙**：canvas 沒有語意，要給 `role="img"` 和 `aria-label`（元件有 `label` prop）；hover 的效果要有鍵盤聚焦的對應（02 已做）；`prefers-reduced-motion` 時不自轉、不播登場（已做）。
- **銳利度**：畫布要整數倍放大，CSS 尺寸不能被拉伸。樣張的 canvas 預留了任何俯角的高度，會比物件高；元件已改成物件貼底對齊，多出來的透明空間往上溢出。正式做時應依實際俯角範圍算更緊的尺寸。
- **顏色**：pigment 用 `oklch(from var(...))`，canvas 不能直接讀，元件靠一個隱藏的 span 讓瀏覽器算出顏色再讀回來，換主題時要重算（已做 MutationObserver）。
- **授權**：原作 MIT。這次只參考了渲染規則與 visual hull 的想法，程式是自己寫的；若正式採用，在原始碼註解註明參考來源即可。
