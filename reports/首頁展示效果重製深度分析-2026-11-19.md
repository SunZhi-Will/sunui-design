# 首頁展示效果重製：深度分析

2026-11-19。對象是首頁開場（`apps/web/components/hero-stage.tsx`）。前一版是「標題 + 靜態展示台，手動切分頁」，問題是不夠搶眼：訪客不動手就什麼都看不到。

## 1. 問題出在哪

| 現象 | 原因 |
|---|---|
| 第一眼是靜的 | 區塊的動畫大多要按、要拖才會發生。展示台只是把區塊放進框裡，沒人操作就是一張截圖 |
| 展示台是平的 | 外殼講「物件有厚度」，但首頁最大的物件沒有任何姿態 |
| 進場沒有節奏 | 標題、指令、展示台同一幀出現，沒有先後 |
| 精選區塊偏弱 | 加入購物車按鈕、結帳步驟放進 600px 高的框裡只佔一小塊 |

SunUI 賣的是動效。首頁沒有在動，等於沒有展示產品。

## 2. 查到的做法

- **開場編排**：整段在載入後約 800ms 內發生，每個元素有自己的延遲與時長，順序是背景、標題、次要元素，產品畫面走自己的時間軸。每個網站只挑一招招牌動作，做到位，不疊加。([Hero Choreography](https://brainy.ink/paper/glossary/hero-choreography))
- **產品畫面傾斜**：同一篇整理提到 Linear 的產品截圖會跟著滑鼠傾斜，第一次互動後就關掉；v0 的首頁是真的 iframe 加一支會動的游標。這些是二手整理，沒有官方說明，當作方向參考。
- **腳本化示範**：游標用減速曲線，時長跟距離走（短距離 0.4 到 0.6 秒，跨畫面 0.7 到 1 秒）；按下時游標縮到約 88% 並加漣漪；每個主要動作後要停約 1.4 秒，拿掉停頓觀眾就跟不上；重播前要把狀態還原。缺點是 UI 一改腳本就壞。([Scripted product demos](https://dev.to/vein05/professional-scripted-product-demos-with-gsap-with-claude-32bf))
- **動效基本功**：只動 `transform` 與 `opacity`；動畫要能被打斷；常看到的動畫要短；一定要處理 reduced motion。([Great Animations](https://emilkowal.ski/ui/great-animations))
- **2026 的首頁趨勢**：主視覺從靜態截圖改成嵌入的產品預覽與導覽；同時多篇都提醒清楚比花俏重要，重動畫會拖慢載入。([SaaSFrame](https://www.saasframe.io/blog/10-saas-landing-page-trends-for-2026-with-real-examples)、[Swipe Pages](https://swipepages.com/blog/12-best-saas-landing-page-examples-of-2026/))

## 3. 決定：只演一招，演產品本身

炫的方法很多（粒子、漸層光、滿版 3D），但那些正是 SunUI 說自己不做的東西。所以招牌動作定為：**展示台自己示範**。一支游標在真的區塊裡操作，訪客看到的每個動畫都是買得到的東西。

和一般做法的差別：別人的腳本示範是另外做一套假畫面，UI 改了就要重做。SunUI 的區塊本來就在同源 iframe 裡跑，所以把合成的指標事件直接送進去，跑的是區塊自己的程式。腳本只有幾行選擇器。

| 層 | 做法 | 為什麼 |
|---|---|---|
| 進場 | 標題逐字從模糊浮上來，指令與展示台依序跟上，共約 1.2 秒 | 給第一眼節奏；CSS 動畫，不等 JS |
| 姿態 | 展示台後仰 13°，捲動或伸手就轉正；跟滑鼠微轉；外框 1px 邊緣反光 | 「有厚度的物件」用姿態講，不用陰影堆 |
| 示範 | 游標點按、拖曳、掃過；做完換下一個區塊，圓形揭開 | 不動手也看得到動效 |
| 交棒 | 一碰就停，狀態改成「換你操作」，離開幾秒才接著演 | 示範不能搶使用者的控制權 |

## 4. 精選區塊換成「一個動作就有大變化」的

景深主視覺（掃過有視差）、玻璃方塊主視覺（拖曳轉 3D）、色溫開關（拖色溫）、主題揭幕切換、環繞圖庫（拖曳轉球）、日夜時段主視覺（切日夜）。兩個免費、四個 Pro；Pro 資料夾不在時自動略過。

## 5. 風險與還沒做的

- **腳本會壞**：區塊改了 role 或順序，那一步會找不到元素而略過（不會報錯），示範就變短。重做這六個區塊時要順手看一次首頁。
- **效能**：同時最多兩個 iframe（目前的與預載的下一個），玻璃方塊有 WebGL。低階手機沒有實測。
- **觸控裝置**：景深主視覺的視差只在滑鼠裝置生效，手機上那一段看起來只是游標在移動。
- **深色模式**：這次只在淺色與手機寬度實看過。
- **正式環境**：只在開發伺服器看過，沒有跑 production build。
- 精選區塊本身的畫風還有舊的紙感（日夜時段主視覺的票券按鈕），要等區塊重做。
