# 七個「太普通」的元件：診斷與重做方向

> 2026-11-08。對象：結帳步驟 `checkout-steps`、授權與兌換面板 `redeem-key-input`、人員標籤 `person-chip`、保留倒數 `reservation-timer`、狀態圓點 `status-dot`（以上 Free），評價牆 `testimonial-wall`、電子報訂閱 `newsletter-signup`（以上 Pro）。
> 限制：Free 型錄凍結到 2027-01-12，這次是重做既有元件，不新增 item；props 只增不刪（PORTING.md 第 2 節）。

## 1. 為什麼它們看起來普通

逐一讀過原始碼後，七個元件有同一組病因：

| 病因 | 出現在 | 說明 |
|---|---|---|
| **沒有招牌時刻** | 結帳步驟、保留倒數、狀態圓點 | registry 描述自己寫著「static, nothing animates」。在一個賣「會動的電商元件」的型錄裡，這三個是死的。使用者點開只看到一排字。 |
| **原樣移植，還帶著別人的顏色** | 結帳步驟、保留倒數、兌換面板、人員標籤 | 前兩個還留著 V窩的粉紅棕 token（`#B4586C`、`#FFFDF9`），違反 PORTING 3.1 的粉色禁令；兌換面板預設 KapZoom 黃；人員標籤用 Tailwind 八色粉彩盤。四個元件四種色系，放進黑白灰型錄裡像外來物，也正是「模板感」的來源。 |
| **資訊太薄** | 全部 | 步驟只有名稱，不知道前面選了什麼；倒數只有數字，不知道保留的是什麼；狀態點沒有時間也沒有歷程；評價只有引言，看不出可不可信。普通的根本原因不是動畫少，是**每個元件只回答了一半的問題**。 |
| **裝飾代替想法** | 評價牆 | 剪報的固定小角度傾斜是 scrapbook 模板的招牌，DESIGN.md 已把傾斜列為 AI 樣貌；註解還寫著已廢止的「朱紅小印」。 |
| **招牌時刻太小** | 電子報 | 明信片概念是好的，但唯一的事件是蓋郵戳。訂閱之後真正讓人在意的事（多久寄一次、下一期何時到、要不要去收信確認）都沒說。 |

結論：重做的重點不是加特效，而是**讓每個元件多回答一個真實問題，再把那個答案變成唯一的招牌動態**。動態仍守 DESIGN.md 第 4 節：只回應動作或資料改變、同一外框變形、錨點不動、400ms 以內、reduced motion 立即切換。

## 2. 參考了什麼

網路研究看過的來源（完整清單見本節末）。對這次最有用的三條原則：

1. **移動元素，不要複製元素**。Family 錢包的卡片在畫面之間移動而不是重畫一張，按鈕變形成托盤再變回來（benji.org/family-values）。這就是 DESIGN.md 的「同一外框變形」，已有成熟產品驗證。
2. **少見的動作才動，頻繁的不動**。鍵盤操作不加動畫，介面動態 300ms 以內（Emil Kowalski, emilkowal.ski/ui/you-dont-need-animations）。
3. **只在狀態真的改變時更新**。Vercel Geist 的狀態點只在 QUEUED、BUILDING 時動，到了終態就靜止，輪詢沒變就不重畫（vercel.com/geist/status-dot）。

要避開的套路：數字圓圈加填滿的連線（步驟）、每格一個框的 OTP 式金鑰輸入、翻牌鐘與消失中的圓環（倒數，21st.dev 已有大量同款）、每個點都在 ping（狀態）、無限跑馬燈加邊緣漸層（評價）、彩帶與「No spam, ever 🔒」（電子報）。另外消費者團體已把 Ticketmaster 式的角落紅色倒數列為暗黑模式，保留倒數必須冷靜。

來源：benji.org/family-values、rauno.me/craft/interaction-design、emilkowal.ski、vercel.com/geist/status-dot、raycast.com（以上實際開啟）；consumer.org.nz 暗黑模式文章、help.ticketmaster.co.uk 保留時間說明、Nothing Glyph Timer、SAP Fiori status indicator、Figma ActiveUser API、framer.com envelope form、github.com/barvian/number-flow（以上僅見搜尋結果）。

## 3. 重做方向：每個元件多回答一個問題

| 元件 | 原本只回答 | 多回答的問題 | 招牌動態（唯一一個） |
|---|---|---|---|
| 結帳步驟 | 現在第幾步 | **前面我選了什麼？** | 完成的步驟收合成一行答案（「7-11 取貨」「Visa ·· 42」），可點回去改；目前步驟展開成帶名稱的膠囊，未來步驟只剩細刻度。換步時同一條軌道變形，墨線推進。手機收成「2/4 付款」。 |
| 狀態圓點 | 什麼狀態 | **進行到哪、多久以前？** | 形狀表達進度，不靠顏色：空環＝待處理、半圓＝處理中、實心＝完成、斜線環＝取消。只有進行中的點在動（Geist 原則），狀態改變時扇形就地填到新的量、文字滾動換字。可附「· 2 小時前」。 |
| 保留倒數 | 還剩幾秒 | **保留的是什麼、到期會怎樣？** | 絕對時間優先（「保留到 18:30」），精度隨剩餘時間誠實提升：一小時以上只顯示時刻，一小時內顯示分鐘，最後五分鐘才出現秒。一排墨點隨時間逐顆熄滅（Nothing Glyph 的語言）。到期時同一張票變形：時刻劃線、`Stamp` 作廢「已釋出」、商品回到庫存的說明。可選一次性的延長。 |
| 人員標籤 | 這是誰 | **哪些人、還有幾個沒顯示？** | 識別色改成同明度低彩度的 OKLCH 色相（不再是 Tailwind 粉彩盤），淺深色一致。新增群組：超出的人收成「+3」，點開時人名從那顆標籤裡滑出，選取外框在標籤之間滑動而不是各自切換。 |
| 授權與兌換面板 | 金鑰對不對 | **我打到哪了、啟用後我有什麼？** | 輸入時自動分組，每組湊滿且格式正確才「落座」；即時判斷是兌換碼還是授權金鑰並改寫標籤。啟用成功時輸入列變形成授權卡，金鑰縮成遮罩過的存根留在卡上當錨點。預設強調色從 KapZoom 黃改為中性墨色。 |
| 評價牆（Pro） | 別人說好 | **這些評價可信嗎？** | 頂部是星等分佈（墨色長條），本身就是篩選器：點「3 星」牆面以版面動畫重排，總數與平均數滾動。每則評價附買了什麼、用了多久、是否驗證購買；點開一則在原位展開店家回覆（深入層）。拿掉傾斜。 |
| 電子報訂閱（Pro） | 訂閱成功了 | **多久寄一次、下一步要做什麼？** | 明信片右半是最近三期的主旨堆疊（先看再訂）。送出後按鈕與欄位在原位變成確認行：「確認信已寄到 a•••@studio.tw」，依網域提供「開啟 Gmail」，重寄有冷卻倒數；主旨堆疊頂端滑入「下一期 11/12（四）」。訂閱人數加一並滾動。 |

## 4. 共通規則

- 顏色全部回到 shadcn token 與墨色；V窩、KapZoom 的品牌色只能透過 `accent` 或 CSS 變數開回來。
- 只依賴 `framer-motion` 與 `cn`，彈簧與 `roll`、`useShake` 從 `sunui-motion` 的同一組數值來。
- props 只增不刪：舊的安裝不會壞。新增的都是可選欄位（`summaries`、`onStepClick`、`since`、`live`、`item`、`onExtend`、`max` 等）。
- reduced motion：所有變形改為立即切換，倒數照常更新但不滾動。


## 5. 預覽要自己演：自動填寫與播放（2026-11-08 追加）

### 問題

重做後的招牌動態幾乎都要**使用者先動手**才看得到：兌換面板要打 32 碼、電子報要填信箱、人員標籤要點「+4」、評價牆要點星等。實測時連我自己都要查 demo 碼才能操作。型錄訪客不會這樣做，他們看三秒就走，所以等於沒做。預覽的目的是「方便使用者看懂」，不是讓使用者測試。

### 做法：一次性的劇本，不是循環動畫

| 原則 | 理由 |
|---|---|
| **進到畫面才開始，播一次停在最終狀態** | 符合 DESIGN.md「不做常駐循環」。網站工具列的「重播」會重新載入 iframe，等於從頭再演一次，不需要自己做循環 |
| **離開畫面或分頁隱藏就暫停** | DESIGN-product 第 4.3 條。暫停是暫停計時，回來從原處繼續 |
| **使用者一碰就交還控制權** | 在預覽區內按下滑鼠或鍵盤（`isTrusted` 事件）就中止劇本、收起游標，不會跟使用者搶 |
| **假游標只是指路** | 一個中性灰箭頭滑到目標再按下，告訴訪客「這裡可以點」。真正的變化仍由元件本身演出，游標不加特效 |
| **打字要像人** | 逐字輸入，每字約 45 到 70ms 帶一點隨機；貼上類動作一次填滿。兌換碼逐字打才能看到分組逐組「落座」 |
| **劇本走元件的真實路徑** | 用原生 input 事件填值、`click()` 觸發按鈕，元件不需要為 demo 加任何 prop 或 data 屬性，安裝到別人專案的程式碼完全不變 |
| **減少動態** | 不顯示游標移動，文字一次填入，狀態照順序切換，資訊不缺 |

共用的驅動放在 `apps/web/lib/demo-autoplay.tsx`（跟 `demo-locale` 一樣只給網站預覽用，不進 registry）。

### 七個劇本

| 元件 | 劇本（約 6 到 12 秒） | 要讓人看到的 |
|---|---|---|
| 結帳步驟 | 從「確認訂單」開始，按主按鈕兩次推進到「付款」；再點已完成的「7-11 取貨」回到配送，又按下一步回來 | 答案一格格留下來、可以點回去改 |
| 狀態圓點 | #1043 處理中 → 已出貨；#1044 等待付款 → 處理中（開始動） | 形狀就地填滿、只有進行中的在動 |
| 保留倒數 | 剩 4 分多鐘時游標按「延長 5 分鐘」 | 分鐘滾動、秒數因為超過 5 分鐘而收起：精度跟著剩餘時間變 |
| 人員標籤 | 點「+4」展開，選「雅婷」，再點「收合」 | 人從 +4 滑出、選取框移動、收合後選中的人仍留著 |
| 兌換面板 | 先打錯一組兌換碼被退回（搖一下），全選後逐字打 Pro 金鑰，按啟用 | 分組落座、偵測標籤、錯誤怎麼說、成功時輸入列變成授權卡 |
| 評價牆 | 點「2 星」篩選，展開店家回覆，再點「顯示全部」 | 牆面重排、差評也有誠實回覆 |
| 電子報 | 點欄位、打 Gmail 信箱、按訂閱 | 原位變成確認行、開啟 Gmail、下一期滑進主旨堆疊、讀者數加一 |

### 實作備註

- Pro 區塊在網站上載入的是展示版 `preview.tsx`（避免 Pro 原始碼進公開 chunk），所以劇本同時加在 `demo.tsx` 與 `preview.tsx`。電子報的展示版原本停在舊設計，已依新版重寫（寫死的烘豆坊內容，沒有 props API），`campaign-landing` 引用的 `ShowcaseNewsletterSignup` 介面不變。
- 比視窗高的區塊（評價牆）用「看得見的高度達到自身 35% 或視窗一半」判斷是否在畫面上，固定比例永遠達不到。
- 計時用 setTimeout 而不是 requestAnimationFrame，背景時 rAF 會被降頻導致打字節奏錯亂。
