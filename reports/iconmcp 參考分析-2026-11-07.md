# iconmcp.com 參考分析

> 日期：2026-11-07
> 對象：https://iconmcp.com/?set=files （Files & data 組，192 個圖示），以及它的 MCP 伺服器 `https://iconmcp.com/mcp`
> 目的：看它哪些做法能放進 SunUI 圖示系統（`apps/web/ICONS.md`、四套 `registry/icons/*`、`/icons`、SunUI MCP），並實作。

## 一句話結論

IconMCP 的賣點不是圖示本身，而是「**agent 用意思找圖示，拿到能直接貼的程式碼**」。SunUI 已經有 MCP 伺服器和 186 個圖示，卻沒有把兩者接起來：agent 做 block 時仍然自己畫 SVG，正是 ICONS.md 開頭盤點出的「同一圖示重畫 12 份」問題來源。所以這次只搬一件事：**在 SunUI MCP 加上 `search_icons` 與 `get_icon`**，再把展示頁補上它的幾個小功能。全自動 agent 畫圖、請求、回報、修圖那一整套不搬。

---

## 1. 它是什麼

| 項目 | 內容 |
|---|---|
| 規模 | 6,955 個圖示、58 組，目標 100,000（含動態） |
| 風格 | 16 單位網格，outline、solid、duotone 三種；預設線寬 1.25px、圓角 2 |
| 授權 | MIT |
| 製作方式 | 「Built by agents, for agents」：一群 AI agent 全天候修圖與畫新圖，頁面上游標旁的名字（Pax、Ada、Juno…「refining Sync mail」）就是正在工作的 agent。每次改動先過自動檢查，再由獨立的 judge 盲比才上線 |
| 入口 | 網站（分組瀏覽、搜尋、單圖面板）＋ MCP 伺服器（Streamable HTTP，無需金鑰） |

## 2. 網站

### 2.1 版面

- 一頁捲到底，每組一個大標題（「Files & data 192」），組內再分小類（Files 62、Folders 31、Documents…）。捲動時網址的 `?set=` 跟著換，任何位置都能分享。
- 圖示格子沒有框、沒有名稱，只有圖示本身，密度很高。新圖示右上角有一個藍點。
- 底部浮動工具列：目前所在組別、搜尋（⌘K）、outline / solid 切換、外觀設定（線寬、圓角）。
- 右上：Use in your agent、Request an icon、Leaderboard（agent 排行）、Stats、About。

### 2.2 單圖面板（`?set=files&icon=file-audio`）

| 區塊 | 內容 |
|---|---|
| 大圖 | 放大顯示，可疊 Grid（網格）、Keylines（圓與方的基準框）、Padding |
| 名稱 | 顯示名稱「Audio file」與程式名稱 `file-audio` |
| 風格 | Outline / Solid |
| 尺寸 | 滑桿與 16、20、24、32、48 刻度，旁邊即時預覽 |
| 取用 | Copy SVG（主按鈕）、Copy JSX、下載 SVG、下載 PNG、展開 SVG code / JSX code |
| 標籤 | music、sound、mp3、track |
| 相關 | 同類的其他圖示 |
| 回報 | 右上旗子 |

## 3. MCP 伺服器

`initialize` 回傳的 instructions 寫得很清楚：先 `search_icons`，選一個名稱，再 `get_icon`；找不到才 `request_icon`。

| 工具 | 唯讀 | 重點 |
|---|---|---|
| `search_icons` | 是 | 用意思找（「failed payment」「dark mode toggle」）。比對名稱、標籤、同義詞，**容忍錯字與複數**，**原型排在變體前**（bell 先於 bell-lock）。回傳 `weak: true` 代表沒有一個圖示同時符合所有字 |
| `get_icon` | 是 | 回傳獨立 SVG 或 TSX 元件。可調 style、size、stroke、radius、color，由網站同一個渲染器產生 |
| `list_sets` / `get_set` | 是 | 列出分組與分類計數；分頁取出一組 |
| `request_icon` | 否 | 請 agent 畫缺的圖示，通常一天內。描述寫明「只在搜尋兩次都找不到時用」 |
| `report_icon` | 否 | 回報具體問題，原因是固定列舉（meaning、name、broken、similar、style…），不收品味意見 |
| `fix_icon` | 否 | 提交自己畫的版本，judge 盲比勝出才上線。附上完整畫圖規則：16 網格、1 單位留白、線寬 1.25、圓頭圓角、只准用 path/line/circle/rect 等元素 |

實測：

- `search_icons("pdf documnts")`：打錯字仍回傳 `file-pdf` 第一名，`matchedAllWords: true`。
- `get_icon("file", format: "jsx")`：回傳 `export function File({ size = 24, ...props })`，`strokeWidth` 已換算成 16 網格下的值（0.833）。
- duotone 是在外框下面多一層同形狀、`#2D68FF` 22% 的填色。

### 3.1 值得學的寫法

1. **工具描述就是使用說明**：每個工具都寫了「什麼時候用、什麼時候不要用」與範例查詢，agent 不必讀文件。
2. **找不到時的出路**：未知名稱回傳最接近的幾個；`weak` 旗標讓 agent 知道該換說法，而不是硬用第一名。
3. **排序的小規則**：原型優先於變體，避免 agent 拿到 `bell-lock` 當鈴鐺。
4. **一個渲染器**：網站與 MCP 輸出同一份，不會出現網站看到的和 agent 拿到的不一樣。

## 4. 和 SunUI 對照

| 面向 | IconMCP | SunUI 現況（實作前） |
|---|---|---|
| 圖示數 | 6,955 | 線條 97、像素 89 |
| 定位 | 通用圖示庫 | 給自家 block 用的招牌圖示（紙品、集點、像素遊戲） |
| 動態 | 目標裡有，尚未見到 | 線條 47、像素 68 個動態版 |
| 網站搜尋 | 錯字、複數、同義詞 | 子字串比對名稱與關鍵字，46 個圖示沒有關鍵字 |
| 單圖面板 | 網格疊圖、尺寸、Copy SVG/JSX、下載、標籤、相關 | 尺寸對照、Copy SVG/JSX |
| 分享連結 | `?set=&icon=` | 沒有 |
| MCP | search / get / list / request / report / fix | 只有 block 工具，**沒有圖示工具** |
| 製作 | 全自動 agent + judge | 人工設計 + `check-icons.mjs` 自檢 |

結論很直接：SunUI 圖示的品質、動態、招牌性都不輸，缺的是 agent 拿得到。

## 5. 決定

### 5.1 做

| 項目 | 理由 |
|---|---|
| MCP `search_icons` | agent 做 block 或幫使用者組頁面時，先找現成圖示，不再自己畫 |
| MCP `get_icon`（SVG / TSX） | block 規定單一檔案、不依賴圖示庫，所以要能拿到可貼的獨立 SVG；同時附上整套安裝指令給要用很多圖示的專案 |
| 搜尋：複數、一個錯字、原型優先、`weak` 旗標 | 照抄它的排序規則，成本低效果大 |
| 補齊 46 個圖示的關鍵字（中英） | 搜尋只靠名稱與關鍵字，沒有關鍵字的圖示等於找不到 |
| 展示頁：`?icon=` 分享連結、網格線、下載 SVG、標籤、相關 | 都是小改動，網格線特別適合 SunUI，因為 ICONS.md 本來就有明確的 3 到 21 內容區與圓 8.5、方 7 |
| skill、llms.txt、文件頁加上新工具；skill 的「Do not」加一條「先 search_icons 再畫」 | 工具要被知道才會被用 |

### 5.2 不做

| 項目 | 理由 |
|---|---|
| `request_icon`、`report_icon`、`fix_icon` | 需要寫入、佇列、審核與防濫用；SunUI MCP 刻意唯讀、免授權。SunUI 的圖示量小、靠人工設計，回饋走 GitHub issue 即可 |
| 全自動 agent 畫圖 | 和 SunUI「招牌物件要有實體細節」的方向相反；量不是 SunUI 的賣點 |
| solid、duotone 風格 | duotone 的藍色填色違反 DESIGN.md（無漸層、一個 accent）；SunUI 已用「一處 accent 部位」與像素 pigment 處理顏色 |
| radius 參數 | SunUI 圖示的圓角是造型的一部分（票券缺口、印章），不開放調整 |
| PNG 下載 | 用途少，SVG 就夠；之後有需求再加 |
| 大量擴充圖示 | 免費目錄凍結到 2027-01-12；圖示庫本身也不追數量 |
| 頁面上的 agent 游標 | 那是它的故事（自動化圖示庫），不是 SunUI 的 |

## 6. 實作內容

| 檔案 | 改動 |
|---|---|
| `apps/web/lib/agent/icons.ts` | 新增。圖示索引（線條＋像素，分組與關鍵字取自 `lib/icon-groups.ts`）、搜尋（複數去尾、編輯距離 1 的錯字、CJK 關鍵字比對、原型優先、同名合併線條與像素）、字串渲染器（SVG 與 TSX，直接讀 `registry/icons` 的幾何，像素 pigment 沿用元件的色階） |
| `apps/web/app/mcp/route.ts` | 新增 `search_icons`、`get_icon` 兩個唯讀工具；伺服器 instructions 加一句「圖示用 search_icons 與 get_icon，不要自己畫」 |
| `apps/web/components/icon-gallery.tsx` | `?icon=<name>&style=pixel` 讀寫網址；預覽放大到 128px 並可開網格線；下載 SVG；關鍵字標籤（按下即搜尋）；同組相關圖示 |
| `apps/web/lib/icon-groups.ts` | 補 46 個圖示的關鍵字 |
| `apps/web/lib/messages.ts` | 四語系：下載 SVG、網格線、標籤、相關圖示；文件頁 MCP 工具清單加一行 |
| `apps/web/lib/agent/skill.ts`、`app/llms.txt/route.ts` | 列出新工具；skill 的 Do not 加一條 |
| `apps/web/ICONS.md` | 新增「給 agent：MCP 與網址」一節 |

### 6.1 實測（本機 dev server）

| 呼叫 | 結果 |
|---|---|
| `search_icons("coupons")` | coupon（line + pixel）第一，scissors 第二 |
| `search_icons("stamp")` | stamp 排在 stamp-check、stamp-tool 前 |
| `search_icons("reciept")` | receipt，標為 weak（錯字只給低分，agent 會知道要確認） |
| `search_icons("印章")` | stamp |
| `search_icons("free shipping")` | weak，truck 第一 |
| `search_icons({})` | 列出 11 個分組與數量 |
| `get_icon("coupon", format: "tsx")` | `export function CouponIcon(...)`，accent 部位保留 `var(--sunui-icon-accent, currentColor)` |
| `get_icon("potion", style: "pixel", tone: "pigment")` | 獨立 SVG，本色色階已代入，不依賴 CSS 變數 |
| `get_icon("sword")` | 錯誤：提示它是像素圖示，改傳 `style: "pixel"` |
| `get_icon("cupon")` | 錯誤：Closest: coupon, scissors |

## 7. 之後可以考慮

1. 新增圖示時，自檢腳本順便檢查「有沒有關鍵字」，避免又出現找不到的圖示。
2. 若 Pro 場景之後做出新的招牌圖示（例如節慶包），同樣放進索引，agent 搜尋時就能看到並導向 Pro。
3. 觀察 MCP 日誌裡 `search_icons` 的 weak 查詢，那就是最該補的圖示清單，等於 IconMCP 的 `request_icon` 但不需要寫入。
