# 為什麼 SunUI 建立在 shadcn 上：深度分析

日期：2026-11-22。起因：使用者問「為什麼要建立在 shadcn 上？」。決定本身是 2026-11-04 重整成 `apps/web` 與 registry 時做的，理由散在〈SunUI 商業化深度規劃〉與〈免費與付費切分規劃-2026-11-05〉，這份把它整理成一份，並用現在的程式碼驗證。

## 1. 結論

**SunUI 不是「用 shadcn 元件做的」，而是「透過 shadcn 發佈的」。** 量過程式碼：114 個免費、95 個 Pro 區塊裡，沒有任何一個 import shadcn 的 Button、Dialog 或 Radix。對 shadcn 的依賴只有三條細線：

1. **發佈協定**：registry JSON 格式加 `npx shadcn add`。
2. **主題 token**：`bg-card`、`text-muted-foreground`、`bg-primary` 這些 CSS 變數。
3. **`cn` 工具函式**：每個 item 唯一的共同依賴 `utils`。

所以真正要回答的問題是「為什麼用 shadcn 當通路與交付格式」。答案是：它同時解決了交付、主題、AI 通路、收費四件事，而且耦合薄到隨時可以抽身。這個選擇是對的。但有一件早該做的事一直沒做：**SunUI 還不在 shadcn 官方索引裡**（今天查 593 個 registry，沒有 SunUI）。

## 2. 實際依賴有多深（2026-11-22 量測）

| 項目 | Free（114） | Pro（95） |
|---|---|---|
| `registryDependencies` 含 `utils` | 114 | 95 |
| 依賴 SunUI 自己的元件（stamp、sunui-motion、social-button 等） | 16 次 | 61 次 |
| 依賴 shadcn 官方元件（button、dialog…） | 0 | 0 |
| npm 依賴 | 只有 `framer-motion`（101 個） | 只有 `framer-motion`（94 個） |
| 使用 Radix 或 Base UI | 0 | 0 |
| 元件主檔使用 shadcn 主題 token | 89 / 113 | 未逐一量 |

區塊之間的 import 全部指向 SunUI 自己的東西（`@/components/ui/stamp` 98 次最多）。換句話說，SunUI 是一套**自成一格的設計系統**，借用 shadcn 的「水管」把原始碼送到使用者專案裡。

## 3. 為什麼選它：五個理由

### 3.1 交付模型：給原始碼，不給黑盒子

舊 SunUI 是 npm 套件（`@sunui-design/react`），走過一次就知道問題在哪（見〈經典SunUI元件深度分析-2026-11-21〉）：

- **只能靠 props 客製**：舊 SidePanel 有 37 個 props，仍然改不到使用者真正想改的地方。
- **主題要自己做一套**：舊套件每個元件都內建 violet、cyan、orange 主題，跟使用者的品牌永遠對不上。
- **動效改不動**：彈簧參數、時間點寫死在套件裡。

registry 模式把原始碼複製進使用者專案，裝完就是他自己的檔案。對「動效與質感」這種需要微調的產品，這是決定性的差別：買家可以改一個彈簧值、換一張圖，不必等我們出新版本。

### 3.2 主題相容：裝進任何專案都成立

shadcn 的 token 已經是 React + Tailwind 社群事實上的主題介面。SunUI 的區塊讀 `--card`、`--primary`，所以裝進任何 shadcn 專案，深淺色與品牌色自動對上。「一處品牌色 `--sunui-spot`，回退到 `--primary`」這個設計（DESIGN.md 第 1 節）就是建立在這個基礎上。

### 3.3 通路：AI agent 會直接從 registry 安裝

這是最重要的理由，也是 2026 年才成立的理由：

- Tailwind Labs 的教訓：AI 直接回答與生成程式碼後，開發者不進網站，文件流量降約 40%、營收降約 80%。**失靈的是「靠網站導購」的漏斗，不是需求。**
- 同期 registry 原生的賣家（shadcnblocks）在成長。
- shadcn MCP 讓 Claude Code、Cursor、VS Code、Codex 能用自然語言搜尋並安裝任何 registry。

所以 registry 本身就是通路：使用者對 agent 說「做一個雙十一活動頁」，agent 透過 shadcn MCP 找到並裝上 SunUI。SunUI 自己的 `/mcp`、`llms.txt`、skill 都疊在這條路上。

### 3.4 收費機制是原生的

shadcn CLI 支援在 `components.json` 用 namespace 加 `headers` 帶授權碼，伺服器回 401 或 403 時 CLI 會顯示我們寫的訊息。SunUI Pro 直接用這個機制（`@sunui-pro` 加 `Authorization: Bearer ${SUNUI_LICENSE_KEY}`）。不必自己做安裝 CLI、帳號系統或私有 npm registry，付費安裝和免費安裝是同一個指令。

### 3.5 零教育成本

React + Tailwind + Motion 是主流（React 19 約 75%、Tailwind 4 約 73% 的下載量；framer-motion 近 30 日 2 億次）。目標買家已經會用，不用學新東西。

## 4. 代價與風險

| 代價 | 說明 | 現在的對策 |
|---|---|---|
| **技術上零差異** | 所有競品都是 React + Tailwind + Motion + shadcn registry。付費區塊市場進入數量軍備競賽：shadcnblocks 2,467+ 個 Pro blocks | 不拚數量，拚「質感 + 動效」與組好的場景（選項 C） |
| **原始碼交出去就收不回** | 買家裝完就有完整原始碼，可以轉貼、餵給 AI 蒸餾 | 授權條款禁止轉售；檔頭寫授權 ID 可追溯；價值放在持續更新與季節包（〈Pro 內容防 AI 蒸餾分析〉） |
| **沒有更新管道** | 複製進去的程式碼不會自動更新，修了 bug 使用者也拿不到 | shadcn CLI v4 有 `--diff`，可以比對差異；目前 SunUI 沒有主動通知更新的機制 |
| **平台風險** | 協定由 shadcn（Vercel 生態）決定。2026-07 預設 primitive 從 Radix 換成 Base UI 就是例子 | 耦合很薄：不用 shadcn 元件、不綁 Radix 或 Base UI，協定變了只影響交付層 |
| **受眾限縮** | 只服務 React + Tailwind，Vue、Svelte、純 HTML 使用者裝不了 | 刻意的取捨：這群人最大，也最會付錢買區塊 |
| **安裝前要先 init** | 沒用過 shadcn 的專案要先跑 `npx shadcn init` | 文件第一步就寫；未來可在 401 與文件裡再講一次 |

## 5. 其他做法比較

| 做法 | 優點 | 為什麼不選 |
|---|---|---|
| npm 套件（舊 SunUI） | 安裝熟悉、版本好管理 | 客製只能靠 props，主題對不上，動效改不動；每月約 300 次下載多半是連帶安裝與鏡像站 |
| 自建 CLI | 完全自主 | 要自己做安裝、授權、相依解析，AI agent 也不認得；shadcn 已經免費提供 |
| 範本或 Figma 檔 | 設計師好用 | 開發者還要自己寫，動效無法交付 |
| Web Components | 跨框架 | 跟 Tailwind 主題、React 生態都隔一層，動效庫要重寫 |

## 6. 判斷：選對了，而且要維持「薄耦合」

shadcn 對 SunUI 的價值在通路與交付格式，不在元件。這個分工是健康的：

- **繼續不依賴 shadcn 的元件與 primitive。** 需要對話框、選單時自己做，或只依賴瀏覽器原生行為。這樣 shadcn 換 primitive、改樣式時，SunUI 不受影響。
- **主題 token 是唯一的「深綁定」，值得保留。** 它就是讓區塊吃買家主題的那層。
- **協定若有一天被取代，換交付層就好。** 區塊原始碼本身只依賴 React、Tailwind 與 framer-motion。

## 7. 建議動作

| # | 動作 | 為什麼 |
|---|---|---|
| 1 | **提交 `@sunui` 到 shadcn 官方索引** | 11-06 就排在第 2 週，至今沒做。索引裡有 593 個 registry，`shadcn search` 與 agent 都會查它，沒列進去等於通路少一半。要先確認收錄條件（開源、公開、registry 結構、通過 `validate:registries`），再到 shadcn-ui/ui 開 PR |
| 2 | 免費 registry 加安裝紀錄 | 〈免費與付費切分規劃〉第 128 行指出 `/r/` 沒有任何紀錄，不知道哪些區塊真的被裝 |
| 3 | 給已安裝的人一條更新路 | 在 changelog 或區塊頁標出「這版修了什麼」，教使用者用 `npx shadcn add --diff` 比對 |
| 4 | 寫進 AGENTS.md：不依賴 shadcn 官方元件與 Radix、Base UI | 把「薄耦合」從默契變成規則 |

第 1 項是對外的動作（在 shadcn-ui/ui 開 PR），需要使用者決定時機。
