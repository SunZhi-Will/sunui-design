## 2. 拆解：它到底在說什麼

1. **敘事是「迭代」，不是「生成」**。線框不是載入骨架，而是「第一版」。中間每一站都有一處被改（側欄分組、面板樣式、間距），最後才上色。整支影片在回應「AI 做的東西都很像」：差別在後面那幾輪修整。
2. **紅線是可信度的來源**。數字標籤（32、48、88）讓觀眾相信每個間距都是被決定過的，而不是隨便排。這是設計師交付（handoff）的語言，工程師與設計師一看就懂。
3. **鏡頭在講重點**。推近、拉遠、平移，等於旁白說「看這裡」。沒有鏡頭，紅線只是一張很吵的截圖。
4. **掃描揭露是收尾的爽點**。前面 20 秒都是灰的，最後 2 秒一次給顏色，對比強、適合剪成短片。
5. **它是一支影片**。要做 After Effects 或 Figma 原型錄影，每改一次設計就要重錄。這是我們能做得比它好的地方。

## 3. 為什麼值得做，以及要避開的地方

值得做：

- **對準 SunUI 的新客群**。2026-11-06 的商業分析把接案設計師與工作室列為主要客群，他們的作品頁最需要「我做得很細」的證明。這個元件就是作品頁上的案例展示。
- **「去 AI 感」同一條線**。和 2026-11-06 的黑白灰去 AI 感分析同方向：把修整過程攤開，本身就是反 slop 的宣言。
- **免費層沒有對應品**。`self-building-page` 是游標群施工（AI 蓋頁面），`depth-hero`、`text-effects` 是視覺特效，沒有一個在講「設計迭代」。通過四項測試：替代性低（市面上是影片）、製作時間長（線框生成、量測、鏡頭、掃描）、離營收近（作品頁與上市頁）、示範價值高（型錄卡片一看就懂）。
- **免費型錄凍結中**（2026-11-06 決定），所以做成 Pro。

要避開：

- **對方的畫面與產品**：工作流程建構器、Warm Site Visitors、它的側欄與節點設計都不用。示範改成陶器店商店編輯器，跟 SunUI 的電商定位一致。
- **影片做法**：我們不錄影。線框、紅線、鏡頭全部即時從 DOM 算出來，換掉介面就自動跟著變。

## 4. 我們的版本：redline-reveal

### 4.1 核心差異：線框與紅線從真實 DOM 長出來

對方每一格都是手工動畫；我們包住任何真實介面：

```
真實介面（React）
  ├─ cloneNode 一份靜態 DOM：保留框線、底色、圓角，文字設成透明、圖片與圖示隱藏、整層去飽和
  ├─ TreeWalker 走過每個文字節點，Range.getClientRects() 拿到每一行的位置 → 一行一條灰色長條（行高 46%，置中）
  ├─ img / svg / video / canvas / [data-wire=block] → 灰色方塊
  └─ data-spec 標記的容器 → 量直接子元素：間距（gaps）、列高（rows）或只量外框（box）
```

買家不用畫線框、不用算數字。介面改了，線框與紅線自己跟著改。

### 4.2 迭代：children 可以是草稿的函式

```tsx
<RedlineReveal stops={[{ target: "nav", measure: "rows", draft: 1 }, ...]}>
  {({ draft }) => <Editor rowHeight={draft >= 1 ? 32 : 26} />}
</RedlineReveal>
```

停在某一站時先量一次（第一版），停留後切到下一版、重量一次，標籤顯示「26→32」、外框顯示「185 × 208 → 185 × 256」。這是影片「側欄改版」那一段的可程式化版本，也是整個元件的賣點：**每一站都是一個看得到的設計決定**。

### 4.3 鏡頭與尺規

| 項目 | 做法 |
|---|---|
| 鏡頭 | 內容以 `canvasWidth` 排版，整層 `translate + scale`。飛行時縮放走對數插值、中心直線移動，拉遠拉近速度感一致 |
| 對準 | 目標外框加邊距放進可視區，縮放限制在總覽的 1 到 4 倍 |
| 尺規 | 兩把 canvas 尺，刻度間距依縮放換檔（1、2、5、10、25 到 5000），左尺數字轉 90° |
| 標註 | 參考線、選取框、尺規座標標籤、間距標籤都用 CSS 變數算螢幕位置：`calc(var(--tx) * 1px + x * var(--s) * 1px)`。鏡頭每一格只改三個變數，不重繪 React |
| 量測 | 縮放取自 DOM（畫布層寬度除以 canvasWidth），外層再被縮放（例如型錄卡片的 FitStage）也量得準 |

### 4.4 播放與揭露

時間軸：線框總覽 0.9 秒 → 每站「飛 1 秒、停 1.7 秒、（換版、重新對準 0.48 秒、停 1.5 秒）」 → 拉回總覽 0.9 秒 → 掃描線 1.5 秒 → 完成版。

- 自己的時鐘：只在「播放中、在畫面內、分頁可見」時前進；暫停、捲走、切分頁都會停在原地，回來接著播。沒有工作時連 rAF 都不排。
- 掃描：真實層 `clip-path: inset(0 W-x 0 0)`、線框層 `inset(0 0 0 x)`，中間一條強調色的線，尺規上的標籤顯示座標。
- 播放列：播放／暫停、每站一個圓點（可點，直接跳過去）、狀態「第 2 版 · 特色卡片」（只在換站時 aria-live 播報）、從線框重播。
- 揭露完成前真實介面是 `inert`，完成後可以點。

### 4.5 減少動態與無障礙

- `useReducedMotion()` 為真：一開始就是完成版（最後一版草稿），沒有自動播放。點圓點會直接跳到那一站，標註疊在完成版上；點最後一個圓點回到總覽。資訊不遺失。
- 線框層 `aria-hidden` 加 `inert`，複本移除 id，避免和真實介面撞名。

### 4.6 符合 DESIGN-product.md

- 一個強調色（`primary`）負責參考線、選取框、標籤；沒有漸層、光暈、彩色陰影。播放列是唯一的浮動 HUD（88% 不透明加 `backdrop-blur-sm`）。
- 緩動用系列的 expo-out；數字全部 `tabular-nums` 與 `font-mono`。
- 自動播放只在可視範圍內，可暫停、可重播。
- 例外：單一檔案上限 300 行。元件 450 行、量測工具 150 行，拆成兩個檔案（和 glass-cube-hero 的 shader.ts 同樣處理）。

## 6. 給買家的注意事項（同 meta.usage）

- 介面是在 canvasWidth 排版後縮放的，裡面要用容器查詢（`@container`），不要用 `sm:`、`lg:` 視窗斷點。
- `data-spec` 標在容器上：間距與列高量的是直接子元素。
- 頁面主要 CTA 放在框外，框內介面在揭露前不能點。
- 示範把 children 寫成 draft 的函式才會真的改版；靜態 children 一樣有線框、紅線與揭露。
