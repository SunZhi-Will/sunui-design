# UI/UX 去 AI 感分析

> 2026-11-05。範圍：`apps/web` 網站外殼與全部 163 個 block（free 139、pro 24）。方法：逐一無頭截圖做成對照表，加上原始碼特徵掃描（漸層、光暈、毛玻璃、紫靛色系、漸層字、常駐脈動、裝飾 emoji）。

## 1. 結論

功能沒有問題，問題出在**移植規則**。`PORTING.md` 原本規定「顏色、漸層、光暈、毛玻璃照原樣」，所以各專案的模板式視覺被原封不動搬進同一個型錄。單看每個專案還好，放在一起就變成一整排紫粉漸層、霓虹光暈、漸層大字，這正是「AI 感」的來源。

網站外殼（首頁、型錄、詳細頁、文件）本身已經很克制，不是主因。

## 2. 什麼讓介面看起來像 AI 生成

| 訊號 | 為什麼像 AI | 出現最多的地方 |
|---|---|---|
| 紫、靛、粉漸層 | 模板與生成工具的預設配色，看不出品牌 | showcase 回顧投影片、classic、cardflow 名片 |
| 漸層文字、霓虹發光 | 用效果代替層級，資訊反而變弱 | classic-countdown-banner、recap-percentile-ring |
| 毛玻璃與模糊光斑 | 沒有疊在任何內容上，只是裝飾 | classic-side-panel、infinite-avatar-grid |
| 常駐漂浮、逐個彈出 | 動畫沒有回應任何使用者動作 | recap-keyword-cloud、ember-particles |
| 一個元件多種強調色 | 沒有主次，像把調色盤全倒上去 | classic-file-upload、checkin-streak（SaaS 靛藍） |
| 千篇一律的示範文案 | 「Learn to build with AI」出現在多個 block | showcase 系列 demo |
| 卡通插畫頭像、假截圖色塊 | 生成式插圖的典型樣子 | infinite-avatar-grid、link-preview-card |

掃描結果：178 個資料夾中 84 個帶有上述特徵，其中約 45 個是主要視覺而不是功能性用途。

## 3. 各系列評估

| 系列 | 數量 | 評估 | 處理 |
|---|---|---|---|
| paper（紙感電商） | 53 | 最有辨識度，紙、墨、朱紅印章，一看就不是 AI | 不動 |
| product（產品介面） | 54 | 大致安靜，少數用了 SaaS 靛藍、霓虹綠、sparkle | 針對性修正 |
| story（敘事遊戲） | 20 | 遊戲氛圍合理，但部分有彩色外發光與霓虹綠 | 收斂到 `--story-*` token，去外發光 |
| showcase（形象頁） | 14 | 最嚴重：紫色回顧投影片、霓虹數字、漸層卡片 | 改成「雜誌式暗色 + 單一琥珀金」 |
| classic（經典套件） | 8 | 典型模板：紫粉漸層、「Build interfaces that glow」 | 改成中性 token + 單一強調色 |
| cardflow（畫布工具） | 14 | 名片藍紫漸層、卡通頭像、✨ | 改成安靜的工具介面 |

## 4. 新規則

`apps/web/PORTING.md` 已修訂：移植保留**行為、時序、結構、無障礙**，視覺一律依第 3 節收斂。重點：

1. 禁止清單：紫靛粉色系、漸層字、彩色光暈、裝飾毛玻璃、常駐漂浮、裝飾 emoji。
2. 每個 block 只有一種強調色，透過 `accent` prop 或 CSS 變數讓買家換回自己的品牌色。
3. 只留功能性漸層：圖片上的黑色遮罩、捲動邊緣淡出、實體材質的同色相明暗。
4. 示範文案要多樣、像真實產品。

## 5. 順手發現的 bug

- `star-rating` 預覽露出 `{t.prompt}` 字樣，`classic-file-upload` 露出 `(t.body)`：i18n 佔位字串沒有被替換。

## 6. 後續建議

- 把第 4 節的禁止清單做成 lint 或 CI 腳本（grep 即可），新 block 進來時自動擋。
- `content/registry-i18n/*.json` 的描述文字裡還寫著「光暈」「漸層標題」，視覺改完後要同步更新。
- lab 資料夾（gradient-background、border-beam、spotlight-card）本質就是 AI 感特效，若要上架建議直接下架或改名為「特效實驗」與主型錄分開。
