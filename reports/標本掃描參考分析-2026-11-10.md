參考：Naved（@Navedux，illos.dev 作者）2026-11-10 在 X 發布的 12 秒影片，說明是「大多是 WebGL 與自寫程式，混一點 illos.dev 的 shader 風格」。它引用的是 gruff（@gruffwashere）11-08 的「my new addiction」，原作是一株用點陣畫的花，香草 JS、可互動、有音效。

## 2. 為什麼好看

1. **一個畫面三層資訊**：點陣是主體，方框與座標是「機器在看它」，連線把兩層綁在一起。看起來像電腦視覺的追蹤畫面，比單純的點陣圖多了一層敘事。
2. **游標是鏡頭**：游標不是裝飾，它是追蹤目標。移開時線收回身體並標「LOCK」，代表系統有一個休息位置。
3. **點陣讓 3D 變便宜**：每個點只是一個小矩形，拍動只要把 x 座標乘上 cos 再做透視，點自然在橫向變窄，看起來就是一片翅膀轉過去。不用模型、不用 WebGL 也做得到。
4. **漣漪說明「你碰到了哪裡」**：進入一片翅膀時亮環從游標擴散，告訴使用者這片是一個獨立部位。

## 3. 技術拆解與做法

| 效果 | 參考的樣子 | SunUI 做法 |
|---|---|---|
| 點陣主體 | 圓角小點，墨多的地方點大、亮 | 把形狀（函式或透明背景圖片）畫到每格 4 × 4 像素的離屏畫布，平均出每格的覆蓋率與亮度，墨量 = 覆蓋率 × 亮度。點的大小是 0.3 + 0.7 × 墨量^1.4，透明度分 8 階 |
| 外緣亮一圈 | 右翅外緣洋紅 | 對格子做兩次掃描的 chamfer 距離，離外面一到兩格的點加亮。沒有用第二個顏色 |
| 拍動 | 兩翅沿身體轉，有透視 | 以 `axis` 為中軸，點離軸的距離 dx 乘 cos θ，深度 z = abs(dx) × sin θ，透視係數 F / (F − z)，同時套在 x、y 與點寬上。左右角度各加減一個 yaw，yaw 跟著游標的水平位置，主體會稍微轉向游標 |
| 追蹤點 | 25 個方框平均散在翅膀上 | 在墨夠多、不是最外圈的格子裡做最遠點取樣，第一點取最靠近中心的格子，所以每次結果都一樣、分布平均 |
| 連線與準星 | 線從每個點連到 LOCK 或 TARGET | 準星以 70ms 時間常數追游標；游標離開時鎖到 anchor 部位中心並標 LOCK；碰到 anchor 部位也標 LOCK。目前部位的點與線用強調色 |
| 部位外框 | HINDWING L / R | 每格依 `rect` 歸到第一個包含它的部位，外框是該部位所有點在當格的投影範圍，所以會跟著拍動伸縮。中軸右邊的部位標籤靠右，避免跟中間的準星標籤疊在一起 |
| 漣漪 | 亮環從游標擴散 | 環半徑 1.1 秒內長到 30 格，環寬 2.4 格的高斯，環經過的點變大、變亮、混入強調色 |
| 游標附近 | 點變亮 | 游標所在格 6 格內的點放大 40%、加亮 |

### 效能

每格畫面只做一件事：算出每個點的投影，依「8 階透明度 × 4 階強調色混合」分到 32 個 Path2D，最後 32 次 fill。在 1320 × 990 的畫布、約四千個點時，一格 CPU 時間約 1.1ms。畫面只在有東西在動時才請下一格（拍動還沒停、準星還沒到、漣漪還在），離開畫面與分頁隱藏時暫停。

## 4. 和 SunUI 規範的對照（哪些沒照抄）

- **顏色**：參考是綠青、藍紫、洋紅三色漸層，正是 PORTING.md 3.1 的禁止清單。改用 showcase 規定的石墨黑底 `#0c0a09`、點用 `#f5f5f4`、次要字 `#a8a29e`，只有一個琥珀強調色 `#d4a24c`，用在目前部位、漣漪與準星。買家可以用 `accent` 換回自己的品牌色。
- **閒置動畫**：參考的翅膀一直拍。SunUI 規則是動態只回應使用者動作，所以預設 `fold="pointer"`：游標在上面移動時才拍，停下 0.65 秒後慢慢攤平。要一直拍可以設 `fold="loop"`（只在畫面內，reduced motion 時不拍）。商品用 `fold="off"`。
- **自訂游標**：規範避免「Custom Cursor」。這裡保留系統游標（crosshair），準星是畫在主體上的追蹤標記，不取代游標，也不跟著游標離開主體區。
- **手機**：參考只有滑鼠。觸控點一下部位就鎖定，放開後準星回到該部位中心；畫布設 `touch-action: pan-y`，不擋捲動。
- **鍵盤與讀屏**：畫布是 `aria-hidden`，舞台是 `role="img"` 加說明。部位清單是真正的按鈕（`aria-pressed`），聚焦或懸停就在畫面上鎖定該部位並起一圈漣漪，Enter 鎖定。
- **reduced motion**：不拍、不起漣漪、準星直接跳到位置，部位外框與強調色照常顯示，沒有資訊遺失。
- **四種語言**：TRACKING、TARGET、LOCK、說明與提示都有 en、zh-TW、zh-CN、ja，可用 `labels` 覆寫。

## 5. 為什麼是 Pro 場景，不是免費 block

- 免費型錄 2026-11-06 起凍結。
- 免費的 `raster-image` 已經有點陣模式。這支賣的不是點陣，而是「點陣 + 追蹤層 + 部位清單」這個組合：商品解剖、上市頁主視覺。符合 option C：效果庫免費，組合好的場景收費。
- 和 `cutaway-spec`（拖切面線看內部）、`hotspots`（數字釘）是同一類「商品有哪些部位」的需求，換成科技感的呈現。

## 6. 示範內容

主體是一隻蝴蝶（`demo-art.ts` 用貝茲曲線畫，含翅脈、斑點與隨機挖點的斑駁感），包成「閃蝶真絲方巾」：中線是手捲邊，四片翅膀是四塊印花，各自寫網版數、染法、尺寸。真實使用時換成透明背景的商品圖（球鞋、耳機、椅子），`fold="off"`。

## 9. 修訂：加深立體與動感（2026-11-10 下午）

回饋是「不夠生動」。重看影片，差在三件事：參考的翅膀轉過去時明顯近大遠小、每片翅膀明暗不同，而且整隻一直在轉向游標。第一版的點是平的白，攤平時像一張貼紙。改法（仍守 showcase 規則：一個強調色、不加彩色光暈、不加閒置動畫）：

| 改動 | 做法 |
|---|---|
| 翅膀往後收 | 深度 z 改成負的（翅尖離鏡頭），透視 F 從 1.7W 收到 1.15W，翅尖收起時又窄又小，不再像放大 |
| 翅尖延遲 | 每個點自己算角度：拍動角 + flex × (離軸比例)²，flex 比拍動慢約 1.1 弧度，翅膀會彎 |
| 同色相明暗 | 翅面法線（帶一點弧度）對左上前方的光做 Lambert，再加 (n·h)^28 的高光。翅膀轉動時一片亮一片暗，高光從翅根滑到翅尖。只改透明度，不換顏色，符合 PORTING 3.3「材質明暗」 |
| 景深 | 離鏡頭越遠越淡（最低 30%），追蹤方框也跟著近大遠小 |
| 轉向與俯仰 | 完整版整隻轉向游標的幅度從 0.5 加到 0.95，新增上下俯仰（繞水平軸），`fold="off"` 的商品也會以 45% 的幅度微轉。展示版仍不轉 |
| 方格視差 | 背景方格線依轉向反方向位移，看得出主體在方格前面 |
| 拍動節奏 | `pointer` 改成游標在主體上就拍：停著時 42% 小幅拍，移動時拍滿，離開後 0.8 秒攤平。仍然只回應游標，不是閒置動畫。頻率固定每秒 0.6 下（約 1.7 秒一拍），不隨游標速度變快：第一版加了「越快拍越快」，最快每秒兩下多，看起來像在抖，生動應該來自立體與明暗，不是速度 |
| 身體起伏 | 下拍時身體往上 1.8% 舞台高 |

驗證：展示版逐格截圖確認翅膀收起時翅尖變小變暗、左翅亮右翅暗；`tsc` 通過。

## 10. 再修訂：照影片量出來的拍動（2026-11-10 晚）

第 9 節的版本拍得太用力：透視太強（翅膀收起時明顯縮小）、明暗與景深太重（收起的翅膀變暗到 30%）、翅尖彎得多、身體上下晃，而且頻率是猜的。這次直接逐格量參考影片（每 0.1 秒取一格，算翅膀有色像素的寬度與數量）：

| 量到的 | 數值 |
|---|---|
| 週期 | 約 1.2 秒一拍（0.0、1.2、2.4、3.6 秒最開，0.65、1.85、3.05 秒最收） |
| 收到最深 | 翅膀寬度剩約 51%，有色像素剩約 61% |
| 高度 | 幾乎不變（上下範圍差 2 到 3%），翅尖沒有變小 |
| 亮度 | 收起時整片幾乎一樣亮，沒有明顯變暗 |
| 節奏 | 攤開停留比較久（約 0.4 秒都在最寬附近），收起是短短一下 |

對應改法：

| 參數 | 第 9 節 | 現在 |
|---|---|---|
| 頻率 | 0.6 Hz | 0.8 Hz（約 1.25 秒一拍） |
| 最大角度 | 1.05 | 0.95（收起時翅膀約剩一半寬） |
| 波形 | 0.5 − 0.5 cos | (0.5 − 0.5 cos)^1.5，攤開停久一點 |
| 透視 F | 1.15W | 3W，收起主要是變窄 |
| 景深淡化 | 最低 30% | 最低 80% |
| 明暗 | 0.2 + 0.95 × Lambert | 0.72 + 0.4 × Lambert，高光 0.7 降到 0.3 |
| 翅尖延遲 | 0.42 | 0.1 |
| 身體起伏 | 1.8% | 0 |
| 轉向／俯仰（完整版） | 0.95／0.55 | 0.5／0.25 |

教訓：「生動」要先去量參考，不是把每個效果都加大。

使用者看過後再調：頻率 0.8 → 0.55 Hz（約 1.8 秒一拍），波形指數 1.5 → 2.6。每一拍裡接近全開（收起不到 15%）的時間從約 36% 變成 49%，也就是每拍攤開停留約 0.9 秒（原本約 0.45 秒）。收起的幅度不變。

## 11. 加上顏色（2026-11-11）

使用者希望點有顏色。第 4 節原本把參考的青、藍紫、洋紅當成 PORTING 3.1 的禁止清單（裝飾性漸層）。這次的處理方式是讓顏色來自主體本身，而不是元件加上去的裝飾：

- **引擎**：取樣時除了覆蓋率，也平均每格的 RGB，存成全亮度的顏色（明暗仍由點的大小與透明度表現）。墨量改用最亮的色版而不是亮度，不然飽和的藍、紅會被當成暗色、點變小。所有點的顏色用加權 k-means 量化成最多 10 色（最遠點取初始中心，結果固定），繪製時的顏色桶變成「調色盤每色 × 強調色混合 4 階 × 透明度 8 階」，只建立用到的 Path2D。接近白色的顏色直接用石墨底上的淺色。有顏色的點在暗底上看起來比白點暗，透明度曲線從 ink^1.3 放鬆成 ink^0.95。
- **新 prop**：`tone="source"`（預設，點帶原圖顏色）或 `tone="mono"`（全部同一個淺色，回到第一版的樣子）。換成真實商品照時，點就是商品本身的顏色。
- **示範圖**：閃蝶本來就是藍色的，所以從翅根往外畫成青 `#3fe3ff`、藍 `#4a8cff`、藍紫 `#6f63ff`、紫 `#b45cff`，外緣一圈 `#e070ff`，翅緣白點與眼紋亮心保留白色，身體淡藍。試過更淡的粉彩版（整隻偏白，看不出顏色）與第一版的深飽和版（在暗底上太暗），最後用飽和色加放鬆的透明度曲線。
- **仍守的規則**：強調色還是只有一個琥珀色，用在目前部位、漣漪與準星；沒有外發光、沒有漸層字。

驗證：展示版截圖可以看到翅根青、中段藍、外緣紫紅；`tsc` 通過。

## 12. 追蹤層改白、漣漪改粉青（2026-11-11）

上一版主體有顏色了，但漣漪、部位外框、準星、連線、清單和示範按鈕都還是琥珀色。重看影片：參考的追蹤層（方框、連線、座標、TARGET、LOCK、部位外框）全部是細的白、灰線，碰到部位時主體不變色，漣漪是一圈粉紅（外緣）加青色（內側），整個畫面沒有琥珀色。改法：

- `accent` 不再有預設值。`tone="source"` 又沒給 `accent` 時，追蹤層用 `#f5f5f4`，目前部位只把點加亮，不混色；漣漪的點換成調色盤裡最偏粉紅（往白提亮 40%）與最偏青（提亮 20%）的兩色，外緣粉、內側青，這兩色加在調色盤尾端。主體如果只有一種顏色，就退回只加亮。
- 環寬從 2.4 格加到 3.4 格，換色門檻從 0.3 降到 0.2，環比較粗，接近參考。
- `tone="mono"` 或有給 `accent` 時，跟以前一樣用強調色（mono 預設琥珀）。
- 清單的目前列、編號、鎖定圖示跟追蹤層同色；示範的購買按鈕從琥珀改成白底。
- 順手修掉第 11 節 commit 弄壞的 Pro registry.json（描述裡的雙引號沒跳脫，網站整頁 500）。

驗證：在 Chrome 全速播放下截圖，追蹤層全白、沒有琥珀色，進入左後翅時粉青環從游標擴散；逐格數畫面上的粉紅點從 4851 升到 8421 再退回。`tsc` 通過，registry.json 能正確解析。
