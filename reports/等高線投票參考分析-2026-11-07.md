## 2. 為什麼好看、為什麼好用

1. **高度就是資料**。山高對應內容量，不用讀數字就知道哪個主題最重。比長條圖多了一件事：靠近的主題會連成山脊，看得出「群」。
2. **疊圈的立體感很便宜**。每一層等高線只是同一條平面輪廓往上抬一段距離，不用 3D 引擎，卻有真實地形的份量。
3. **強調只換顏色，不換形狀**。懸停時整座山的線變色，幾何完全不動，符合 DESIGN.md「同一個幾何貫穿所有狀態」。
4. **因果在原地發生**。拖動節點，山就跟著長；改變發生在使用者手指下面。

## 3. 轉成電商場景

原影片是內容規劃工具，SunUI 不做筆記或心智圖。保留「高度＝數量、靠近會連成山脊、強調只換墨色」這三點，套到活動頁最常見、又最缺新意的元件：**投票**。

- 口味復刻、顏色票選、下一站快閃店、新品前的粉絲投票，現況幾乎都是長條圖或卡片加百分比。
- 換成地形後，「誰領先」是一眼看出的山高，投票這個動作也有了實體：墨從你那座山的山頂往下染。

## 4. 技術拆解與做法

| 效果 | 參考的樣子 | SunUI 做法 |
|---|---|---|
| 地形 | 多座山相加成山脈 | 每個選項一座高斯山，高度＝票數 ÷ 最高票，半徑隨高度開根號變大；整片高度場在 84×48 的網格上取樣，取樣範圍比山頂位置大一圈，外圈線不會被切掉 |
| 等高線 | 一圈圈平滑輪廓 | 標記方塊（marching squares）逐層求線段，馬鞍格用格子中心值判斷連法 |
| 立體 | 斜視角、層層往上抬 | 投影：遠處窄、近處寬（0.78 到 1 倍），每一層依高度往上抬，沒有用 3D 或 canvas，整張是 SVG path |
| 哪條線屬於哪座山 | 懸停時整座山變色 | 每個格子記下「貢獻最大的山」，線段依此分組，每層每座山各一條 path；共用的山脊外圈會一半屬於各自的山 |
| 強調 | 橘色光 | 只用墨：一般 18% 透明度、懸停 50%、自己投的那座 90% 並加粗。不用彩色與光暈 |
| 投票回饋 | 無（原影片是編輯工具） | 墨從山頂往下染，一圈一圈依序（380ms）；票數用 roll 捲動；底部出現 `Stamp`「已投票」 |
| 改票 | 無 | 票從舊的山移到新的山，所有山高用 gentle 彈簧重新成形，等高線每格重算 |
| 點擊判定 | 點節點 | 每座山在畫布上是一個往上延伸的橢圓範圍，指標落在哪個橢圓就投哪座；另外每座山都有真正的按鈕 |

### 時序

- 懸停：等高線透明度 120ms 轉換，不動幾何。
- 投票：先染墨（山頂到山腳 380ms）與票數捲動，同時山高以 gentle 彈簧調整（只有改票或票數差很小時看得到）。
- reduced motion：墨直接染滿、山高直接跳到終點，票數直接換。

## 5. 和 SunUI 規範的對照

- 顏色：只有墨 `#171717 / #ededed` 的深淺與紙色底，標籤底用 85% 紙色，避免線穿過字。
- 沒有進場動畫與常駐循環；地形只在投票或傳入的票數改變時動。
- 精確讀法：每座山的標籤都寫出確切票數與百分比，按鈕的 aria-label 也包含兩者；總票數在底部。這是「深入層要保留精確讀法」那一條。
- 結果用 `Stamp`，放在底部狀態列（動作的結果出現的位置），不壓在地形上。
- 已知取捨：線段每格各一段 `M L`，沒有串成連續折線，path 字串較長（4 座山約數十 KB），但每次重算都在幾毫秒內。選項超過六個時標籤容易重疊，所以 props 提供 `at` 讓使用者指定位置。

## 6. 為什麼放 Pro

免費型錄 2026-11-06 起凍結。依四項測試：可替代性低（市面上的投票元件沒有地形呈現）、自己做要處理高度場、marching squares、投影與線段歸屬、直接用在活動頁的互動與名單收集、型錄展示價值高（一張卡就是一幅地形）。歸 Pro，排在型錄 B 組（免費沒有對應的招牌互動），緊接在 `hoop-upload` 之後。
