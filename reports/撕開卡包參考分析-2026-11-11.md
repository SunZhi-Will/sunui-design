# 撕開卡包：拆解與元件化（2026-11-11）

來源：YASH @Yassshhu 的貼文〈made a card pack you can actually tear open〉，2026-11-09。成品：Pro showcase 場景 `tear-pack-reveal`。

## 原作在做什麼

一包鋁箔卡包浮在淺灰底上。游標沿頂端的鋸齒封口拖過去，封口一路撕開翹起，袋口露出一疊彩虹色的卡緣；撕完後五張全像卡升起攤成一排，撒一陣彩紙。卡片懸停時傾斜、反光帶移動，底下一顆「Open another pack」換下一包（換色、換卡序）。

## 好在哪裡

- 撕的手勢就是內容：不是按鈕觸發動畫，而是手跟著封口走，撕到哪裡看得到。
- 袋口先露出卡緣，打開前就給了期待。
- 卡片各有顏色與稀有度，攤開後一排就是一組收藏，值得截圖。

## 搬進 SunUI 時改了什麼

| 原作 | 這個元件 |
|---|---|
| 收藏角色卡（可愛臉的 3D 物件） | 每張卡是一份**獎勵**：免運、折扣、贈品、點數、購物金、搶先購。卡圖是自己畫的六種小圖（`PackArt`），不沿用原作角色 |
| 只能用滑鼠撕 | 左右兩個方向都能撕；只會往前撕不會倒退；撕過六成放手就扯下，不到就彈回；點一下封口會翹一下提示要用撕的 |
| 沒有鍵盤路徑 | Enter / 空白鍵自動撕開，`aria-live` 念出拿到的獎勵 |
| 一排五張在手機上會擠 | 窄螢幕排兩列（3 + 2），卡寬低於 124px 時收起標籤與稀有度文字（螢幕閱讀器仍讀得到） |
| 「再開一包」 | `onAgain` 回呼，由頁面決定下一包的卡與顏色；另有 `onClaim` 領取按鈕（非同步狀態） |
| 減少動態 | 直接打開成一排，沒有傾斜、彩紙與飛走的封口 |

幾何做法：封口與袋身共用同一條鋸齒撕線，所以封住時看不出縫；撕的時候把封口在切點分成兩段 `clip-path`，撕下的那段以切點為軸旋轉。全部是 DOM 與 CSS，沒有 WebGL；彩紙是一次性的 Canvas 2D，2.4 秒後停。

## 放在哪裡

免費目錄凍結到 2027-01-12，而且漸層、全像反光、彩紙都超出紙感規則，所以它是 Pro 的 showcase 場景（一頁一個招牌時刻）。網站預覽是 `preview.tsx` 展示版：沒有 props API、彩紙、鍵盤開封與播報、領取流程，卡包也沒有隨游標的反光；完整元件只由 `/r/pro/tear-pack-reveal` 授權後交付。

## 已知限制

- 卡包尺寸固定 184 × 256；要更大或更小請在外層縮放。
- 超過六張卡在手機上仍會擠，建議三到六張。
- 只在 Chromium 驗證過（桌機與 375px 手機寬度、淺色與深色）。
