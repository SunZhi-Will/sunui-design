# tuffui.com 參考分析

> 2026-11-07。來源：https://tuffui.com/ 首頁、`/llms.txt`、元件頁（rolling-number、tool-approval-queue、tick-gauge、support-widget），以及頁面 CSS 變數。
>
> 標記：【已驗證】實際看到的頁面或資料；【推論】由資料推導；【建議】行動提案。所有建議遵守免費目錄凍結（2026-11-06 起到 2027-01-12 PH 上線前，不新增免費 block 與動效庫；新免費項目只能是 Pro 場景拆出的原子）。

## 0. 結論先講

1. **TUFFUI 是 AI agent 介面的免費元件庫，跟 SunUI 不同賽道。** 76 個元件，全部 MIT，shadcn CLI 安裝，「No Pro tier, no paywall」【已驗證】。它是《八家 UI 元件庫競品分析》說的那片 agent UI 紅海裡的第九家，再次證實不要轉去做 agent UI。
2. **它的商業模式是「免費元件庫當作另一個產品的漏斗」。** 每頁右側固定一張 Tuff（團隊任務、文件、聊天，單一價格不按人頭）的廣告卡，加 Ko-fi 贊助【已驗證】。這跟 SunUI「免費引流、Pro 收費」是兩條路；它證明免費庫本身很難直接變現，要嘛賣 Pro，要嘛賣別的產品。
3. **最值得借的是三件事，不是元件本身**：
   - **Screens 這一層**：7 個「整頁畫面」（AI Chat、Coding Agent、Support Widget…）把幾十個元件組在一個真實情境裡，安裝時一次帶入全部依賴【已驗證】。這正是 SunUI Pro 場景該有的樣子（`campaign-landing`、`black-friday-weekend` 已經在走這條路）。
   - **元件頁的情境切換**：預覽列右上角是「Counter / Currency」「Below SLO / Healthy」「Grouped / Flat」這種**情境名**，不是「Variant 1 / 2」【已驗證】。SunUI block 頁的 variants 可以照做。
   - **Surface 分層 token**：`surface` / `surface-inset` / `surface-raised` 三層無框線底色，取代邊框來分層【已驗證】。SunUI 的紙感走「1px 紙邊」，不適合整套照搬，但說明了「少畫框線」是 2026 年的主流方向。
4. **唯一跟電商直接交會的是 Support Widget**：它的示範背景就是一間戶外用品店，泡泡在右下角【已驗證】。SunUI 的訂單類 Pro 場景（`order-tracker`、`order-island`、`receipt-printer`）都缺一個「買家主動問」的入口。**據此做了一個 Pro 場景 `store-help-widget`**（§4），以電商語言重做，不是 agent 工具。

## 1. 網站拆解

### 1.1 定位與數字【已驗證】

### 1.3 視覺語言【已驗證】

- 預設深色，背景 `#0c0c0c`，三層 surface（`#191919` / `#101010` / `#252525`），邊框幾乎看不見（`#ffffff0f`）。
- 主按鈕是「銀色」：白到 `#ababab` 的線性漸層加亮邊。品牌色借 Apple 系統色（`#0a84ff`、`#30d158`、`#ff453a`）。
- 字體 Geist；狀態用小面積色塊 pill。
- 【推論】整體是 Linear / Vercel 系的深色儀表板美學。SunUI 已決定黑白灰紙感、禁止漸層，**銀色漸層按鈕不借**。

### 1.4 元件頁結構【已驗證】

麵包屑分類 → 標題 → 一句描述 → `2 variants` `MIT` 小標 → Preview / Code 切換 + 情境切換 + Replay → Installation（pnpm / npm / yarn / bun 分頁）→ Usage → Props。右側目錄下方是 Tuff 廣告。

| # | 做法 | 套到 SunUI | 成本 |
|---|---|---|---|
| 1 | 情境名的 variant 切換（「Below SLO / Healthy」） | block 頁 variants 改用「活動中 / 已結束」「有庫存 / 售完」這類情境名 | 低，改文案 |

## 4. 已製作：`store-help-widget`（Pro 場景）

**為什麼是這個**：TUFFUI 的 Support Widget 把聊天泡泡放在商店頁上，代表「agent UI」和「電商」的交界其實是**售後與導購的客服入口**。SunUI 已經有訂單狀態（`order-island`）、物流（`order-tracker`）、收據（`receipt-printer`），缺的是買家主動發問的那一格。這是 Pro 場景，不違反免費凍結。

**做法（原創，以 SunUI 紙感重做，不抄版面）**：

- 右下角一顆「Help」膠囊，點開時**同一個外框**長成面板（`gentle` 彈簧改寬高），左上的問號圖示是貫穿兩個狀態的錨點。
- 四個快捷問題：查訂單、找禮物、退換貨、找真人。
- **查訂單**：輸入訂單編號（`font-mono`），回一張紙面訂單卡（編號、商品、四段狀態墨色標目前步驟、預計送達）。
- **找禮物**：選預算，回橫向可捲動的商品卡，加入購物袋後按鈕位置換成 `Stamp`「已加入」。
- **退換貨**：顯示退貨期限與條件，一鍵開始，結果用 `Stamp`。
- **找真人**：顯示排隊，接上後顯示真人名字，結束時一行評分，送出後 `Stamp`「謝謝」。
- 所有資料走 props 的 async callback（`lookupOrder`、`findGifts`、`startReturn`、`requestAgent`），元件本身不假裝有 AI。
- 不做打字中常駐動畫以外的循環（查詢中的三點屬於「載入」，允許）。

## 5. 後續候選（不在這次範圍）

| 候選 | 來源 | 用在哪個 Pro 場景 | 判斷 |
|---|---|---|---|
| 集氣刻度表（tick gauge 改成團購達標） | Tick Gauge | 檔期主視覺、團購頁 | 可當 Pro 原子；跟 `tier-progress` 重疊要先比較 |
| 預約時段選擇 | Slot Picker | 門市取貨、試穿預約 | 中，等有實體門市需求的檔期包 |
| 購買前確認卡 | Confirmation Card | 一鍵加購、訂閱變更 | 低，`checkout-steps` 大致涵蓋 |
| 售出時段分布（radial dots） | Radial Dots | 商家端活動成效頁 | 不追，屬儀表板，不是買家頁 |

## 6. 不要做的事

- 不做 agent 監控、工具審核、trace、eval 這些元件。紅海，而且稀釋檔期定位（同《八家 UI 元件庫競品分析》§結論 2）。
- 不借銀色漸層按鈕、Apple 系統色、深色預設。違反 `DESIGN.md` 顏色規則。
- 不把客服泡泡做成「AI 聊天」賣點。對外描述是「售後與導購入口」，AI 只是買家可以接上的其中一種後端。
