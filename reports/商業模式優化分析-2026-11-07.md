# SunUI 商業模式優化分析

> 2026-11-07。接續 `商業模式深度分析-2026-11-06.md`（檔期行事曆、季節包、主攻 agency）與 `型錄排序與免費付費價值分析-2026-11-07.md`（付費單位從 block 換成場景），不重複其內容。這份回答三件事：過去 36 小時執行有沒有回到軌道、商業模式本身還能怎麼優化、離 2026-11-27 Founding 開賣剩 20 天該怎麼排。【已驗證】是這次直接查 repo、正式網站或 GitHub；【估算】【建議】是推論；【未驗證】是我查不到、需要你確認的。

## 0. 結論先講

1. **水管接通了一半。** 11/06 列的七件基礎建設，部署（`sunui.synvize.com` 回 200）、推送（只領先 3 個 commit）、401 升級訊息都做好了。但**收錢那一端還是斷的**：定價頁仍顯示 waitlist，沒有任何 Polar 結帳連結。這件事只有你能做（KYC），而且是整條路上最長的前置時間。
2. **偏移從免費層搬到了 Pro 層。** 免費層確實停了。但 11/07 一天新增 14 個 Pro 單品（Pro 從 41 到 55），而 11/07 報告建議的 6 個「組好的場景」一個都沒做。整頁組合仍然只有 2 個。Pro 數量在漲，付費理由沒有變多：同一個問題換了一層樓。
3. **最值得做的優化：賣「組裝能力」，不賣「元件數量」。** 現在的 55 個 Pro 已經夠組出 8 套整頁。把場景做成「配方 + 主題 token」，透過 MCP 只對有授權的 agent 開放，每套成本 1 到 2 天，卻是 agent 自己寫不出來、競品也沒有的東西。
4. **像素系列意外打開了第二個垂直市場：遊戲營運活動頁。** 簽到、轉蛋、事前預約、Boss 特賣、等級獎勵，正好是手遊每週都在做的活動頁，頻率比電商檔期高好幾倍。建議當成一個「套件假設」去驗證，不要再往裡加東西。
5. **定價結構只需要動兩處**：Team 方案補上 agency 交件條款，並在定價頁加「7 天檔期頁」接案服務。其他維持 11/06 的設計。

### 1.1 Pro 層發生了什麼

11/07 新增的 14 個 Pro：`order-island`、`day-night-hero`、`black-friday-weekend`、`gift-card-designer`、`price-history`、`receipt-printer`、`store-help-widget`、`hoop-upload`、`ink-filter-bar`、`vote-terrain`、`cutaway-spec`、`ask-to-shop`、`recipe-glass`、`curve-rail-hero`、`lineup-shelf`，加上 5 個像素場景（`pixel-check-in`、`pixel-preregister`、`pixel-gacha`、`pixel-boss-sale`、`pixel-level-track`）。

拿 11/07 報告的分級去套：多數落在 B 組（有獨特機制的招牌），品質不是問題。問題是**它們幾乎全是單一畫面**，`registryDependencies` 只有 1 到 2 個（都是 `utils` 類的基礎依賴）。真正組合多個 Pro 的仍然只有 `campaign-landing`（8）與 `black-friday-weekend`（7）。

這呼應 11/06 報告的觀察：做新東西很順手，接水管與組裝不順手。這是作者偏好，不是能力問題，所以解法要寫成規則，而不是期待自己改變。

## 2. 商業模式還有哪些可以優化

11/06 報告處理了「沒有回購」，11/07 報告處理了「Pro 跟免費同一個單位」。剩下三個還沒被正面處理的結構問題。

### 2.1 問題一：護城河仍然靠元件，而元件會被 agent 抄

免費層透過 MCP 把完整原始碼交給 agent，這是對的（它是獲客管道）。但這也代表 agent 看過 76 個免費 block 之後，仿一個 Pro 單品並不難。Agent 做不好、而 SunUI 已經具備的是：

- 跨 block 一致的紙感設計規則（`lib/agent/guidelines.ts`）
- 多個 block 之間的狀態串接（購物車、倒數、庫存在同一頁互相知道彼此）
- 一份主題換掉整頁的保證
- 四語文案與 CJK 排版

這四件全部是「組裝層」的價值，不是「元件層」。**所以 Pro 該往上長一層，而不是往旁邊再多一個。**

### 2.2 問題二：agent 管道只會「安裝」，不會「組頁」

現在 MCP 的流程是 `search_blocks → get_block → plan_install`，產出是「裝好幾個 block」。使用者真正要的是「給我一頁農曆新年活動頁，品牌色是這個」。中間的組裝工作目前留給 agent 自己發揮，結果品質不一，也看不出 Pro 的價值。

### 2.3 問題三：目標客群的關鍵條款沒寫清楚

授權寫了「可用於客戶專案」與「不可公開原始碼」。但 agency 的日常是**把整個 repo 交給客戶**，之後客戶自己的工程師會接手修改。現在的文字沒有回答「交件後客戶的工程師能不能改？要不要另外買？」這是 Team 方案的買家第一個會問的問題，也是 Tailwind Plus、shadcnblocks 授權頁都有寫的條款。

## 3. 優化方案

### 3.1 場景配方：把「組裝」變成 Pro 的主力商品【建議】

**做法**：每個場景是一份配方，內容是

1. 要裝哪些 Pro 與免費 block
2. 區段順序與每段的 props（含四語文案）
3. 一份主題 token（紙色、墨色、強調色、字體、圓角）
4. 狀態串接的膠水程式（一個共享 store 或 context）
5. 給 agent 的組裝指示（哪裡可以換、哪裡不要動）

**交付方式**：

- 一般使用者：`npx shadcn add @sunui-pro/scene-checkout` 一次裝好整頁（registry item 本身就支援 `registryDependencies` 與 `files`）。
- Agent：MCP 新增一個 `plan_scene` 工具，有授權就回傳完整配方，沒授權就回傳場景描述與 401 升級訊息。配方只走 `/r/pro/*`，符合「Pro 原始碼不進 MCP 與 llms-full.txt」的規則。

**用現有 55 個 Pro 就能組的 8 套**：

| 場景 | 組成 | 對應買家 |
|---|---|---|
| 結帳流程 | `cart-drawer` → `upsell-drawer` → `checkout-button` → `receipt-printer` → `order-island` | 電商 agency |
| 商品頁 | `product-gallery` + `price-history` + `flash-sale-product-card` + `testimonial-wall` + `faq-accordion` | 電商 agency |
| 會員集點 | `stamp-card` + `prize-wheel` + `scratch-card` + `coupon-claim-card` | 電商、品牌 |
| 新品上市 | `launch-stage-hero` + `launch-countdown-wall` + `newsletter-signup` + `drop-release-hero` | 品牌、DTC |
| 訂閱定價頁 | `pricing-cards` + `plan-comparison` + `upgrade-modal` + `faq-accordion` | Indie SaaS |
| 雙 11 / 黑五 | 現有 `campaign-landing`、`black-friday-weekend` | 已完成 |
| 農曆新年 | `festival-banner` + `gift-box-reveal` + `fold-invite-card` + `prize-wheel` + 倒數 | **第一個季節包** |
| 手遊活動 | `pixel-preregister` → `pixel-check-in` → `pixel-gacha` → `pixel-boss-sale` → `pixel-level-track` | 遊戲營運（見 3.3） |

對外說法從「55 個 Pro block」變成「**8 套整頁場景，裝一次就是一頁**」。工時每套 1 到 2 天【估算】，前兩套（結帳流程、農曆新年）可以在 11/27 前完成。

### 3.2 主題 token：給 agency 的單一理由【建議】

所有 Pro 場景讀同一組 CSS 變數，配方附一個 `theme.css`。賣點寫成一句話：「換一個檔案，就是下一個客戶的品牌。」這是 agency 願意付 Team 價的核心，也是單一免費 block 做不到的保證。header 已經有 theme picker 可以驅動預覽，正好拿來在場景頁示範「同一頁、三個品牌」。

### 3.3 第二垂直：遊戲營運活動頁，當成一個要驗證的假設【建議】

| | 電商檔期 | 手遊活動 |
|---|---|---|
| 頻率 | 一年 6 到 7 檔 | 每 1 到 2 週一檔 |
| 誰在做 | 接案者、agency、品牌內部 | 遊戲公司營運與前端，或外包 |
| 預算 | 中 | 中到高（活動直接連到營收） |
| 現有元件 | 多 | 5 個像素場景剛好是一條完整漏斗：預約、簽到、轉蛋、特賣、等級 |
| 市場 | 全球 | 台、日、中、韓特別大，和四語系完全重疊 |

這是 SunUI 目前唯一一組「連在一起就是一條營運漏斗」的 Pro。風險是再度分散定位，所以規則是：**不再新增像素場景**，只把現有 5 個組成「手遊活動套件」一個場景頁，掛在型錄與定價頁。PH 前看兩個數字：這個場景頁的造訪佔比、waitlist 裡留下遊戲相關公司信箱的比例。超過 15% 再投入，否則維持現狀。

### 3.4 定價結構：只動兩處【建議】

| 方案 | 價格 | 變更 |
|---|---|---|
| Free | 0 | 不變 |
| Founding | US$79，限量 | 不變；主訊息照 11/06 改成「鎖定終身 + 農曆新年套件 12 月底送到」 |
| Pro | US$129 | 不變 |
| Team | US$349 / 5 席 | **補交件條款**：可將 Pro 原始碼作為最終產品的一部分交給客戶，客戶可在該專案內修改維護，不需另購；但不得從該專案抽出 block 另作他用 |
| 季節包 | 單售 US$49，Pro 會員 US$29 | 不變；第一套是農曆新年 |
| **7 天檔期頁** | NT$3 萬起 / US$990 起 | **新增入口**：用 SunUI 場景交付一頁完整活動頁，含部署 |

為什麼要把接案服務放到定價頁：

- 第一年最可靠的現金。兩件案子就超過 30 個 Founding 席位的收入【估算】。
- 每一件案子都是一個真實的場景配方測試，直接回饋到 3.1。
- 對 agency 客群是信任訊號：「作者自己也用這套接案」。

不建議現在改成訂閱，理由與 11/06 相同（買斷是對開發者最清楚的承諾，回購交給季節包）。

### 3.5 收入結構的重新估算【估算】

| 來源 | 到 2027-01-31 的保守情境 | 備註 |
|---|---|---|
| Founding | 50 席 × US$72 = US$3,600 | 11/06 設定的門檻 |
| Team | 5 席 × US$319 = US$1,595 | 佔 10% |
| 農曆新年季節包 | 15 份 × 平均 US$35 = US$525 | 主要賣給 Founding |
| 7 天檔期頁 | 2 件 × US$990 = US$1,980 | 可能是最大單項 |
| 合計 | 約 US$7,700 | 約為 11/06 基準情境的五成，時間只有三個月 |

重點不是總數，而是**接案服務與季節包加起來接近一半**。只靠授權，三個月的天花板很低；加上這兩項，模式才有第二條腿。

## Conclusion

這 36 小時最大的進展是網站真的上線、程式真的推上去了；最大的缺口還是同一個：**沒有地方可以付錢**。商業模式本身不需要大改，需要的是往上長一層。55 個 Pro 已經是足夠的零件庫，接下來的價值在於把它們組成「裝一次就是一頁」的場景，用一份主題換掉品牌，再透過 agent 管道交付給有授權的人。再加上接案服務當第二條收入腿、手遊活動當第二個垂直假設，SunUI 就從「一堆好看的 block」變成「做活動頁最快的方法」。而這一切的第一步，是這週把 Polar 的 KYC 送出去。
