# 經典 SunUI 元件深度分析（npm `@sunui-design/react`）

日期：2026-11-21。起因：昨天的〈舊元件盤點與恢復深度分析〉只用一行帶過經典 SunUI 的 8 個元件，這份把它們逐一拆開看。

## 1. 結論

**元件本身沒有能力遺失。** 8 個裡有 6 個已經有 craft 版的接班人在型錄裡，file-upload 升級成 Pro，filter-grid 是刻意不做。真正值得搬回來的只有兩個小功能，都可以併進現有 block，不增加項目數。

**真正的問題不在元件，而在它們還「掛著 SunUI 的名字在外面」：**

1. GitHub repo 首頁的 `README.md` 還在介紹這 8 個舊元件，教人 `npm install @sunui-design/react`。Product Hunt 上線時，點進 GitHub 的人看到的第一個畫面就是舊產品。
2. npm 上 10 個套件都沒有標 deprecated，最新版 0.0.55（最後發佈 2026-11-04）。裝下去拿到的是紫色、青色、橘色主題、粒子特效的舊風格，跟現在「黑白灰、質感」的定位正面衝突。
3. 每個套件每月仍有 250 到 400 次下載（見第 4 節），所以這不是沒人看的角落。

建議：上線前把 README 改成指向 registry，並 deprecate npm 套件（第 6 節）。元件程式碼不用再花力氣。

## 2. 盤點

`packages/` 共 4,422 行，8 個元件加 `core`（樣式）與 `all`（總包 `@sunui-design/react`）。

| 元件 | npm 名稱 | 行數 | 舊版主要能力 |
|---|---|---|---|
| Card | `@sunui-design/card` | 638 | 5 種外觀（outlined、filled、elevated、glass、gradient）× 6 種色彩主題，載入態 overlay / skeleton / shimmer，Header、Content、Footer、Image 子元件 |
| CountdownBanner | `@sunui-design/countdown-banner` | 915 | 倒數促銷橫幅，粒子背景，3 種版面 × 3 種形式（card、banner、floating），中英文 |
| FileUpload | `@sunui-design/file-upload` | 735 + 295 | 拖放上傳、進度條、圖片預覽，**PDF 第一頁縮圖**（pdfjs，worker 從 cdnjs 載入） |
| SidePanel | `@sunui-design/side-panel` | 595 | 左右側欄，Escape、點外關閉，**多面板協調**（Provider：一個開著時隱藏其他開關），內建日期區間選擇器 |
| FloatingButton | `@sunui-design/floating` | 407 | 放射狀展開的浮動按鈕，內建 5 個社群圖示 |
| FilterGrid | `@sunui-design/filter` | 252 + 100 | 六角形「技能牆」，分類篩選、無限捲動或分頁 |
| SocialButton | `@sunui-design/social` | 115 | 社群按鈕，petal、vertical、grid 三種排法 |
| GradientBackground | `@sunui-design/gradient` | 74 | 漸層光暈加格線背景，呼吸動畫 |

## 3. 逐一比對

| 舊元件 | 現在的接班人 | 舊版獨有、值得保留的 | 舊版不該保留的 | 處置 |
|---|---|---|---|---|
| Card | `card-effects`（9 種效果 + 5 種群組效果）、`skeleton-set` | 無 | 6 種色彩主題（違反黑白灰）、`glass`、`gradient` 外觀、`glow` | 已取代 |
| CountdownBanner | 免費 `countdown-banner`（421 行，已 craft 化） | `floating` 形式（角落浮動小卡）可考慮，但 Pro 的 flash-sale、festival-banner 已涵蓋檔期情境 | **預設 `endDate = 現在 + 7 天`**：每次重新整理都重新倒數，是假稀缺。新版改成 `endDate` 必填，並加了 `startDate` 與 SSR 一致的 `dateLabel`。粒子背景屬於裝飾 | 已取代，新版明顯更好 |
| FileUpload | Pro `file-dropzone`（511 行）、Pro `hoop-upload` | PDF 第一頁縮圖 | pdfjs 很重（約 1 MB），worker 與字型從 cdnjs、jsdelivr 外部載入，有 CSP 與供應鏈風險；3 種色彩主題 | 已取代。PDF 縮圖若要做，放 Pro file-dropzone 的可選功能，由使用者自帶 pdfjs |
| SidePanel | 免費 `side-panel`（248 行，有焦點管理、portal、四語） | 多面板協調：同頁有好幾個側欄時，一個打開就收起其他開關 | 內建日期區間選擇器（把報表需求寫死在通用元件裡）、6 種色彩主題 | 已取代。多面板協調可當 B 類小功能併入 |
| FloatingButton | `morph-menu` 的 `layout="radial"`（昨天 B 批次已併入）＋ `social-links` | 無 | 寫死的社群圖示與品牌色 | 已取代 |
| SocialButton | `social-links`（昨天 A 批次恢復） | 無，petal 排法已決定不保留 | | 已取代 |
| GradientBackground | `gradient-backdrop`（541 行） | 無 | 預設紫色漸層 | 已取代 |
| FilterGrid | 無直接對應；電商篩選是 Pro `product-filter-grid` | 無 | 六角形技能牆只適合個人作品集，買家太窄；5 種色彩主題 | 不做 |

整體風格層面，舊套件有共同問題，這也是不能直接搬回來的原因：

- 色彩：7 個檔案出現 violet、cyan、orange 等主題字串，Card 53 處、CountdownBanner 80 處、FileUpload 49 處。
- 動效：全部是 `duration` 加 `easeOut` 或 `transition-all duration-300`，沒有彈簧，也沒有按下狀態。
- 架構：npm 套件靠 props 開關一切（SidePanel 有 37 個 props），跟 registry「複製原始碼、自己改」的模式相反。

各套件數字非常平均，而且總包 `react` 會連帶裝下所有子套件。所以多數下載很可能來自總包的連帶安裝、CI 重裝與 npm 鏡像站，真人用戶數遠低於 300，無法從這份資料分辨。但不管真實數字多少，結論一樣：**有人透過 npm 接觸到「SunUI」，而他們看到的是舊風格。**

## 5. 為什麼不把舊元件「恢復」

昨天恢復的條件是「型錄沒有同等能力」。經典 8 個全部不符合：每一個都有更好的接班人，或者用途太窄。而且凍結規則的例外只涵蓋昨天報告清單上的元件，經典 8 個在那份報告裡已列為 C 類。這份分析沒有改變那個判斷，只是把理由補完整。

可以做的只有兩個 B 類小功能（不增加項目數，不違反凍結）：

| 功能 | 併進 | 優先度 |
|---|---|---|
| 多面板協調（同時只開一個） | 免費 `side-panel` | 低，等有使用者提出再做 |
| PDF 第一頁縮圖（使用者自帶 pdfjs） | Pro `file-dropzone` | 低，Pro 需求驅動 |

## 6. 建議動作（依優先序）

| # | 動作 | 為什麼 | 可逆性 |
|---|---|---|---|
| 1 | **改寫根目錄 `README.md`**：首頁介紹 registry 與 `npx shadcn add`，舊套件縮成底部一段「Legacy npm packages」 | PH 訪客點 GitHub 第一眼看到的東西 | 完全可逆 |
| 2 | **`npm deprecate` 10 個套件**，訊息指向 SunUI 網站與 registry。不刪除、不 unpublish，現有使用者不受影響，只是安裝時看到提示 | 避免新使用者把舊風格當成 SunUI | 可用 `npm deprecate <pkg> ""` 取消 |
| 3 | 停用 `.github/workflows/release.yml` 的自動發佈（推 `v*` tag 就會發佈） | 避免誤推 tag 又發一版舊套件 | 可逆 |
| 4 | 根目錄 `package.json` 裡 lerna、storybook、jest、snyk 的腳本與 `@sunui-design/*` 依賴，PH 之後再清 | 現在清會動到 workspace 與 lockfile，風險大於好處 | 之後再評估 |

第 2 項是對外發佈的動作，需要你確認後才做（也需要你本機有 npm 登入權限）。指令會是：

```bash
npm deprecate "@sunui-design/react@*" "Legacy package. SunUI is now a shadcn registry: https://<網站網域>"
```

其餘 9 個子套件同樣處理。

## 7. 2026-11-22 決定：三個恢復

使用者看完舊版與現在的並排截圖（`.compare/legacy-compare.html`）後判斷：FloatingButton、SocialButton、FilterGrid 跟接班人「完全不一樣」，應該保留。上面第 3 節把它們判為「已取代」或「不做」，是只看能力、沒看樣子的結果，這裡改判。

| 舊元件 | 恢復為 | 保留的樣子 |
|---|---|---|
| FloatingButton | `floating-social` | 角落主按鈕，點開後社群按鈕以花瓣（四分之一圓、分層）、直排或格狀展開 |
| SocialButton | `social-button` | 實心品牌色圓鈕，四個方向的標題提示 |
| FilterGrid | `skill-grid` | 六角形（或圓形、方形）圖示格，分類篩選時格子重新排列 |

同一天使用者也取消了黑白灰限制：「不想要再單調的色調了，請幫我增加色彩，但不要太過 AI」。所以這三個用實心顏色（平台品牌色、logo 原色、淡色底），但不用漸層、光暈與彩色陰影。重做照 `apps/web/DESIGN.md` 的手感、高度、焦點與 reduced motion 規則。
