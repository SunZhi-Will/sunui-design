# 型錄排序與免費付費價值分析

**結論先講**：兩個問題其實是同一個問題。首頁前 35 張卡全是 Pro，是因為排序規則寫成「系列內 Pro 先」；但如果直接改成交叉排，會把另一個問題放大：41 個 Pro 裡有 22 個在自家免費層或別家免費層找得到近親，排在一起時訪客會更確定「免費就夠了」。所以順序要這樣做：(1) 先把 Pro 分級，只讓「免費做不到」的 Pro 站在前排；(2) 用固定比例交叉，每排一張 Pro；(3) 把付費的單位從「再多一個 block」改成「組好的場景」，現有的 Pro block 大多可以直接組進場景，不用寫新元件。

> 【已驗證】表示這次直接讀 repo 量到的；【建議】與【估算】是推論。延續 `免費與付費切分規劃-2026-11-05.md`（方案 C）、`商業模式深度分析-2026-11-06.md`、`首頁顯示方式分析-2026-11-06.md`，不重複其中內容。

## 1. 首頁排序現況【已驗證】

`apps/web/app/(site)/page.tsx` 的排序是：系列（paper → story → showcase → product → motion），系列內 Pro 優先，再依 `addedAt` 新到舊。

結果：

| 位置 | 內容 |
|---|---|
| 第 1 到 35 張 | 全部 Pro（paper 系列的 35 個 Pro） |
| 第 36 到 80 張 | 全部免費 paper |
| 第 81 到 117 張 | story、showcase、product，各段又是 Pro 在前 |
| 第 118 到 145 張 | 動效庫，全部免費 |

桌機三欄等於**前 12 排全是鎖頭**，手機單欄要滑過 35 張卡才看到第一個可以直接裝的東西。首頁英雄區的安裝指令是免費 block，數量條寫著「104 個免費」，但往下滑看到的是一整面 Pro，訊息互相打架，容易被讀成「免費只是誘餌」。

## 2. 為什麼不能只改成交叉

交叉排的直覺是對的，但它會讓相鄰的兩張卡被拿來比較。把 41 個 Pro 一一對照免費層之後，分成四組：

### A. 整頁與檔期場景（5 個）：免費做不到

`campaign-landing`、`black-friday-weekend`、`day-night-hero`、`self-building-page`、`festival-banner`

前兩個是真正把多個 block 組成整頁的（`registryDependencies` 分別引用 7 個與 6 個 Pro block）。`day-night-hero` 與 `self-building-page` 是單一畫面但有完整敘事。`festival-banner` 帶四個檔期預設。

### B. 有獨特機制的招牌（14 個）：免費沒有對應

`physics-cart-jar`、`peel-sticker-coupon`、`bundle-node-builder`、`order-island`、`receipt-printer`、`checkout-button`、`gift-box-reveal`、`fold-invite-card`、`scratch-card`、`prize-wheel`、`gift-card-designer`、`price-history`、`coupon-claim-card`、`stamp-card`

這些一看就知道「這要寫很久」，而且免費層沒有長得像的東西。

### C. 被自家免費層吃掉（16 個）：有免費近親

| Pro | 免費近親 | 訪客會怎麼想 |
|---|---|---|
| `cart-drawer` | `side-panel` + `quantity-stepper` + `addon-checklist` | 自己拼一下就有了 |
| `upsell-drawer` | `side-panel` + `addon-checklist` | 同上 |
| `product-gallery` | `lightbox` + `product-media` | 免費版已經會放大、換圖 |
| `product-filter-grid` | `sliding-tabs` + `range-slider` | 篩選元件都在免費層 |
| `testimonial-wall` | `testimonial-marquee` | 免費版還會動、還有 3D 傾斜 |
| `free-shipping-progress` | `tier-progress` | 都是進度條 |
| `flash-sale-hero` | `countdown-banner` | 免費版就有翻牌倒數 |
| `launch-countdown-wall` | `countdown-banner` | 同上 |
| `loop-shader-hero`、`shader-campaign-banner` | `gradient-backdrop`（9 種）、`background-effects`（13 種） | 免費背景比 Pro 還多樣 |
| `showcase-mosaic` | `infinite-canvas` | 免費的更炫 |
| `launch-stage-hero`、`drop-release-hero` | `depth-hero` + `text-effects` | 免費能做出更花的主視覺 |
| `store-help-widget` | `morph-menu` | 同一個「從角落長出來」的機制 |
| `upgrade-modal` | `dialog-sheet` | 都是對話框 |
| `order-tracker` | `order-history` + `checkout-steps` | 訂單狀態免費就有 |

### D. 通用元件（6 個）：別家免費層都有

`faq-accordion`、`newsletter-signup`、`pricing-cards`、`plan-comparison`、`file-dropzone`、`flash-sale-product-card`

shadcn、Magic UI、各家 blocks 站的免費層都有同類元件。紙感做工再好，訪客也很難為「一個 FAQ」付錢。

**小結**：A + B 共 19 個是站得住的付費理由；C + D 共 22 個，超過一半，放在免費近親旁邊會直接證明「免費就夠了」。

## 3. 為什麼「免費的就很香」：四個結構原因

1. **最驚豔的東西都在免費層。** `book-3d`、`cloth-curtain`、`plush-portrait`、`point-cloud`、`spring-rig`、`orbit-gallery`、`infinite-canvas` 全是免費。訪客看預覽判斷價值，看到的是「免費的會讓人哇，付費的是表單和價目卡」，價值感倒過來了。
2. **免費的程式碼量比 Pro 大。**【已驗證】最大的免費檔 `app-shell` 1,661 行、`book-3d` 1,297 行、`micro-interactions` 1,136 行；最大的 Pro 檔 `cart-drawer` 866 行。前 25 名免費檔都在 560 行以上，Pro 有一半在 450 行以下。「付費的比較費工」這件事從數字上看不出來。
3. **Pro 跟免費是同一個單位。** 41 個 Pro 裡只有 2 個是整頁組合，其他 39 個都是單一 block，跟免費的一樣大小、一樣安裝方式、一樣一張卡。對訪客來說 Pro 就是「另外 41 個 block，剛好上鎖」，而不是「另一種東西」。
4. **Pro 真正多出來的價值是看不見的。** Pro 的強項是狀態完整（空、錯、載入、成功）、四語系、無障礙、CJK 排版、伺服器接點（例如 `prize-wheel` 的 `onSpin`）、JSON-LD。這些在 15 秒預覽裡完全看不出來，卡片上也沒寫。

## 4. 誰會付錢、為什麼付

`商業模式深度分析-2026-11-06.md` 已經把主要買家收窄成**接案者與小型 agency**。他們付錢買的是：

| 他們在乎的 | 現在的 Pro 有沒有給 |
|---|---|
| 一個檔期整頁半天上線 | 只有 2 頁（雙 11、黑五週末） |
| 換客戶品牌色一次改完 | 沒有統一的主題設定 |
| 結帳、加購、集點這些流程接好 | 是分開的 block，狀態沒串 |
| 每檔期都有新素材 | 季節包計畫中，尚未上架 |
| 給客戶用不會有授權問題 | 有（不限專案） |

他們不缺「再多一個 FAQ」。他們缺的是**組好、串好、換色就能交件的東西**。

## 5. 建議：把付費單位從 block 換成場景

不違反兩個既有決定：MIT 已公開的不收回、免費層凍結到 2027-01-12。

### 5.1 用現有 Pro block 組場景，幾乎不寫新元件【建議】

C、D 組的 block 不要再當成賣點，改當場景的零件。每個場景是一個 Pro 項目，有共享狀態與一份主題設定：

| 場景 | 組成（Pro + 免費） | 賣點 |
|---|---|---|
| 結帳流程 | `cart-drawer` → `upsell-drawer` → `checkout-button` → `receipt-printer` → `order-tracker`，共享一個購物車狀態 | 從加入購物車到出貨追蹤，一條線接好 |
| 商品頁 | `product-gallery` + `variant-picker` + `price-history` + `flash-sale-product-card` + `testimonial-wall` + `faq-accordion` | 一頁商品頁含 JSON-LD |
| 會員集點 | `stamp-card` + `tier-progress` + `prize-wheel` + `scratch-card` + `coupon-claim-card` | 會員活動頁一次到位 |
| 新品上市 | `launch-stage-hero` + `launch-countdown-wall` + `newsletter-signup` + `drop-release-hero` | 預告、倒數、開賣三個狀態 |
| 訂閱定價頁 | `pricing-cards` + `plan-comparison` + `upgrade-modal` + `faq-accordion` | SaaS 或會員制定價頁 |
| 檔期整頁 | 現有 `campaign-landing`、`black-friday-weekend`，加上農曆新年 | 已有，接季節包 |

六個場景加上 A、B 組的 19 個招牌，對外的說法就變成「**6 個整頁場景 + 19 個招牌互動**」，而不是「41 個 block」。工時主要在串狀態和主題 token，估計每個場景 1 到 2 天【估算】。

### 5.2 讓看不見的價值看得見【建議】

- Pro 的 block 頁加一段「跟免費版差在哪」：列出免費近親，再列 Pro 多了什麼（狀態、語系、伺服器接點、無障礙測過的項目）。C 組最需要。
- 預覽加狀態切換（空、載入、錯誤、成功），讓「狀態完整」在 15 秒內看得到。
- 定價頁 Pro 欄第一行改寫成場景：「6 個整頁場景，結帳、商品頁、集點、上市、定價、檔期，換一份主題就是客戶的品牌」。四個語系都要改（`lib/messages.ts` 的 `pricing`）。

### 5.3 一份主題設定換掉所有 Pro【建議】

給 agency 最直接的理由：所有 Pro 場景讀同一組 CSS 變數（紙色、墨色、強調色、字體），換一個檔案就是另一個客戶。免費 block 個別也能改色，但沒有「一次全換」的保證。

### 5.4 搭橋，讓免費替 Pro 說話【延用 11/06 報告】

免費的驚豔元件頁底加「在哪個 Pro 場景裡用到」。例如 `theme-picker` 連到 `day-night-hero`、`scripted-demo` 連到 `self-building-page`、`countdown-banner` 連到「新品上市」場景。免費越強，越能證明場景的完成度。

### 5.5 不建議

- **不建議把免費驚豔元件移到 Pro。** 已推上去的是 MIT，收不回；沒推的也違反方案 C。
- **不建議為了拉開差距故意削弱免費版。** 會傷害流量與信任。
- **不建議再新增單一 Pro block。** 加到 50 個還是同一個單位，問題不會變。

## 6. 交叉排序的具體做法【建議】

在 5.1 做完之前也可以先改排序，但要按分級排，不要隨機交叉。

**規則**

1. 「全部」檢視取消系列分段（動效庫仍然排最後，維持 11/06 的決定）。
2. Pro 依 A → B → C → D 排，免費依精選順序排（紙感電商的招牌在前：`add-to-cart-button`、`coupon-wallet`、`copy-code-button`、`book-3d`、`cloth-curtain` 等）。
3. 合併時固定比例：**每 3 張放 1 張 Pro**，Pro 放在每排中間（第 2、5、8 張）。桌機每排一個鎖頭，手機每 3 張一個。41 個 Pro 剛好分布在前 123 張，跟 104 免費 + 41 Pro 的比例吻合。
4. 第一屏（前 6 張）手動精選：2 個 A 組 Pro（`campaign-landing`、`day-night-hero`）配 4 個最強的免費。
5. C 組 Pro **不要**排在它的免費近親旁邊，至少隔一排。

**分級存哪裡**：Pro 清單在私有 repo，分級建議放在 `registry/pro/registry.json` 的 `meta.rank`；免費的精選順序放在 `registry.json` 的 `meta.rank`。公開 repo 沒有 Pro 清單時，排序自動退回純免費，建置不受影響。

**改動範圍**：`app/(site)/page.tsx` 的排序函式，加上兩份 registry 的 `meta.rank` 欄位，約半天【估算】。

**實作紀錄（2026-11-07）**：已上線到首頁，分級沒有放進 `meta.rank`，改成放在 `apps/web/lib/catalog-order.ts` 的名單裡（Pro 名稱在型錄上本來就公開，不用動私有 repo）。結果：第 2、5、8…張是 Pro，前 6 張是 `campaign-landing`、`day-night-hero` 配 4 張免費；C 組 Pro 與免費近親至少隔 4 張；免費卡排完後，剩下 3 個 D 組 Pro 照同樣節奏落進動效庫開頭，不會連排。新增 Pro 時要把名稱加進對應分級，沒加的會排在 Pro 最後。

## 7. 需要你決定的事

1. 交叉排序要不要現在先做（第 6 節），還是等場景組好一起改？
2. 5.1 的六個場景，要不要排進 2026-11-27 Founding 開賣前？若時間不夠，建議先做「結帳流程」和「商品頁」，這兩個最貼近 agency 的日常需求。
3. C、D 組的 22 個 Pro 單品要繼續單獨列在型錄，還是只在場景裡出現？我的建議是繼續列，但卡片標示「屬於某某場景」。

## Conclusion

首頁前 35 張卡全是 Pro 是排序規則造成的，改成每 3 張放 1 張 Pro、Pro 按分級排就能解決。但「免費就很香」才是根本問題：最驚豔的元件都免費、免費的程式碼量比 Pro 大、Pro 跟免費是同一個單位，而且 41 個 Pro 有 22 個在免費層找得到近親。解法不是削弱免費，而是把付費單位換成場景：用現有 Pro block 組出結帳、商品頁、集點、上市、定價、檔期六個整頁場景，加上一份主題設定，讓 Pro 從「另外 41 個上鎖的 block」變成「換色就能交件的整頁」。
