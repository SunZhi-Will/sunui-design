# Tinycharts 參考分析

> 日期：2026-11-05
> 對象：https://april-zhu.com/tinycharts （April Zhu 的付費 Claude skill，免費版 9 種圖、Pro $34.90 共 28 種）
> 產出：`apps/web/registry/free/tiny-chart`（免費 block，paper 系列）

## 一句話結論

它賣的不是插圖，是「**每張圖背後都有一台被檢查過的狀態機**」：按鈕照規則走，不合規則的按鈕不藏起來，而是用一句白話說為什麼不行。插圖（等角手繪鉛筆、紙紋）是付費的價值，**我們只學互動模型與資訊結構，不碰畫風程式與插圖**。

---

## 1. 它是什麼

- 一個 skill：使用者說「畫我們的退款流程」，Claude 挑圖種、寫狀態機、檢查規則，輸出單一 HTML 頁。
- 28 種圖依「要回答什麼問題」分六類，不是依圖形分類：

| 類別 | 圖種 |
|---|---|
| 時間 | 時間軸（照比例）、平行時間軸、時鐘、縮時、時序圖、區間帶 |
| 空間 | 爆炸圖、標註場景、縮放、路線圖、泡泡圖 |
| 順序與分岔 | 流程圖、決策樹、漫畫格、循環、流程機器、看板、桌遊 |
| 流量 | 桑基、漏斗、存量與流量 |
| 誰影響誰 | 時序圖、網路、魚骨、升級鏈 |
| 比較 | 型錄、損益平衡、象限 |

## 2. 拆開一張圖（refunds.html）

| 層 | 做法 | 我們學不學 |
|---|---|---|
| 狀態機 | 一份 `.mmd` statechart，id 對應畫面上的 `data-state` 群組 | 學：資料驅動 |
| 規則檢查 | 建置時跑 `refund.check.mjs`：每個狀態可達、無死路，加上業務規則（「包裹沒回來前不退款」），並用「拿掉某個條件，幾步內會破」來證明條件有用 | 學：做成 `checkMachine` |
| 控制列 | 全部播放、下一步、每個分岔一顆選擇鈕、「邏輯」面板 | 學 |
| 拒絕訊息 | 「Not yet: the parcel is only arrived.」「Too late: already marked worn.」 | 學：這是整套的靈魂 |
| 讀數 | 右上「step 1 of 7 · form sent」＋目前狀態名 | 學 |
| 軌跡 | 走過的路用紅墨描出，小人沿路走 | 學：朱紅描線＋小點 |
| 畫風 | 自寫的筆觸引擎：阻尼彈簧追點讓轉角變圓、壓力變化的填色筆畫、鉛筆紙紋 PNG、套色微錯位、等角投影 | **不學**：付費核心，且引用 Kevin T. Ngo statechart-art（MIT）的筆，我們不搬 |
| 插圖 | 等角小場景（書桌、郵局、倉庫） | **不學**：DESIGN.md 要求中性、不編故事 |

## 3. 我們做了什麼：`tiny-chart`

一台機器、四種版面。選這三種，是因為它們能共用同一份資料形狀，而且都是電商頁真的會用到的：

| layout | 對應它的圖種 | 電商用途 |
|---|---|---|
| `isometric` | 等角場景與人物 | 同 flow，但步驟是立在等角地板上的方塊，旁邊可配小場景（9 種道具：書桌、店面、櫃台、倉庫、包裹、貨車、住家、層架、郵筒），一個穿朱紅上衣的小人跳到目前這一步；適合當頁面主視覺 |
| `flow` | 流程圖、決策樹 | 訂單到哪了、退款流程、付款失敗重試 |
| `timeline` | 時間軸（照比例） | 預購時程、客製商品交期 |
| `cycle` | 循環 | 訂閱盒、會員續約、點數循環 |

API 重點：

- `TinyMachine`：`states`、`transitions`（`on` 事件、`guard` 條件、`label`）、`events`（按鈕文字）、`play`（全部播放的劇本）、`rules`（顯示在邏輯面板的業務規則）。
- 拒絕訊息自動產生：在終點按下一步、在分岔按下一步、在錯的步驟按選擇鈕，各有一句；文字全在 `copy`，四語系都能換。
- `checkMachine(machine)`：連線指向不存在的步驟、到不了的步驟、走不到終點的步驟、同一步同一顆按鈕有兩條路。邏輯面板直接列出結果。
- `useStatechart(machine)`：不畫任何東西的引擎，可以拿去驅動自己的插圖（對應它的「Draw your own」）。
- 手畫感只做到 DESIGN.md 允許的程度：方框四邊略超出轉角，抖動由 id 決定（`sketch` 可關）。沒有紙紋貼圖、沒有漸層。
- 朱紅只有一種用途：「現在在哪、走過哪」（描線、目前框、讀數、可按鈕的小點）。

## 4. 刻意沒做的

- 其他 25 種圖：桑基、漏斗、網路這類是不同的資料形狀，不是同一台機器換版面。真的需要時再各自做，不要塞進這個 block。
- 建置時的變異測試（拿掉條件看幾步會破）：要使用者寫規則斷言，對 block 使用者太重；`checkMachine` 只做結構檢查。
- 它的插圖與筆觸引擎。我們的場景與人物是自己用程式疊出來的平塗等角方塊（`tiny-scenes.tsx`），只共用同一條 30° 投影公式這個通用數學，沒有手繪筆壓、紙紋貼圖或套色錯位。

## 5. 免費或付費（四問）

| 問題 | 判斷 |
|---|---|
| 可替代性 | 低：沒有現成的「可玩、會拒絕的流程圖」shadcn 元件 |
| 製作時間 | 中 |
| 離營收距離 | 遠：說明頁元件，不直接賣東西 |
| 展示價值 | 高：型錄裡一看就懂 |

結論：**免費**，屬於可被 Pro 場景組合的原子（例如 Pro 的活動頁可以用它畫「預購到出貨」）。符合 option C：函式庫免費，Pro 賣組好的場景。
