# m3e-canvas 參考分析：草圖變 prompt 的工具，兩個月一萬星

日期：2026-11-06
參考：https://github.com/lnkiai/m3e-canvas （線上版 https://lnkiai.github.io/m3e-canvas/）
方法：clone 原始碼逐檔讀（`lib/prompt.ts`、`lib/share.ts`、`lib/ai.ts`、`lib/project.ts`、`public/agent.md`、`app/Editor.tsx`、測試與 CI），加上 GitHub API 查數字與 issue。【已驗證】是這次直接查到的，【推論】是判斷。

## 0. 結論先講

1. **它賣的不是元件，是「把畫面翻成 AI 聽得懂的話」。** 核心資產是一個 1,889 行的確定性編譯器（`lib/prompt.ts`），把畫布上的座標翻成「上方一列、左到右、不准折行」「3 欄網格、間距 16dp」這種 coding agent 不會誤讀的句子。元件渲染只是輸入介面。
2. **它最聰明的設計是 `agent.md`：讓 agent 反過來產出設計。** 一份公開的 Markdown 規格教 agent 寫 JSON 文件，再壓縮進網址 `#docz=`，回給使用者一條能直接打開的連結。沒有伺服器、沒有帳號，agent 與人之間多了一條雙向通道。
3. **一萬星，README 只列出 1 位贊助者。** 開源、全免費、只靠 GitHub Sponsors。一份第三方報告（issue #477）直說「護城河第一週就被複製」。對 SunUI 是最直接的反面教材：**星數與營收是兩條不相交的曲線**，SunUI 的 Pro 授權路線是對的。
4. **SunUI 可以借三件事，不用借產品：** (a) 端到端 demo GIF 的敘事結構，直接用在 2027-01-12 的 Product Hunt；(b)「agent 產出組合 → 網址預覽」的協定，可變成 Pro 的轉換引擎；(c) i18n 一致性測試，SunUI 有四種語言卻沒有測試守著。

## 2. 架構拆解

### 2.1 資料模型：一份 JSON 就是全部

`Doc`（`lib/tokens.ts:2349`）只有 `frames`（畫面）、`groups`（元件群組）、主題、調色盤、標題、簡介、手改的 prompt。存檔就是把它 `JSON.stringify` 下載；開檔走 `isProject()` 手寫的形狀驗證（`lib/project.ts`），不用 zod。

- 一個 **group** 是一顆元件，或同族元件的「連體」（按鈕橫排、列表直排）。磁吸效果靠這個：同族靠近就合併成一組，相接處圓角變小。
- 座標全部是畫布座標，畫面歸屬是即時算的（`frameOfGroup`），不存。
- 元件尺寸照 M3 規格分級（按鈕 xs 到 xl 五級），級與級之間線性內插（`onScale`），滑桿拉到哪都還是 M3 的比例。

### 2.2 Prompt 編譯器（核心資產）

`buildPrompt()`（`lib/prompt.ts:1769`）的流程：

1. **建版面樹**（`layoutTree`）：完全包在較大元件裡的元件，掛成它的子節點，所以「卡片上疊按鈕」會寫成「卡片裡面疊放以下內容」。上下 app bar 永遠不當容器。
2. **分列**（`rowsOf`）：垂直範圍重疊、左右不相交的兄弟歸成一列，列內由左到右排序。
3. **偵測網格**（`gridAt`）：連續兩列以上、同種卡片或圖片、左緣對齊誤差 6dp 內、寬度一致，就整段改寫成「N 欄網格，欄距 X、列距 Y，保持 N 欄，不要排成一列或一直疊」。
4. **位置用文字講**（`zone`）：把元件中心落在容器的上 22% / 中 / 下 20%、左 36% / 中 / 右 36%，翻成「靠上、置中」這種措辭；占寬 85% 以上就不講左右。
5. **重疊**：蓋到前一個兄弟 25% 以上面積就加註「部分壓在 X 上，畫在前面」。
6. **樣式說明只給用到的元件**：`STYLE_NOTES` 依 kind 查表，網頁目標另有一套；沒用到的元件不浪費 token。
7. **色票全展開**：亮暗兩套 scheme 的每個 role 都寫進去，agent 不必猜色。
8. **使用者可勾的附加指示**：交付物、測試、深色模式、多語、離線，各一行。

值得注意的寫法：每一句都寫成「禁止誤解」的形式，例如列的描述一定附上「保持同一行、垂直置中、不要堆疊或折行」。這是作者從 agent 實際犯的錯反推回來的防呆句。

代價：四種語言各寫一份生成函式（`itemJa`、`itemEn`、`itemZh`、`itemKo`），每加一種語言要改上千行。法文 PR #463 最後沒有合併【已驗證】，這是可預見的結果。

### 2.3 分享連結與 agent 協定

- `lib/share.ts`：文件剝掉本機圖片與 AI 改寫歷史，`deflate-raw` 壓縮、base64url 編碼，放在 `#docz=` 之後。fragment 不會送到伺服器，所以「靜態站維持靜態」。瀏覽器不支援 raw deflate 時退回 `#doc=` 明文 JSON。
- `public/agent.md`：給 coding agent 讀的規格書。內容包含文件格式、每種元件的欄位與預設尺寸表、Node 與 Python 兩支產生連結的小程式，以及幾條很務實的指令：「不要驗證、不要 decode、不要來回測試，app 開啟時會檢查」「概略擺位就好，使用者按 Tidy 會自動對齊」。
- 同一份 `agent.md` 也是內建 AI 起草功能的 system prompt（`draftDesign`，`lib/ai.ts`）。**人用的 AI 與外部 agent 走同一份規格**，不會兩邊漂移。

這條迴路是：使用者在 Claude Code 說「幫我畫一個食譜 app」→ agent 讀 `agent.md`、寫 JSON、跑 `link.mjs` → 回一條連結 → 使用者打開微調 → 複製 prompt → 貼回 agent 實作。agent 先出草稿，人再修，最後 agent 實作。

### 2.4 AI 助手

- 自帶金鑰（OpenAI、Claude、Gemini、DeepSeek），金鑰存 `localStorage`，瀏覽器直接打供應商 API（Claude 用 `anthropic-dangerous-direct-browser-access`）。
- 每個動作都是固定 prompt、固定 JSON 回覆形狀，只改文字欄位（元件說明、畫面描述），**座標永遠不交給模型**。結果先給作者看，可一鍵復原（`pushHistory` / `popHistory`）。
- 安全面：非 HTTPS 的端點拒絕送金鑰（本機除外）。金鑰放 `localStorage` 對同源 XSS 沒有防護，但靜態站沒有第三方腳本，風險可接受。曾出過把金鑰寫成字面字串的 bug（#472），已修。

### 2.5 程式品質

| 面向 | 觀察 |
|---|---|
| 好 | `lib/` 純函式、幾乎每檔有測試，`i18n.parity.test.ts` 逐葉節點比對四語鍵值；CI 跑 typecheck、test、build；fork PR 的 workflow 權限唯讀 |
| 好 | 相依極少，色彩系統自寫（CIE L\*C\*h 近似 HCT，`lib/color.ts`），不拉 material-color-utilities |
| 差 | `app/Editor.tsx` 4,992 行、66 個 `useState`，所有編輯器狀態塞一個元件；`components/ui.tsx`、`M3Node.tsx` 也各近 2,000 行 |
| 差 | 多語字串寫死在生成函式裡，擴語系成本線性成長 |
| 中性 | 全部 client-side，畫布元件以 React + CSS 自繪，不依賴任何 M3 元件庫 |

## 3. 對 SunUI 的意義

### 3.1 定位差異

| | m3e-canvas | SunUI |
|---|---|---|
| 產物 | prompt（讓 agent 從零寫） | 可安裝的程式碼（shadcn registry） |
| 設計語言 | Google M3 Expressive | 自有紙感風格 |
| 使用者 | 想做 app 的 vibe coder | 做檔期頁的接案者、小型 agency |
| agent 介面 | `agent.md` + 網址 | MCP、skill、`llms-full.txt` |
| 商業 | 全免費，Sponsors | Free 引流、Pro 買斷 |

兩者不競爭。m3e-canvas 證明了一件事：**「讓 agent 用得對」本身就是產品價值**，而 SunUI 的 `meta.usage`、`guidelines.ts`、MCP 走的是同一個方向，方向正確。

### 3.2 可以借的（依投入報酬排序）

1. **Product Hunt 的 demo GIF 照它的敘事結構拍**【建議，低成本】
   一支 15 到 20 秒的循環：在 Claude Code 說「做一個雙 11 活動頁」→ MCP `search_blocks` → `plan_install` → `shadcn add` → 瀏覽器出現完整活動頁，Pro 場景帶出升級訊息。重點是「一口氣從需求到成品」，不是逐一展示 block。這屬於上市工作，不違反免費凍結。

2. **「agent 組頁面 → 網址預覽」協定**【建議，中成本，需決定時程】
   照 `agent.md` 的做法：agent 寫一份「頁面組合 JSON」（選哪些 block、文案、品牌色），壓縮進 `sunui.../compose#docz=`，網站直接渲染整頁。免費 block 正常顯示，Pro block 顯示真實預覽加上解鎖按鈕。這是在 agent 對話裡**讓使用者先看到 Pro 長在自己頁面上的樣子**，比 401 訊息有說服力得多。它不是新的免費 block，是轉換工具，但工作量不小，建議排在 11/27 Founding 開賣之後、PH 之前評估。

3. **i18n 一致性測試**【建議，小成本】
   SunUI 的 `lib/messages.ts`（四語）與 `content/registry-i18n/*.json`（三語）目前沒有測試確認每個鍵四語齊全。照 `i18n.parity.test.ts` 的逐葉比對寫一份，之後改文案漏翻會直接在 CI 失敗。

4. **給 agent 的防呆句**【建議，小成本】
   m3e-canvas 的每條 prompt 都附「不要做什麼」。SunUI 的 `meta.usage.watchOut` 已有這個精神，可檢查高流量 block 是否都寫了，尤其是排版類（網格不要塌成一欄、價格不要折行）。

5. **四語 README 與圖片按鈕**【可選】
   對中日社群的擴散很有效。SunUI 已有四語網站，README 可比照。

### 3.3 不要借的

- **全免費 + Sponsors 的商業模式。** 一萬星換來一位贊助者，第三方分析直指護城河一週被複製。SunUI 的護城河要放在 Pro 場景與檔期內容的持續產出，而不是工具本身。
- **巨型單一元件。** 4,992 行的 `Editor.tsx` 對獨立開發者短期有效，但貢獻者難以進入。SunUI 的 block 本來就是小檔案，維持現狀。
- **每語言一份生成函式。** 如果 SunUI 之後也做 prompt 或組合描述的產生器，用「一份結構 + 語言字典」的寫法，不要複製它的四份分支。

## 4. 一句話

m3e-canvas 的成功來自「時機 + 零門檻 + 一張講完故事的 GIF + 讓 agent 不會誤讀的輸出」，它的弱點是沒有生意。SunUI 已經有生意的骨架，該向它學的是**展示方式與 agent 協定**，不是產品形態。
