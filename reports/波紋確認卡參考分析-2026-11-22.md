# 波紋確認卡（wave-confirm）參考分析

> 2026-11-22。來源是 Abraham John（@Abmankendrick）在 X 的貼文，介紹一套叫 Distortion Waves 的免費效果庫，附一支 13 秒、1066×720 的錄影（x.com/Abmankendrick/status/2123689441084522798）。貼文裡沒有原始碼連結，技術拆解是逐格看錄影推回來的。【已驗證】表示這次在瀏覽器實際看過；【推論】是從錄影反推；【估算】【建議】是判斷。

## 0. 結論先講

1. **招牌只有一個：狀態改變時，一道波從按鈕的位置往上掃過整張卡，新狀態跟著波一起「長」出來。** 貼文列出的邊緣光、預備動作、色差、粒子，都是掛在這道波上的配件。拿掉配件，波本身仍然成立；拿掉波，配件就只是光暈和閃爍。【推論】
2. **值得做，而且只能做成 Pro。** 免費型錄凍結到 2027-01-12；這也不是「更多效果變體」，而是轉帳、儲值、付款這種直接要錢的確認流程。放 showcase 系列，跟 card-dock、liquid-glass-nav 同一條路線。【建議】
3. **不照抄長相。** 原作的虹彩邊緣光（粉、紫、橘、藍）和粒子都在 `DESIGN.md` 的禁止清單上。帶走的是「波帶著新狀態走過去」這個行為；邊緣光改成跟著波走的中性光（成功時染一點品牌專色），色差預設做成單色的殘影，彩色分光留成選項，粒子不做。【建議】
4. **零相依。** 一個 SVG 濾鏡（雜訊加位移圖），濾鏡參數由 rAF 直接寫，靜止時不掛濾鏡、不跑迴圈；新舊兩層內容用遮罩跟著波的位置交接。沒有 WebGL、沒有 canvas。【已驗證】

## 1. 錄影逐項拆解

逐格取樣 0.5、1.0、1.5、2.1、2.5、3.5、5.0、6.5、8.5、11 秒。畫面裡有四個元件：轉帳確認卡、儲值卡、USDC 傳送膠囊、投資人更新卡。【已驗證】

| 時間 | 畫面 | 怎麼做的（推論） | 判斷 |
|---|---|---|---|
| 0.5s | 轉帳卡「Sending to Maya Chen $1,250.00」，按下 Confirm；整張卡文字出現紅藍錯位，卡片四邊亮起虹彩光 | 按壓瞬間就開始：色差（RGB 三通道各自位移）加邊緣內發光 | 色差帶走成單色殘影；邊緣光改中性 |
| 1.0s | 整張卡糊成一片，水平拉絲，下半部有彩色光帶，Confirm 按鈕還清楚 | 一道水平帶狀的位移加模糊，從底部往上走；按鈕在波的起點，已經走過 | **帶走**，這就是招牌 |
| 1.5s | 卡片已變成「Sent to Maya Chen」、綠色勾、Arrived 9:41 AM、按鈕變 Done；邊緣光還在退 | 波走過的地方換成新內容，波到頂後光慢慢退掉 | **帶走**：新內容在波後面出現，不是整塊淡入 |
| 2.1s | 儲值卡從「Processing...」變「Credits added」，這次的波是綠色 | 成功用綠色的波 | 帶走，綠色改成買家的品牌專色 |
| 3.5s | USDC 膠囊被一道波從左往右掃，「Sending」變「Sent」 | 同一個效果，橫向 | 帶走，做成膠囊版 |
| 3.5s | 投資人卡被波掃過，標題從「Q3 at a glance」換成「A strong third quarter」 | 內容更新（AI 改寫）也用同一個波 | 記下用途，demo 不做 |
| 5.0s | 鏡頭推近轉帳卡，卡片往後傾斜 | 3D 預備動作：按下時卡片後仰，像被壓了一下 | **帶走**，做成按下時的預備動作 |
| 6.5s | 推近看：金額和列文字有清楚的紅藍邊，下半部是粉紫光帶和細小白點 | 色差加粒子 | 色差帶走成殘影；粒子不做 |
| 8.5s 到 11s | 膠囊推近，傾斜；完成後出現 View 按鈕 | 完成後多一個次要動作 | 帶走 |

為什麼有效：確認付款最怕「按了沒反應」和「不確定有沒有成功」。這道波把「送出去了」畫成一個從手指位置出發、走完整張卡的動作，使用者的視線被帶著從按鈕走到頂部的結果，剛好讀完每一列變了什麼（Sending → Sent、In seconds → 9:41 AM、Confirm → Done）。這比一個打勾圓圈多交代了一件事：**哪些資訊因為這次動作而改變**。

## 2. 跟 SunUI 規則的衝突與取捨

| 原作元素 | 規則 | 處理 |
|---|---|---|
| 虹彩邊緣光（粉紫橘藍） | 禁止多色相、光暈、彩色陰影 | 改成跟著波走的中性內緣光；成功時染品牌專色，不透明度壓在 0.35 以下。showcase 系列有 card-dock 的染色光池先例 |
| 色差（RGB 錯位） | 禁止多色相；Glitch Text 列在避免清單 | 預設 `spectrum="neutral"`：同色的殘影，讀起來是光學的模糊，不是彩色故障。`spectrum="prism"` 才分光，給暗色上市頁用，文件寫清楚 |
| 粒子 | 禁止粒子、彩帶 | 不做。波的雜訊紋理已經有細節 |
| 模糊 | 動效字典寫「SunUI 不用模糊」，指的是 Blur In 進場 | 這裡的模糊只在波帶內、只在狀態改變的那 0.7 秒，是轉場的一部分，不是進場效果；reduced motion 完全不模糊 |
| 預備動作（卡片後仰） | 避免「3D Tilt 跟著游標」 | 不跟游標。只在按下的那一下後仰約 4°，用 snappy 彈簧回來，是按壓重量的延伸 |
| 動畫長度 | 單次 400ms 內，多步依序 | 拆成三段：預備 140ms、波走 380ms、光退與位移歸零 300ms |
| 整塊換內容 | 連續性：同一個外框、留錨點 | 外框不動；金額與頭像位置是錨點；新舊內容由波的位置交接，不是交叉淡化 |
| 結果標記 | 正面結果要用 `Result` 圓片 | 完成狀態的頭像位置換成品牌色小圓片加勾，pop 回彈一次（卡片版沿用 `Result` 的圓片做法，不壓在內容上） |

## 3. 和現有 block 的差別

用 wave、ripple、distortion、confirm、transfer、payment 比對免費與 Pro registry：【已驗證】

| 現有 | 差在哪 |
|---|---|
| `checkout-button`（Pro） | 付款成功後印收據，是收據機的隱喻；這裡是同一張卡被一道波改寫 |
| `order-island`（Pro） | 同一個膠囊依序變形，靠外框寬度變化；沒有掃過內容的波 |
| `confirm-button`（免費） | 按兩次確認，沒有卡片與轉場 |
| `payment-status-banner`（免費） | 回到頁面的狀態橫幅，輪詢；沒有轉場 |
| `card-effects` border-beam（免費） | 邊框上跑一段光，是 hover/處理中狀態；這裡的光是波的一部分，只在狀態改變時出現 |
| `liquid-glass-nav`（Pro） | 同樣用 SVG 位移濾鏡，但它是常駐的折射玻璃；這裡是一次性的轉場 |

四個問題（`免費與付費切分規劃-2026-11-05.md`）：
- **可替代性低**：Magic UI、React Bits 有 glitch 字、border beam，沒有「新狀態跟著波一起長出來」這種把轉場和資料交接綁在一起的元件。原作 Distortion Waves 本身是設計稿與影片，不是 React 元件。
- **工時中**：濾鏡調校（雜訊頻率、帶寬、位移強度）、雙層遮罩交接、預備動作與 async 狀態，約 1 天。【估算】
- **商業距離很近**：轉帳、儲值、付款、訂閱升級的確認卡，都是直接要錢的頁面。
- **展示價值高**：型錄卡片按一下就懂，也是 Product Hunt 影片的好素材。

## 4. 元件設計

```
WaveSurface      通用：stateKey 一換，舊內容被一道波推走，新內容跟著波出現
 ├ direction     "up"（卡片，從底部按鈕往上）或 "right"（膠囊，從左往右）
 ├ tint          "neutral" | "spot"：邊緣光的顏色
 └ spectrum      "neutral"（單色殘影，預設）| "prism"（分光）
WaveConfirmCard  轉帳/儲值確認卡：頭像或圖示錨點、標題、金額、明細列、主按鈕
                 idle → 按下（後仰）→ processing（await onConfirm）→ done（品牌色波）
                 error 不放波：按鈕變重試，狀態列說明沒有扣款
WaveStatusPill   狀態膠囊：pending（轉圈）→ done（勾 + 次要動作），橫向的波
```

### 4.1 波怎麼做

一個 SVG `<filter>`，用 `userSpaceOnUse` 以像素為單位：

1. `feTurbulence` 產生拉長的雜訊（往上的波用水平拉絲 `0.004 0.09`，橫向的波反過來），alpha 設成 1。
2. `feFlood` 用子區域（`y`、`height`）畫出一條波帶，`feGaussianBlur` 把邊緣柔化。rAF 每一格改它的 `y`，波帶就在走。
3. 雜訊 `in` 波帶，再疊在 50% 灰上，得到「只有波帶裡有起伏、其他地方是中性灰」的位移圖。中性灰代表不位移，這一步不做的話整張卡會被平移半個強度。
4. `feDisplacementMap` 用這張圖推動內容；同一條波帶內再疊一層水平模糊，做出錄影裡的拉絲。
5. 色差：`neutral` 把位移結果再偏移幾像素、降到 35% 疊回去（殘影）；`prism` 把 R、G、B 三通道各自偏移再相加。兩種都只在波帶裡出現。

濾鏡只在轉場那 0.7 秒掛在內容上，結束就拿掉：靜止時零成本，也不會讓文字一直被重新點陣化。

### 4.2 新舊內容交接

舊內容在轉場時以 `absolute` 疊在新內容上，`inert`、`aria-hidden`。兩層各有一個 `mask-image` 線性漸層，邊界放在波帶中心：波下方（已經走過）顯示新內容，上方顯示舊內容。邊界有 24px 柔邊，剛好藏在模糊最重的位置，所以看不到切線。

### 4.3 邊緣光

外框上一層 `pointer-events: none` 的內陰影（`inset 0 0 22px`），用同一條波帶當遮罩：只有波經過的那一段卡緣會亮。這層不進濾鏡，所以邊緣光是乾淨的，不會被扭曲。

### 4.4 無障礙

- 狀態變化用 `role="status"` 的隱藏文字播報（「已送出 $1,250.00 給 Maya Chen」）。
- 處理中按鈕 `aria-busy`、`disabled`。
- reduced motion：沒有預備動作、沒有濾鏡、沒有遮罩，直接切換；資訊完整。
- 動畫只在使用者按下或資料改變時跑，沒有常駐迴圈。

## 7. 第二輪：原作怎麼做的（2026-11-22 猜解）

使用者看了第一版後說「原作比較帥」，並要求去 libraries.dev/waves 猜解，做出獨屬於 SunUI 的樣式。以下是在原作頁面實際檢查 DOM 與載入的程式後得到的結論。只讀結構，沒有複製任何程式碼。【已驗證】

| 觀察 | 證據 | 意思 |
|---|---|---|
| 卡片上疊一張 WebGL2 canvas（380×447，2 倍解析度，`border-radius` 跟卡片一樣） | 動畫中 `document.querySelectorAll('canvas')` | 光與扭曲都在 GPU 上畫，不是 CSS |
| 程式裡有 `foreignObject`、`drawImage`、`texImage2D` | 下載的 chunk 計數 | 先把兩個狀態的 DOM 截成圖（SVG foreignObject 轉成圖片），再當貼圖丟給 shader 混合 |
| uniform 有 `uC0..uC2`、`uR0..uR2`、`uPoint` | shader 原始碼的 uniform 清單 | 波前由三個圓組成，從按下的點長出來，所以是圓頂 |
| `uLens`、`uLensWidth`、`uAmplitude`、函式 `lensed` | 同上 | 波前是一片透鏡，內容在那裡被放大折射（設定面板叫 Swell，34pt） |
| `uAberration`、`uBlurAhead`、`uBlurBehind`、`uStep`/`uSigma`/`uLod` | 同上 | 前後各有模糊（預先做好幾層模糊貼圖），加上色差 |
| `uPal`、`paletteAt`、`oklabToSRGB`、`perimeterAt`、`rimThickness`、`uLumps`、`uHair*` | 同上 | 邊緣光沿著卡片周長取色（OKLab 調色盤），厚度不均（lumps），外加一條白色細線 |
| 設定面板：Duration 3.62s、Swell 34pt、Edges 14pt；Vertical / Center / Horizontal / Diagonal；Touch orientation | 頁面文字 | 很慢、很重的轉場；按壓方向與斜向是付費功能 |

## 8. SunUI 日出波：獨屬於 SunUI 的樣式

原作的招牌是「彩虹圓頂」。SunUI 不跟它比彩虹，把品牌名字變成動態本身：**一道從你按下的點升起的日出**。

| 面向 | 原作 | SunUI 日出波 |
|---|---|---|
| 波前形狀 | 三個圓組成的圓頂 | 寬而平的橢圓波峰，表面有液體般的晃動（fbm 雜訊），從按下的確切位置升起 |
| 顏色 | 固定彩虹，按周長取色 | 波峰金色，後面的天空依深度從金色冷卻成珊瑚、洋紅、靛藍，中心保持暗色；`palette` 可換 sunrise、dusk、tide、mono 或自訂四色 |
| 細節 | 粒子、白色細線 | 太陽光芒：最高點一個光點加一道水平光線；波峰旁短短的刻蝕光（caustics），取代粒子 |
| 預備動作 | 畫面被拉向按鈕 | 卡片以按下點為原點縮向手指並微微後仰，波峰出發時用帶回彈的彈簧放開 |
| 邊緣 | 留下彩色邊 | 留下溫暖的餘暉，從金色到靛藍依高度漸變，再慢慢退掉 |
| 時間 | 3.6 秒 | 波峰 1.05 秒、餘暉 0.75 秒 |
| 技術 | DOM 截圖成貼圖，整張在 WebGL 裡合成 | 內容保持真的 DOM（文字可選、可讀、無需截圖），只有光是 WebGL；內容的抹開與分光是 SVG 濾鏡，新舊內容用跟波峰同形狀的橢圓遮罩交接 |

不截圖的好處：不用處理字型、圖片跨網域、截圖延遲；螢幕閱讀器一直讀得到內容；沒有 WebGL 時仍有遮罩交接與抹開。代價：做不到原作那種透鏡放大，改用位移與分光表現扭曲。

光的 shader 是 SunUI 自己寫的（WebGL 1、單一片段著色器）：橢圓距離場決定波峰，`sky()` 依波峰後的深度取色，fbm 產生晃動與刻蝕光，圓角矩形距離場畫邊緣光，最後加抖動避免色帶。canvas 用 `mix-blend-mode: screen` 疊在卡片上，所以黑色等於沒有光，只會讓底下變亮。

和設計文件的關係：這是 showcase 系列的招牌時刻，使用者在 2026-11-22 明確要求彩色與更強的效果，所以超出 `DESIGN.md` 的「400ms 內、無光暈」規則。它只在使用者按下確認時跑一次，reduced motion 完全關閉。

比對圖：`.compare/wave-original-vs-sunrise.png`（上排原作，下排日出波，同樣四個時刻）。

## 9. 第三輪：更多變化（2026-11-22）

使用者問「能否做更多變化」，四個方向全選。都做成同一個 `WaveSurface` 的參數，不是另外的元件。【已驗證】

| 方向 | 參數 | 選項 |
|---|---|---|
| 波的形狀 | `shape` | rise（從按下處升起，預設）、ring（從按下處圓環擴散）、sweep（由左往右）、diagonal（從左下角斜上）、drop（從上往下落） |
| 光的性格 | `light` | sun（太陽光芒加刻蝕光，預設）、eclipse（銳利的日蝕光環與鑽石環亮點）、sparks（波峰附近閃爍的火花點）、lens（白色細鏡緣加紅藍色散）、mist（寬而柔的霧光，無線條） |
| 色盤 | `palette` | sunrise、dusk、tide、mono、ember、sakura、aurora、brand（波開始時讀 `--sunui-spot` 或 `--primary`，畫一個像素轉成 sRGB，再推出四個色階），或自訂四色 |
| 場景（demo） | 用 `WaveSurface` 組成 | 付款（ring · ember · sparks）、升級 Pro（drop · aurora · eclipse）、AI 改寫（sweep · tide · lens）、通行金鑰登入（diagonal · sakura · mist） |

做法：形狀只換原點、橢圓拉伸比與行進方向（`geometry()`），從畫面外開始的形狀直接從最近的一點起跑；shader 加 `uDir`（光芒與邊緣光的方向）與 `uMode`（五種光的分支）。抹開與分光的方向跟著行進方向。

比對圖：`.compare/wave-variations.png`。

注意：每個正在用的 `WaveSurface` 會在第一次起波時建一個 WebGL context，瀏覽器大約 16 個上限；同一頁別放超過十來個。

## 10. 效能最佳化（2026-11-22）

量法：無頭 Chromium（Metal GPU），按下轉帳按鈕，只在光亮著的那 1.8 秒記錄每一格的間隔。桌機 1280 寬、2 倍密度；手機模擬 390 寬、3 倍密度、CPU 降速 4 倍（GPU 無法降速，所以手機數字對 shader 是偏樂觀的）。各跑 3 次，第 1 次就是「第一次起波」。【已驗證】

| 情境 | 改前 | 改後 |
|---|---|---|
| 桌機第一次起波，最慢一格 | 250 ms（6 格超過 33 ms） | 16.8 ms（0 格） |
| 桌機之後幾次 | 57.8 到 60 fps，最慢 83 ms | 60 fps，最慢 16.8 ms |
| 手機模擬第一次起波，最慢一格 | 66.6 ms | 16.8 ms |
| 手機模擬之後幾次 | 60 fps | 60 fps |

改了什麼：

1. **預先暖機**：卡片進入畫面附近（200px）時，在瀏覽器閒置時建立 WebGL、編譯 shader 並空畫一次。第一次起波的卡頓就是這一步，現在不會落在按下的那一刻。
2. **離開畫面就釋放**：卡片離開畫面 3 秒後呼叫 `WEBGL_lose_context` 釋放，回來時再暖機；波正在跑時不會釋放。一頁同時佔用的 context 只剩看得到的那幾個，避開瀏覽器約 16 個的上限。
3. **解析度預算**：桌機最多 2 倍，手機（粗指標）與 4 核以下的機器最多 1.5 倍，再設總像素上限（桌機 90 萬、手機 50 萬）。手機上的轉帳卡從約 66 萬像素降到約 37 萬（少 44%），光是柔的，看不出差別。
4. **shader 減量**：晃動雜訊 4 層改 3 層；刻蝕光只在波峰後方近處計算；霧光改 2 層雜訊；波峰前方很遠的像素直接只算邊緣光就結束（波剛出發時這是大部分畫面）。
5. **不變的 uniform 只設一次**：每一格只更新波峰位置、亮度與時間。
6. **Safari 與 iOS**：WebKit 把套在 HTML 上的 SVG 濾鏡放在 CPU 算，改用 CSS `blur()` 做抹開（GPU 加速）；光與遮罩交接不變。

沒做到的：GPU 單獨計時在無頭模式不可信（回報的每次繪製時間低到不合理），所以 shader 省下多少沒有量化；Safari 與真機尚未實測。
