# 其他元件庫怎麼設計首頁：深度分析

2026-11-19。看了 12 個 React / Tailwind 元件庫的首頁，目的是回答：SunUI 現在的首頁（2026-11-19 重製版）和同類比，哪裡對了、哪裡還可以更好。

方法與限制：每一站都抓了首頁的文字結構（標題、按鈕、每一段的順序、數字、社會證明），並實際打開看了首屏。沒有逐段往下截圖，也沒有量轉換率，所以這份講的是「大家怎麼做」，不是「哪種做法賣得最好」。Motion Primitives 擋掉了自動抓取，那一站只有首屏和頁面文字。

## 2. 所有人都在做的事

**開場的文字量很少。** 標題 3 到 9 個字，下面一句話，兩顆按鈕。十二站沒有一站在開場放第二段說明。SunUI 現在的開場（兩行標題、一句、兩顆按鈕）是合格的。

**兩顆按鈕的分工固定。** 第一顆永遠是「看元件」（Browse Components、Get Started、View Components）。第二顆是下一個最想要你做的事：付費站放 Pro（Aceternity 的 Get All-Access、HeroUI 的 Explore HeroUI Pro），免費站放 GitHub（Mantine、Motion Primitives）。SunUI 的「瀏覽區塊」加「看 Pro 場景」屬於付費站的配法，對。

**數字寫在最顯眼的地方。** Magic UI 寫在副標（150+ free and open-source animated components），Aceternity 寫 200+，Mantine 寫 120 個元件與 70 個 hooks。Cult UI 最直接，把數字寫在按鈕上：「Browse 154 components」，副標是「154 animated components, all free.」

**標題上方有一顆公告小標籤。** shadcn（New：最新元件）、Magic UI（Introducing Dither Field）、Cult UI（58 new components）、Aceternity（Changelog）。內容都是「最近新增了什麼」，不是口號。SunUI 現在放的是創始會員開賣日，用法一樣。

**幾乎都是黑白灰。** shadcn、Cult UI、Animate UI、Motion Primitives、HeroUI 的外殼是純黑白，顏色只出現在被展示的元件裡。有重點色的是 Aceternity（藍）、React Bits 與 Untitled UI（紫）、Mantine（藍），都是老牌或付費站。SunUI 維持黑白灰是主流做法，不是缺點。

**給 AI agent 的段落已經是標準配備。** 十二站裡有七站在首頁講 agent：Aceternity（Copy, paste, or build with your AI agent.）、Animate UI（Ask for motion in plain words.）、Mantine（Built for the AI-assisted workflow）、HeroUI（Supercharge your AI workflow.）、21st.dev（For agents）、Untitled UI（AI-ready kits），daisyUI 甚至把開場第一顆按鈕給了「Official MCP Server」。SunUI 有這一段，位置在中後段，可以考慮往前。

## 3. 真正分出高下的地方：首頁是「展示」還是「介紹」

十二站可以分成兩種。

**展示型：首頁本身就是產品。** shadcn、Animate UI、Motion Primitives、Cult UI。標題一結束就是可以操作的元件，幾乎沒有段落標題，更沒有說明文字。

- shadcn 做得最徹底：開場下面沒有任何行銷段落，就是一整面即時元件（表單、圖表、滑桿、聊天框），全部是同一套風格、同一個假想產品的資料。整頁沒有一句「為什麼選我們」。
- Animate UI 的第一段標題是「Every primitive, alive.」，副標只有「Go ahead, play with them.」，然後是一格一格的開關、分頁、手風琴，每一格都能按。
- Cult UI 的段落標題短到只有兩個字：「Just added」「Try one」。

**介紹型：首頁是一份銷售頁。** Aceternity、HeroUI、Untitled UI、Mantine、daisyUI。十二段上下，有品牌牆、功能卡、使用者推文、YouTube 影片、FAQ、價格表。

這兩種的分界很清楚：**免費或新的庫走展示型，有大量付費內容與大量既有用戶的庫走介紹型。** 介紹型需要的材料（38 萬設計師、12 萬用戶、Google 與 Spotify 的標誌、四十則推文）是累積出來的，沒有這些材料卻硬做介紹型，頁面就會被文字和空洞的段落撐長。

SunUI 現在的位置在中間偏介紹型：九段，但沒有任何社會證明可以放。上一輪你說「不用太多文字描述」，其實就是在把它往展示型推，方向是對的。

## 4. 各段落別人怎麼處理

**元件展示。** 展示型的站把它放在開場正下方，而且量大（shadcn 一屏就有二十幾個元件）。介紹型的站放六張卡加「看更多」（Aceternity：Free animated components，六張加 Show more components）。沒有一站在首頁放完整型錄與篩選器，SunUI 把型錄搬到 `/blocks` 是所有人的做法。

**安裝方式。** 把指令放在開場的只有 Animate UI（它的賣點就是「一行指令」）。其他站把安裝留給文件頁，或放在頁面最下面（daisyUI）。SunUI 把指令放在開場按鈕下面，是少數派，但還算合理，因為「shadcn 一行安裝」是賣點之一。

**付費產品。** 三種放法：最上方一條橫幅（Magic UI）、開場第二顆按鈕加中段一整段（HeroUI、Aceternity）、首頁直接放價格表（Untitled UI，五個方案）。Cult UI 的說法值得注意：它有一段叫「Cult UI stays free」，直接講免費的部分靠付費產品養。

**社會證明。** 有的放很多（daisyUI 約四十則推文、Untitled UI 十四則附五星評價），沒有的就完全不放（shadcn、Animate UI、Cult UI 一則都沒有，只在導覽列放 GitHub 星數）。沒有人放假的或空的。

**agent 段落的呈現。** Animate UI 用聊天對話的樣子：使用者說一句人話（幫儲存按鈕加動畫），下面是結果。Aceternity 用八張成果圖。Mantine 放一段示範用的 prompt。都是「一句話進去、成品出來」，沒有人畫流程圖。SunUI 現在是三步驟的流程示意，比別人抽象。

| 項目 | 同類的做法 | SunUI 現況 | 判斷 |
|---|---|---|---|
| 開場文字量 | 標題、一句、兩顆按鈕 | 相同 | 對 |
| 按鈕分工 | 看元件加 Pro | 相同 | 對 |
| 公告小標籤 | 最新消息 | 創始會員開賣日 | 對 |
| 黑白灰 | 主流 | 是 | 對 |
| 首屏視覺 | 即時元件，或成品截圖 | 七個即時小元件 | 對，而且比多數站更接近產品本身 |
| 完整型錄不放首頁 | 全部如此 | 已搬到 `/blocks` | 對 |
| 數字 | 寫在副標或按鈕上 | 寫在副標，另外還有一整段四張數字卡 | 重複了，數字卡那段可以拿掉 |
| 段落數 | 展示型 0 到 6 段 | 9 段 | 偏多 |
| 段落標題 | 兩到四個字 | 一整句（讓一個頁面活起來需要的，都在這裡。） | 偏長 |
| 可搭配的技術 | 多數不放，放的也只是一排小圖示 | 獨立一段文字列 | 可以併進別處或拿掉 |
| 免費元件展示 | 開場正下方 | 排在第八段 | 太後面 |
| agent 段落 | 一句話進、成品出 | 三步驟流程示意 | 可以更具體 |
| 社會證明 | 有就放，沒有就不放 | 沒有 | 對，等有真的再放 |
| GitHub 星數 | 幾乎都在導覽列顯示數字 | 只有圖示 | 星數還少的話維持現狀 |

## 6. 建議

依影響大小排序。都是建議，還沒有動程式。

1. **把首頁推到展示型，段落從九段減到六段。** 順序改成：開場加小元件桌、免費區塊九張（從第八段提到第二段）、Pro 場景、比較示範、agent、價格加收尾。拿掉「可搭配」文字列和「裡面有什麼」四張數字卡，這兩段都是在「講」而不是在「給人看」。
2. **數字放到按鈕上。** 主要按鈕從「瀏覽區塊」改成「瀏覽 194 個區塊」，副標可以再短。這是 Cult UI 的做法，一顆按鈕同時回答「有多少」和「下一步」。
3. **段落標題縮到兩到四個字。** 例如「免費區塊」「Pro 場景」「差在哪裡」「交給 agent」。現在每段上面有灰色小標、下面又有一整句大標題，兩層說的是同一件事，留一層就夠。
4. **agent 段落改成一句話對一個成果。** 左邊一句人話（幫我做雙 11 活動頁），右邊是裝好的區塊在跑。比三步驟流程圖直接，也和首頁其他段落「給人看」的做法一致。
5. **維持不做的事。** 不加品牌牆、推文牆、FAQ、價格表。這些是介紹型站的材料，SunUI 還沒有，放了只會變長。

## 7. 這份分析沒有回答的

- 哪一種首頁轉換率比較高。沒有任何一站公開數字。
- 各站的手機版長什麼樣。這次只看了桌機寬度。
- 各站首屏以下的實際視覺。段落順序與標題是從頁面文字整理的，除了首屏以外沒有逐段截圖確認。
- Aceternity 首頁上的數字自己對不上（元件寫 100+ 也寫 118+，區塊寫 183+ 也寫 200+），引用它的數字時要小心。
