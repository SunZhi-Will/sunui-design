# 首頁為什麼普通無趣：深度分析

2026-11-20。對象是現在的首頁（`apps/web/app/(site)/page.tsx`、`components/home/`，2026-11-19 的元件牆版本）。這份只有分析與方向，沒有動程式。

方法：在 1440 寬把 SunUI 首頁從頭到尾逐段截圖，再用同樣的寬度實際打開八個網站的首頁並往下捲：shadcn/ui、React Bits、Aceternity UI、Skiper UI、Motion、Osmo Supply、Devouring Details、animations.dev。前四個是元件庫，後四個是「賣動效與手感」的產品，這次特別加進來，因為 SunUI 賣的是後者。

## 1. 結論

**首頁不是做得差，是長得跟預設值一樣。** 把 SunUI 首屏和 shadcn/ui 首屏並排，是同一張圖：置中的公告小標籤、置中的兩行標題、一句灰字、兩顆按鈕、下面一整面深灰色的小卡片牆。上一輪我把「別人都有元件牆」當成答案，結果做出了所有元件庫裡最常見的那個輪廓。

標題寫的是「少一點閃爍，多一點手感」，但畫面上沒有任何一樣東西讓人在三秒內感覺到手感。訪客看到的是「又一個 shadcn 系的元件庫」，而且是灰色的那種。

## 2. SunUI 首頁逐段看到的

| 位置 | 實際畫面 | 問題 |
|---|---|---|
| 首屏 | 標題 72px，下面四欄深灰卡片：商品卡、星等、通知開關、配送方式 | 和 shadcn 首屏同構圖。卡片內容是一般的表單控制項，靜止的一眼看不出哪裡有質感 |
| 元件牆下半 | 優惠碼、尺寸、購物車、長條圖、倒數、亮度滑桿 | 都在動，但每個動作只有幾十像素大，放在 330px 寬的卡片裡。整面牆沒有主角 |
| 免費區塊 | 標題加四欄卡片 | 預覽被裁切（「靜水」兩個字被切掉、「陶馬克杯」貼到邊緣）。卡片大小和上面的牆一樣 |
| Pro 場景 | 標題加四欄卡片 | 要賣錢的東西只有縮圖大小。四張四種畫風（藍黑、紫粉、白底、星雲） |
| 差在哪裡 | 置中一個 670px 寬的對照框 | 全頁唯一在「證明」標題的東西，排在第四段，而且是全頁最窄的一段 |
| 交給 agent | 一句話加三張卡片 | 還是同一種卡片 |
| 價格、收尾 | 一個框、一句話、兩顆按鈕 | 正常，沒有記憶點 |

把這些合起來，有五個根因。

### 2.1 輪廓和別人一樣

元件庫首頁有一個所有人都認得的輪廓，SunUI 完整照做了。看過的八站裡，讓人記得住的那幾站都刻意避開它：

- **React Bits**：標題靠左，下面是一整塊會流動的波浪背景，上面浮著程式碼和預設值面板，面板切到哪個預設值，背景就變成那個樣子。
- **Osmo**：標題字大到從螢幕左邊撐到右邊，下面的作品卡排成一個大弧形，被螢幕下緣切掉，捲動時整個弧跟著轉。
- **Skiper UI**：整個首屏是一片藍色的流體，中間一行很粗的窄體大字。
- **Motion**：首屏中間一顆金色粒子球，文字壓在左下角。
- **Devouring Details**：灰底上一張白紙，一條橘色水平線跟著你捲動走，開頭不是標題而是一個問句。

每一站都只有**一樣**東西是招牌，但那一樣是它自己的。SunUI 現在沒有那一樣。

### 2.2 沒有大小對比

全頁最大的是 72px 的標題，其次就直接掉到 30px 的段落標題，然後是一百多張差不多大的小卡片。七段裡有四段是「標題加四欄卡片」，卡片尺寸完全相同。捲動的時候畫面的節奏沒有變過。

Osmo 的同一頁裡有滿版大字、傾斜的卡片、一個佔半個螢幕的圓、一張紫色的人像。Aceternity 的展示區是白卡片和黑卡片交錯、大小不一、還有格線。尺寸落差本身就是視覺上的刺激。

### 2.3 黑白灰用成了「只有灰」

黑白灰不是問題。React Bits 的波浪切到 Silk 預設值的時候整個畫面是灰階的，一樣很好看；Devouring Details 幾乎沒有顏色。問題是 SunUI 把黑白灰用在很窄的一段：底色近黑、卡片是深一點的灰、框線是再淺一點的灰、文字是灰。整頁真正的白色只有按鈕和幾行字。

沒有顏色的時候，能用的只有明度的落差、面積和材質。現在三樣都沒用到：沒有大面積的白、沒有照片、沒有光。Pro 場景那一排反而是全頁最吸引眼睛的地方，因為那裡有一張白底的卡和一個發光的星雲。

### 2.4 產品的賣點在靜止畫面裡看不到

SunUI 賣的是動效和手感，這兩樣都要時間和觸碰才感覺得到。元件牆上的東西雖然自己在動，但動作小、灰階、同時有二十個在動，眼睛沒有地方停。訪客也沒有被邀請去碰任何東西。

animations.dev 的做法值得注意：它的頁面幾乎全是文字，但第一屏下面就放了一個很小的左右對照，旁邊寫「你說得出右邊為什麼感覺比較好嗎」。它不展示數量，它讓你自己感覺到差別。SunUI 其實有同樣的東西（「差在哪裡」的對照），卻放在第四段、做得最小。

### 2.5 要賣的東西最小

Pro 場景是整頁要賣的，而且是整頁的構圖（主視覺、結帳流程、購物車抽屜）。把一整頁的場景縮進 330px 的卡片，看起來就和免費的小按鈕一樣大。Aceternity 把成品頁面做成一整面往右衝出螢幕的牆，React Bits 把一個背景鋪滿整個主視覺。

## 3. 並排比較

| | SunUI | 有記憶點的那幾站 |
|---|---|---|
| 首屏主角 | 沒有，二十張等大的卡片 | 一樣東西（波浪、弧形卡片、流體、粒子球） |
| 標題位置 | 置中，下面接牆 | 靠左、壓在視覺上、或大到撐滿寬度 |
| 最大與最小元素的落差 | 小 | 很大 |
| 明度範圍 | 近黑到深灰 | 純黑到純白，或有一塊亮的面積 |
| 訪客第一個能做的動作 | 按「瀏覽 194 個區塊」離開首頁 | 在首屏就能碰一樣東西 |
| 往下捲的變化 | 同一種格線重複四次 | 每段的版面都不同 |
| 有沒有人的聲音 | 沒有 | Osmo 放創作者本人，Devouring Details 用第一人稱寫，animations.dev 掛作者名字 |

## 4. 建議的方向

原則：不加顏色、不回到紙感、不新增免費區塊。用的都是已經有的 Pro 場景和網站自己的元件。

### 4.1 首屏換成一個招牌：太陽調光

SunUI 的名字是 Sun，全站只有黑和白，而且 Pro 裡已經有日夜主視覺、主題揭幕切換、色溫開關、桌燈調光場景。這四樣指向同一個點子：**首屏放一個很大的調光器，訪客拖它，整個首頁從黑夜亮到白天。**

- 這一招只有 SunUI 做得了：別的站有顏色所以不會把明暗當主角，SunUI 只有明暗。
- 它直接回應 2.3：純黑到純白的整段明度，第一次出現在首頁上。
- 它直接回應 2.4：訪客在首屏就動手，手感是自己拖出來的，不是看別人演。
- 它不是 2026-11-19 被否決的那個展示台：沒有傾斜、沒有自動游標、沒有分頁列。只有一個可以拖的東西和跟著變的頁面。
- 沒有人動手時，它自己很慢地呼吸一次當作提示，碰了就交給訪客。

標題改成靠左或壓在視覺上，字級再大（桌機 120px 以上），先把輪廓和 shadcn 分開。

備案（比較省工）：把「差在哪裡」的對照搬到首屏，放大到滿寬，讓拖那條線成為訪客的第一個動作。它已經做好了，缺點是內容是一張優惠券，份量比調光小。

### 4.2 元件牆降級

元件牆不拿掉，但不當首屏。移到第二段或第三段，當作「裡面有什麼」。同時把二十張等大的卡片改成有大有小：兩三張放大成兩欄寬（購物車、長條圖、倒數），其餘維持小張。

### 4.3 Pro 場景放大

從「十張縮圖」改成「三到四個大場景」，每個至少半個螢幕寬，最好的那一個滿版。挑畫風一致的。一個場景配一句話就夠。其餘的用一顆按鈕帶到 `/blocks`。

### 4.4 節奏

每一段換一種版面，不要連續兩段都是四欄卡片。可以是：滿版招牌、對照（左右各半）、大場景、密集的小元件牆、一句話的 agent 示範、價格。大的和密的交替。

### 4.5 加一點人的聲音

頁尾現在寫「由 Sun 製作」。可以在中段放兩三行第一人稱的話，講為什麼不做閃爍的東西。這是標題那句話的來源，目前整頁沒有任何地方解釋它。

## 5. 先後順序

| 順序 | 做什麼 | 為什麼先做 |
|---|---|---|
| 1 | 首屏招牌（4.1），先做一個粗的版本看感覺 | 這是「普通」的主因，其他都是加分 |
| 2 | Pro 場景放大（4.3） | 直接影響賣不賣得出去 |
| 3 | 元件牆降級與大小不一（4.2）、節奏（4.4） | 解決捲動時的單調 |
| 4 | 人的聲音（4.5） | 最便宜，最後補 |

第 1 步做完應該先停下來看，因為招牌對不對要用眼睛判斷，寫再多也沒用。

## 6. 沒有確認的事

- 開發伺服器在截圖途中自己結束了，所以免費區塊第二排卡片一度是空白的。這是不是正式環境也會發生的載入問題，沒有確認。
- 只看了桌機 1440 寬、深色、繁體中文。手機和淺色沒有看。
- 八個參考站都只看了首屏和往下兩到三屏，沒有看到底。
- 「太陽調光」是推論出來的方向，還沒有做任何原型。它會不會好看，要做出來才知道。
- 沒有任何轉換率數據，這裡講的「吸引人」是視覺上的判斷。
