# 網站外殼的動效規範

> 這份管的是 SunUI 網站本身（頁首、型錄、面板、首頁開場、文件頁），不是 block。
> block 的動畫看 `DESIGN.md`、`DESIGN-motion.md`。一個 UI 庫的官網，手感就是產品展示：寧可少動、動得準，也不要多動、動得慢。

## 一句話

**動畫只用來說明因果，不用來表演。** 使用者按了什麼，畫面在 200ms 內回應；沒按的東西不要自己動。首頁的例外寫在 §6。

## 1. 時長與曲線（tokens）

同一組數字寫在兩個地方，改一邊要改另一邊：
CSS 在 `app/globals.css` 的 `@theme`（`ease-site` 曲線，並把預設 transition 設成 150ms + 這條曲線，所以 `transition-colors` 不用另寫時長），JS 在 `lib/motion.ts`（`EASE_SITE`、`DURATION`）。CSS 端其他時長用 `duration-100` / `duration-200` / `duration-300`。

| 用途 | 時長 | 例子 |
|---|---|---|
| `press` 按下回饋 | 100ms | 按鈕 `active:scale-[0.97]` |
| `fast` 狀態變化 | 150ms | hover 底色、文字顏色、圖示切換 |
| `base` 小元件進出 | 200ms | 下拉、提示、遮罩淡入 |
| `panel` 面板開合 | 260ms 開、180ms 關 | 區塊面板、側欄 |
| `reveal` 內容淡入 | 300ms | iframe 預覽載入完成 |

- 曲線只有一條：`cubic-bezier(0.23, 1, 0.32, 1)`（快出慢停）。退場用 `ease-in` 的鏡像也可以，但不另造曲線。
- 不用彈簧做版面變形。彈簧只留給跟著游標或手指的東西（視差、拖曳）。
- 退場比進場短：使用者關掉一個東西時，已經在想下一件事。

## 2. 禁止

- **不做會擋住內容的開場。** 首頁標題與按鈕在第一幀就要看得到、可以點。
- **不對含 iframe、影片、canvas 的容器做縮放變形**（含 framer-motion `layoutId`）。縮放會拉伸內容、強迫重新繪製，看起來就是卡。只做 opacity 與小位移（≤ 12px）。
- **不做整頁截圖式轉場**（View Transitions 全頁 crossfade）。頁面上有大量預覽 iframe，截圖本身就會卡一下。
- 不用 `transition-all`。寫明要動的屬性：`transition-colors`、`transition-opacity`、`transition-[opacity,translate]`。
- 不讓常駐動畫在畫面外或分頁在背景時繼續跑。

## 3. 一定要有

- 每個可點的東西都有 hover（有滑鼠時）與 `focus-visible` 樣式，兩者明顯但不跳動。
- 目前所在的頁面、選中的選項，要有靜態可見的標示，不只靠動畫。
- `prefers-reduced-motion`：保留淡入淡出，拿掉位移、縮放、旋轉與常駐循環。
- 首頁開場的規則在 §6。2026-11-19 拿掉了紙牆，不要再鋪縮圖牆或 3D 傾斜的卡片牆。
- 重複造訪不重播：開場類動畫在同一次瀏覽（sessionStorage）只播一次。

## 4. 載入中的東西

- 佔位與真內容尺寸一致，換上時只淡入，不位移。
- 佔位不閃：骨架的脈動要慢（≥ 2s 一輪）且對比低；載入很快時（< 150ms）不顯示骨架。
- 同一列的卡片不要各自決定什麼時候出現：進入畫面的那一刻一起開始載入，淡入時長一致。

## 5. 外殼材質（2026-11-18 起）

網站外殼是「精密的物件」：黑白灰、不准裝飾性漸層、光暈、彩色陰影、毛玻璃內容層，但物件有厚度。2026-11-19 起 block 也用同一套質感語言（`DESIGN.md`），這一節只列外殼的實際數值。分析見 `reports/網站質感升級深度分析-2026-11-18.md` 與 `reports/拋棄紙感全面改質感深度分析-2026-11-18.md`。

- **邊線**：外殼用 `border-line`（透明度 9% / 深色 10%），比較強的用 `line-strong`。block 用的 `--border` 維持實色，型錄外觀不變。
- **高度**：只用 `globals.css` 的四個陰影，每一層都已含 1px hairline，不要再疊 `border`。
  - `shadow-hair`：只有邊線。
  - `shadow-e1`：卡片、預覽框、次按鈕、指令列、分段控制的選中格。
  - `shadow-e2`：hover 的卡片、強調的定價卡。
  - `shadow-e3`：面板、對話框。
  - 深色模式不靠投影，改成頂邊 1px 白色高光加邊線，tokens 已經處理好。
- **按鈕**：主按鈕 `btn-primary`、次按鈕 `btn-secondary`（含 hover、按下 0.97、內高光）。不要再手寫 `bg-fg text-bg hover:opacity-90`。
- **分段控制**：軌道 `bg-accent-soft p-0.5 rounded-md`，選中格 `bg-card shadow-e1 rounded-[4px]`（同心：6 − 2 = 4），不用整塊黑底。
- **圓角**：控制項 6px（`rounded-md`），卡片與預覽框 12px（`rounded-xl`），面板 16px（`rounded-2xl`）。巢狀時內圓角 = 外圓角 − 內距。
- **字重**：`font-medium` 是 510、`font-semibold` 是 590（Geist 可變字重）。
- **字體**：`body` 直接讀 `--font-geist-sans`。`@theme inline` 不會在 `:root` 產生 `--font-sans`，不要改回 `var(--font-sans)`。
- **焦點環**：全站 `outline-offset: 2px`，和元件之間留間隙。

## 6. 首頁（2026-11-19 重製）

整個首頁照 `reports/首頁全面重製完整規劃-2026-11-19.md` 重做過。傾斜展示台、自動示範游標、分頁列都已拿掉，不要加回來。

- **首頁是展示，不是介紹**：開場（一個完整區塊）、更多完整場景、免費區塊、比較示範、交給 agent、價格、收尾。完整型錄在 `/blocks`。不加品牌牆、推文牆、FAQ、功能說明卡這類「用講的」段落，除非有真的材料。理由見 `reports/元件庫首頁設計深度分析-2026-11-19.md`。
- **每段的開頭只有一層**：兩到四個字的標題，右邊最多一個按鈕（`page.tsx` 的 `SectionHead`）。不加小標，不加說明段落。段與段之間 `mt-24 sm:mt-32`。
- **完整場景，不縮成小卡**（2026-11-20）：`SHOWCASE` 第一個是開場，其餘由 `components/home/full-scenes.tsx` 接在開場下面，把做好的整個畫面（玻璃方塊首屏、日夜首屏、弧線首屏、結帳流程）用 `LivePreview mode="sheet"` 原尺寸跑，一個接一個鋪滿寬度，每個高 `clamp(560px, 86svh, 980px)`，下面一行是名稱和「看這個區塊」。使用者否決了把 Pro 場景縮成格線小卡：首頁要讓人看到完整的內容，不是一格一格普通的 UI。Pro 資料夾不在時改放免費的完整區塊。
- **展示段落也滿寬**：免費區塊、交給 agent 兩段和元件牆一樣鋪到螢幕兩邊，格線欄數 1、2、3、4、5。每一列都要排滿：傳 10 張卡，用 `page.tsx` 的 `showAt` 依欄數隱藏多出來的。比較示範與價格卡是單一物件，維持置中、有上限寬度。
- **自訂斷點用 rem**：第五欄的斷點寫 `min-[106.25rem]`，不要寫 `min-[1700px]`。px 和內建的 rem 斷點比不出先後，會被 `xl:` 的規則蓋掉。
- **數字寫在按鈕上**：主要按鈕是「瀏覽 N 個區塊」，不另外做數字卡。
- **只有黑白灰**：首頁和全站一樣不用任何彩色。2026-11-19 試過琥珀色重點色，和整體不搭，已經拿掉，不要再加品牌色或彩色按鈕。主要按鈕是 `btn-primary`，次要是 `btn-secondary`。
- **預設深色**：使用者沒選過主題時是深色（`lib/theme.ts` 的 `defaultDarkScript`，網站與預覽 iframe 的 layout 都有放）。
- **開場**（2026-11-20 第二次重做）：`components/home/scene-opening.tsx`。第一個畫面就是一個完整的區塊（新品發表主視覺，`LivePreview mode="sheet"` 原尺寸跑，可以直接操作），高度補滿第一個畫面。上面只留一條窄的介紹列：左邊標題（`clamp(32px, 3.4vw, 56px)`）和一句話，右邊兩顆按鈕。使用者選了這個，否決太陽調光開場和自製小卡：第一眼要看到做好的整個畫面，不是普通的 UI。太陽調光（`sun-dimmer.tsx`）與即時元件牆（`live-wall.tsx`）不再放在首頁，下面兩條是它們當時的規則，留著備查。
  - 不要改回置中標題加元件牆：那個構圖和 shadcn 首頁一樣。
  - **標題字級** `clamp(40px, 4.6vw, 80px)`，靠左，每個片語一行。不要再放大：第一版做到 160 到 208px，被否決（太大）。同寬度下量到的競品標題是 40 到 72px（shadcn 48、React Bits 54、Linear 64、Magic UI 72），而且中文字是滿格方塊，同樣的 px 看起來比英文大。
  - **首屏要是滿的**：第二版只有小標題加一顆平的白圓，被否決（上面一大塊空白，圓也不特別）。主視覺一定要有真的產品內容，而且要看得出材質。
- **開場的場景**（`components/home/hero-scene.tsx`）：七張即時卡片像桌上的物件，前後交疊，右邊和下面被切掉。卡片就是元件牆的那些（從 `live-wall.tsx` 匯出），照樣自己動、可以操作；牆用 `staged` 略過這七張。
  - 每張卡包在 `Lit` 裡，`depth` 1 到 3 是離桌面的高度。光由四個 CSS 變數決定：`--lx` / `--ly`（光在卡片座標裡的位置）畫表面的亮面與朝光那一側的邊緣反光，`--shx` / `--shy` 是影子的偏移。
  - 深色靠亮面與邊緣反光（黑底上黑影子看不到），淺色靠影子。兩種都只有黑白灰。
  - 卡片可以互相壓到，但不要蓋住別張卡的標題。手機只放三張。
- **太陽**（`components/home/sun-dimmer.tsx`，2026-11-20 起不在首頁）：它是光源，不是裝飾。
  - **拖曳**：太陽跟著指標走，每一幀把位置寫進開場段落的 `--sun-x` / `--sun-y`，並替每張 `[data-lit]` 卡片重算上面四個變數。放手後留在原地。
  - **按一下**（或鍵盤 Enter）：光圈從太陽擴到整個畫面（0.7 秒），蓋滿的那一幀呼叫 `commitSiteTheme`（`theme-menu.tsx`，和頁首按鈕同一個函式）並把圓收回原本大小。
  - 光圈是一顆白色的圓加 `mix-blend-mode: difference`。全站只有黑白灰，差值反相就等於另一個主題，所以整頁不用畫兩次。淺色時同一顆圓是黑的。
  - 開場那一段和它的祖先不能有 `transform`、`opacity`、`filter`、`z-index`、`isolation`：中間多一層 stacking context，光圈就反相不到頁首和其他段落。
  - 起始位置由段落上的 CSS `--sun-x`、`--sun-y`、`--sun-d` 決定。沒人碰過時繞著起始位置慢慢轉（16 秒一圈），光掃過卡片；第一次拖或按就停。reduced motion 下不轉，切換不播動畫。
  - 深色時太陽周圍有一圈光暈照在桌面上（`home-hero.tsx` 裡的 radial-gradient），DOM 順序要在場景前面，才會畫在卡片下面。
  - 圓不接事件，上面另外疊一顆透明按鈕負責拖曳與焦點。
- **即時元件牆**（`components/home/live-wall.tsx`，2026-11-20 起不在首頁）：一整面小場景，像一家真的店正在運作。不進 registry。規則：
  - **滿寬**：跳出頁面的 `max-w` 容器，鋪到螢幕兩邊。欄數隨寬度 1、2、3、4、5。不要收回窄欄裡。
  - **要被切掉**：牆比一個畫面高，下緣裁掉並淡出，讓人知道下面還有。卡片不夠多時加卡片，不要縮短高度。
  - **卡片比底色亮一階**（深色是 `#151515` 對 `#0a0a0a`），裡面用實心的黑白按鈕和大數字，對比要夠。
  - **每張卡是一個組好的場景**，資料填滿（商品名、價格、訂單編號），不是一個孤立的控制項加一個標籤。
  - 每張卡只重複一個動作，節拍 0.7 到 5.2 秒，各卡的起始時間錯開。
  - 滑鼠或鍵盤焦點進入某一張，那一張立刻停止自動播放；離開 2.6 秒後才繼續。其他卡不受影響。
  - 整面牆不在畫面上、分頁在背景、`prefers-reduced-motion` 時都不自動播放，卡片照樣可以操作。
  - 只用明度與材質表達狀態（實心變描邊、明暗），不用彩色。
  - 沒有進場動畫：牆和標題同一幀出現。
  - 2026-11-20 起牆不是開場，接在開場下面，上緣從第一個畫面底部露出來。
  - 這個做法的由來：和 shadcn、Linear、Aceternity 等站同尺寸並排比較後，差距在寬度、密度、對比、內容真實感與層次，不在段落順序。見 `reports/元件庫首頁設計深度分析-2026-11-19.md` 的更正段。
